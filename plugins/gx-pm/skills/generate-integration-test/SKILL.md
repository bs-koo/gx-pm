# 통합테스트 시나리오 생성 (generate-integration-test)

요구사항정의서(AN-02)와 화면목록표(DE-03)를 기반으로, 업무 흐름에 따른 통합테스트 시나리오를 생성한다. 단순 CRUD가 아닌 업무 프로세스 기반의 시나리오를 작성한다.

## 입력

- 요구사항정의서 데이터 (필수)
- 화면목록표 데이터 (필수)
- 화면정의서 내용 (선택 — 더 정확한 시나리오 생성)

추가 확인:
- 시스템 코드 (A~I)
- 주요 사용자 역할 (관리자, 일반사용자, 민원인 등)

## 처리 절차

### Step 1: 요구사항-화면 매핑 확인
요구사항정의서의 각 요구사항이 어떤 화면에 매핑되는지 확인:
- 이미 추적매트릭스가 있으면 참조
- 없으면 요구사항 내용과 화면명을 기반으로 매핑 추론

### Step 2: 시나리오 그룹핑
관련 요구사항과 화면을 업무 흐름으로 그룹핑:
- 같은 업무 프로세스에 속하는 화면들을 하나의 시나리오로 묶음
- 예: "과정 등록 → 대상자 배정 → 교육 실시 → 결과 확인" = 1개 시나리오

### Step 3: 통합테스트ID 부여
- 패턴: `{시스템코드}-TE-{3자리순번}`
- 예시: `A-TE-001`
- 시나리오 단위로 부여 (Step이 아닌 시나리오에 ID)

### Step 4: Step 분해
각 시나리오를 구체적인 Step으로 분해:

각 Step에 포함할 내용:
- **Step 번호**: 1, 2, 3...
- **사용자구분**: 이 Step을 수행하는 역할
- **예상 입력 (사용자 행위)**: 사용자가 하는 구체적 행동
  - "~메뉴 클릭", "~버튼 클릭", "~입력 후 저장"
- **예상 출력 (시스템 결과)**: 시스템이 보여주는 결과
  - "~리스트 조회", "~팝업 호출", "~등록 완료 메시지"

### Step 5: 테스트 데이터 제안
각 시나리오에 필요한 테스트 데이터를 제안:
- 사전 등록 필요 데이터
- Step에서 입력할 테스트 값

## 출력 형식

```
## 통합테스트시나리오 — {시스템명}

### {시나리오명} (통합테스트 ID: A-TE-001)

| 통합테스트 ID | 요구사항 ID | 시나리오명 | Step | 사용자구분 | 예상 입력 (사용자 행위) | 예상 출력 (시스템 결과) | 테스트 데이터 |
|-------------|-----------|-----------|------|----------|---------------------|---------------------|-------------|
| A-TE-001 | SFR-030 | 운영자 권한 관리 | 1 | 관리자 | 운영자 권한 관리 메뉴 클릭 | 운영자 권한 리스트 조회 | |
| | SFR-030 | | 2 | 관리자 | 권한-메뉴 매핑 버튼 클릭 | 권한코드, 권한명 조회 및 매핑 팝업 호출 | |
| | SFR-030 | 코드관리 | 1 | 관리자 | 코드관리 메뉴 클릭, 등록 버튼 클릭 | 코드 리스트 조회, 등록 팝업 호출 | |
```

## 시나리오 작성 원칙

1. **업무 흐름 기반**: 단순 CRUD가 아닌 실제 업무 프로세스를 반영
2. **End-to-End**: 시작부터 완료까지의 전체 흐름
3. **사용자 관점**: 기술 용어가 아닌 사용자 행위로 기술
4. **구체적 행위**: "데이터 입력" (X) → "과정명, 교육기간 입력 후 저장 버튼 클릭" (O)
5. **기대 결과 명확**: "정상 동작" (X) → "과정 리스트에 신규 등록 과정 표시" (O)

## 체크포인트

시나리오 구성을 사용자에게 확인:
"다음 시나리오 구성이 맞는지 확인해주세요:
- A-TE-001: 운영자 권한 관리 (4 Steps)
- A-TE-002: 코드/메뉴 관리 (6 Steps)
- ..."
