# 프로젝트 프로파일 로드 (load-project-profile)

모든 커맨드의 **Step 0**에서 자동 호출되는 스킬.
작업 폴더에서 프로젝트 프로파일을 찾아 로드하고, 이후 커맨드가 프로파일 정보를 활용할 수 있게 한다.

---

## 입력

- 현재 작업 폴더 경로 (자동)

---

## 처리 절차

### Step 1: 프로젝트 폴더 스캔

작업 폴더 자체 및 **직속 하위 디렉토리**를 스캔하여 `profile.json`이 존재하는 폴더를 모두 찾는다.

```
Glob 패턴: profile.json, */profile.json
```

### Step 2: 프로젝트 수에 따른 분기

#### 프로젝트가 0개인 경우

**AskUserQuestion 도구**로 다음을 안내하고 커맨드를 종료한다:

```
프로젝트 설정이 없습니다.
/gx-프로젝트설정 을 먼저 실행하여 프로젝트를 생성해주세요.
```

#### profile.json 파싱 에러 또는 필수 필드 누락인 경우

profile.json 파일이 존재하지만 JSON 파싱에 실패하거나, 필수 필드(`name`, `type`, `systemCode`, `prefix`, `framework`, `db`, `author`, `networkType`)가 누락된 경우:

**AskUserQuestion 도구**로 다음을 안내한다:

```
프로젝트 설정 파일({프로젝트폴더}/profile.json)을 읽을 수 없습니다.
원인: {JSON 파싱 에러 메시지 또는 "필수 필드 누락: systemCode, prefix"}
기존 파일을 backup/에 보존한 뒤, /gx-프로젝트설정 을 다시 실행해주세요.
```

손상된 profile.json을 `backup/profile_{YYMMDD}.json`으로 복사한 뒤, `/gx-프로젝트설정` 재실행을 안내한다.

#### 프로젝트가 1개인 경우

해당 프로파일을 로드한다.

**자동 활성화 조건**: `date +%Y-%m-%d` 명령으로 오늘 날짜를 확인한 뒤, `lastUsed`와 같으면 확인 없이 자동 활성화하고 간단히 안내만 한다:

```
프로젝트: {프로젝트명} ({유형라벨})을 사용합니다.
```

**확인 요청 조건**: `date` 명령으로 확인한 오늘 날짜가 `lastUsed`와 다르면 (새로운 날에 처음 사용), 확인을 요청한다:

프로젝트 정보를 출력한 후, **AskUserQuestion 도구**로 확인을 요청한다:

```
프로젝트: {프로젝트명} ({유형라벨})
시스템코드: {systemCode} / 접두어: {prefix}
프레임워크: {framework} / DB: {db}
소스경로: {sourcePath 또는 "없음"}
감리: {auditDate 또는 "없음"}

이 프로젝트로 진행할까요?
(다른 프로젝트를 만들려면 /gx-프로젝트설정 실행)
```

사용자가 승인하면 해당 프로파일을 활성화한다.

#### 프로젝트가 2개 이상인 경우

목록을 표시하고 선택을 요청한다:

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
프로젝트 {N}개를 찾았습니다:

  1. {프로젝트명1} ({유형라벨}, 마지막 작업: {lastUsed})
  2. {프로젝트명2} ({유형라벨}, 마지막 작업: {lastUsed})
  ...
  ─────────────
  N. 새 프로젝트 생성 (/gx-프로젝트설정 실행)

어떤 프로젝트로 작업할까요?
```

사용자가 번호를 선택하면 해당 프로파일을 활성화한다.

### Step 3: 프로파일 활성화

선택된 프로파일을 로드하고:
1. `lastUsed`를 오늘 날짜로 갱신하여 profile.json에 저장
2. 이후 커맨드 워크플로우에서 다음 값들을 자동 사용:
   - `systemCode` → 산출물 파일명, ID 접두어
   - `prefix` → 화면ID 접두어
   - `framework` → 프로그램정의서 소스파일 구조
   - `db` → DDL 문법, 데이터타입
   - `type` → 커맨드 워크플로우 분기 (정방향/역방향/병합)
   - `assets.sourcePath` → 소스코드 스캔 경로
   - `author` → 산출물 작성자명

### Step 4: 프로젝트 폴더 확인

활성 프로젝트의 폴더 구조를 확인한다:
- `backup/` 폴더가 없으면 생성 안내
- `xlsx/` 폴더가 없으면 생성 안내
- 기존 산출물 파일 목록을 파악 (후속 스킬에서 사용)

---

## 출력

활성화된 프로파일 정보를 반환한다. 이후 커맨드의 모든 Step에서 이 정보를 참조한다.

---

## 주의사항

1. **매 커맨드 실행 시 호출**: 모든 커맨드의 Step 0에서 이 스킬을 먼저 실행한다
2. **프로파일 없으면 진행 불가**: 프로파일이 없는 상태에서는 어떤 커맨드도 실행하지 않는다
3. **프로파일 정보 재질문 금지**: 프로파일에 이미 있는 정보(시스템코드, 접두어 등)를 사용자에게 다시 물어보지 않는다
4. **설정 변경은 /gx-프로젝트설정으로**: 프로파일 값을 변경하려면 `/gx-프로젝트설정`을 다시 실행하도록 안내한다
