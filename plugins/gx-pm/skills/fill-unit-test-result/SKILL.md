# 단위테스트 결과 기입 (fill-unit-test-result)

단위테스트계획서(DE-13)를 기반으로 테스트 수행 결과를 기입하여 단위테스트결과서(IM-03)를 완성한다.
결과서는 계획서와 동일한 구조(화면 목록, 검사항목 27개)를 유지하되, 검사기준 칸에 적합/부적합/점검제외가 채워진다.
계획서에서 배정된 "해당없음"은 그대로 유지된다.

---

## 검사항목 구조 (총 27개)

| 구분 | 항목 수 |
|------|--------|
| 공통부문 | (1)~(8) |
| 조회 | (1)~(4) |
| 입력 | (1)~(6) |
| 수정 | (1)~(2) |
| 삭제 | (1)~(2) |
| 첨부파일 | (1)~(3) |
| 출력 | (1)~(2) |

> **항목명·예상결과·판정기준·점검방법은 `templates/inspection-criteria.md`가 단일 정본이다.**
> 이 파일에 항목명을 중복 정의하지 않는다 — 계획서(`generate-unit-test-plan`)와 정의가 어긋나면
> 계획서에서 배정한 "해당없음"이 결과서에서 엉뚱한 항목번호에 붙는다.

> "해당없음"은 계획서(DE-13) 작성 시 이미 결정된 것을 유지한다. 결과서 작성 단계에서 변경하지 않는다.

## 판정값 — 4종

| 값 | 정하는 시점 | 의미 | 사유 기재 |
|------|-----------|------|---------|
| 해당없음 | 계획서 | 이 화면 유형에 적용 대상이 아님 | 불필요 |
| **적합** | 결과서 | 판정기준 충족 | 불필요 |
| **부적합** | 결과서 | 판정기준 미충족 | **결함ID 발급 필수** |
| **점검제외** | 결과서 | 적용 대상이나 이번에 확인 불가 | **사유 필수** |

### 점검제외 인정 사유 (그 외는 인정되지 않음)

- 테스트 환경 미준비
- 선행 기능 결함으로 진입 불가
- 외부 환경 변화 (연계기관 시스템 미개방 등)
- 과업 범위 외 판정 (발주처 협의 근거 필요)

> "시간 부족"은 점검제외가 아니라 **미수행**이다. 미실행 케이스는 종료기준(실행률 100%)에 걸린다.

## Step 1: 기본 정보 수집

사용자에게 다음 정보를 확인한다.

```
- 프로젝트명:
- 시스템명:
- 테스트 실시자 (전체 동일이면 1명, 화면별로 다르면 "화면별 입력" 선택):
- 테스트 일자 (전체 동일이면 1개 날짜, 화면별로 다르면 "화면별 입력" 선택):
- 결재선 (작성자 / 검토자 / 승인자):
```

---

## Step 2: 입력 모드 선택

다음 3가지 모드 중 하나를 선택하도록 안내한다.

```
[단위테스트 결과 입력 모드를 선택하세요]

1. 전체 적합
   - 모든 "해당있음" 항목을 일괄 "적합"으로 기입
   - 부적합 항목이 없는 경우 사용

2. 부적합 목록 입력
   - 부적합 항목만 입력하고, 나머지는 자동으로 "적합" 처리
   - 권장 방식: 부적합이 소수일 때

3. 항목별 입력
   - 화면별로 하나씩 확인하며 입력
   - 정밀 입력이 필요할 때 사용
```

---

## Step 3-A: 전체 적합 처리

모드 1 선택 시:
- 계획서의 모든 "해당있음" 항목 → "적합" 기입
- "해당없음" 항목 → 그대로 유지
- 테스트 실시자, 테스트 일자 → Step 1에서 수집한 값으로 일괄 기입
- 부적합 관련 컬럼(부적합 내역, 결함ID, 점검제외 사유)은 공란

---

## Step 3-B: 부적합 목록 입력 처리

모드 2 선택 시, 다음 형식으로 부적합 항목을 입력받는다.

```
[부적합 항목 입력 형식]
화면ID | 구분 | 항목번호 | 부적합 내역 | 테스트일자 | 실시자

예시:
EHR_01_01_020 | 입력 | (4) | 중복 권한코드가 오류 없이 저장됨 | 2026-04-10 | 홍길동
```

- 입력된 항목 → "부적합" 기입 후 **manage-defects 호출 → 결함ID 발급**
- 원인·조치·조치일·조치자는 여기서 받지 않는다 (결함관리대장 DF-01에서 관리)
- 나머지 "해당있음" 항목 → 자동 "적합" 처리

---

## Step 3-C: 항목별 입력 처리

모드 3 선택 시, 화면 단위로 순서대로 확인한다.

```
[화면: EHR_01_01_020 운영자 권한 등록]
공통부문 (1)~(8) 결과를 입력하세요.
(해당없음 항목은 자동 스킵됩니다)

공통(1) 표준 준수:  [적합/부적합/점검제외]
공통(2) 정상 표출:  [적합/부적합/점검제외]
공통(3) 화면 이동:  [적합/부적합/점검제외]
...

→ 부적합 발생 시 즉시 결함 등록(manage-defects), 점검제외 시 사유 입력 요청
```

> 항목명은 `templates/inspection-criteria.md`의 정본을 그대로 출력한다.
> 이 파일에서 항목명을 지어내지 않는다.

---

## Step 4: 부적합 항목 처리 — 결함관리대장 연계

부적합 판정이 나오면 **manage-defects 스킬을 호출**하여 결함ID를 발급하고 DF-01 결함관리대장에 등록한다.
결과서에는 **결함ID만 참조**하고, 원인·조치·재테스트 이력은 대장에 기록한다.

| 기록 위치 | 내용 |
|---------|------|
| **결과서(IM-03)** | 부적합 내역(현상) + 결함ID |
| **결함관리대장(DF-01)** | 심각도·우선순위·상태·재현절차·원인·조치·재테스트 |

### 왜 대장으로 분리하나

- 같은 원인의 결함이 여러 화면에서 나와도 **하나의 결함ID로 병합**된다
- 심각도·우선순위가 생겨 조치 순서를 문서로 설명할 수 있다
- 재테스트 이력이 남아 "고쳤다"는 주장에 근거가 생긴다
- 결함 통계로 **종료기준 판정**이 가능해진다

> 종전에는 결과서 안에 원인·조치를 직접 적었다. 그 방식은 중복 기록과 통계 부재 문제가 있어
> v1.5.0부터 대장으로 분리했다. **결과서에만 있고 대장에 없는 결함은 감리 지적 대상**이다.

부적합 입력 시 결과서에 기입할 최소 항목:

| 필드 | 내용 | 예시 |
|------|------|------|
| 검사결과 | 부적합 | 부적합 |
| 부적합 내역 | 발생한 현상 | "중복 권한코드 저장 시 오류 없이 등록됨" |
| **결함ID** | manage-defects가 발급 | B-DF-001 |

조치 완료 여부는 대장의 **상태(Open~Closed)**로 관리한다. 결과서에 "조치중"을 별도로 적지 않는다.

## Step 6: 결과 통계 산출 및 종료기준 판정

결과서 하단에 다음 통계를 자동 산출하여 표시한다.

```
[단위테스트 결과 통계]

검사기준 항목
  총 항목 (해당있음): N건
  - 적합:     N건 (X%)
  - 부적합:   N건 (X%)
  - 점검제외: N건 (X%)  ← 사유별 내역 첨부
  해당없음:   N건

테스트케이스
  총 케이스: N건 (정상 N / 경계 N / 예외 N)
  - 적합:     N건
  - 부적합:   N건
  - 점검제외: N건
  실행률: (적합+부적합) / 전체 × 100 = X%

적합률: 적합 / (적합 + 부적합) × 100 = X%
발급 결함: N건 (Critical N · Major N · Minor N · Trivial N)
```

### 종료기준 판정 (TE-01 §7 대조)

총괄 테스트계획서가 있으면 그 종료기준으로 판정한다. 없으면 기본값을 쓴다.

```
[종료기준 판정]

| 기준 | 목표 | 현재 | 판정 |
|------|------|------|------|
| 케이스 실행률 | 100% | N% | 충족 / **미충족** |
| Critical 결함 잔존 | 0건 | N건 | 충족 / **미충족** |
| Major 결함 잔존 | 0건 | N건 | 충족 / **미충족** |
| Minor 결함 조치율 | 90% 이상 | N% | 충족 / **미충족** |
| 적합률 | 95% 이상 | N% | 충족 / **미충족** |

종합: 통합테스트 진입 가능 / **진입 불가**
```

미충족이면 다음을 안내한다:

```
단위테스트 종료기준을 충족하지 않아 통합테스트 진입 조건을 만족하지 않습니다.

  미조치 Critical: {결함ID 목록}
  미조치 Major: {결함ID 목록}
  미실행 케이스: {N}건

  1. 결함 조치 후 재판정
  2. PM 승인으로 진입 (사유가 기록됩니다)
```

결과서 출력 전 다음 항목을 사용자에게 확인한다.

```
[최종 확인]

   → 미조치 항목 목록을 함께 표시

2. 테스트 실시자 / 일자가 화면별로 다릅니다. 일괄 적용하시겠습니까?
   → 화면 목록과 현재 입력값 표시

3. 결과서를 최종 확정하시겠습니까? (확정 후에는 수정이 어렵습니다)
```

## 주의사항 및 규칙

1. **검사기준 항목명은 `templates/inspection-criteria.md`를 참조**한다. 이 파일에 중복 정의하지 않는다
2. "해당없음"은 계획서(DE-13)에서 결정된 것이므로 결과서 단계에서 임의 변경 금지
3. **"해당없음"과 "점검제외"를 구분**한다 — 전자는 적용 대상이 아닌 것, 후자는 적용 대상인데 못 잰 것(사유 필수)
4. 부적합 항목은 반드시 **결함ID를 발급**한다 (`manage-defects` 호출). 결과서에만 있고 대장에 없는 결함은 감리 지적 대상
5. 원인·조치·재테스트 이력은 결과서가 아니라 **결함관리대장(DF-01)**에 기록한다
6. 적합률이 95% 미만이면 경고 메시지 출력 및 PM 보고 권고
7. 동일 화면에서 동일 항목번호의 중복 입력은 불가
8. 결과서 문서번호 IM-03은 변경 불가 (공공 SI 표준 산출물 코드)
9. 테스트 실시자는 실제 테스트를 수행한 담당자 성명이어야 함 (PM 이름 대리 기입 금지)
10. 종료기준 미충족 상태로 다음 레벨에 진입하려면 **PM 승인 + 사유 기록**이 필요하다
