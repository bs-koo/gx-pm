# 확인요청서 반영 (apply-confirmations)

## 언제 도는가

`/gx-명세일괄` Step 0-2 에서 **「확인요청서 반영하고 이어가기」** 를 고를 때 돈다.
본문을 불필요하게 다시 만들지 않는다. **새 응답만 반영하고 실제 새 질문이 있을 때만 다음 차수를 낸다.**

낱개 커맨드 `/gx-요구사항정의서` · `/gx-기능명세서` · `/gx-테이블정의서` · `/gx-단위테스트계획서` · `/gx-추적매트릭스` 의 Step 0 에서
같은 선택지를 고를 때도 돈다. 그 커맨드가 확인요청서를 다시 뽑기 직전에 이번 실행에서
아직 반영하지 않았으면 그때도 먼저 돈다 — 반영 없이 뽑으면 사람이 xlsx 에 적은 답이
덮인다. 정본은 `templates/confirmation-request.md` §낱개 커맨드에서도 같은 규칙으로 낸다.
낱개 커맨드에서 불렸으면 아래 출력의 `/gx-명세일괄` 자리에 **그 커맨드**를 적는다.

**어느 커맨드에서 불려도 파일 전체를 반영한다.** 확인요청서는 시스템당 하나라
AN-02·AN-03·DE-08·DE-13·AN-05 항목이 섞여 있다. 부른 커맨드의 산출물만 반영하면 답이 적힌
다른 행이 반영 안 된 채 남고, 다음 발행이 그 답을 md 내용으로 덮는다
(`templates/confirmation-request.md` §한 파일 안에서 가르는 법).

착수 협의로 값이 정해진 뒤 다시 부를 수 있다. 같은 파일에 이어 쓰면 된다.
세 번 물은 항목에 답이 오면 해소하되 **그 항목 때문에 차수를 올리지 않는다** —
`templates/confirmation-request.md` §세 번 물은 항목 이 정본이다.

## 왜 이 방식인가

질문을 대화가 아니라 파일로 주고받는 근거와, **되묻기에 대화형 질문 도구를 쓰지
않는다**는 규칙의 정본은 `templates/pipeline-protocol.md` §질문 정책이다.
이 스킬은 그 정책의 실행부다 — 사람이 **엑셀에서 한 번에** 답하고 이 스킬은
**읽고 파급만** 처리한다. 대화 왕복이 1~2회로 준다.

답변이 새 애매성을 만들면 즉시 되묻지 않고 다음 차수 행으로 쓴다.
이것이 왕복을 0으로 만드는 자리다.

## 입력

| 항목 | 필수 | 설명 |
|------|------|------|
| 확인요청서 | Y | `{시스템코드}-확인요청서.md` 또는 사람이 채운 `.xlsx` |
| 가용 산출물 | Y | 응답의 실제 반영 대상. 아직 만들지 않은 후속 문서까지 필수로 요구하지 않는다 |

양식은 `templates/confirmation-request.md` 가 정본이다.

## 처리 절차

### Step 1: 응답 읽기

시트 1 의 `판정`·`정정값`, 시트 2 의 `상태`·`응답` 을 읽는다.
xlsx의 드롭다운은 붙여넣기 등으로 우회될 수 있으므로 실제 값을 검증한다. 중복 항목번호, 잘못된 산출물 코드, 목록 밖 판정·상태, `수정`의 빈 정정값, `확정`의 빈 응답은 그 행만 보류하고 원문을 보존한다. 다른 정상 행은 반영할 수 있다.

읽은 md와 xlsx를 반영 전 백업한다. 미응답 md에 들어온 xlsx 답이나 지난 이력·백업 대비 한쪽만 바뀐 답은 정상 입력이다. 양쪽의 서로 다른 새 답, 또는 기준을 확인할 수 없는 비어 있지 않은 답끼리의 차이만 충돌로 보류한다. 최신 수정 시각만으로 승자를 정하지 않는다. 이미 처리한 동일 응답은 다시 반영하거나 이력·차수를 늘리지 않는다.

**같은 항목은 항목번호로 대조한다.** 시트 1·2 의 행과 시트 3 의 지난 행, 시트 1 에서
시트 2 로 옮긴 행을 `항목번호` 로 잇는다. `위치` 문장은 차수마다 조금씩 달라질 수
있어 키로 쓰지 않는다. 본문의 표식은 `산출물` + `위치` 로 찾는다.

`항목번호` 열이 없는 옛 양식이면 먼저 채운다 — `templates/confirmation-request.md`
§옛 양식 파일.

### Step 2: 분기

| 응답 | 처리 | 되묻나 |
|------|------|--------|
| `맞음` | 가정을 확정으로 승격. `[가정]` 태그를 뗀다 | 아니오 |
| `수정` + 정정값 정상 | 값을 바꾸고 Step 3 으로 | 아니오 |
| `미확정으로` | 값을 걷어내고 `[미확정]` 으로 바꿔 시트 2 로 옮긴다. `항목번호` 는 그대로 | 아니오 |
| **무응답 (빈칸)** | **가정과 항목을 대기로 유지한다.** 승인·반영으로 기록하지 않는다 | 아니오 |
| `확정` + 응답값 | `[미확정]` 을 해소하고 본문에 반영. Step 3 으로 | 아니오 |
| `대기` | 그대로 둔다 | 아니오 |
| `해당없음` | **대장에서만** 지운다. 본문은 손대지 않는다 | 아니오 |
| **값 대신 질문이 왔다** | 아래 §되질문에 답한다 | 아니오 — **파일로 답한다** |

**무응답도 처리 가능한 상태다.** 파일을 보관하고 독립된 작업을 계속할 수 있지만 해당 판단과 문서 최종본은 미완료다. 제시한 CQ 항목 전체를 수락한다는 명시적 지시가 있으면 각 항목에 그 답을 기록한다.

### 되질문에 답한다

응답 칸에 값이 아니라 **질문**이 오는 경우가 있다. 「왜 이게 필요한지 설명해줘」,
「네가 직접 정해줘」, 「어떤 선택지가 있나」 같은 것들이다.

1차 시험에서 실제로 그랬다. `[미확정]` 두 건에 값 대신 자유 텍스트 요청이 달려
왔고, **답변이 대화로만 나가고 파일에는 안 남았다.** 다음에 파일을 여는 사람은
질문만 보고 답은 못 본다 — 이 양식이 대화를 대신하려던 이유가 무너진다.

**대화로 답하지 않는다. 다음 차수 행에 답을 실어 돌려준다.**

| 질문의 성격 | 처리 |
|------------|------|
| 「왜 필요한가」 · 「설명해달라」 | 다음 차수 `물은 것` 에 **답을 먼저 적고** 같은 질문을 다시 낸다 |
| 「네가 정해라」 | **설계 재량으로 넘어온 것**이다. 값을 정해 `[가정]` 으로 바꾸고 시트 1 로 옮긴다 |
| 「선택지를 달라」 | 다음 차수 `AI 가 정한 값` 에 후보를, `근거` 에 각각의 근거를 적어 시트 1 로 낸다 |

시트 3 에는 그 차수를 `되질문` 으로 기록한다. **주고받은 것이 다 남아야 이력이다.**
다시 낸 질문은 **같은 `항목번호`** 이고 `물은 횟수` 가 1 오른다 — 되물어 온 것도 한 번
물은 것이다. 「네가 정해라」로 시트 1 로 옮긴 것도 번호는 그대로다.

「네가 정해라」가 `[가정]` 이 되는 근거는 2단 판정이다 — 값을 우리가 정해도 되는지가
축이고, 정하라는 지시를 받았으면 설계 재량이 맞다
(`templates/evidence-rules.md` §[가정] 과 [미확정] 은 2단 판정으로 갈린다).

`해당없음` 이 본문 행을 지우지 않는 근거는
`templates/AN-02-requirements-definition.md` §상태 판정과 같다 —
**행은 지우지 않고 상태만 바꾼다.** 본문에서 빼려면 `열기` 경로로 명시적으로
지운다. 대장 응답 하나로 산출물 행이 사라지면 되돌릴 근거가 없어진다.

### AN-02·AN-05 응답의 반영 위치

AN-02의 범위·해석 변경은 근거와 해당 요구사항을 함께 갱신하고 기존 ID를 유지한다.
AN-05의 응답은 실제 원인 산출물의 연결·범위 근거에 반영한 뒤 매트릭스를 다시 대조한다.
매트릭스의 누락 칸만 지우거나, 사람이 괜찮다고 했다는 이유로 시험을 Pass로 바꾸지 않는다.
`해당없음`은 질문을 철회할 뿐 본문의 범위·삭제·시험 판정을 자동으로 바꾸지 않는다.

### Step 3: 파급 처리

값이 바뀐 곳은 그 자리만 끝나지 않는다.
`templates/pipeline-protocol.md` §재생성 파급 규칙을 그대로 적용한다.
규칙표는 5줄이고 깊이는 최대 3단(요구사항→기능→테이블→테스트)이라 **유한하다.**

`[가정]` 값이 바뀌면 표식이 선 세 자리를 함께 고친다
(`templates/evidence-rules.md` §표식은 세 홉을 관통한다).

```
AUTHRT_NM 길이 100 → 50 으로 정정
  ↓ AN-03  입력항목 괄호의 [가정] 100자 → 50자
  ↓ DE-08  길이 열 100 → 50, 근거의 [가정] 길이 100 → 50
  ↓ DE-13  UT-089 입력 "권한명 101자 [가정:100]" → "권한명 51자 [가정:50]"
```

`[미확정]` 이 `확정` 으로 바뀌면 **경계 케이스가 새로 생긴다** — 그동안
보강하지 않던 제약이 값을 얻기 때문이다
(`templates/evidence-rules.md` §[미확정] 제약은 자동 보강 대상이 아니다).

### Step 4: 후속 질문을 다음 차수 행으로 쓴다

응답이 새 애매성을 만들면 **묻지 않고 시트 1 에 다음 차수 행을 추가한다.**

| 상황 | `AI 가 정한 값` | `근거` |
|------|----------------|--------|
| `수정` 인데 정정값이 비었다 | 원래 값 | 정정값이 비어 있어 원래 값을 유지했습니다 |
| 형식이 안 맞는다 | 원래 값 | 숫자가 필요한데 문장이 들어왔습니다: "{입력값}" |
| 다른 행과 충돌한다 | 둘 중 하나를 제안 | TB_A.EML 은 100, TB_B.EML 은 255 로 갈립니다 |
| 파급 방향이 갈린다 | 파급 결과 제안 | EML 을 100 으로 정정하셔서 UT-089 경계값을 101 로 바꿉니다 |

```
| CQ-008 | DE-13 | 1 | UT-089 경계값 | 101자로 조정 | EML 을 100 으로 정정하셔서 | | | |
```

후속 질문은 **새 항목**이다 — 파일의 다음 `항목번호` 를 받고 `물은 횟수` 1 로 시작하며,
`산출물` 에는 그 질문이 선 자리(위 예는 DE-13)를 적는다. 원래 항목(EML 정정)은
`반영` 으로 이미 닫혔다.

`판정`을 비워 두면 미응답으로 남긴다. 제안값을 자동 확정하지 않고 그 판단에 의존하는
최종본만 보류한다. 독립된 작업은 계속할 수 있다.

### Step 4-1: 응답과 요청 횟수를 기록한다

시트 3 의 `차수`·`발행일`·`발행처` 는 반영하는 차수의 시트 0 `현재` 에서 옮긴다.
`항목번호`·`산출물` 은 그 행의 값을 그대로 적는다.

| 상황 | 처리 |
|------|------|
| 시트 0 「안내」 | `현재` 차수와 시트별·산출물별 건수를 다시 쓴다. 사람이 파일을 열고 맨 처음 읽는 자리다 |
| 시트 0 의 **다음 차수** | **쓰지 않는다.** 아래 §다음 차수를 예고하지 않는다 |
| 답을 못 받은 항목 | 실제로 다시 제시할 때만 `물은 횟수`를 +1 한다. 파일 재열기·무변경 재반영은 세지 않는다 |
| 새로 생긴 후속 질문 | 새 `항목번호` · `물은 횟수` 1 로 시트 1 에 추가한다 |
| 이번 차수에 처리된 것 | 시트 3 「요청 이력」에 `반영` 으로 기록 |
| 시트 1 빈칸 | 미응답·대기로 유지한다. 실제 재질문할 때만 `이월` 또는 상한 도달 시 `미해소`를 기록한다 |
| 이번 차수에 답이 없던 `[미확정]` | 시트 3 에 `미응답` · `이월` 로 기록 |
| `해당없음` 응답 | 시트 3 에 `철회` 로 기록 |
| **세 번 물었는데 답이 없는 것** | 시트 3 에 `미응답` · **`미해소`** 로 기록. 해당 시트 1·2 에 남기되 `물은 횟수` 를 올리지 않는다 |
| **값 대신 질문이 온 것** | 시트 3 에 그 질문을 `받은 답` 으로, `되질문` 으로 기록 |

### 시트 3 은 지우지 않고 쌓는다

시트 1·2 는 **지금 답해야 할 것**만 보여주므로 차수가 올라가면 지난 값이
거기서 사라진다. **그 값이 남는 유일한 자리가 시트 3 이다.**

그래서 이 시트에는 세 가지가 지켜져야 한다. 정본은
`templates/confirmation-request.md` 의 시트 3 절이다.

1. **차수마다 새 행.** 같은 항목을 세 번 물었으면 세 줄이다. 기존 행의 차수를
   고쳐 쓰지 않는다 — 고치면 「1차에 무엇을 물었나」가 사라진다.
2. **시트 1 항목도 남긴다.** 가정 확인도 요청이다. 빼면 「AI 가 255자로 정했는데
   답으로 100 을 받았다」가 어디에도 안 남아, 값이 왜 그것인지가 지워진다.
   `물은 것` 에 **AI 가 제시한 값을 괄호로 병기**한다.
3. **마지막 행의 `처리` 가 최종 결론이다.** 「마지막」은 같은 `항목번호` 의 마지막 행이다.
   `이월` 로 끝나는 항목은 없다 — 세 번 물어도 답이 없으면 `미해소` 로 닫는다.

**상한은 항목마다 세 번이다.** 차수(발행 번호)에는 상한이 없다 —
`templates/confirmation-request.md` §차수는 발행 번호이고, 상한은 항목마다 세 번이다 가
정본이다. 세 번 물은 항목에 나중에 답이 오면 이 표가 아니라 같은 문서의
§세 번 물은 항목 을 따른다 — **그 항목의 `미해소` 행을 갱신하고 새 행을 만들지 않는다.**

### 다음 차수를 예고하지 않는다

시트 0 에 「게이트 3 이후 2차 발행 예정」처럼 **앞으로 낼 차수를 쓰면 안 된다.**
다음 질문 여부와 대화·파일 방식은 `review-confirmations`가 그 시점의 미결 상태로 정한다.
반영 시점의 이 스킬은 아직 생기지 않은 후속 질문 수를 모른다.

1차 시험에서 실제로 어긋났다. 반영 뒤 남은 것이 1건이라 게이트 3 이 발행을
건너뛰었는데, 시트 0 은 「2차 발행 예정」이라고 적힌 채 남았다. **오지 않을 차수를
파일이 약속한다.**

시트 0 에는 **지금 상태만** 쓴다 — 몇 차를 반영했고, 각 시트·산출물에 몇 건이 남았는지.
왕복이 끝났는지는 게이트가 판정하고 게이트가 다시 쓴다
(`commands/gx-명세일괄.md` 의 게이트 2·3 절). 낱개 커맨드에서는 그 커맨드의 저장 뒤
판정이 같은 일을 한다.

### Step 5: 개정이력

값이 바뀐 산출물마다 **manage-revision-history** 스킬로 개정이력 행을 만든다.
`개정 사유` 는 `보완` 이다 — 요구사항이 바뀐 것이 아니라 미확정이 채워진 것이다.

## 출력

```
2차 확인요청서를 읽었습니다. (2026-09-20 /gx-테이블정의서 발행)

  가정 12건 — 맞음 8 · 수정 3 · 미확정으로 1
  미확정 33건 — 확정 9 · 대기 23 · 해당없음 1
  산출물별 — AN-03 30건 · DE-08 9건 · DE-13 6건

  반영
    AN-03  입력항목 3건의 제약 갱신
    DE-08  컬럼 길이 3건 갱신
    DE-13  경계 케이스 18건 추가 (미확정 9건이 값을 얻어 보강 대상이 됨)

  3차로 넘어가는 것 27건
    · 답을 못 받은 미확정 23건 (그중 세 번째로 묻는 것 15건)
    · 정정값에서 생긴 후속 확인 4건

  📄 {프로젝트폴더}/xlsx/{시스템코드}-확인요청서.xlsx

같은 항목은 세 번까지 묻습니다. 그 뒤로는 값이 정해질 때마다 이 파일에 적고
다시 부르시면 반영합니다. 미확정이 0이 되어야 최종본이 나갑니다.
```

**「3차로 넘어가는 것」을 갈라 보여준다** — 사람이 "내가 안 채운 것" 과
"물었는데 답이 안 온 것" 을 구분할 수 있어야 한다.

4회차(3차 반영)의 출력은 이렇다. 남은 둘이 모두 세 번 물은 항목인 경우다.

```
3차 확인요청서를 읽었습니다. (2026-10-05 /gx-단위테스트계획서 발행)

  가정 4건 — 맞음 3 · 수정 1
  미확정 23건 — 확정 21 · 미응답 2

  세 번 물어도 답이 없는 것 2건 — 더 묻지 않습니다
    CQ-003  AN-03  DAR-006  오류유형 코드값
    CQ-011  AN-03  INR-001  평가프로그램 연계 규격

  ⚠ 미확정이 남아 최종본(xlsx)을 내지 않습니다.
     마크다운 5종은 저장돼 있습니다.

  값이 정해지면 「미확정 확인」 시트의 응답 칸에 적고
  /gx-명세일괄 을 다시 부르세요. 그 두 항목 때문에 차수가 올라가지는 않습니다.
```

**총계를 앞에 두고 갈래를 센다** — 두 출력이 같은 형식이다. 숫자도 이어진다:
2차 반영이 3차로 넘긴 27건(미확정 23 · 후속 확인 4)이 3차 시트의 모수이고,
미확정 23건은 확정 21건과 미응답 2건으로 갈린다.
예시라도 합이 맞아야 사람이 화면의 건수를 믿는다.

**값을 대신 정하지 않는다.** 세 번 물어도 답이 없으면 관행값으로 채우지 않는다.
채우는 순간 「전부 해소돼야 최종본이 나간다」는 규칙이 무의미해진다 —
해소된 것처럼 보이지만 실은 우리가 정한 값이기 때문이다.

## 주의사항

- **본문을 다시 만들지 않는다.** 응답이 닿는 행만 고친다
- **`[미확정]` 을 임의로 채우지 않는다.** `확정` 응답이 온 것만 반영한다
- 무응답을 재촉하지 않는다 — 착수 전에는 답할 수 없는 것이 많다
- ID 를 바꾸지 않는다. 값이 바뀌어도 요구사항ID·기능ID·테스트ID 는 그대로다
- **되묻지 않는다.** 애매하면 다음 차수 행으로 쓴다 — 대화 왕복이 이 스킬의 비용이다
