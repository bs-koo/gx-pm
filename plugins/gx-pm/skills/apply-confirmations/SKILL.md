# 확인요청서 반영 (apply-confirmations)

## 언제 도는가

`/gx-명세일괄` Step 0-2 에서 **「확인요청서 반영하고 이어가기」** 를 고를 때 돈다.
본문을 다시 만들지 않는다 — **응답만 반영하고 다음 차수를 낸다.**

착수 협의로 값이 정해진 뒤 다시 부를 수 있다. 같은 파일에 이어 쓰면 된다.
3차를 마친 파일을 다시 부른 경우 **차수를 올리지 않는다** —
`templates/confirmation-request.md` §3차를 마친 파일을 다시 불렀을 때가 정본이다.

## 왜 이 방식인가

질문을 대화가 아니라 파일로 주고받는 근거와, **되묻기에 대화형 질문 도구를 쓰지
않는다**는 규칙의 정본은 `templates/pipeline-protocol.md` §질문 정책이다.
이 스킬은 그 정책의 실행부다 — 사람이 **엑셀에서 한 번에** 답하고 이 스킬은
**읽고 파급만** 처리한다. 대화 왕복이 1~2회로 준다.

답변이 새 애매성을 만들면 즉시 되묻지 않고 다음 차수 행으로 쓴다.
이것이 왕복을 0으로 만드는 자리다.

## 입력

| 항목 | 필수 | 설명 |
|------|------|------|
| 확인요청서 | Y | `{시스템코드}-확인요청서.md` 또는 사람이 채운 `.xlsx` |
| 산출물 5종 | Y | 반영 대상 |

양식은 `templates/confirmation-request.md` 가 정본이다.

## 처리 절차

### Step 1: 응답 읽기

시트 1 의 `판정`·`정정값`, 시트 2 의 `상태`·`응답` 을 읽는다.
xlsx 로 받았으면 드롭다운이 걸려 있어 목록 밖 값은 애초에 들어오지 못한다.

### Step 2: 분기

| 응답 | 처리 | 되묻나 |
|------|------|--------|
| `맞음` | 가정을 확정으로 승격. `[가정]` 태그를 뗀다 | 아니오 |
| `수정` + 정정값 정상 | 값을 바꾸고 Step 3 으로 | 아니오 |
| `미확정으로` | 값을 걷어내고 `[미확정]` 으로 바꿔 시트 2 로 옮긴다 | 아니오 |
| **무응답 (빈칸)** | **가정을 그대로 둔다.** 묵시적 승인 | 아니오 |
| `확정` + 응답값 | `[미확정]` 을 해소하고 본문에 반영. Step 3 으로 | 아니오 |
| `대기` | 그대로 둔다 | 아니오 |
| `해당없음` | **대장에서만** 지운다. 본문은 손대지 않는다 | 아니오 |

**무응답도 정상 종료다.** 사람이 한 줄도 안 써도 문서는 완성된다.

`해당없음` 이 본문 행을 지우지 않는 근거는
`templates/AN-02-requirements-definition.md` §상태 판정과 같다 —
**행은 지우지 않고 상태만 바꾼다.** 본문에서 빼려면 `열기` 경로로 명시적으로
지운다. 대장 응답 하나로 산출물 행이 사라지면 되돌릴 근거가 없어진다.

### Step 3: 파급 처리

값이 바뀐 곳은 그 자리만 끝나지 않는다.
`templates/pipeline-protocol.md` §재생성 파급 규칙을 그대로 적용한다.
규칙표는 5줄이고 깊이는 최대 3단(요구사항→기능→테이블→테스트)이라 **유한하다.**

`[가정]` 값이 바뀌면 표식이 선 세 자리를 함께 고친다
(`templates/evidence-rules.md` §표식은 세 홉을 관통한다).

```
AUTHRT_NM 길이 100 → 50 으로 정정
  ↓ AN-03  입력항목 괄호의 [가정] 100자 → 50자
  ↓ DE-08  길이 열 100 → 50, 근거의 [가정] 길이 100 → 50
  ↓ DE-13  UT-089 입력 "권한명 101자 [가정:100]" → "권한명 51자 [가정:50]"
```

`[미확정]` 이 `확정` 으로 바뀌면 **경계 케이스가 새로 생긴다** — 그동안
보강하지 않던 제약이 값을 얻기 때문이다
(`templates/evidence-rules.md` §[미확정] 제약은 자동 보강 대상이 아니다).

### Step 4: 후속 질문을 다음 차수 행으로 쓴다

응답이 새 애매성을 만들면 **묻지 않고 시트 1 에 다음 차수 행을 추가한다.**

| 상황 | `AI 가 정한 값` | `근거` |
|------|----------------|--------|
| `수정` 인데 정정값이 비었다 | 원래 값 | 정정값이 비어 있어 원래 값을 유지했습니다 |
| 형식이 안 맞는다 | 원래 값 | 숫자가 필요한데 문장이 들어왔습니다: "{입력값}" |
| 다른 행과 충돌한다 | 둘 중 하나를 제안 | TB_A.EML 은 100, TB_B.EML 은 255 로 갈립니다 |
| 파급 방향이 갈린다 | 파급 결과 제안 | EML 을 100 으로 정정하셔서 UT-089 경계값을 101 로 바꿉니다 |

```
| 8 | 2 | UT-089 경계값 | 101자로 조정 | EML 을 100 으로 정정하셔서 | | | |
```

`판정` 을 비워 두면 다음 회차에서 「그 값으로 진행」으로 처리된다 —
사람이 아무것도 안 해도 파이프라인이 멈추지 않는다.

### Step 4-1: 차수를 올린다

| 상황 | 처리 |
|------|------|
| 시트 0 「안내」 | `현재` 차수와 시트별 건수를 다시 쓴다. 사람이 파일을 열고 맨 처음 읽는 자리다 |
| 답을 못 받은 `[미확정]` | 차수를 +1 해서 시트 2 에 다시 올린다 |
| 새로 생긴 후속 질문 | 새 차수로 시트 1 에 추가한다 |
| 이번 차수에 처리된 것 | 시트 3 「요청 이력」에 `반영` 으로 기록 |
| 이번 차수에 답이 없던 것 | 시트 3 에 `미응답` · `이월` 로 기록 |

**최대 3차다.** `templates/confirmation-request.md` §차수는 최대 3차다 가 정본이다.
3차를 마친 파일을 다시 부른 경우는 이 표가 아니라 같은 문서의
§3차를 마친 파일을 다시 불렀을 때를 따른다 — **차수를 올리지 않는다.**

### Step 4-2: 3차 미응답을 `[임시확정]` 으로 전환한다

3차 확인요청서에도 답이 오지 않은 `[미확정]` 이 이 단계의 대상이다.
전환 규칙은 `templates/evidence-rules.md` §[임시확정] 은 3차 미응답의 결과다 가
정한다 — **여기서 다시 정의하지 않는다.**

1. 관행값을 정하고 근거에 **`3차 미응답`** 을 반드시 적는다
2. 전환으로 값이 새로 생기므로 그 값은 표식을 달고 아래로 내려간다 —
   `templates/evidence-rules.md` §표식은 세 홉을 관통한다
3. 시트 3 에 `임시확정` 으로 기록한다
4. 그 값이 실린 산출물의 `## 개정이력` 위에 위험 표시를 넣는다
5. AN-05 `누락` 열에 `임시확정` 판정이 뜨도록 `trace-requirements` 를 다시 돌린다

**관행값을 못 정하는 것은 전환하지 않는다.** 파일 항목 구성처럼 관행이 없는
것은 `[미확정]` 으로 남기고 위험 목록에만 올린다 — 없는 항목을 지어내는 것은
`[임시확정]` 의 범위가 아니다.

### Step 5: 개정이력

값이 바뀐 산출물마다 **manage-revision-history** 스킬로 개정이력 행을 만든다.
`개정 사유` 는 `보완` 이다 — 요구사항이 바뀐 것이 아니라 미확정이 채워진 것이다.

## 출력

```
2차 확인요청서를 읽었습니다.

  가정 12건 — 맞음 8 · 수정 3 · 미확정으로 1
  미확정 33건 — 확정 9 · 대기 23 · 해당없음 1

  반영
    AN-03  입력항목 3건의 제약 갱신
    DE-08  컬럼 길이 3건 갱신
    DE-13  경계 케이스 18건 추가 (미확정 9건이 값을 얻어 보강 대상이 됨)

  3차로 넘어가는 것 27건
    · 답을 못 받은 미확정 23건
    · 정정값에서 생긴 후속 확인 4건

  📄 {프로젝트폴더}/xlsx/{시스템코드}-확인요청서.xlsx

3차가 마지막입니다. 답이 없는 항목은 [임시확정] 으로 채우고 위험 항목으로
표시합니다.
```

**「3차로 넘어가는 것」을 갈라 보여준다** — 사람이 "내가 안 한 게 아니라
발주기관 답이 안 온 것" 을 구분할 수 있어야 한다.

4회차(3차 반영)의 출력은 이렇다.

```
3차 확인요청서를 읽었습니다.

  가정 4건 — 맞음 3 · 수정 1
  미확정 23건 — 확정 5 · 미응답 18

  미응답 18건 중 16건을 [임시확정] 으로 채웠습니다.

    DAR-006  오류유형 코드값 목록   → EM01~EM09 임시 부여
    SFR-016  표본 최소 기준값       → 30건 (통계 관행)
    ...

  관행값을 정할 수 없어 [미확정] 으로 남긴 것 2건
    DAR-001  원천 파일 4종 항목 구성

  ⚠ 이 18건은 개발 착수 시 재작업 위험 항목입니다.
     산출물 5종 머리말과 AN-05 `누락` 열에 표시했습니다.
     요청 이력은 확인요청서 「요청 이력」 시트에 남아 있습니다.

5종이 최종 확정됐습니다. 차수 왕복을 마칩니다.
```

**총계를 앞에 두고 갈래를 센다** — 두 출력이 같은 형식이다. 숫자도 이어진다:
2차 반영이 3차로 넘긴 27건(미확정 23 · 후속 확인 4)이 3차 시트의 모수이고,
미응답 18건은 `[임시확정]` 16건과 관행값을 못 정한 2건으로 갈린다.
예시라도 합이 맞아야 사람이 화면의 건수를 믿는다.

## 주의사항

- **본문을 다시 만들지 않는다.** 응답이 닿는 행만 고친다
- **`[미확정]` 을 임의로 채우지 않는다.** `확정` 응답이 온 것만 반영한다
- 무응답을 재촉하지 않는다 — 착수 전에는 답할 수 없는 것이 많다
- ID 를 바꾸지 않는다. 값이 바뀌어도 요구사항ID·기능ID·테스트ID 는 그대로다
- **되묻지 않는다.** 애매하면 다음 차수 행으로 쓴다 — 대화 왕복이 이 스킬의 비용이다
