# 확인 항목 검토와 발행

명세 5개 커맨드의 저장 전 검토와 저장 후 확인요청서 단계, 명세일괄의 각 게이트에서 사용한다.
양식·항목번호·발행 기준은 `templates/confirmation-request.md`, 질문 방식은
`templates/approval-protocol.md`가 정본이다. 응답 반영은 **apply-confirmations**가 맡는다.

## 1. 기존 응답 보호

프로젝트의 확인요청서 md와 xlsx를 먼저 읽는다. 파일 존재나 수정 시각만으로 응답했다고
판단하지 않고 `항목번호`별 입력 칸을 대조한다. 새 답이 있고 반영을 요청받았으면 바로
**apply-confirmations**를 실행한다. 의도가 불분명할 때만 「확인요청서 반영하고 이어가기」를 묻는다.
답이 없는 파일을 다시 열었다고 차수·물은 횟수를 올리지 않는다.

응답 반영 전 파일을 백업한다. md의 미응답 칸에 xlsx로 새 답이 들어온 것은 정상 입력이다.
지난 요청 이력·백업의 응답을 기준으로 한쪽만 바뀌었으면 그 새 답을 적용한다. 양쪽에 서로 다른
새 답이 있거나 기준을 확인할 수 없는 비어 있지 않은 답끼리 다르면 충돌한 항목만 보여준다.
수정 시각으로 승자를 정하지 않는다. 반영하지 않기로 한 파일은 재발행·xlsx 추출로 덮지 않는다.

## 2. 각 산출물에서 수집할 것

| 산출물 | 확인할 항목 | 질문으로 만들지 않는 것 |
|---|---|---|
| AN-02 요구사항정의서 | 원문 간 충돌, 적용 범위·해석 미결, 소스에서 역추출해 발주 요구로 확인되지 않은 내용 | 근거가 명확한 추출·분류, 이미 답한 시안 |
| AN-03 기능명세서 | 입력·처리·출력의 `[가정]`·`[미확정]` | 상위에서 확정된 값을 다시 묻기 |
| DE-08 테이블정의서 | 제약·근거의 미결, 사용자 판단이 필요한 표준 판정 | 기존 물리명 유지 등 이미 정한 정책 |
| DE-13 단위테스트계획서 | 입력·기대결과·경계값의 미결, 실제 실행할 수 없는 조건 | 이미 확인한 제약의 반복 질문 |
| AN-05 추적매트릭스 | 예외 흐름 필요 여부, 범위 제외·연계 해석 등 사람이 판단할 누락 | 명백한 끊긴 ID·실패·미수행의 단순 재확인 |

`산출물`은 질문이 처음 생긴 곳, `위치`는 안정적인 ID와 필드다. AN-02·AN-05에서
태그를 새로 심거나 본문 열을 늘릴 필요는 없다. 확인요청서에 원문 근거·미결 내용을 기록한다.
같은 원인이 뒤 산출물로 전파되면 기존 CQ 항목에 관련 ID를 덧붙인다. 닫힌 항목은 재질문하지
않되 전제·값이 실제로 바뀌었으면 변경 근거를 붙여 다시 검토한다.

시안·표 판정·신규 컬럼명·ID 승계처럼 `templates/pipeline-protocol.md`의 이월 금지 항목은
작업 전에 해결한다. 여기에 쌓아두고 그 결정을 필요로 하는 문서를 먼저 만들지 않는다.

## 3. 묻고 기록하기

검토 화면에는 추가·변경·미결 건수, 대표 변경 행, 개정이력 초안, 저장/추출 범위를 함께 보여준다.
이미 받은 승인·출력 형식은 재사용한다. 없는 판단만 질문한다.

- **0건:** 「확인 필요 0건 — 확인요청서 추가 발행 없음」을 알린다. 빈 파일은 만들지 않는다.
- **1~5건:** 대화로 묻고 **실제 응답을 기다린다**. 답변·보류를 같은 확인요청서 md의 항목과
  요청 이력에 기록한다. 파일이 없으면 4개 표를 가진 md를 만든다. Excel을 요청했으면 그
  확인요청서도 xlsx로 낸다. 한 번의 항목 묶음에 차수를 한 번만 부여한다.
- **6건 이상:** 고정 파일명으로 md와 xlsx를 발행하고 관련 작업을 보류한다. 파일 링크,
  답할 칸, 남은 건수, 재개할 커맨드를 보여준다. 사용자가 파일로 받기를 요청하면 소량도 이 경로다.

한 질문은 한 판단만 요구한다. 한 응답으로 여러 항목을 일괄 확정하려면 CQ 번호와 제안값을
먼저 보여주고 적용 범위를 명시한다. 빈칸·시간 경과·사전 선택 옵션은 답이 아니다.
부분 응답은 그 항목만 반영하고 나머지는 대기로 남긴다. 질문을 표시하기만 하고 해결로 세지 않는다.

## 4. 문서 완료 상태

확인요청서 생성 여부와 산출물 완료 여부를 나눠 알린다. 미결이 있으면 어떤 문서가 초안인지,
어떤 결정이 있어야 최종본이 되는지 적는다. 독립적으로 처리할 수 있는 문서는 계속 작업한다.
요청된 검토용 초안은 `templates/confirmation-request.md`의 초안 출력 규칙에 따라 제공한다.

마지막에는 생성 파일, 반영/대기/미해소 건수, 다음에 할 한 가지를 제시한다.
단순 다음 작업 제안을 필수 질문으로 만들거나 해당 커맨드를 자동 실행하지 않는다.
