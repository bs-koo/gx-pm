# ID 양방향 추적 (id-trace)

임의의 ID(요구사항ID·기능ID·테스트ID)를 입력받아 연결된 체인을 양방향으로 조회하고,
누락된 매핑을 탐지한다. 단건 추적과 전체 교차 검증 두 가지 모드를 제공한다.

**추적 범위는 AN-05 추적매트릭스와 같다.** 화면·프로그램·통합테스트·시스템테스트는
DE-03·DE-05·DE-14·ST-01 이 각자의 산출물에서 다루고, 이 스킬과 AN-05 는 관여하지 않는다.

## ID 체인 구조

```
요구사항ID (AN-02)
    ├─→ 기능ID (AN-03, `연계요구사항ID` 역조회)
    │       ├→ 테이블·컬럼 (DE-08, `연계기능ID` 역조회)
    │       └→ 테스트ID (DE-13, `연계기능ID` 역조회)
    └─→ 테스트ID (DE-13, `연계기능ID` 공란 + `연계요구사항ID` 직접 조회 — 비기능 경로)
```

**갈래가 둘이다.** 기능이 연계된 요구사항은 기능을 거쳐 테이블·테스트로 내려가고,
기능이 연계되지 않은 요구사항은 DE-13 의 비기능 테스트 행(`연계기능ID` 공란)으로
직접 검증된다. 후자는 정상 경로이며, 이 경로로도 테스트가 없을 때만 누락이다.

## 입력

- 추적 모드 선택:
  - **단건 추적**: 특정 ID 1개 입력 → 해당 ID 기준 위·아래 전체 체인 추적
  - **전체 교차 검증**: "전체" 입력 → 모든 요구사항의 ID 교차 검증
- 산출물 데이터 (요구사항정의서 AN-02, 기능명세서 AN-03, 테이블정의서 DE-08,
  단위테스트계획서 DE-13)

## ID 유형 자동 판별

입력된 ID 유형은 각 산출물 템플릿의 채번 규칙으로 판별한다 — 정본은
`templates/AN-02-requirements-definition.md`·`templates/AN-03-function-spec.md`·
`templates/DE-13-unit-test-plan.md` 의 각 ID 컬럼 값 규칙이다. 여기서 접두어를
다시 정의하지 않는다.

| ID 유형 | 판별 근거 |
|--------|---------|
| 요구사항ID | AN-02 `요구사항ID` 열에 존재 |
| 기능ID | AN-03 `기능ID` 열에 존재 |
| 테스트ID | DE-13 `테스트ID` 열에 존재 |

세 산출물 어디에도 없는 ID 는 "인식하지 못했습니다" 로 안내하고, 오탈자 가능성이
있는 가장 유사한 ID 를 제안한다.

## 처리 절차

### 모드 A: 단건 추적

#### Step 1: ID 유형 판별 및 시작 위치 결정

입력 ID 가 어느 산출물에 존재하는지로 유형을 정한다.

#### Step 2: 상향 추적 (입력 ID → 상위 체인)

| 시작 ID 유형 | 상향 추적 경로 |
|-----------|------------|
| 테스트ID | 테스트ID → (연계기능ID 가 있으면) 기능ID → 요구사항ID / (공란이면) 연계요구사항ID → 요구사항ID |
| 기능ID | 기능ID → 요구사항ID (연계요구사항ID, 복수 가능) |

#### Step 3: 하향 추적 (입력 ID → 하위 체인)

| 시작 ID 유형 | 하향 추적 경로 |
|-----------|------------|
| 요구사항ID | 요구사항ID → 기능ID(복수 가능) → 테이블·컬럼 + 테스트ID / 기능이 없으면 → 비기능 테스트ID |
| 기능ID | 기능ID → 테이블·컬럼 + 테스트ID |

#### Step 4: 트리 시각화 출력

트리 문자(┌─ ├─ │ └─)를 사용한다.

```
## ID 추적 결과 — REQ-001

└─ 요구사항: REQ-001 (벤치마크 스코어테이블 생성 기능) ← [시작]
    └─ 기능: FN-001 (벤치마크 스코어테이블 생성)
        ├─ 테이블: TB_SCORE (신규 4) ✅
        └─ 테스트: UT-001~UT-006 (6건, Pass 6 / Fail 0) ✅
```

```
## ID 추적 결과 — REQ-045

└─ 요구사항: REQ-045 (동시접속 500명 응답 3초) ← [시작]
    └─ 기능: 연계 없음 (비기능 요구사항)
        └─ 테스트: UT-051, UT-052 (2건, 결과 전건 공란) ⚠ 미수행
```

- ✅: 해당 ID 가 산출물에 등록되어 있고 결과에 이상이 없음
- ⚠: 「누락 판정」 표에 해당하는 상태(뒤 「누락 탐지 7가지 유형」 참조)
- ?: 산출물이 제공되지 않아 확인 불가

### 모드 B: 전체 교차 검증

#### Step 1: 모든 요구사항ID 수집

AN-02 의 모든 요구사항ID 를 수집한다.

#### Step 2: 각 요구사항에 대해 하향 추적 수행

모든 요구사항에 대해 단건 추적의 하향 추적(Step 3)을 수행한다.

#### Step 3: 역방향 불일치 확인

- AN-03 에 존재하지만 어떤 요구사항의 `연계요구사항ID` 에도 없는 기능ID
- DE-08 에 존재하지만 어떤 기능의 `연계기능ID` 참조도 받지 않는 테이블·컬럼
- DE-13 에 존재하지만 `연계기능ID`·`연계요구사항ID` 어느 쪽도 유효하지 않은 테스트ID

#### Step 4: 추적 완료율 계산

```
누락 없음 비율 = 누락 판정이 빈칸인 요구사항 수 / 전체 요구사항 수 × 100%
```

세부 비율도 함께 계산한다:
- 기능 도출률: 기능이 1건 이상 연계된 요구사항 / 전체 요구사항 × 100%
- 테스트 작성률: 테스트 수가 1건 이상인 기능 / 전체 기능 × 100%
- 비기능 검증률: DE-13 비기능 테스트가 1건 이상인 무기능 요구사항 / 무기능 요구사항 × 100%
- 결과 수행률: `결과` 가 1건 이상 채워진 테스트 / 전체 테스트 × 100%
- Pass 율: Pass 건수 / (Pass + Fail 건수) × 100%

## 누락 탐지 7가지 유형

**정본은 `templates/AN-05-traceability-matrix.md` 의 「누락 판정」 절이다.** 판정을
실행 가능한 순서로 어떻게 적용하는지는 `skills/trace-requirements/SKILL.md` 의
「조립 절차 Step 5」를 따른다 — 여기서 조건을 다시 정의하지 않는다.

| 유형 | 정의 |
|------|------|
| 기능 미도출 | 기능 요구사항인데 연계된 기능이 0건 |
| 테스트 미작성 | 기능이 있는데 테스트가 0건 |
| 비기능 검증 누락 | 어느 기능에도 안 걸린 요구사항인데 비기능 테스트도 0건 |
| 예외 케이스 없음 | 그 기능의 테스트가 전부 정상 흐름(테스트 수 1건) |
| 미수행 | 테스트는 있는데 `결과` 가 전건 공란 |
| 실패 잔존 | `Fail` 이 1건 이상 |
| 삭제 미정리 | 상태가 `삭제` 인데 연계된 기능·테스트가 살아 있음 |

## 출력

### 단건 추적 출력

```
## ID 추적 결과 — {입력 ID}

{트리 시각화}

### 누락 항목
- ⚠ REQ-045: 미수행 (테스트 2건, 결과 전건 공란)
```

### 전체 교차 검증 출력

```
## 전체 ID 교차 검증 결과 — {시스템명}

### 추적 완료율
| 항목 | 완료 | 전체 | 완료율 |
|------|------|------|--------|
| 누락 없는 요구사항 | N | N | N% |
| 기능 도출 | N | N | N% |
| 테스트 작성 | N | N | N% |
| 비기능 검증 | N | N | N% |
| 결과 수행 | N | N | N% |

### 누락 목록

#### 기능 미도출 (N건)
| 요구사항ID | 요구사항명 |
|-----------|----------|

#### 테스트 미작성 (N건)
| 요구사항ID | 기능ID | 기능명 |
|-----------|-------|-------|

#### 역방향 불일치 (N건)
| ID | 유형 | 불일치 내용 |
|----|------|-----------|
| FN-014 | 기능ID | 어떤 요구사항도 연계하지 않음 |
```

## 체크포인트

추적 결과를 사용자에게 확인한다:

"ID 추적 결과를 확인해주세요:
- REQ-001: 기능 1개 연계, 테스트 6건 전부 Pass
- REQ-032: 연계된 기능 없음 ⚠ (AN-03 에서 이 요구사항을 참조하는 기능을 찾지 못함)
- 전체 요구사항 N건 중 누락 없음 N건
추적매트릭스(AN-05) 보완이 필요하면 trace-requirements 스킬을 사용하세요.
누락 항목을 한 번에 정리할까요?"

## 주의사항

- 비기능 요구사항은 기능ID 연계가 없는 것이 정상 — 대신 DE-13 비기능 테스트가
  없으면 누락이다
- 요구사항 하나에 기능이 여럿 걸리는 것은 정상 — 각 기능이 따로 판정을 받는다
- `예외 케이스 없음` 은 결함이 아니라 확인 요청이다 — 자동으로 결함 처리하지 않는다
- 전체 교차 검증 모드는 AN-02·AN-03·DE-08·DE-13 이 모두 제공된 경우에 가장
  정확하다 — 일부만 있으면 확인 불가 항목(?)으로 표시한다
