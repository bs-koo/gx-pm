# 시스템테스트 생성 (generate-system-test)

**비기능 요구사항을 검증하는 유일한 산출물**을 만든다.
성능·보안·접근성·호환성·유지보수성·법적준수를 측정 항목으로 전개하고, 목표치 대비 판정한다.

---

## 왜 필요한가

비기능 요구사항(AN-02 구분="비기능")은 화면·프로그램에 매핑되지 않는다.
그래서 단위테스트(화면 기준)와 통합테스트(업무 흐름 기준) 어디에도 걸리지 않고,
추적매트릭스에서 **검증 칸이 통째로 빈다**. 감리에서 "비기능 요구사항 검증 누락"으로 지적되는 전형적 패턴이다.

시스템테스트ID(`{시스템코드}-ST-{순번}`)가 그 빈칸을 메운다.

---

## 입력

| 항목 | 필수 | 설명 |
|------|------|------|
| 요구사항정의서 | Y | **구분="비기능"** 항목 전건 (AN-02) |
| 비기능 유형 분류 | 권장 | classify-requirements의 6유형 분류 결과 |
| 총괄 테스트계획서 | 권장 | TE-01의 테스트 환경·종료기준 |
| systemCode | Y | ID 채번용 |

---

## 처리 절차

### Step 1: 비기능 요구사항 수집

요구사항정의서에서 구분="비기능"을 전건 추출한다.
`classify-requirements`가 부여한 비기능 유형(성능/보안/접근성/호환성/유지보수성/법적준수)을 그대로 쓴다.

분류가 없으면 여기서 판별한다.

```
비기능 요구사항 {N}건을 찾았습니다.

| 요구사항ID | 요구내역 | 비기능 유형 | 목표치 추출 |
|-----------|--------|-----------|-----------|
| B-RE-015 | 동시접속 500명 이상 지원 | 성능 | 500명 |
| B-RE-016 | 웹접근성 2.0 준수 | 접근성 | 지침 준수 |
| B-RE-017 | 개인정보 암호화 저장 | 보안 | 암호화 |
| B-RE-018 | 응답시간 3초 이내 | 성능 | 3초 |
```

### Step 2: 측정 항목 전개

하나의 요구사항에 측정 항목이 여럿이면 **항목별로 별도 시스템테스트ID**를 부여한다.

```
B-RE-015 "동시접속 500명 이상, 응답시간 3초 이내"
  → B-ST-001  동시접속 처리 (목표 500명)
  → B-ST-002  화면 응답시간 (목표 3초)
```

유형별 표준 측정 항목은 `templates/ST-01-system-test.md`를 따른다.

### Step 3: 목표치 확정

**요구사항 원문의 수치를 그대로 옮긴다.** 임의로 만들지 않는다.

| 상황 | 처리 |
|------|------|
| 요구사항에 수치가 있음 | 그대로 사용 (예: "3초 이내" → 3초) |
| 수치가 없고 관례가 있음 | 관례값 제안 + **사용자 확인** (예: 세션 만료 30분) |
| 수치도 관례도 없음 | **발주처 협의 필요**로 표시하고 공란 유지 |

```
목표치가 확정되지 않은 항목이 {N}건 있습니다.

| ID | 요구사항 | 측정 항목 | 제안 목표치 | 근거 |
|----|--------|---------|-----------|------|
| B-ST-005 | B-RE-020 시스템 안정적 운영 | 가용성 | 99.9% | 관례 (연간 8.7시간 다운) |
| B-ST-006 | B-RE-021 신속한 조회 | 대용량 조회 응답 | ? | **발주처 협의 필요** |

목표치를 확정해주세요. 협의가 필요하면 "협의"로 두시면 비고에 표시합니다.
```

> 목표치 없는 측정은 판정이 불가능하다. 공란으로 두면 결과서에서 자동 "점검제외"가 된다.

### Step 4: 측정 방법 작성

**도구명과 조건**을 적는다. "테스트함"은 불충분하다.

| 유형 | 측정 방법 예시 |
|------|-------------|
| 성능(응답시간) | 브라우저 개발자도구 Network 탭 / JMeter — 주요 화면 10종, 정상 부하 |
| 성능(동시접속) | JMeter 부하 테스트 — 500 스레드, 10분 지속, 오류율 측정 |
| 보안(취약점) | 진단 도구 (행안부 SW 보안약점 진단가이드 기준 47개 항목) |
| 보안(암호화) | DB 실 데이터 조회 — 주민번호·비밀번호 컬럼 평문 여부 확인 |
| 접근성 | 자동진단(K-WAH/OpenWAX) + 수동점검 — 주요 화면 20종 |
| 호환성 | 브라우저별 주요 화면 실행 — Chrome·Edge·Safari 최신 |

### Step 5: 테스트 조건 명시

부하 조건·데이터 규모·환경을 적는다. 조건이 다르면 같은 시스템도 다른 값이 나온다.

```
B-ST-001 동시접속 처리
  조건: 운영 유사 환경(WAS 2대), 데이터 10만 건 적재 상태,
        로그인→목록조회→상세조회 시나리오, 500 스레드 10분 지속
```

### Step 6: [결과서 모드] 측정값 기입 및 판정

계획서가 이미 있으면 결과 기입 모드로 동작한다.

**판정 3값**

| 판정 | 조건 | 후속 |
|------|------|------|
| **적합** | 측정값이 목표치 충족 | — |
| **부적합** | 측정값이 목표치 미달 | **manage-defects 호출** → 결함ID 발급 |
| **점검제외** | 측정 자체가 불가능 | **사유 필수** |

**점검제외 인정 사유** (그 외는 인정되지 않음)

- 테스트 환경 미준비 (운영 유사 환경 미구축)
- 선행 기능 결함으로 측정 불가
- 외부 환경 변화 (연계기관 시스템 미개방)
- 과업 범위 외 판정 (발주처 협의 근거 필요)

```
측정값을 입력해주세요.

| ID | 측정 항목 | 목표치 | 측정값 | 판정 |
|----|---------|--------|--------|------|
| B-ST-001 | 동시접속 처리 | 500명 오류율 1% 미만 | ? | |
| B-ST-002 | 화면 응답시간 | 3초 이내 | ? | |

입력 형식: B-ST-001 | 520명 오류율 0.3% | 적합
점검제외 시: B-ST-005 | 점검제외 | 사유: 운영 유사 환경 미구축
```

**보안 부적합 자동 격상**: 보안 유형 항목이 부적합이면 결함 심각도를 **Critical**로 발급한다
(P1 법적 필수 영역이므로 심각도 하향 판단을 하지 않는다).

### Step 7: 증적 확인

성능·보안은 **증적이 없으면 측정하지 않은 것으로 본다**. 증적 파일명을 기입받는다.

```
증적을 확인해주세요.

| ID | 유형 | 필요 증적 | 파일명 |
|----|------|---------|--------|
| B-ST-001 | 성능 | JMeter 결과 리포트 | ? |
| B-ST-003 | 보안 | 취약점 진단 결과서 | ? |
| B-ST-004 | 접근성 | 자동진단 리포트 | ? |
```

### Step 8: 커버리지 판정

```
[비기능 요구사항 커버리지]

전체 비기능 요구사항: N건
시스템테스트 연결됨: N건
미연결: N건 ← 추적매트릭스 검증 칸이 빕니다

커버리지 = N / N = N%   (목표 100%)

미연결 목록:
| 요구사항ID | 요구내역 | 사유 |
|-----------|--------|------|
| B-RE-022 | 유지보수 편의성 확보 | 측정 항목 미도출 — 발주처 협의 필요 |
```

```

  성능 N/N · 보안 N/N · 접근성 N/N · 호환성 N/N · 유지보수성 N/N · 법적준수 N/N
```

## 체크포인트 (승인 루프)

```
시스템테스트 항목 {N}건을 생성했습니다.

주요 확인:
1. 목표치가 요구사항 원문의 수치와 일치하는지
2. 목표치 미확정 {N}건을 발주처와 협의할지
3. 측정 방법이 실제 수행 가능한지 (도구·환경 확보 여부)
4. 비기능 요구사항 커버리지 {N}% — 미연결 {N}건을 어떻게 할지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "B-ST-001 목표를 300명으로 하향. 근거: 2026-04-10 발주처 협의"
• "접근성은 자동진단만. 수동점검은 범위 외"
• "B-RE-022에 유지보수성 측정 항목 추가"
```

## 주의사항

1. **비기능 요구사항 1건당 최소 1개의 시스템테스트ID**를 부여한다 — 커버리지 100%가 목표
2. 목표치는 **요구사항 원문 수치를 그대로** 옮긴다. 임의 생성 금지
3. 목표치 미확정 항목은 공란으로 두고 **발주처 협의 필요**를 명시한다
4. 측정 방법에 **도구명과 조건**을 적는다
5. 성능·보안은 **증적이 없으면 미측정으로 간주**한다
6. 보안 항목 부적합은 **Critical 결함**으로 발급한다 (심각도 하향 판단 없음)
7. 성능 측정은 통합테스트 후반이 아니라 **개발 중 주기적으로** 실시하도록 안내하고, 시스템테스트는 최종 확인임을 명시한다
8. 점검제외는 4가지 인정 사유에 한한다 — "시간 부족"은 점검제외가 아니라 **미수행**이다
