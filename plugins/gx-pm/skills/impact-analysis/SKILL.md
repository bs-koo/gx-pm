# 변경 영향도 분석 (impact-analysis)

요구사항 변경, 감리 지적, 설계 변경 시 영향을 받는 산출물과 범위를 분석한다.
**추적(`id-trace`)이 "지금 어떻게 이어져 있나"라면, 이 스킬은 "이걸 바꾸면 무엇을 다시 만드나"다.**

## 파급 규칙의 정본은 여기가 아니다

무엇이 무엇을 재생성시키는지는 `templates/pipeline-protocol.md` 의
**§재생성 파급 규칙**이 정본이다. 이 스킬은 그 표를 적용해 **범위를 세고 공수를 매기고
변경요청서를 만드는** 일을 한다. 규칙을 여기에 복제하면 두 벌이 갈린다.

**파생 ID 가 없다.** 요구사항ID·기능ID·테스트ID 는 각각 독립 채번이므로,
상위 ID 를 바꿔도 하위 ID 를 재채번하지 않는다 (`templates/id-naming-rules.md`).
다시 만들어야 하는 것은 `연계~ID` 열로 이어진 **행**들뿐이다.

## 입력

- 변경 대상: 요구사항ID · 기능ID · 테이블/컬럼 · 테스트ID 중 하나 이상 (또는 텍스트 설명)
- 변경 내용: 무엇이 어떻게 변경되는지 설명
- 기존 산출물 (AN-02 · AN-03 · DE-08 · DE-13 · AN-05 — 있는 만큼 정확해진다)

## 처리 절차

### Step 1: 변경 유형 식별

| 변경 유형 | 시작 위치 | 추적 방향 | 영향 산출물 |
|---------|---------|---------|-------------|
| **요구사항 변경** | 요구사항ID | 하향 — AN-03 을 `연계요구사항ID` 로 역조회 | AN-02 · AN-03 · DE-08 · DE-13 · AN-05 |
| **기능 변경** | 기능ID | 양방향 — 위로 연계 요구사항, 아래로 컬럼·테스트 | AN-03 · DE-08 · DE-13 · AN-05 |
| **컬럼 변경** | 테이블명·컬럼명 | 상향 — DE-08 의 `연계기능ID` 로 기능 역조회 | DE-08 · DE-13 · AN-05 |
| **비기능 변경** | 요구사항ID (비기능) | 하향 — DE-13 의 `연계기능ID` 공란 행 | AN-02 · DE-13 · AN-05 |

비기능은 기능을 거치지 않는다. AN-03 에 행이 없는 것이 정상이며,
DE-13 의 `연계기능ID` 공란 행이 없는 것이 누락이다.

### Step 2: 직접/연쇄 영향 분류

파생 ID 가 없으므로 "간접 영향"이라는 세 번째 층이 생기지 않는다. 두 층으로 나눈다.

| 영향 유형 | 정의 | 예 |
|---------|------|-----|
| **직접 영향** | 변경 대상 행 자체 | REQ-003 변경 → AN-02 의 REQ-003 행 |
| **연쇄 영향** | `연계~ID` 로 그 행을 가리키는 다른 산출물의 행 | AN-03 에서 `연계요구사항ID` 가 REQ-003 인 기능 행 → 그 기능ID 를 가리키는 컬럼·테스트 행 |

같은 컬럼을 여러 기능이 공유하면 그 컬럼을 쓰는 **테스트 전건**이 연쇄에 들어온다.
이 경우가 유일하게 범위가 넓어지는 자리이므로, 건수를 반드시 세어서 보여준다.

#### 영향 추적 예 (요구사항 변경)

```
[변경 시작] REQ-003 (교육 과정 관리 — 첨부파일 항목 추가)
    ↓ 직접
    [AN-02] REQ-003 행 — 요구사항 상세내용·상태·변경 근거 수정
    ↓ 연쇄 (기능)
    [AN-03] FN-007 (과정 등록) — 입력항목에 첨부파일 추가, 처리내용 수정
    ↓ 연쇄 (컬럼)
    [DE-08] TB_COURSE.ATCH_FILE_ID — 신규 컬럼. 표준용어 MCP 판정 필요
    ↓ 연쇄 (테스트)
    [DE-13] UT-014 ~ UT-018 — 첨부 유무·용량 경계 케이스 추가
    ↓ 대조
    [AN-05] REQ-003 행 — 자동으로 다시 조립된다 (대조 결과라 손으로 고치지 않는다)
```

### Step 3: 산출물별 수정 필요 항목 목록화

| 산출물 | 수정 항목 | 영향 유형 | 수정 난이도 |
|--------|---------|---------|-----------|
| AN-02 요구사항정의서 | REQ-003 행 — 상세내용·상태·변경 근거 | 직접 | 낮음 |
| AN-03 기능명세서 | FN-007 — 입력항목·처리내용 | 연쇄 | 중간 |
| DE-08 테이블정의서 | TB_COURSE 신규 컬럼 1건 | 연쇄 | 중간 |
| DE-13 단위테스트계획서 | UT-014~UT-018 — 경계·필수값 케이스 | 연쇄 | 낮음 |
| AN-05 추적매트릭스 | 다시 대조 (`/gx-추적매트릭스`) | 연쇄 | 낮음 |

**AN-05 는 손으로 고치지 않는다.** 대조기의 출력이므로 앞의 넷을 고친 뒤 다시 돌린다.

### Step 4: 작업량 추정

#### 기준 작업량 단위 (공수 = 인일)

| 수정 단위 | 기준 공수 | 비고 |
|---------|---------|------|
| 요구사항 행 수정 (1건) | 0.1 인일 | 산출물 작성 기준 |
| 요구사항 행 신규 (1건) | 0.2 인일 | 분류·근거 확인 포함 |
| 기능 행 수정 (1건) | 0.4 인일 | 입력항목·처리내용 재작성 |
| 기능 행 신규 (1건) | 0.8 인일 | 요구사항 연계 확인 포함 |
| 컬럼 변경 (1건) | 0.2 인일 | 기존 컬럼은 `현행유지`가 기본 |
| 컬럼 신규 (1건) | 0.4 인일 | 표준용어 MCP 판정·승인 포함 |
| 테스트 케이스 수정 (1건) | 0.2 인일 | 경계값 재도출 포함 |
| 추적매트릭스 재대조 | 0.3 인일 | 누락 판정 검토 포함 |


## 주의사항

- **삭제는 행을 지우지 않는다.** AN-02 는 행을 남기고 상태만 `삭제`로 바꾼다.
  연계된 기능·테스트도 같은 방식으로 정리하며, 그러지 않으면 AN-05 가
  "삭제 미정리"로 잡는다
- 컬럼 변경은 그 컬럼을 쓰는 **다른 기능의 테스트**까지 세어야 한다.
  여기가 범위가 조용히 넓어지는 유일한 자리다
- 기존 컬럼명은 표준 미준수라도 `현행유지`가 기본이다 — 개명은 별도 변경 건으로 다룬다
- 작업량 추정은 **산출물 작성 공수** 기준이다. 실제 개발 공수는 별도 산정한다
- 변경요청서 승인 전에는 산출물 수정에 착수하지 않는다 (특히 감리 기간 중)
- 여러 요구사항이 한 변경에 걸리면 각각 추적한 뒤 합산한다 — 기능이 겹치면 중복 계상하지 않는다
