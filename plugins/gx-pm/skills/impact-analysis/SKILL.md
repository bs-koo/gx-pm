# 변경 영향도 분석 (impact-analysis)

요구사항 변경, 감리 지적, 설계 변경 시 영향을 받는 산출물과 범위를 분석한다. ID 추적 체인(제안요청 → 요구사항 → 화면 → 프로그램 → 단위테스트 → 통합테스트)을 기반으로 직접·연쇄·간접 영향을 추적하고, 작업량을 추정하며 변경요청서 초안을 생성한다.

## 입력

- 변경 대상: 요구사항ID, 화면ID, 테이블ID, 인터페이스ID 중 하나 이상 (또는 텍스트 설명)
- 변경 내용: 무엇이 어떻게 변경되는지 설명
- 변경 유형: 요구사항 변경 / 화면 변경 / DB 변경 / 인터페이스 변경 (복수 선택 가능)
- 기존 산출물 데이터 (추적매트릭스, 화면목록표 등 — 제공 시 더 정확한 분석)

## 처리 절차

### Step 1: 변경 유형 식별 및 분석 방향 결정

변경 유형에 따라 ID 체인 추적 방향이 달라진다.

| 변경 유형 | 시작 위치 | 추적 방향 | 주요 영향 산출물 |
|---------|---------|---------|-------------|
| **요구사항 변경** | {시스템코드}-RE-xxx | 하향 (요구사항 → 화면 → 프로그램 → 테스트) | 요구사항정의서, 화면목록표, 프로그램정의서, 테스트계획서, 추적매트릭스 |
| **화면 변경** | {접두}_{xx}_{xx}_{xxx} | 양방향 (상위 요구사항 확인 + 하위 프로그램·테스트) | 화면목록표, 화면정의서, 프로그램정의서, 단위테스트계획서, 추적매트릭스 |
| **DB 변경** | 테이블ID | 사용 화면 역추적 | 테이블정의서, ERD, 화면정의서, 프로그램정의서(DAO/Mapper), 테스트계획서 |
| **인터페이스 변경** | 인터페이스ID | 연계 요구사항 역추적 | 인터페이스정의서, 요구사항정의서, 프로그램정의서, 통합테스트계획서 |

### Step 2: 직접/연쇄/간접 영향 분류

각 영향 항목을 3단계로 분류한다.

| 영향 유형 | 정의 | 예시 |
|---------|------|------|
| **직접 영향** | 변경 대상 자체 및 ID 체인으로 1단계 직접 연결된 산출물 | 요구사항 변경 → 해당 요구사항 행 수정 (요구사항정의서), 연결된 화면ID |
| **연쇄 영향** | ID 체인을 따라 2단계 이상 전파되는 산출물 | 화면 변경 → 프로그램 수정 → 단위테스트 케이스 수정 → 추적매트릭스 갱신 |
| **간접 영향** | ID 체인 외부에서 같은 테이블·인터페이스·공통 컴포넌트를 공유하는 화면/프로그램 | 테이블 컬럼 변경 → 해당 테이블을 조회하는 다른 화면 전체 |

#### 영향 추적 절차 (요구사항 변경 예시)

```
[변경 시작] B-RE-003 (교육 과정 관리 — 파일첨부 기능 추가)
    ↓ 직접 영향
    [요구사항정의서] B-RE-003 행 수정 (요구내역, 상세내역 변경)
    [추적매트릭스 AN-05] B-RE-003 행 수정
    ↓ 연쇄 영향 (화면 레벨)
    [화면목록표 DE-03] EHR_03_01_020 (과정 등록) — 첨부 영역 추가
    [화면정의서] EHR_03_01_020 화면정의 수정
    ↓ 연쇄 영향 (프로그램 레벨)
    [프로그램정의서 DE-05] PG_EHR_03_01_020 — 파일 업로드 처리 로직 추가
    ↓ 연쇄 영향 (테스트 레벨)
    [단위테스트계획서 DE-13] U_EHR_03_01_020 — 첨부 검사기준 항목 추가
    [통합테스트계획서 DE-14] B-TE-002 — 파일 첨부 Step 추가
    ↓ 간접 영향
    [테이블정의서] TB_COURSE_FILE 테이블 신규 생성 또는 컬럼 추가
    [ERD] TB_COURSE ↔ TB_COURSE_FILE 관계 추가
```

### Step 3: 산출물별 수정 필요 항목 목록화

영향받는 산출물 전체를 목록화하고, 각 산출물에서 수정이 필요한 구체적 항목을 명시한다.

| 산출물 | 수정 항목 | 영향 유형 | 수정 난이도 |
|--------|---------|---------|-----------|
| 요구사항정의서 (AN-02) | B-RE-003 행 — 요구내역, 상세내역 | 직접 | 낮음 |
| 화면목록표 (DE-03) | EHR_03_01_020 — 화면 설명 수정 | 연쇄 | 낮음 |
| 화면정의서 (DE-04) | EHR_03_01_020 — 첨부 영역 레이아웃 추가 | 연쇄 | 중간 |
| 프로그램정의서 (DE-05) | PG_EHR_03_01_020 — 처리 로직 변경 | 연쇄 | 중간 |
| 테이블정의서 (DE-09) | TB_COURSE_FILE 신규 / TB_COURSE 컬럼 추가 | 간접 | 높음 |
| ERD (DE-10) | 관계선 추가 | 간접 | 중간 |
| 단위테스트계획서 (DE-13) | U_EHR_03_01_020 — 첨부 케이스 추가 | 연쇄 | 낮음 |
| 통합테스트계획서 (DE-14) | B-TE-002 — Step 추가 | 연쇄 | 낮음 |
| 추적매트릭스 (AN-05) | B-RE-003 행 전체 갱신 | 직접 | 낮음 |

### Step 4: 작업량 추정

영향받는 화면 수, 프로그램 수, 테스트 케이스 수를 기반으로 작업량을 추정한다.

#### 기준 작업량 단위 (공수 = 인일)

| 수정 단위 | 기준 공수 | 비고 |
|---------|---------|------|
| 요구사항 행 수정 (1건) | 0.1 인일 | 산출물 작성 기준 |
| 화면 설계 변경 (1화면) | 0.5 인일 | 화면정의서 + 목록표 |
| 화면 신규 추가 (1화면) | 1.0 인일 | 화면정의서 전체 작성 |
| 프로그램 로직 변경 (1건) | 1.0~2.0 인일 | 난이도에 따라 조정 |
| DB 테이블 변경 (1테이블) | 0.5 인일 | 테이블정의서 + ERD |
| DB 테이블 신규 (1테이블) | 1.0 인일 | 설계 + 정의서 작성 |
| 단위테스트 케이스 수정 (1건) | 0.2 인일 | 계획서 수정 기준 |
| 통합테스트 시나리오 수정 (1건) | 0.3 인일 | Step 추가/수정 포함 |
| 추적매트릭스 갱신 | 0.3 인일 | 전체 정합성 검토 포함 |

```
## 작업량 추정 요약

| 항목 | 수량 | 단위 공수 | 소계 |
|------|------|---------|------|
| 요구사항 행 수정 | 1건 | 0.1 | 0.1 인일 |
| 화면 변경 | 1화면 | 0.5 | 0.5 인일 |
| 프로그램 변경 | 1건 | 1.5 | 1.5 인일 |
| DB 변경 | 1테이블 | 1.0 | 1.0 인일 |
| 테스트 수정 | 2건 | 0.2 | 0.4 인일 |
| 추적매트릭스 갱신 | 1회 | 0.3 | 0.3 인일 |
| **합계** | | | **3.8 인일** |
```

```

| 요청일 | {오늘 날짜} |
| 요청자 | (PM 기입) |
| 변경 대상 | B-RE-003 (교육 과정 관리) |
| **변경 사유** | 발주처 요청: 과정 등록 시 첨부파일(계획서 등) 업로드 기능 추가 필요 |
| **변경 내용** | EHR_03_01_020 (과정 등록) 화면에 파일 첨부 영역 추가. 관련 테이블(TB_COURSE_FILE) 신규 생성 |
| **영향 범위** | 직접: 요구사항정의서, 추적매트릭스 / 연쇄: 화면정의서, 프로그램정의서, 테스트계획서 / 간접: 테이블정의서, ERD |
| **일정 영향** | 예상 추가 공수: 3.8 인일. 현 납기 영향 여부는 PM 판단 필요 |
| **우선순위** | P4 (발주처 요청) |
| **승인** | [ ] PM  [ ] 발주처 담당자  [ ] 기술 검토 |
```

- 직접 영향: 2개 산출물
- 연쇄 영향: 5개 산출물 (화면·프로그램·테스트 포함)
- 간접 영향: 2개 산출물 (테이블·ERD)
- 예상 추가 공수: 3.8 인일

변경요청서를 공식 문서 형식으로 작성할까요?"

## 주의사항

- DB 변경(컬럼 추가/삭제/타입 변경)은 반드시 간접 영향(해당 테이블 사용 화면 전체)까지 추적
- 인터페이스 변경은 수신 측 시스템 영향도까지 명시 (타 시스템 담당자 협의 필요 안내)
- 작업량 추정은 산출물 작성 공수 기준 — 실제 개발 공수는 별도 산정 필요
- 변경요청서 승인 전에는 산출물 수정 착수하지 않도록 주의 (특히 감리 기간 중)
- 동일 변경으로 여러 요구사항이 영향받으면 각각 별도 추적 후 합산
