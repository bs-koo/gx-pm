# 공공/SI 우선순위 결정 (prioritize-si)

공공/SI 프로젝트의 맥락에 맞는 우선순위 기준으로 **AN-02 요구사항**의 처리 순서를 결정한다.
일반 SaaS의 RICE, MoSCoW가 아닌 공공 프로젝트 특화 기준(법적 준수 > 감리 > 계약 > 협의 > 품질)을 적용한다.

**산출 대상은 요구사항이다.** 기능·테이블·테스트는 요구사항의 우선순위를 물려받으므로
따로 매기지 않는다 — 두 벌로 매기면 어느 쪽이 정본인지 갈린다.

## 입력

- AN-02 요구사항 목록 (또는 아직 산출물이 아닌 작업 항목 목록)
- 프로젝트 맥락 (선택이나 정확도 향상):
  - 납기일 및 주요 마일스톤
  - 감리 예정일 (1차, 2차, 최종)
  - 관련 법령 목록
  - 현재 진행 단계 (분석/설계/구현/시험)

## 처리 절차

### Step 1: 5단계 우선순위 기준 적용

각 항목에 대해 아래 기준을 순서대로 검토하여 해당하는 가장 높은 등급을 배정한다.

| 등급 | 기준 | 정의 | 판별 방법 | 대표 예시 |
|------|------|------|---------|---------|
| **P1** | 법적 필수 | 법령·고시·행정규칙에 의해 의무 구현. 미이행 시 검수 불가 또는 법적 제재 | "~법 제N조", "~고시 준수", "개인정보", "접근성" 키워드 | 개인정보보호법 암호화, 웹접근성(과기부 고시), 정보보안 취약점 조치, 전자정부 표준프레임워크 |
| **P2** | 감리 필수 | 감리원이 반드시 확인하는 항목. 누락 시 감리 지적 → 시정 조치 요구 | 산출물 목록, 추적매트릭스, 요구사항 상태·변경 근거, 표준 준수 | AN-05 추적매트릭스 완성도, 필수 산출물 누락, ID 체계 불일치, 테스트 결과 미기록 |
| **P3** | 과업 명시 | RFP/과업지시서에 기능 요구사항으로 명시. 계약 범위 내 의무 이행 | 과업지시서 기능 목록, SFR-xxx 등 원문 ID가 병기된 요구사항 | 과업지시서 3.1절 전체 기능 요구사항 |
| **P4** | 발주처 요청 | 과업 범위 외 발주처가 추가 요청. 협의하여 반영 여부 결정 | 회의록, 협의 메모, 담당자 구두 요청 | 중간 보고 후 추가 요청 기능, 운영 편의 요청 |
| **P5** | 품질 개선 | 기능 요건에 직접 영향 없는 품질·편의 향상 | 팀 내 제안, 코드 리뷰 결과 | UI 개선, 쿼리 최적화, 공통 컴포넌트 리팩토링 |

### Step 2: 영향도 세분화

같은 등급 내에서 영향도(높/중/저)로 세분화하여 처리 순서를 결정한다.

| 영향도 | 기준 |
|--------|------|
| **높** | 3개 이상 기능/업무 흐름에 영향 / 핵심 업무 처리(등록·승인·결제 등) / 다른 요구사항의 선행 조건 |
| **중** | 1~2개 기능에 영향 / 보조 업무 처리 / 독립적으로 개발 가능 |
| **낮** | 표시 방식·문구·색상 조정 / 단일 기능 내 세부 수정 / 기능 흐름에 무관 |

최종 처리 순서: P1-높 > P1-중 > P1-낮 > P2-높 > P2-중 > ... > P5-낮

### Step 3: 납기/감리 일정 반영 — 시급도 매트릭스

납기 및 감리 일정을 고려하여 시급도를 추가로 반영한다.

| 시급도 | 기준 |
|--------|------|
| **긴급** | 감리일 또는 납기까지 2주 이하 남은 상태에서 미완료 항목 |
| **조속** | 4주 이하. 착수 지연 시 납기 영향 |
| **일반** | 4주 초과. 일정 여유 있음 |
| **대기** | 현재 단계에서 착수 불필요 (예: 구현 단계에서 시험 항목) |

시급도와 우선순위 결합 매트릭스:

|  | 긴급 | 조속 | 일반 | 대기 |
|--|------|------|------|------|
| **P1** | 즉시 착수 | 즉시 착수 | 이번 스프린트 | 다음 단계 |
| **P2** | 즉시 착수 | 이번 스프린트 | 다음 스프린트 | 다음 단계 |
| **P3** | 이번 스프린트 | 다음 스프린트 | 계획대로 | 계획대로 |
| **P4** | 협의 후 결정 | 협의 후 결정 | 여유 시 처리 | 보류 |
| **P5** | 보류 | 보류 | 여유 시 처리 | 보류 |

### Step 4: 감리 지적 고위험 항목 자동 식별

다음 패턴에 해당하는 항목은 자동으로 P2(감리 필수) + 영향도 높으로 분류하고 별도 표시한다.

| 고위험 패턴 | 감리 지적 사유 |
|-----------|-------------|
| 추적매트릭스 미작성 또는 공백 다수 | AN-05 완성도 불량 |
| 요구사항 상태·변경 근거 미기재 | AN-02 불완전 |
| 요구사항ID ↔ 기능ID ↔ 테스트ID 연계 끊김 | 산출물 정합성 위반 |
| 단위테스트 결과(`Pass`/`Fail`) 미기록 | 검증 누락 |
| 필수 산출물 목록 중 누락 항목 | 산출물 납품 누락 |
| 보안 취약점 미조치 항목 | 보안 감리 지적 |
| 개인정보 처리 로그 미구현 | 법적 필수 누락 |

### Step 5: 요구사항 변경 시 우선순위 재조정

변경 요청이 발생하면 다음 절차로 재조정한다:

1. 변경 대상 요구사항의 현재 우선순위 확인
2. 변경으로 인해 새로 영향받는 요구사항 파악 (impact-analysis 스킬 연계)
3. 납기/감리 일정 재검토 → 시급도 재산정
4. 변경 요구사항의 등급이 올라가면 → 동일 등급 내 기존 항목의 순서 재조정
5. 변경으로 P5 항목이 P1로 격상되는 경우 (법령 신설 등) → PM에게 즉시 보고 권고

## 출력

### 우선순위 매트릭스 표

```
## 우선순위 매트릭스 — {시스템명} / {기준일}

| 순번 | 요구사항ID / 작업명 | 내용 요약 | 등급 | 영향도 | 시급도 | 처리 순서 | 판단 근거 | 비고 |
|------|------------------|---------|------|--------|--------|---------|---------|------|
| 1 | REQ-016 | 웹접근성 2.0 준수 | P1 | 높 | 긴급 | 즉시 착수 | 과기부 고시 의무 | 감리 고위험 |
| 2 | AN-05 작성 | 추적매트릭스 완성 | P2 | 높 | 긴급 | 즉시 착수 | 감리 핵심 산출물 | 감리 고위험 |
| 3 | REQ-001 | 운영자 권한 관리 | P3 | 높 | 조속 | 이번 스프린트 | 과업지시서 3.1.1 | |
```

### 감리 고위험 항목 목록

```
## ⚠ 감리 지적 고위험 항목 (즉시 조치 필요)

| 항목 | 현황 | 감리 지적 근거 | 권장 조치 |
|------|------|-------------|---------|
| AN-05 추적매트릭스 | 기능 미도출 15건 | 추적성 확보 미흡 | trace-requirements 스킬로 즉시 보완 |
```

### 추천 실행 순서

```
## 추천 실행 순서

### 이번 주 (즉시 착수)
1. [P1-높-긴급] REQ-016 웹접근성 조치
2. [P2-높-긴급] AN-05 추적매트릭스 완성

### 이번 스프린트
3. [P3-높-조속] REQ-001 운영자 권한 관리
4. [P3-높-조속] REQ-003 교육 과정 관리

### 다음 스프린트
5. [P3-중-일반] REQ-010 통계 현황
...
```

## 체크포인트

우선순위 결과를 사용자에게 확인한다:

"다음 우선순위 판정 결과를 확인해주세요:
- REQ-016 → P1(법적 필수) — 웹접근성 고시 근거
- REQ-025 → P4(발주처 요청) — 중간보고 회의록 기준. P3로 상향 필요 시 알려주세요.
- 감리 고위험 항목 3건 → 즉시 착수 권고
납기일 또는 감리 일정이 있으면 알려주시면 시급도 매트릭스를 더 정확하게 적용합니다."

## 주의사항

- P1/P2 항목은 PM 임의 판단으로 등급 하향 불가 — 법적 근거 또는 감리 기준에 의해 결정
- P4(발주처 요청) 항목은 공식 협의록이 없으면 P5로 처리 후 PM 확인 요청
- 납기가 촉박할 때 P5 항목은 전면 보류하고 P1~P3에 집중
- 동일 등급 다수 항목은 ID 체인 선행 순서(요구사항 → 기능 → 테스트) 기준으로 정렬
