# 통합/인수테스트 결과 기입 (fill-integration-test-result)

통합테스트계획서(DE-14)를 기반으로 판정결과, 테스트 데이터, 수행자 정보를 기입하여
통합테스트결과서(TE-02) 또는 인수테스트결과서(TE-06)를 완성한다.

두 문서(TE-02/TE-06)는 양식이 동일하나 수행 주체가 다르다.
- TE-02 통합테스트결과서: 개발팀이 수행
- TE-06 인수테스트결과서: 발주처(고객)가 수행

---

## 결과서 추가 컬럼 구조

계획서(DE-14)에서 다음 컬럼이 추가된다.

| 추가 컬럼 | 설명 |
|----------|------|
| 테스트 데이터 | 해당 Step에서 사용한 입력값 또는 조건 |
| 판정결과 | 적합 / 부적합 / **점검제외** |
| **점검제외 사유** | 판정이 점검제외일 때 필수 |
| 부적합 내역 | 부적합 발생 시 구체적 현상 |
| **결함ID** | 부적합 시 DF-01 참조 (`{시스템코드}-DF-{순번}`) |
| 테스트 일시 | 테스트 수행 일시 (YYYY-MM-DD HH:MM) |
| 수행자 | 테스트 수행자 성명 |

> **원인·조치·재테스트 이력은 이 표가 아니라 결함관리대장(DF-01)에 기록한다.**
> 결과서에는 결함ID만 참조하여 중복 기록과 통계 부재 문제를 없앤다.

### 판정값 3종

| 값 | 의미 | 필수 후속 |
|------|------|---------|
| **적합** | 예상 출력과 일치 | — |
| **부적합** | 예상 출력과 불일치 | **결함ID 발급** (manage-defects 호출) |
| **점검제외** | 수행 자체가 불가능 | **사유 기재** |

점검제외 인정 사유: 테스트 환경 미준비 / 선행 기능 결함 / 외부 환경 변화 / 과업 범위 외 판정.
그 외("시간 부족" 등)는 인정되지 않으며 **미수행**으로 집계된다.

```
2. TE-06 인수테스트결과서 (발주처 수행)

[기본 정보]
- 프로젝트명:
- 시스템명:
- 테스트 수행 기간:
- 테스트 환경 (서버/DB/OS):
- 총괄 수행자:
- 결재선 (작성자 / 검토자 / 승인자):
```

> 체크포인트: 문서 유형을 확인한다. TE-06 선택 시 발주처 담당자 정보(소속/직위/성명)를 추가로 수집한다.

## Step 2: 입력 모드 선택

```
[통합/인수테스트 결과 입력 모드를 선택하세요]

1. 전체 적합
   - 모든 시나리오의 모든 Step을 "적합"으로 일괄 처리
   - 테스트 데이터 컬럼에 "정상동작" 자동 기입
   - 부적합이 전혀 없는 경우 사용
   - ※ 예외 시나리오는 "차단되는 것이 정상"이므로 차단 확인 시 적합이다

2. 부적합 목록 입력
   - 부적합 시나리오/Step만 입력하고 나머지는 "적합" 자동 처리
   - 권장 방식: 부적합이 소수일 때

3. 시나리오별 입력
   - 시나리오 단위로 하나씩 확인하며 입력
   - 모든 시나리오를 꼼꼼히 기록해야 할 때 사용
```

---

## Step 3-A: 전체 적합 처리

모드 1 선택 시:
- 모든 시나리오의 모든 Step → 판정결과: "적합"
- 테스트 데이터: "정상동작"
- 테스트 일시, 수행자: Step 1에서 수집한 값으로 일괄 기입
- 부적합 관련 컬럼 전체 공란

---

## Step 3-B: 부적합 목록 입력 처리

모드 2 선택 시, 다음 형식으로 부적합 항목을 입력받는다.

```
[부적합 입력 형식]
시나리오ID | Step번호 | 테스트데이터 | 부적합내역

원인·조치·조치후 판정은 여기서 받지 않는다 (결함관리대장 DF-01에서 관리)

예시:
B-TE-001 | 교육과정 등록 및 수강신청 | Step 3 | 신청 후 목록 반영 확인 | user01 | 목록에 즉시 반영되지 않음 (새로고침 필요)
```

부적합 항목 입력 후 **manage-defects**를 호출하여 결함ID를 발급한다.

---

## Step 3-C: 시나리오별 입력 처리

모드 3 선택 시, 시나리오 단위로 순서대로 확인한다.

```
[시나리오: B-TE-001 교육과정 등록 및 수강신청]  (구분: 정상)
사전조건: 관리자(admin01) 로그인, 과정코드 C001 미등록

Step 1. 교육관리 > 과정등록 메뉴 클릭 → 판정결과: [적합/부적합/점검제외]
Step 2. 과정명·교육기간 입력 후 저장 → 판정결과: [적합/부적합/점검제외]
  ↑ 테스트 데이터: 과정명=정보보안기초, 기간=2026-05-01~05-30
Step 3. 일반사용자로 해당 과정 신청 → 판정결과: [적합/부적합/점검제외]
...

→ 부적합 발생 즉시 manage-defects 호출하여 결함ID 발급
→ 점검제외 시 사유 입력 요청
```

---

## Step 4: 부적합 처리 — 결함관리대장 연계

부적합 발생 시 **manage-defects 스킬을 호출**하여 결함ID를 발급하고 DF-01에 등록한다.
조치·재테스트 워크플로우는 대장의 **상태 흐름**으로 관리한다.

```
[결과서에 기록]                    [결함관리대장 DF-01에 기록]

부적합 내역 (현상)          ──→   결함ID 발급
결함ID 참조                        심각도 · 우선순위 판정
                                   재현 절차
                                   Open → Assigned → Fixed
                                        → Retest → Closed
                                          └→ Reopen (재테스트 부적합)
```

결과서에 기입할 최소 항목:

| 필드 | 내용 | 예시 |
|------|------|------|
| 판정결과 | 부적합 | 부적합 |
| 부적합 내역 | 발생한 현상 구체 기술 | "저장 시 500 오류 발생, 목록 미반영" |
| **결함ID** | manage-defects가 발급 | B-DF-007 |

> 종전에는 결과서에 원인·조치·조치후 판정을 직접 적었다. 그 방식은 같은 결함이 여러 시나리오에서
> 중복 기록되고, 심각도·통계가 없어 종료기준을 판정할 수 없었다. v1.5.0부터 대장으로 분리했다.

### 인수테스트(TE-06) 특이사항

발주처가 발견한 부적합도 **동일한 결함ID 체계**로 등록한다.
단, 발견자에 발주처 담당자 실명을 기재하고, 우선순위는 기본 High로 제안한다.

## Step 6: 결과 통계 산출 및 종료기준 판정

```
[통합/인수테스트 결과 통계]

총 시나리오: N건 (정상 N / 예외 N)
총 Step:    N건

판정 결과:
- 적합:     N건 (X%)
- 부적합:   N건 (X%)
- 점검제외: N건 (X%)  ← 사유별 내역 첨부

실행률 = (적합 + 부적합) ÷ 전체 × 100 = X%
적합률 = 적합 ÷ (적합 + 부적합) × 100 = X%

발급 결함: N건 (Critical N · Major N · Minor N · Trivial N)
결함 조치 현황 (DF-01 기준):
- Closed: N건 · 진행중: N건 · Deferred: N건 · Reopen 이력: N건
```

### 종료기준 판정 (TE-01 §7 대조)

```
[종료기준 판정]

| 기준 | 목표 | 현재 | 판정 |
|------|------|------|------|
| 시나리오 실행률 | 100% | N% | 충족 / **미충족** |
| Critical 결함 잔존 | 0건 | N건 | 충족 / **미충족** |
| Major 결함 잔존 | 0건 | N건 | 충족 / **미충족** |
| Minor 결함 조치율 | 90% 이상 | N% | 충족 / **미충족** |
| 적합률 | 95% 이상 | N% | 충족 / **미충족** |

종합: 시스템테스트 진입 가능 / **진입 불가**
```

> TE-06(인수테스트)에서 종료기준 미충족이면 **인수 판정에 직접 영향**을 준다.
> 미조치 결함 목록과 조치 계획을 발주처에 제시하도록 안내한다.

## 주의사항 및 규칙

1. 문서 유형(TE-02/TE-06) 혼용 금지: 수행 주체가 다르므로 반드시 별도 작성
2. 부적합 항목은 **결함ID를 발급**하고 대장의 상태가 Closed가 될 때까지 추적한다
3. 원인·조치·재테스트 이력은 결과서가 아니라 **결함관리대장(DF-01)**에 기록한다
4. TE-06(인수테스트)은 발주처 담당자가 직접 수행자로 기재되어야 함 — 개발팀 인원 대리 기입 금지
5. 테스트 데이터는 단순 "정상동작" 외에 구체적 입력값 기재 권장
6. 동일 시나리오에 복수 부적합 발생 시 모두 별도 행으로 기록하고 각각 결함ID를 확인한다
   (같은 원인이면 manage-defects가 하나의 결함으로 병합한다)
7. 인수테스트 결과서(TE-06)는 발주처 날인/서명란이 추가될 수 있음
8. **점검제외는 4가지 인정 사유에 한한다** — 사유 없는 미실행은 실행률에 그대로 반영된다
9. 예외 시나리오는 "차단되는 것이 정상"이므로, **차단되면 적합**이다. 판정 방향을 혼동하지 않는다
