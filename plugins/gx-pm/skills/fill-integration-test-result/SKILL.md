# 통합/인수테스트 결과 기입 (fill-integration-test-result)

통합테스트계획서(DE-14)를 기반으로 판정결과, 테스트 데이터, 수행자 정보를 기입하여
통합테스트결과서(TE-02) 또는 인수테스트결과서(TE-06)를 완성한다.

두 문서(TE-02/TE-06)는 양식이 동일하나 수행 주체가 다르다.
- TE-02 통합테스트결과서: 개발팀이 수행
- TE-06 인수테스트결과서: 발주처(고객)가 수행

---

## 결과서 추가 컬럼 구조

계획서(DE-14)에서 다음 컬럼이 추가된다.

| 추가 컬럼 | 설명 |
|----------|------|
| 테스트 데이터 | 해당 Step에서 사용한 입력값 또는 조건 |
| 판정결과 | 적합 / 부적합 |
| 부적합 내역 | 부적합 발생 시 구체적 현상 |
| 테스트 일시 | 테스트 수행 일시 (YYYY-MM-DD HH:MM) |
| 수행자 | 테스트 수행자 성명 |
| 부적합 원인 및 조치내역 | 원인 분석과 수행된 조치 내용 |
| 조치일시 | 조치 완료 일시 |
| 조치자 | 조치 수행자 성명 |
| 조치후 판정결과 | 재테스트 후 최종 판정 (적합 / 부적합) |

---

## Step 1: 문서 유형 및 기본 정보 수집

```
[문서 유형 선택]
1. TE-02 통합테스트결과서 (개발팀 수행)
2. TE-06 인수테스트결과서 (발주처 수행)

[기본 정보]
- 프로젝트명:
- 시스템명:
- 테스트 수행 기간:
- 테스트 환경 (서버/DB/OS):
- 총괄 수행자:
- 결재선 (작성자 / 검토자 / 승인자):
```

> 체크포인트: 문서 유형을 확인한다. TE-06 선택 시 발주처 담당자 정보(소속/직위/성명)를 추가로 수집한다.

---

## Step 2: 입력 모드 선택

```
[통합/인수테스트 결과 입력 모드를 선택하세요]

1. 전체 적합
   - 모든 시나리오의 모든 Step을 "적합"으로 일괄 처리
   - 테스트 데이터 컬럼에 "정상동작" 자동 기입
   - 부적합이 전혀 없는 경우 사용

2. 부적합 목록 입력
   - 부적합 시나리오/Step만 입력하고 나머지는 "적합" 자동 처리
   - 권장 방식: 부적합이 소수일 때

3. 시나리오별 입력
   - 시나리오 단위로 하나씩 확인하며 입력
   - 모든 시나리오를 꼼꼼히 기록해야 할 때 사용
```

---

## Step 3-A: 전체 적합 처리

모드 1 선택 시:
- 모든 시나리오의 모든 Step → 판정결과: "적합"
- 테스트 데이터: "정상동작"
- 테스트 일시, 수행자: Step 1에서 수집한 값으로 일괄 기입
- 부적합 관련 컬럼 전체 공란

---

## Step 3-B: 부적합 목록 입력 처리

모드 2 선택 시, 다음 형식으로 부적합 항목을 입력받는다.

```
[부적합 입력 형식]
시나리오ID | 시나리오명 | Step번호 | Step명 | 테스트데이터 | 부적합내역

예시:
SN-003 | 사용자 등록 | Step 4 | 저장 후 목록 반영 확인 | 신규사용자 홍길동 | 목록에 즉시 반영되지 않음 (새로고침 필요)
```

부적합 항목 입력 후 자동으로 조치 정보를 요청한다.

---

## Step 3-C: 시나리오별 입력 처리

모드 3 선택 시, 시나리오 단위로 순서대로 확인한다.

```
[시나리오: SN-003 사용자 등록]
Step 1. 사용자관리 메뉴 접근 → 판정결과: [적합/부적합]
Step 2. 신규 등록 버튼 클릭 → 판정결과: [적합/부적합]
Step 3. 사용자 정보 입력 → 판정결과: [적합/부적합]
  ↑ 테스트 데이터: (입력값 기재)
Step 4. 저장 버튼 클릭 → 판정결과: [적합/부적합]
...

→ 부적합 발생 즉시 상세 정보 요청
```

---

## Step 4: 부적합 처리 워크플로우

부적합 항목 발생 시 다음 5단계 워크플로우를 진행한다.

```
[부적합 처리 흐름]

① 부적합 발생
   └ 부적합 내역: 구체적 현상 기술

② 원인 분석
   └ 부적합 원인: 기술적/프로세스적 원인 명시

③ 조치 수행
   └ 조치내역: 수행한 구체적 조치 내용
   └ 조치일시: YYYY-MM-DD HH:MM
   └ 조치자: 조치 수행자 성명

④ 재테스트 수행
   └ 동일 Step에 대해 재테스트 실시

⑤ 조치후 판정
   └ 조치후 판정결과: 적합 / 부적합 (반복 시 ②로 복귀)
```

| 필드 | 내용 | 예시 |
|------|------|------|
| 부적합 내역 | 발생한 현상 구체 기술 | "저장 시 500 오류 발생" |
| 원인 | 원인 분석 결과 | "DB 커넥션 풀 설정 오류" |
| 조치내역 | 수행한 조치 | "application.properties 수정 후 재배포" |
| 조치일시 | 조치 완료 일시 | "2025-03-14 15:30" |
| 조치자 | 조치 담당자 | "김개발" |
| 조치후 판정결과 | 재테스트 결과 | "적합" |

---

## Step 5: TE-02/TE-06 결과서 출력

### 문서 헤더

```
문서번호: TE-02 (또는 TE-06)
문서명: 통합테스트결과서 (또는 인수테스트결과서)
프로젝트명: {프로젝트명}
시스템명: {시스템명}
테스트 수행 기간: {기간}
테스트 환경: {환경}
작성일: {작성일}
결재선: {작성자} / {검토자} / {승인자}
```

### 결과서 본문 표 (시나리오별)

| 시나리오ID | 시나리오명 | Step | Step명 | 테스트데이터 | 판정결과 | 부적합내역 | 테스트일시 | 수행자 | 원인및조치 | 조치일시 | 조치자 | 조치후판정 |
|-----------|-----------|------|--------|------------|--------|----------|----------|--------|----------|--------|--------|--------|
| SN-001 | 로그인 | Step 1 | 정상 로그인 | ID: admin | 적합 | | 2025-03-13 10:00 | 홍길동 | | | | |
| SN-003 | 사용자등록 | Step 4 | 저장 후 반영 | 신규사용자 | 부적합 | 목록 미반영 | 2025-03-13 14:00 | 홍길동 | 캐시 미갱신 → 캐시 초기화 처리 추가 | 2025-03-14 09:00 | 김개발 | 적합 |

## Step 6: 결과 통계 산출

결과서 하단에 다음 통계를 자동 산출하여 표시한다.

```
[통합/인수테스트 결과 통계]

총 시나리오 수: N건
총 Step 수:    N건

판정 결과:
- 적합:   N건 (X%)
- 부적합: N건 (X%)

부적합 조치 현황:
- 조치완료 (조치후 적합): N건
- 조치중 (조치후 판정 미기입): N건
- 재부적합 (조치후 부적합): N건

최종 적합률: N / (N + N) × 100 = X%
```

## 주의사항 및 규칙

1. 문서 유형(TE-02/TE-06) 혼용 금지: 수행 주체가 다르므로 반드시 별도 작성
2. 부적합 항목은 조치후 판정결과가 "적합"이 될 때까지 워크플로우 반복
3. TE-06(인수테스트)은 발주처 담당자가 직접 수행자로 기재되어야 함
4. 테스트 데이터는 단순 "정상동작" 외에 구체적 입력값 기재 권장
5. 동일 시나리오에 복수 부적합 발생 시 모두 별도 행으로 기록
6. 인수테스트 결과서(TE-06)는 발주처 날인/서명란이 추가될 수 있음
