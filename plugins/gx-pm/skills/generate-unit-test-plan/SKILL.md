# 단위테스트계획서 생성 (generate-unit-test-plan)

AN-03 기능명세서의 `입력항목`·`처리내용(로직)`·`출력결과`를 근거로 기능 1건당 테스트 케이스 N건을
기계적으로 도출한다. 화면 유형 판별이나 27개 검사기준 매핑은 하지 않는다 — 그 구조는 폐지됐다.

## 입력

| 항목 | 필수 | 설명 |
|------|------|------|
| AN-03 기능명세서 | Y | 승인된 것만 |
| DE-08 테이블정의서 | N | 있으면 제약을 우선한다 |
| AN-02 요구사항정의서 | Y | 비기능 요구사항 목록용 |
| 테스트ID 채번 규칙 | Y | 프로파일. 미설정이면 묻는다 |

## 처리 절차

### Step 1: 기능별 케이스 도출

`templates/DE-13-unit-test-plan.md` 의 케이스 도출 규칙표를 따른다.
설계기법(동등분할·경계값·결정테이블·상태전이) 적용은 **design-test-cases** 스킬을 따른다.
기법 이름은 컬럼으로 내보내지 않는다 — 내부 도출 규칙이다.

### Step 2: 제약 출처 우선순위

같은 항목의 제약이 AN-03 과 DE-08 에서 다르면 **DE-08 이 우선**한다.
스키마가 실제로 강제하는 값이기 때문이다. 불일치는 게이트에서 목록으로 보고한다.

### Step 3: 연계요구사항ID 자동 채움

`연계기능ID` 로 AN-03 을 조회해 그 기능의 `연계요구사항ID` 를 그대로 옮긴다.
**사용자에게 묻지 않는다.**

### Step 4: 비기능 요구사항 케이스

AN-02 에서 어느 기능에도 안 걸린 요구사항을 모은 뒤 **둘로 가른다.** 가르는 기준은
`skills/extract-requirements/SKILL.md` 의 「기능 / 비기능 판정 (정본)」 사다리를 그
요구사항에 재적용한 결과다 (AN-02 에 `구분` 열이 없어 읽어올 수 없다).

| 재적용 결과 | 처리 |
|------|------|
| **비기능** | `연계기능ID` 공란 행으로 만든다. 측정 조건·목표치가 요구사항 상세내용에 없으면 그 자리에서 묻는다 |
| **기능** | **행을 만들지 않는다.** `기능 미도출` 후보로 모아 게이트에 보고한다 — 기능 요구사항인데 AN-03 에 기능이 없는 것은 정상 갈래가 아니라 결함이다 |

**여기서 가르지 않으면 `기능 미도출` 이 파이프라인 경로에서 영영 나오지 않는다.**
전건을 공란 행으로 만들면 AN-05 의 누락 판정 2번이 "비기능 테스트가 1건 이상" 에 걸려
기능 없음 판정을 건너뛴다 (`skills/trace-requirements/SKILL.md` Step 5). 산출물을 더
만들수록 결함이 가려지는 셈이 된다.

### Step 5: 의존성 판정

선행 케이스가 만든 데이터를 쓰는 케이스에만 선행 테스트ID 를 적는다.
순환 의존이 생기면 차단한다.

### Step 6: 충분성 검증

- 정상 케이스만 있는 기능이 있으면 **차단**한다
- 필수 항목이 있는데 미입력 예외가 없으면 자동 보강한다
- 길이·범위 제약이 있는데 경계 케이스가 없으면 자동 보강한다

### Step 7: 개정이력

**manage-revision-history** 스킬로 개정이력 행을 만든다.

## 출력 형식

```
## 개정이력

| 버전 | 개정일 | 개정 사유 | 개정 내용 | 작성자 | 승인자 |
|------|--------|----------|----------|--------|--------|
| 1.0 | 2026.09.03 | 신규 | 최초 작성 | 구본승 | |

## 단위테스트계획 — {시스템명}

| 테스트ID | 연계기능ID | 연계요구사항ID | 사전조건 | 입력 | 기대결과 | 사후조건 | 의존성 | 테스트담당자 | 수행일 | 결과 |
|---|---|---|---|---|---|---|---|---|---|---|
| UT-001 | FN-001 | REQ-001 | 원단위 통계파일 업로드 완료 | 세부용도=업무시설, 이상치제외=N | 세부용도별 EUI 중위값 테이블 생성, CDF 스코어 0~1 | TB_SCORE 1건 저장, 이력 로그 1건 | 없음 | | | |
| UT-002 | FN-001 | REQ-001 | 〃 | 헤더 컬럼 순서가 뒤바뀐 파일 | "헤더 형식 오류" 안내 후 처리 중단 | **저장 없음** | UT-001 | | | |
```

계획서이므로 `테스트담당자`·`수행일`·`결과` 칸은 빈칸으로 둔다.

## 체크포인트

케이스 도출 결과를 사용자에게 확인:

```
기능 {N}건에서 테스트 케이스 {N}건을 도출했습니다.

주요 확인:
1. 경계값이 실제 컬럼 길이·업무 제약과 맞는지
2. 예외 케이스의 사후조건에 "변화 없음"이 정확한지
3. 정상 케이스만 있는 기능 {N}건을 보강할지
4. 비기능 요구사항 {N}건이 연계기능ID 공란 행으로 빠짐없이 반영됐는지
5. 기능 요구사항인데 연계된 기능이 없는 {N}건 (`기능 미도출` 후보) — AN-03 을 보강할지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.
