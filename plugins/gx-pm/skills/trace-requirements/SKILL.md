# 추적매트릭스 생성/갱신 (trace-requirements)

**이 문서는 대조기다.** AN-02·AN-03·DE-08·DE-13 네 산출물을 읽어 끊긴 곳을 찾는 것이
본업이고, AN-05 표는 그 부산물이다. **손으로 채우지 않는다** — 네 산출물에서
기계적으로 조립한다. 새 정보를 만들지 않는다.

## 입력

| 산출물 | 산출물 코드 | 필수 여부 | 이 스킬이 읽는 열 |
|--------|-----------|---------|------------------|
| 요구사항정의서 | AN-02 | 필수 | 요구사항ID·요구사항명·상태 |
| 기능명세서 | AN-03 | 있는 만큼만 | 기능ID·기능명. `연계요구사항ID` 로 역조회 |
| 테이블정의서 | DE-08 | 있는 만큼만 | 테이블명·컬럼명·구분. `연계기능ID` 로 역조회 |
| 단위테스트계획서 | DE-13 | 있는 만큼만 | 테스트ID·결과. `연계기능ID`·`연계요구사항ID` 로 역조회 |

AN-03·DE-08·DE-13 중 없는 산출물이 있으면, 그 산출물이 채우는 열만 빈칸으로 두고
나머지는 그대로 조립한다. 없는 산출물 때문에 생긴 빈칸은 「누락 판정」이 아니라
"확인 불가"다 — 사용자에게 어떤 산출물이 없어서 못 채웠는지 밝힌다.

## AN-05 컬럼 구조

**컬럼 구조와 누락 판정표의 정본은 `templates/AN-05-traceability-matrix.md` 다.**
9개 컬럼 목록·순서는 그 파일의 「본문 컬럼 (정본)」 절을, 누락 표기는 「누락 판정」
절을 따른다. 여기서 복제하지 않는다.

## 조립 절차

### Step 1: 요구사항 행 만들기

AN-02 의 요구사항ID 마다 시작 행을 만든다. `요구사항ID`·`요구사항명`·`상태` 를
그대로 옮긴다.

### Step 2: 기능 역조회 (AN-03)

AN-03 에서 `연계요구사항ID` 에 이 요구사항ID 가 들어간 행을 전부 찾는다.

- **0건** → 기능 관련 칸(`기능ID`·`기능명`·`테이블·컬럼`)을 비운 채 Step 4 로 간다
  (기능 미도출 후보 — 최종 판정은 Step 5).
- **1건 이상** → 기능마다 행을 나눈다. 한 요구사항이 여러 기능에 걸리면 행이 여러
  개가 되고, `요구사항ID` 는 xlsx 추출 시 세로 병합 대상이다. `기능ID`·`기능명` 을
  각 행에 채운다.

### Step 3: 테이블·컬럼 역조회 (DE-08)

기능이 있는 행마다, DE-08 에서 `연계기능ID` 에 그 기능ID 가 들어간 행을 찾는다.
테이블명으로 묶고 `구분`(기존/신규/변경) 별 건수를 센다.

`{테이블명} ({구분} {건수})` 형태로 적는다. 한 테이블에 구분이 섞이면
`TB_SCORE (기존 2, 신규 1)` 처럼 쉼표로 나열한다. 테이블이 여럿이면 셀 안에서
줄바꿈(`\n`)으로 구분한다. DE-08 이 없거나 매칭이 0건이면 빈칸으로 둔다 —
테이블 매핑 없음은 이 스킬의 누락 판정 대상이 아니다(DE-08 은 역생성 문서라
아직 없을 수 있다).

### Step 4: 테스트 역조회 (DE-13)

- 기능이 있는 행 → DE-13 에서 `연계기능ID` 가 그 기능ID 와 같은 행을 센다.
- 기능이 없는 행(Step 2 에서 0건) → DE-13 에서 `연계기능ID` 가 **공란**이고
  `연계요구사항ID` 가 이 요구사항ID 와 같은 행을 센다. DE-13 템플릿이 정의한
  비기능 테스트 형태다.

`테스트 수` = 위에서 찾은 행 수.

`Pass/Fail` = `{결과=Pass 건수}/{결과=Fail 건수}`.
- 테스트 수가 0 이면 `—` (나눌 대상이 없다)
- 테스트는 있는데 `결과` 가 전건 공란이면 `0/0` 으로 적는다 — 실행은 안 됐어도
  Pass 0건·Fail 0건은 사실이다. 이유는 `누락` 열의 `미수행` 이 설명한다

### Step 5: 누락 판정

`templates/AN-05-traceability-matrix.md` 의 「누락 판정」 표를 아래 순서로 검사한다.
**먼저 걸리는 조건이 그 행의 `누락` 값이다.** 순서가 없으면 같은 행이 두 유형에
동시에 해당할 때 어느 쪽을 적을지 매번 갈린다.

1. **삭제 미정리** — 이 요구사항의 `상태` 가 `삭제` 인데, AN-03 에 아직 이
   요구사항ID 를 연계한 기능이 있거나 DE-13 에 아직 이 요구사항ID·기능ID 를
   연계한 테스트가 있다. (증거가 하나도 없으면 정리가 끝난 것이므로 `누락` 은
   비운다.)
2. **기능도 비기능 테스트도 0건** — Step 2 가 0건이고 Step 4 의 비기능 테스트도
   0건. 요구사항명·상세내용에 `classify-requirements` 스킬의 비기능 판별
   키워드(성능·보안·접근성·호환성 계열 — "이상"·"이하"·"이내"·"준수"·"암호화"·
   "인증" 등)가 있으면 `비기능 검증 누락`, 없으면 `기능 미도출`. 키워드 판별은
   `classify-requirements` 정본을 재적용한 것이지 새 기준이 아니다
3. **기능은 있는데 테스트 수 0** — `테스트 미작성`
4. **테스트는 있는데 `결과` 가 전건 공란** — `미수행`
5. **`Fail` 이 1건 이상** — `실패 {N}건` (N 은 Fail 건수)
6. **기능이 있는 행의 테스트 수가 정확히 1건** — `예외 케이스 없음`. DE-13 은
   기능 1건당 정상 흐름 최소 1건을 만드는 게 규칙이므로(`templates/DE-13-unit-test-plan.md`
   의 케이스 도출 규칙), 테스트가 1건뿐이면 그게 정상 흐름 하나뿐이라는 뜻이다.
   이 판정은 결론이 아니라 확인 요청이다 — 정말 예외가 없는 단순 기능일 수도 있다
7. 위 어디에도 안 걸리면 `누락` 은 빈칸이다

**비기능 요구사항에 `기능ID` 가 없는 것은 그 자체로 누락이 아니다.** 2번에서
비기능 테스트가 1건 이상 확인되면 기능 없음 판정을 건너뛰고 3~6번(테스트 수 기준
판정)만 적용한다.

매핑 결과를 사용자에게 확인한다:

- REQ-001 → 기능 1개 연계 (FN-001), 테스트 6건 전부 Pass
- REQ-032 → 연계된 기능 없음 ⚠ (AN-03 에서 이 요구사항을 참조하는 기능을 찾지 못함)
- 비기능 요구사항 5건 → 기능ID 없이 DE-13 비기능 테스트로만 검증
수정 또는 추가 매핑이 필요한 항목을 알려주세요."

## 주의사항

- 추적매트릭스는 감리 핵심 산출물 — 공백 행이나 ID 불일치는 반드시 제거
- 하나의 요구사항에 기능이 여러 개 걸리면 행을 나누고, `요구사항ID` 를 세로 병합한다
- **비기능 요구사항의 `기능ID`·`기능명`·`테이블·컬럼` 칸이 빈 것은 정상**이다.
  대신 DE-13 비기능 테스트(`연계기능ID` 공란 + `연계요구사항ID` 일치)가 없으면 누락이다
- `예외 케이스 없음` 은 확정 판정이 아니라 확인 요청이다 — 자동으로 결함 처리하지 않는다
- 기존 추적매트릭스 갱신 시 기존 행의 순서를 유지하고 바뀐 값만 갱신한다
- 누락 판정은 `templates/AN-05-traceability-matrix.md` 의 「누락 판정」 표가 정본이다.
  여기서 조건을 다시 정의하지 않는다 — 위 「조립 절차 Step 5」는 그 표를 실행 가능한
  순서로 푼 것일 뿐이다
