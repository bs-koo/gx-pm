# 추적매트릭스 생성/갱신 (trace-requirements)

요구사항정의서(AN-02), 화면목록표(DE-03), 프로그램정의서(DE-05), 테스트계획서(DE-13/14)의 ID를 교차 매핑하여 AN-05 요구사항추적매트릭스를 생성하거나 갱신한다. 감리 지적의 핵심 산출물이므로 누락 없이 정확하게 작성한다.

## 입력

다음 산출물 중 가용한 것을 제공한다:

| 산출물 | 산출물 코드 | 필수 여부 | 제공 컬럼 |
|--------|-----------|---------|---------|
| 요구사항정의서 | AN-02 | 필수 | 제안요청ID, 요구사항ID, 요구내역, **구분(기능/비기능)** |
| 화면목록표 | DE-03 | 설계 매핑용 | 화면ID, 화면명 |
| 프로그램정의서 | DE-05 | 설계 매핑용 | 프로그램ID, 프로그램명 |
| 인터페이스정의서 | DE-04 | 설계 매핑용 (선택) | 인터페이스ID, 인터페이스명 |
| 테이블정의서 | DE-08 | 설계 매핑용 (선택) | 테이블ID |
| 단위테스트계획서 | DE-13 | 검증 매핑용 | 단위테스트ID, **테스트케이스ID** |
| 통합테스트계획서 | DE-14 | 검증 매핑용 | 통합테스트 시나리오ID, 시나리오명 |
| **시스템테스트계획서** | **ST-01** | **비기능 검증 매핑용** | 시스템테스트ID, 테스트 항목 |
| **결함관리대장** | **DF-01** | 잔존 결함 확인용 | 결함ID, 상태 |

> 산출물 코드는 `CLAUDE.md`의 산출물 범위표를 정본으로 한다.
> 인터페이스정의서 = **DE-04**, 테이블정의서 = **DE-08**.

## AN-05 추적매트릭스 컬럼 구조

**컬럼 구조의 정본은 `templates/AN-05-traceability-matrix.md` 다.** 여기서 복제하지 않는다 —
컬럼 목록과 순서는 그 파일의 「본문 표 헤더 (플랫)」 절을 따른다.

아래는 그 컬럼들을 **어떻게 채우는가** 에 대한 규칙이다.

### 채우는 규칙

| 컬럼군 | 채우는 방법 |
|--------|-----------|
| 제안요청 (영역 1) | RFP 원문에서. 대/중/소분류는 **classify-requirements** 결과를 그대로 쓴다 |
| 요구사항 (영역 2) | AN-02 요구사항정의서에서. `근거` 는 AN-02 의 같은 열을 그대로 옮긴다 — **extract-requirements** 가 표에서 뽑은 요구사항은 원문 ID(예: `과업지시서 BR-01`)가 거기 들어 있다 |
| 설계 (영역 3) | DE-04·DE-08·DE-03·DE-05 에서. 복수 매핑은 셀 안에서 줄바꿈(`
`)으로 구분 |
| 검증 (영역 4) | DE-13·DE-14·ST-01·DF-01 에서. `테스트케이스 수` 는 해당 화면의 `TC_` 건수 |

**비기능 요구사항은 채워지는 칸이 다르다.** 화면ID·프로그램ID·단위테스트는 `-` 이고,
`시스템테스트ID` 가 그 요구사항의 유일한 검증 근거다. 판정 기준은
`templates/AN-05-traceability-matrix.md` 의 요구사항 구분별 매핑 규칙이 정본이다.

**없는 산출물의 컬럼은 `-` 로 채운다.** 빈칸으로 두면 감리에서 "미작성" 과 "해당없음" 이
구분되지 않는다.

## 처리 절차

### Step 1: 가용 산출물 확인

어떤 산출물이 제공되었는지 확인하고, 없는 산출물의 컬럼은 빈칸("-") 처리한다.

"다음 산출물이 제공되었습니다:
- AN-02 요구사항정의서: ✅ (N건)
- DE-03 화면목록표: ✅ (N건)
- DE-05 프로그램정의서: ⚠ 미제공 → 프로그램ID/명 컬럼 빈칸
- DE-13 단위테스트계획서: ⚠ 미제공 → 단위테스트 컬럼 빈칸
- DE-14 통합테스트계획서: ✅ (N개 시나리오)"

### Step 2: 요구사항 기준으로 행 생성

요구사항ID 하나당 1개 행을 기본으로 생성한다.

- 하나의 요구사항에 화면이 여러 개 매핑되면 → **화면ID, 화면명, 프로그램ID, 프로그램명, 단위테스트ID 컬럼을 줄바꿈(`\n`)으로 구분**하여 한 셀에 모두 기재
- 하나의 요구사항에 여러 통합테스트 시나리오가 연결되면 → 통합테스트 ID/명도 동일하게 줄바꿈 처리

복수 매핑 예시:
```
| B-RE-003 | 교육 과정 관리 | 수용 | - | TB_COURSE\nTB_COURSE_FILE | EHR_03_01_010\nEHR_03_01_020 | 과정 목록\n과정 등록 | PG_EHR_03_01_010\nPG_EHR_03_01_020 | 과정 목록 조회\n과정 등록/수정 | U_EHR_03_01_010\nU_EHR_03_01_020 | 과정목록 단위테스트\n과정등록 단위테스트 | B-TE-002 | 과정 등록 및 수강 신청 흐름 | 진행중 |
```

### Step 3: ID 체인 기반 자동 매핑

**요구사항 구분에 따라 매핑 경로가 갈린다.**

**기능 요구사항**
1. 요구사항ID → 화면목록표에서 해당 요구사항이 반영된 화면 검색 (화면명/기능명 키워드 매칭)
2. 화면ID → 프로그램정의서에서 `PG_{화면ID}` 패턴으로 프로그램ID 매핑
3. 화면ID → 단위테스트계획서에서 `U_{화면ID}` 패턴으로 단위테스트ID 매핑
4. 화면ID → 테스트케이스 시트에서 `TC_{화면ID}_*` 건수 집계
5. 요구사항ID → 통합테스트계획서에서 해당 요구사항ID를 참조하는 시나리오 매핑 (정상·예외 모두)

**비기능 요구사항**
6. 요구사항ID → 시스템테스트계획서(ST-01)에서 해당 요구사항ID를 참조하는 `-ST-` ID 매핑

**공통**
7. 각 테스트ID → 결함관리대장(DF-01)에서 상태가 Closed/Rejected가 아닌 결함ID 수집

### Step 4: 과업완료여부 자동 판정

요구사항 구분별로 판정 기준이 다르다.

**기능 요구사항**

| 판정 | 조건 |
|------|------|
| **완료** | 화면ID·프로그램ID·단위테스트ID·통합테스트ID 모두 매핑 **AND 잔존 결함 0건** |
| **진행중** | 일부 매핑 완료, 일부 누락 — 또는 매핑은 완료됐으나 잔존 결함 존재 |
| **미착수** | 화면ID부터 매핑 없음 |

**비기능 요구사항**

| 판정 | 조건 |
|------|------|
| **완료** | 시스템테스트ID 매핑 AND 판정=적합 AND 잔존 결함 0건 |
| **진행중** | 시스템테스트ID는 있으나 미측정·부적합·점검제외 |
| **미착수** | 시스템테스트ID 없음 |

- 수용여부가 "불가"인 요구사항 → 과업완료여부 **"해당없음"**
- **잔존 결함이 있으면 매핑이 완전해도 "완료"로 판정하지 않는다** — 결함이 남은 채 과업완료로 표기하면
  감리에서 "결함 미조치 상태 완료 처리"로 지적된다

### Step 5: 누락 탐지 및 리포트 생성

다음 6가지 누락 여부를 확인한다:

| 누락 유형 | 탐지 기준 | 대상 | 표시 |
|---------|---------|------|------|
| 화면 미매핑 | 화면ID 없음 | 기능 | ⚠ |
| 프로그램 미등록 | 화면ID는 있는데 프로그램ID 없음 | 기능 | ⚠ |
| 단위테스트 미작성 | 화면ID는 있는데 단위테스트ID 없음 | 기능 | ⚠ |
| **테스트케이스 미작성** | 단위테스트는 있는데 `TC_` 0건 | 기능 | ⚠ |
| 통합테스트 미연결 | 통합테스트 시나리오 없음 | 기능 | ⚠ |
| **비기능 검증 누락** | 시스템테스트ID 없음 | **비기능** | ⚠ |
| **결함 미종결** | 잔존 결함 존재 | 공통 | ⚠ |

- B-RE-010 → 화면 미매핑 ⚠ (화면목록에서 해당 기능 화면을 찾지 못함)

## 주의사항

- 추적매트릭스는 감리 핵심 산출물 — 공백 행이나 ID 불일치는 반드시 제거
- 화면ID와 프로그램ID는 1:1 대응 원칙 (`PG_` 접두어만 다름)
- 통합테스트 시나리오는 여러 요구사항을 묶을 수 있음 → 동일 시나리오ID가 여러 행에 반복될 수 있음
- **비기능 요구사항의 화면·프로그램 칸이 빈 것은 정상**이다. 대신 시스템테스트 칸이 비면 누락이다
- **잔존 결함이 있으면 과업완료로 판정하지 않는다**
- 수용여부 "부분수용" 항목은 수용된 범위의 화면만 매핑하고 주석 처리
- 기존 추적매트릭스 갱신 시 기존 행의 ID를 유지하고 변경된 부분만 수정
- 산출물 코드는 CLAUDE.md 산출물 범위표를 따른다 (인터페이스=DE-04, 테이블=DE-08)
