# 기존 산출물 감지 (detect-existing-artifact)

커맨드 실행 시 활성 프로젝트 폴더에 해당 산출물 파일이 이미 존재하는지 확인하고,
존재하면 사용자에게 처리 방식을 선택하도록 요청한다.

---

## 입력

| 항목 | 필수 | 설명 |
|------|------|------|
| 프로젝트 폴더 경로 | Y | load-project-profile에서 확인된 활성 프로젝트 폴더 |
| 산출물 유형 | Y | 찾을 산출물명 — 5종 중 하나 (요구사항정의서 · 기능명세서 · 테이블정의서 · 단위테스트계획서 · 추적매트릭스) |
| 시스템코드 | Y | 파일명 매칭용 (예: "B") |

---

## 처리 절차

### Step 1: 파일 탐색

프로젝트 폴더에서 해당 산출물 파일을 찾는다:

```
패턴: {프로젝트폴더}/{시스템코드}-{산출물명}.md
예시: 교육행정시스템/B-요구사항정의서.md
```

### Step 2: 파일 존재 여부에 따른 분기

#### 파일이 없는 경우

별도 안내 없이 해당 커맨드의 정상 워크플로우를 진행한다 (새로 생성).

#### 파일이 있는 경우

파일을 읽어 항목 수와 마지막 수정일을 파악한 후, **AskUserQuestion 도구**로 선택을 요청한다:

```
기존 {산출물명}을 찾았습니다:
  {시스템코드}-{산출물명}.md ({N}건, 마지막 수정: {날짜})

어떻게 진행할까요?

  1. 이어쓰기
     기존 {N}건을 그대로 유지하고, 새로운 항목을 뒤에 추가합니다.
     ID는 기존 마지막 번호에 이어서 부여됩니다.
     예: 기존 {마지막ID}까지 → 새 항목은 {다음ID}부터

  2. 새로쓰기
     기존 파일을 backup/ 폴더에 날짜를 붙여 백업한 후,
     처음부터 다시 생성합니다.
     백업 위치: backup/{시스템코드}-{산출물명}_{YYMMDD}.md

  3. 열기
     기존 산출물을 불러와서 특정 항목을 수정하거나 삭제합니다.
     전체를 다시 만들지 않고, 원하는 부분만 고칠 수 있습니다.
     예: "3번 행 수정", "REQ-012 행 상태를 삭제로", "5번 뒤에 행 추가"
```

### Step 3: 선택에 따른 처리

#### 1. 이어쓰기 선택 시

1. 기존 파일을 읽어 전체 내용을 메모리에 로드
2. 마지막 ID 번호를 파악 (정규식으로 ID 패턴 매칭)
3. 이후 워크플로우에서 새로 생성되는 항목의 ID를 이어서 부여
4. 최종 출력 시 기존 내용 + 새 내용을 하나의 표로 합침
5. 합쳐진 전체 내용으로 파일을 덮어쓰기

**마지막 ID 파악 패턴**:

ID 패턴은 프로파일의 `idNaming` 이 정한다 (`templates/project-profile-schema.md`).
프로파일에 없으면 기존 파일의 표기에서 읽어 쓰고, 그것도 없으면 기본값을 쓴다.

| 산출물 | 읽을 열 | 기본 패턴 | 예시 |
|--------|--------|----------|------|
| 요구사항정의서 | `요구사항ID` | `REQ-\d{3}` | REQ-035 → 다음은 REQ-036 |
| 기능명세서 | `기능ID` | `FN-\d{3}` | FN-012 → 다음은 FN-013 |
| 단위테스트계획서 | `테스트ID` | `UT-\d{3}` | UT-048 → 다음은 UT-049 |
| 테이블정의서 | — | — | 컬럼 단위라 순번 ID 가 없다. 테이블명·컬럼명으로 대조한다 |
| 추적매트릭스 | — | — | 대조 결과라 이어쓰기 대신 매번 다시 만든다 |

**파생 ID 가 없으므로 상위 ID 를 봐도 하위 번호를 알 수 없다.** 각 산출물의 마지막
순번을 그 산출물에서 직접 읽는다.

#### 2. 새로쓰기 선택 시

1. `backup/` 폴더가 없으면 생성
2. 기존 파일을 `backup/{시스템코드}-{산출물명}_{YYMMDD}.md`로 복사
3. 기존 파일을 삭제
4. "기존 파일을 backup/{파일명}으로 백업했습니다." 안내
5. 처음부터 새로 생성하는 워크플로우를 진행

#### 3. 열기 선택 시

1. 기존 파일을 읽어 마크다운 표로 화면에 출력
2. **AskUserQuestion 도구**로 수정할 내용을 요청:

```
기존 {산출물명}을 불러왔습니다. ({N}건)

수정할 내용을 입력해주세요:

  수정 예시:
  • "3번 행의 요구사항 상세내용을 '사용자 인증 강화'로 변경"
  • "REQ-012 행의 상태를 삭제로 변경"
  • "REQ-005와 REQ-006 사이에 새 행 추가"
  • "대분류가 '시스템관리'인 항목들의 중분류를 '권한관리'로 변경"

수정이 끝나면 "승인" 또는 "OK"를 입력해주세요.
```

3. 수정 요청을 반영하여 표를 재생성
4. 변경 내용 안내 후 다시 승인 요청 (승인 루프)
5. 승인 시 파일 덮어쓰기

---

## 이어쓰기 후 하위 산출물 연쇄 안내

요구사항정의서·기능명세서 등 앞선 산출물에 항목을 이어쓰기 한 경우,
`연계~ID` 로 이어진 뒤 산출물도 갱신이 필요할 수 있으므로 안내한다:

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
새로 추가된 항목 {N}건에 대해 하위 산출물도 업데이트가 필요할 수 있습니다:

  1. /gx-기능명세서 — 새 요구사항에 대한 기능 추가
  2. /gx-테이블정의서 — 새 기능의 입력항목을 컬럼으로 대조
  3. /gx-단위테스트계획서 — 새 기능에 대한 테스트 추가
  4. /gx-추적매트릭스 — 대조 다시 돌리기

이어서 진행할 커맨드 번호를 입력하세요.
(나중에 하려면 "나중에" 입력)
```

**연쇄 안내 조건** (상위→하위 관계):

| 이어쓰기한 산출물 | 뒤 산출물 안내 |
|-----------------|----------------|
| 요구사항정의서 | 기능명세서, 단위테스트계획서, 추적매트릭스 |
| 기능명세서 | 테이블정의서, 단위테스트계획서, 추적매트릭스 |
| 테이블정의서 | 단위테스트계획서(경계값), 추적매트릭스 |
| 단위테스트계획서 | 추적매트릭스 |

비기능 요구사항은 기능명세서를 건너뛰고 단위테스트계획서로 바로 간다
(`연계기능ID` 공란 행).

---

## 주의사항

1. **파일이 없으면 이 스킬을 건너뛴다**: 별도 안내 없이 새로 생성 워크플로우 진행
2. **이어쓰기 시 기존 항목은 수정하지 않는다**: 새 항목만 추가
3. **새로쓰기 시 반드시 백업한다**: 사용자 데이터를 절대 유실하지 않는다
4. **열기 시 승인 루프를 적용한다**: 수정 완료까지 반복
5. **모든 선택은 AskUserQuestion으로 받는다**: 텍스트 출력만으로 대체하지 않는다
