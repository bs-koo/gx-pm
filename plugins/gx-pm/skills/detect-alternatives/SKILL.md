# 시안/대안 감지 (detect-alternatives)

입력 문서(RFP, 과업지시서, 기획서 등)에서 복수의 시안이나 대안을 자동 감지하여, 산출물 생성 전에 사용자가 명시적으로 선택하도록 유도한다.

---

## 입력

사용자로부터 받은 다음 중 하나:
- RFP/과업지시서 텍스트
- 기획서/제안서
- 요구사항정의서 (이미 작성된 것)
- 이전 커맨드 결과물

---

## 감지 패턴

### 명시적 시안 표기

| 패턴 | 정규식 | 예시 |
|------|--------|------|
| 숫자 안 | `[제]?\d+안` | "1안", "제1안", "2안" |
| 알파벳 안 | `[A-Z]안` | "A안", "B안" |
| 방안 번호 | `[방대]안\s*\d+` | "방안 1", "대안 2" |
| 영문 표기 | `(?i)alt(?:ernative)?\s*[1-9A-Z]` | "Alternative 1", "Alt A" |

### 구조적 시안 표기

| 패턴 | 설명 |
|------|------|
| 섹션 제목에 "(안)", "(선택)", "(옵션)" | 제목 수준에서 대안 분기 |
| 동일 기능에 대해 2개 이상의 설명 블록 | 같은 기능명 아래 서로 다른 구현 방식 |
| "또는", "혹은"으로 연결된 상호배타적 기술 | 인라인 대안 |
| 표에서 같은 항목에 "/"로 구분된 값 | "REST API / gRPC", "React / Vue" |
| 비교표 (장단점, 비용 비교 등) | 의사결정이 필요한 비교 |

### 암시적 시안

| 패턴 | 설명 |
|------|------|
| "검토 필요", "협의 필요", "추후 결정" | 아직 결정되지 않은 항목 |
| "~도 가능", "~도 고려" | 대안 존재 암시 |
| 조건부 기술 ("만약 ~라면 A, 아니면 B") | 분기 조건이 있는 설계 |

---

## 처리 절차

### Step 1: 전문 스캔

입력 텍스트 전체를 스캔하여 위 패턴에 해당하는 구간을 모두 식별한다.

### Step 2: 시안 그룹핑

같은 기능/주제에 대한 대안들을 그룹으로 묶는다:

```
시안 그룹 1: 화면 구성 방식
  ├─ 1안: 이중 슬라이더 단일 화면
  └─ 2안: 쾌적성/온도 별도 메뉴

시안 그룹 2: 기술 스택
  ├─ A안: React + REST API
  └─ B안: Vue + GraphQL
```

### Step 3: 영향 범위 파악

각 시안 선택이 후속 산출물에 미치는 영향을 파악:
- 화면 수 변화 (1안: 5개, 2안: 8개)
- 프로그램 수 변화
- 테스트 항목 변화
- 인터페이스 차이

### Step 4: 사용자 선택 요청

각 시안 그룹에 대해 **AskUserQuestion 도구**로 선택을 요청한다:

```json
AskUserQuestion({
  "question": "시안 선택 [{그룹번호}/{총그룹수}]: {주제}\n\n  1안: {요약}\n     → 화면 {N}개, 프로그램 {N}개 예상\n\n  2안: {요약}\n     → 화면 {N}개, 프로그램 {N}개 예상\n\n어떤 시안으로 진행할까요? (1/2/병행)"
})
```

### Step 5: 선택 결과 반영

- 선택된 시안만 후속 산출물에 반영
- "병행" 선택 시: 양쪽 모두 포함하되 `[1안]`, `[2안]` 태그로 명확히 구분
- 선택 결과를 산출물 상단 메타 정보에 기록

---

## 출력

선택 결과를 다음 형식으로 반환:

```
## 시안 선택 결과

| 그룹 | 주제 | 선택 | 비고 |
|------|------|------|------|
| 1 | 화면 구성 방식 | 1안 (이중 슬라이더) | |
| 2 | 기술 스택 | A안 (React) | 발주처 요구 |
```

이 결과는 후속 스킬(generate-screen-list, generate-program-list 등)에 전달되어 선택된 시안 기준으로만 산출물을 생성한다.

---

## 주의사항

1. **감지되지 않을 수 있음**: 암시적 패턴은 놓칠 수 있으므로, 각 커맨드의 체크포인트에서도 "혹시 선택이 필요한 부분이 있나요?"를 추가 질문
2. **병행 선택의 비용**: 병행 시 산출물 양이 거의 2배가 되므로, 사용자에게 "산출물 양이 크게 늘어납니다. 괜찮으시겠어요?" 확인
3. **후속 변경**: 이미 산출물이 생성된 후 시안 변경 요청 시, 영향받는 산출물 목록을 안내하고 재생성 여부 확인
