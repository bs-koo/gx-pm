# gx-pm — 공공/SI PM 플러그인

## 이 플러그인은

공공/SI 프로젝트의 PM(프로젝트 매니저)을 위한 Claude Cowork 플러그인입니다.
실제 공공 프로젝트 산출물 양식(요구사항정의서, 기능명세서, 테이블정의서, 단위테스트계획서, 추적매트릭스)에 맞는 데이터를 자동 생성하고, 산출물 간 ID 추적 체계를 관리합니다.

## 핵심 개념

### ID 추적 체인
모든 산출물은 하나의 ID 체인으로 연결됩니다:
```
요구사항ID (예: B-RE-001)
  └→ 기능ID (예: B-FN-001)          ← 파생 아님. 독립 채번, N:M 매핑
       ├→ 테이블·컬럼 (DE-08)        ← 입력항목이 컬럼으로 매핑된다
       └→ 테스트ID (예: B-UT-001)   ← 파생 아님. 독립 채번, N:1 매핑
```

**갈래가 둘입니다.** 기능 요구사항은 기능명세를 거쳐 테스트로,
비기능 요구사항은 기능을 거치지 않고 바로 테스트로 갑니다
(DE-13 의 `연계기능ID` 공란 행).

**파생 ID 가 없습니다.** 어떤 ID 도 다른 ID 에서 만들어지지 않으므로,
ID 를 바꿔도 재채번 파급이 없습니다. 연결은 전부 `연계~ID` 열이 맡습니다.
채번 규칙의 정본은 `templates/id-naming-rules.md`, 재생성 파급 범위의 정본은
`templates/pipeline-protocol.md` 의 "재생성 파급 규칙" 절입니다.

이 체인이 끊기지 않도록 관리하는 것이 감리 대응의 핵심입니다.
`/gx-추적매트릭스` 커맨드로 언제든 추적 상태를 확인하고 누락을 탐지할 수 있습니다.

### 시스템 코드
프로젝트의 각 시스템은 영문 1자리 코드(A~I) 또는 프로젝트별 자유 코드를 가집니다.
이 코드는 요구사항ID·기능ID·테스트ID의 접두어로 쓸 수 있습니다 — 채번 규칙은 프로파일이
정하며 정본은 `templates/id-naming-rules.md`입니다.

## 프로젝트 프로파일

`/gx-프로젝트설정`으로 프로젝트 상황을 한 번 설정하면, 이후 모든 커맨드가 자동으로 활용합니다.
새 대화를 열어도 설정이 유지됩니다 (파일로 저장).

### 프로젝트 유형 4가지

| 유형 | 설명 |
|------|------|
| **A. 신규 구축** | RFP만 있고 코드 없음. 설계부터 시작 |
| **B. 추가 개발** | 운영 중 시스템에 새 기능 추가. 기존 유지 + 새 것 추가 |
| **C. 산출물 정비** | 개발 완료 후 산출물 역생성. 소스/DB에서 추출 |
| **D. 변경 관리** | 기존 기능 수정. 변경 대상 산출물만 갱신 |

### 기존 산출물 처리

커맨드 실행 시 기존 산출물이 있으면 3가지 선택지를 제공합니다:
- **이어쓰기**: 기존 유지 + 새 항목 추가 (ID 이어서 부여)
- **새로쓰기**: backup/ 폴더에 백업 후 처음부터 재생성
- **열기**: 기존 내용에서 특정 항목만 수정/삭제

## 승인 루프 & xlsx 추출

모든 커맨드는 **단계별 승인 루프**로 동작합니다:
0. **프로파일 로드**: 프로젝트 설정 자동 로드 + 기존 산출물 감지
1. 각 단계 산출물 생성 → 마크다운 표로 표시
2. **시안 감지**: 입력에 1안/2안 등 대안이 있으면 먼저 선택 요청
3. **승인 요청**: 사용자가 "승인"할 때까지 수정 → 재출력 반복
4. **xlsx 추출**: 승인 후 공공 양식에 맞는 xlsx로 추출 가능 (복붙용)

상세 규칙: `templates/approval-protocol.md` 참조

## 시작하기

**파이프라인이 1순위입니다.** 사용자가 커맨드 순서를 외우지 않아도 되는 것이 이 플러그인의 요점입니다.

1. **`/gx-프로젝트설정`으로 프로젝트 프로파일 설정** (최초 1회)
2. **`/gx-spec`으로 명세 5종 일괄 생성** — 요구사항정의서 → 기능명세서 → 테이블정의서 →
   단위테스트계획서 → 추적매트릭스. 승인 게이트 3곳에서만 판단하면 됩니다
3. 게이트 통과 후 필요하면 `/gx-추적매트릭스`로 누락을 다시 대조합니다

### 낱개로 만들 때

산출물 하나만 다시 만들거나 손보고 싶으면 개별 커맨드를 그대로 부릅니다. 생성 로직은 파이프라인과 같습니다.

- `/gx-요구사항정의서`, `/gx-기능명세서`, `/gx-테이블정의서`, `/gx-단위테스트계획서`, `/gx-추적매트릭스` — `/gx-spec` 구성 5종

각 커맨드의 선행조건은 `templates/prerequisites.md`가, 단독 실행과 파이프라인 실행의 차이는 `templates/pipeline-protocol.md`가 정본입니다.

### 산출물 정비 모드 (C유형)

개발 완료 후 산출물을 맞출 때는:
1. `/gx-프로젝트설정`에서 유형을 **C. 산출물 정비**로 선택
2. 소스코드 경로와 DDL을 입력
3. `/gx-spec` 실행 시 DE-08 은 DDL 에서 역생성하고, 나머지 4종은 기존 산출물·RFP 를
   근거로 정비합니다. 소스 인덱스는 실제 구현과의 대조에 씁니다

## 주의사항

- 비기능 요구사항은 기능을 거치지 않습니다 — **DE-13 에서 `연계기능ID` 공란 행**으로 검증합니다
  (`templates/DE-13-unit-test-plan.md`)
- **파생 ID 가 하나도 없습니다.** 어떤 ID 도 다른 ID 에서 만들어지지 않으므로, ID 를 바꿔도
  재채번 파급이 없습니다. 정본은 `templates/id-naming-rules.md`입니다
- 단위테스트 판정값은 **`Pass` / `Fail`** 2값입니다
- **기능/비기능 판정의 정본은 `skills/extract-requirements/SKILL.md` 의 「기능 / 비기능 판정 (정본)」** 입니다.
  `classify-requirements`·`generate-unit-test-plan`·`trace-requirements` 는 이 사다리를 재적용할 뿐 기준을 다시 세우지 않습니다.
  AN-02 10컬럼에 `구분` 열이 없어 판정을 저장하지 않으므로, 재적용해도 같은 답이 나오는 것이 이 사다리의 요건입니다
- **`classify-requirements` 의 분류 결과 표는 승인용 작업용 뷰**입니다 — `구분`·`비기능유형`·`소분류`·`우선순위`·`영향도` 는 AN-02 에 열이 없습니다
- 요구사항은 문장뿐 아니라 **ID 표**로도 제시된다 — 표 인식 규칙의 정본은 `skills/extract-requirements/SKILL.md` 의 "ID 접두 표 행" 절입니다. 섹션 제목이 "기능 요구사항" 이 아니어도(도메인 규칙·업무 규칙·제약사항) 뽑아야 합니다
- 커맨드별 하드/소프트 선행조건의 정본은 `templates/prerequisites.md`입니다 — 커맨드는 이 값을 복제하지 않고 참조합니다
- 파이프라인(`/gx-spec`)의 실행 규약(단독/파이프라인 차이, 이월 금지 항목, 재생성 파급 규칙)의 정본은 `templates/pipeline-protocol.md`입니다
- 개정이력은 5종 공통 횡단 규칙입니다 — 정본은 `templates/revision-history.md`, 기입은 `manage-revision-history` 스킬이 담당합니다
- 템플릿은 `templates/` 폴더에서 양식 상세를 확인할 수 있습니다
- **시안이 감지되면 반드시 사용자 선택을 받은 후 산출물을 생성합니다**
- **각 단계는 사용자 승인 없이 다음 단계로 진행하지 않습니다**
- xlsx 추출은 `utils/export-xlsx.py` 스크립트를 사용합니다 (openpyxl 자동 설치)

## 표준용어 MCP 연계 (DDL·컬럼)

`/gx-테이블정의서`로 DDL·컬럼을 생성할 때, 사업부 표준용어사전 `sqi-comn-term` MCP로 컬럼명을 표준화합니다. 기존 컬럼은 이름을 바꾸지 않고 `현행유지`로 두며(표준 권고명만 병기), 표준형 채택 대상은 **신규 컬럼뿐**입니다. (gx-pm 스킬은 `allowed-tools` 제한이 없어 실행 중 MCP 를 그대로 호출합니다 — 이 연계를 위해 도구를 따로 배선할 필요가 없다는 뜻이지, 스킬·커맨드·템플릿을 고치면 안 된다는 뜻이 아닙니다.)

- **MCP 준비(없으면 설치→재연결 안내)**: 세션에 `sqi-comn-term` 도구가 없으면 설치 후 재연결을 안내합니다
- **출처 우선순위(기본): `["BLDG_ENGY", "MOIS_STD"]`** — 건물에너지 우선 → 행안부 공통표준 보강. 프로젝트별 조정 가능
- DE-08 의 열 모델(`구분`·`표준 판정`·`표준 권고명`·`근거`)은 바꾸지 않습니다 — 정본은
  `templates/DE-08-table-definition.md` 의 「본문 컬럼 (정본)」 절입니다
- **상세 프로토콜(출처 카테고리·`translate_column`/`validate_column` 처리표·워크드 예시·설치 방법)의
  단일 정본은 `docs/표준용어-mcp-연계.md`입니다** — 여기서 복제하지 않습니다
