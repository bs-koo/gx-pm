# 검사기준 참조

감리의 **검사기준서**는 항목명만으로 성립하지 않는다. 항목마다 **예상결과 · 판정기준 · 점검방법**이 붙어야
제3자(감리원)가 같은 판정을 재현할 수 있다. 아래가 27개 검사기준의 정본이다.

> **이 파일이 검사기준 항목명의 단일 정본이다.**
> `generate-unit-test-plan`(계획서)과 `fill-unit-test-result`(결과서)는 모두 이 정의를 따른다.
> 두 스킬이 서로 다른 항목명을 쓰면 계획서의 "해당없음" 배정이 결과서에서 엉뚱한 항목에 붙는다.

## 공통부문 (8)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 표준 준수 | UI 표준 가이드에 정의된 레이아웃·버튼 위치·색상을 따른다 | 표준 가이드와 상이한 요소 없음 | 화면 육안 확인 + 표준 가이드 대조 |
| (2) | 정상 표출 | 버튼·이미지·테이블이 깨짐·누락 없이 표시된다 | 콘솔 오류 0건, 깨진 요소 0건 | 화면 진입 + 브라우저 콘솔 확인 |
| (3) | 화면 이동 | 메뉴·탭 선택 시 해당 화면으로 이동한다 | 전체 메뉴 경로 정상 이동 | 메뉴 전건 클릭 |
| (4) | 화면 Title | 화면 타이틀이 선택한 메뉴명과 일치한다 | 타이틀 = 메뉴명 | 화면 상단 타이틀 대조 |
| (5) | 화면 Default | 날짜·필수값·체크박스 초기값이 설계대로 설정된다 | 화면 진입 시 초기값이 화면정의서와 일치 | 화면 진입 직후 값 확인 |
| (6) | 화면 Button | 버튼이 데이터 상태에 따라 활성/비활성된다 | 상태별 버튼 활성화가 설계와 일치 | 상태별 데이터로 진입 |
| (7) | 권한 | 사용자 권한에 따라 메뉴·기능 접근이 제어된다 | 권한 없는 계정으로 메뉴 미표시 **및 URL 직접 접근 차단** | 권한별 계정 로그인 + URL 직접 입력 |
| (8) | 에러 처리 | 예외 발생 시 사용자가 이해할 수 있는 메시지가 표시된다 | 스택트레이스·시스템 오류코드 미노출 | 오류 유발 후 화면 확인 |

> (7) 권한은 **메뉴 숨김만으로는 부적합**이다. URL 직접 접근 차단까지 확인해야 한다.

## 조회 (4)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 조건 검색 | 검색 조건별로 해당 데이터만 조회된다 | 조건 적용 결과가 예상 건수와 일치 | 조건별 검색 실행 |
| (2) | 페이징 | 페이지 이동 시 해당 구간 데이터가 표시된다 | 첫 페이지·끝 페이지·범위 초과 모두 정상 | 첫·끝·초과 페이지 요청 |
| (3) | 정렬 | 컬럼 클릭 시 오름/내림차순 정렬된다 | 정렬 결과 순서가 정확 | 주요 컬럼 정렬 실행 |
| (4) | 상세 조회 | 목록 항목 클릭 시 해당 상세 화면으로 이동한다 | 이동 화면의 데이터가 선택 항목과 일치 | 목록 항목 클릭 |

## 입력 (6)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 필수값 | 필수 항목 미입력 시 안내 메시지가 표시되고 저장이 차단된다 | 미입력 저장 시 DB 미반영 | 필수 항목 공란 저장 시도 |
| (2) | 유효성 | 형식·길이 제약을 위반한 입력이 거부된다 | 최대길이+1, 잘못된 형식 모두 차단 | **경계값 입력** |
| (3) | 저장 | 입력 데이터가 DB에 정상 저장된다 | 저장 후 조회 시 입력값과 일치 | 저장 후 재조회 |
| (4) | 중복 검사 | 중복 키 입력 시 안내 메시지가 표시된다 | 동일 키 재저장 시 차단 | 기존 키로 저장 시도 |
| (5) | 초기화 | 초기화 시 입력 폼이 초기 상태로 되돌아간다 | 전 항목 초기값 복원 | 값 입력 후 초기화 |
| (6) | 취소 | 취소 시 저장 없이 이전 화면으로 복귀한다 | 취소 후 DB 미반영 | 값 입력 후 취소 |

## 수정 (2)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 데이터 수정 | 변경한 값이 저장되고 조회에 반영된다 | 수정 후 재조회 시 변경값 표시 | 값 변경 후 저장·재조회 |
| (2) | 수정 확인 | 수정 전 확인 메시지가 표시된다 | 확인 취소 시 미반영 | 저장 클릭 후 취소 |

## 삭제 (2)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 데이터 삭제 | 선택 데이터가 삭제 처리된다 | **소프트 삭제(`DEL_YN='Y'`)** 반영, 목록 미표시 | 삭제 후 목록·DB 확인 |
| (2) | 삭제 확인 | 삭제 전 확인 메시지가 표시된다 | 확인 취소 시 미삭제 | 삭제 클릭 후 취소 |

> 공공 시스템은 물리 삭제를 쓰지 않는다. DB에서 행이 사라지면 **부적합**이다.

## 첨부파일 (3)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 업로드 | 허용 확장자·용량 내 파일이 업로드된다 | **허용 외 확장자·용량 초과 파일은 차단** | 정상 파일 + 위반 파일 각각 업로드 |
| (2) | 다운로드 | 업로드한 파일이 원본과 동일하게 내려받아진다 | 파일명·용량·내용 일치 | 업로드 후 다운로드 대조 |
| (3) | 삭제 | 첨부파일이 삭제되고 목록에서 사라진다 | 삭제 후 다운로드 불가 | 삭제 후 재접근 시도 |

> (1) 업로드는 **위반 파일 차단 확인이 없으면 부적합**이다. 파일 업로드 취약점은 보안 감리 지적 항목이다.

## 출력 (2)

| 번호 | 항목 | 예상결과 | 판정기준 | 점검방법 |
|------|------|---------|---------|---------|
| (1) | 엑셀 다운로드 | 화면 목록과 동일한 데이터가 엑셀로 내려받아진다 | 화면 건수 = 엑셀 행 수, 컬럼 일치 | 다운로드 후 대조 |
| (2) | 인쇄 | 인쇄 미리보기가 레이아웃 깨짐 없이 표시된다 | 항목 잘림·누락 없음 | 인쇄 미리보기 실행 |

## 판정 기준 — 3값 + 계획단계 배정값

| 값 | 단계 | 의미 |
|------|------|------|
| **해당없음** | 계획서(DE-13)에서 배정 | 이 화면 유형에 애초에 적용되지 않는 항목 |
| **적합** | 결과서(IM-03)에서 판정 | 판정기준을 충족함 |
| **부적합** | 결과서에서 판정 | 판정기준 미충족 → **결함ID 발급 필수** |
| **점검제외** | 결과서에서 판정 | 적용 대상이지만 이번에 확인 불가 → **사유 필수** |

### 해당없음 vs 점검제외

혼동하기 쉬우나 감리에서 다르게 취급된다.

| | 해당없음 | 점검제외 |
|---|---------|---------|
| 정하는 시점 | 계획 수립 시 | 테스트 수행 시 |
| 의미 | 적용 대상이 아님 | 적용 대상인데 못 쟀음 |
| 사유 기재 | 불필요 (화면 유형으로 설명됨) | **필수** |
| 종료보고서 | 미기재 | **잔여 항목으로 기재** |

### 점검제외 인정 사유

- 테스트 환경 미준비
- 선행 기능 결함으로 진입 불가
- 외부 환경 변화 (연계기관 시스템 미개방 등)
- 과업 범위 외 판정 (발주처 협의 근거 필요)

> 위 4가지 외의 사유는 감리에서 인정되지 않는다. "시간 부족"은 점검제외 사유가 아니라 **미수행**이다.
