# Changelog

## [Unreleased]

v2.0.0 최종 리뷰가 변이 테스트로 찾아낸 하네스 구멍 중, 머지를 막지 않아 후속으로 미룬 것들.

### Changed

- **`[필수 중단점]` 라벨의 위치를 검사한다.** 종전에는 개수만 세어, 라벨을 게이트에서
  저장·xlsx 단계로 옮겨도 통과했다. 이제 1번째는 "게이트 1", 2번째는 "게이트 2" 단계여야 한다
- **파이프라인 산출물의 등장 순서를 고정한다.** 순서는 이 기능의 전제인데(화면목록표가 확정돼야
  `PG_`·`U_`·`TC_` 가 파생된다) 참조 존재만 검사해 순서를 뒤집어도 통과했다
- **백틱 강제 검사가 코드펜스 안을 예외로 둔다.** 펜스 안은 사용자에게 그대로 출력되는
  메시지라 백틱이 리터럴로 보인다. 규약이 사용자 화면을 망가뜨리고 있었다
  - 단, 진입점 3종(`gx-프로젝트설정`·`gx-spec`·`gx-testplan`)에서는 백틱을 유지해야 한다.
    도달 가능성 검사가 백틱으로 감싼 참조만 세기 때문 — `templates/prerequisites.md` 에 명시
- `gx-testplan.md` 의 하드 선행 안내가 산출물 이름을 복제하지 않고 `{누락된 선행 산출물}`
  자리표시자를 쓴다. 정본(`templates/prerequisites.md`)이 바뀌어도 문구가 낡지 않는다

### Fixed

- **`extract-requirements` 가 ID 표로 제시된 요구사항을 놓쳤다.** 공공 RFP 는 요구사항을
  ID 표로 주는데, 그 표가 "기능 요구사항" 제목 아래 있지 않으면(도메인 규칙·업무 규칙·
  제약사항 등) 종전 규칙이 전부 놓쳤다. 실측: 실제 요구사항서의 업무 규칙 표 8건 중
  **1건만** 추출됐고, 나머지 7건이 요구사항정의서에서 통째로 빠졌다
  - 표 인식 정규식을 `SKILL.md` 에 문자 그대로 싣고, 테스트가 그것을 문서에서 뽑아
    픽스처에 적용한다 — 문서의 규칙과 시험하는 규칙이 같은 문자열이라 갈라질 수 없다
  - 중복 제거·기능/비기능 판정·원문 ID 보존 규칙을 함께 명시했다.
    원문 ID 는 `근거` 열에 병기하며 `제안요청ID` 열의 `SFR-` 체계는 건드리지 않는다
- **`export-xlsx.py` 의 컬럼 세트 판단이 두 벌이었다.** 시트명(`_matched_set_index`)과
  컬럼 순서(`_reorder_columns`)가 각자 "가장 잘 맞는 세트" 를 다시 계산했다. 지금은 동작이
  같지만 한쪽 임계값만 고치면 시트가 A 세트의 **이름**을 달고 B 세트의 **순서**로 나온다.
  `_best_column_set()` 하나로 합치고, 어긋날 수 없음을 테스트로 고정했다
- **프로필 컬럼명과 문서를 묶었다.** `DOCUMENT_PROFILES` 의 컬럼은 xlsx 재배열의 기준인데,
  그 이름을 실제로 만드는 것은 스킬·템플릿 문서다. 한쪽에서 이름이 바뀌면 매칭률이 임계값
  아래로 떨어져 **조용히** 재배열이 멈추고 사용자는 원본 순서를 받는다 — 예외도 오류도 없다
- **스킬 참조 검사가 평문을 놓치고 있었다.** `**name** 스킬`·`` `name` 스킬`` 만 봐서
  평문으로만 적힌 참조 6곳이 검사 밖에 있었다
- `/gx-프로젝트설정` §D(변경 관리)가 개별 커맨드 이름을 보여주지 않았다. D 유형 사용자는
  파이프라인 안내를 거치지 않으므로 여기서 안 보여주면 무엇을 부를 수 있는지 알 길이 없었다
- README 디렉토리 트리가 저장소 루트와 플러그인 디렉터리를 뭉개고 있었다
  (`marketplace.json` 은 루트, `plugin.json` 은 `plugins/gx-pm/` 인데 형제로 나열)
- 도달 가능성 검사의 실패 메시지가 진입점 수를 하드코딩("파이프라인 2종")하고 있었다
- `nul` 을 `.gitignore` 에 추가 — Windows `> nul` 리다이렉트가 만드는 0바이트 잔재

계약 테스트 55 → 65.

## [2.0.0] - 2026-08-31

사용자가 커맨드 순서를 외우고 있어야 했던 문제를 고쳤다.
산출물 사이의 선행 관계를 명시하고, 묶음 파이프라인 2종을 도입했다.

  | `/화면목록표` | `/gx-화면목록표` |
  | `/프로그램정의서` | `/gx-프로그램정의서` |
  | `/인터페이스정의서` | `/gx-인터페이스정의서` |

  | `/총괄테스트계획서` | `/gx-총괄테스트계획서` |

### Added

- **`/gx-spec`** — 명세 5종 일괄 생성 (요구사항 · 화면목록 · 프로그램 · 인터페이스 · 테이블).
  게이트 2곳: 화면ID 확정, 5종 일괄 검토
- **`/gx-testplan`** — 테스트 계획 4종 일괄 생성 (총괄 · 단위 · 통합 · 시스템).
  게이트 2곳: 종료기준 확정, 4종 일괄 검토
- **`templates/prerequisites.md`** — 커맨드별 하드/소프트 선행조건 정본.
  하드가 없으면 진행 중단, 소프트가 없으면 무엇이 빠지는지 알리고 계속 여부 확인
- **`templates/pipeline-protocol.md`** — 단독/파이프라인 실행 차이, 이월 금지 항목,
  재생성 파급 규칙(요구사항ID · 화면ID · 종료기준이 바뀌면 무엇을 다시 만드는지)
- 계약 테스트 17건 추가 (38 → 55) — `gx-` 접두 강제, 선행조건 레지스트리 완전성,
  파이프라인 게이트 수, **커맨드 도달 가능성**

### Fixed

- **`/gx-프로젝트설정` Step 7 이 v1.5.0 신규 커맨드 3종을 안내하지 않던 문제.**
  `/총괄테스트계획서`·`/시스템테스트`·`/결함관리대장` 은 기능이 있는데도
  어느 안내에도 등장하지 않아 발견 경로가 0이었다. Step 7 을 파이프라인 중심으로
  다시 쓰고, 16개 커맨드가 전부 도달 가능한지 테스트로 고정했다.
- `test_백틱으로_참조된_커맨드가_모두_존재한다` 의 정규식이 `gx-` 접두를
  매칭하지 못하던 문제

## [1.5.1] - 2026-08-31

실제 프로젝트(Spring Boot 회의실예약 시스템) 드라이런에서 드러난 규칙 구멍과
xlsx 시트명 버그를 고치고, 재발 방지용 테스트 하네스를 도입했다.

### Added

- **테스트 하네스** (`plugins/gx-pm/tests/`) — 표준 `unittest` 기반, 새 의존성 없음
  - `test_export_xlsx.py`: 마크다운 파싱·컬럼 재배열·시트명 결정 단위 테스트
  - `test_plugin_consistency.py`: 스킬·커맨드·템플릿·매니페스트 계약 테스트.
    v1.5.0 에서 수작업으로 찾은 불일치 10건을 회귀 테스트로 고정
- **CI** (`.github/workflows/test.yml`) — push·PR 에서 테스트 실행. 종전에는 워크플로가 없었다

### Changed

- **`design-test-cases` 경계값 도출 규칙을 3유형으로 세분화**
  - 유형 A 길이·수량: **영값(0·빈 문자열·0분)** 케이스 필수화
  - 유형 B 시각·순서: **경계 정확히 일치** 필수화 + 비교 연산자별 통과 측 판정표
  - 유형 C 단위: **하위 정밀도 잔여(초·나노초)** 전개
  - 제약 출처에 **도메인 검증 코드** 추가 — C유형에서는 사실상 유일한 출처
  - 오류코드 enum 을 예외 케이스 완전 목록으로 활용
  - 검증 조건 순차 검사 규칙 명시

### Fixed

- **xlsx 보조 표가 `_1`·`_2` 시트로 쌓이던 문제** — 산출물 유형이 인식되면 문서 안 모든 표가
  양식 시트명을 물려받았다. 드라이런에서 12시트 중 6시트가 무의미한 이름이었다.
  본문 표만 양식명을 쓰고 보조 표는 자기 제목을 쓰도록 분리하고, 컬럼 세트별 시트명을 지원
- **산문 한 줄이 시트명이 되던 문제** — 표 직전 첫 비-표 라인을 제목으로 채택해
  문단이 시트명이 됐다. 인용문·목록을 건너뛰고 짧은 라벨만 인정하도록 수정

## [1.5.0] - 2026-08-31

시험 단계 산출물을 공공 감리 기준과 ISO/IEC/IEEE 29119-3에 맞춰 고도화했다.
**기존 27개 검사기준 체크리스트(DE-13)는 그대로 유지**하고, 그 위에 케이스·결함·비기능 레이어를 덧붙였다.

### Added

- **테스트케이스 설계** (`design-test-cases` 스킬, DE-13 테스트케이스 시트)
  - 검사기준 체크리스트를 실행 가능한 케이스로 분해 — 사전조건·입력데이터·수행절차·기대결과·요구사항ID
  - 설계기법 자동 적용: 동등분할 · 경계값분석 · 결정테이블 · 상태전이
  - **정상/경계/예외 케이스 강제** — 예외가 0건이면 자동 보강 (정상 흐름만 검증하는 문제 차단)
  - 테이블정의서(DE-08)가 있으면 컬럼 길이·NotNull에서 경계값 자동 도출
  - 신규 ID: `TC_{화면ID}_{2자리}`
- **결함관리대장** (`DF-01`, `manage-defects` 스킬, `/결함관리대장` 커맨드)
  - 테스트 레벨 무관 단일 번호 체계 `{시스템코드}-DF-{순번}`
  - 심각도(Critical/Major/Minor/Trivial) · 우선순위(High/Medium/Low) · 상태 흐름(Open→Assigned→Fixed→Retest→Closed / Deferred / Rejected / Reopen)
  - 중복 결함 병합, 재현 절차 강제, 보안·개인정보·데이터정합성 결함 Critical 자동 격상
  - 결함 통계 기반 **종료기준 자동 판정**
- **총괄 테스트계획서** (`TE-01`, `generate-master-test-plan` 스킬, `/총괄테스트계획서` 커맨드)
  - 목적·범위(제외 범위 포함) / 테스트 레벨 4단계 / 추진 체제 / 일정 / 환경 / 테스트 데이터 / **진입·종료기준** / 결함 관리 기준 / 위험
  - 종료기준이 이후 모든 결과서의 판정 근거가 되는 단일 출처
  - 운영 데이터 사용 시 비식별 조치 방법 입력 강제 (개인정보보호법 P1)
- **시스템테스트** (`ST-01`/`ST-02`, `generate-system-test` 스킬, `/시스템테스트` 커맨드)
  - **비기능 요구사항을 검증하는 유일한 산출물** — 종전에는 비기능 요구사항의 검증 칸이 통째로 비었다
  - 성능·보안·접근성·호환성·유지보수성·법적준수 6유형별 표준 측정 항목과 목표치
  - 신규 ID: `{시스템코드}-ST-{순번}`
  - 보안 항목 부적합은 Critical 결함으로 자동 발급
- **예외 흐름 시나리오** (`generate-integration-test`)
  - 업무 흐름 성격에서 필수 예외 자동 도출 (권한 없음 / 중복 / 상태 위반 / 연계 실패 / 동시성 / 세션 만료)
  - 정상 시나리오 1건마다 예외 시나리오 1건 이상, **별도 ID**로 부여
- **판정값 "점검제외" 추가** (감리 과업이행여부 판정 기준 반영)
  - 적합 / 부적합 / **점검제외** 3값 — 점검제외는 4가지 인정 사유와 함께 기재
  - 계획 단계의 "해당없음"(적용 대상 아님)과 구분

### Changed

- **검사기준서 강화** (`templates/inspection-criteria.md`)
  - 27개 항목 전건에 **예상결과 · 판정기준 · 점검방법** 3컬럼 추가 (항목명만으로는 감리 검사기준서 요건 미충족)
  - 이 파일을 **검사기준 항목명의 단일 정본**으로 확정
- **추적매트릭스 확장** (`AN-05`, `trace-requirements`, `id-trace`)
  - 컬럼 추가: 테스트케이스 수 · **시스템테스트 ID/항목** · 잔존 결함
  - 요구사항 구분별 매핑 규칙 명문화 — 비기능은 화면·프로그램 대신 시스템테스트로 검증
  - 누락 탐지 4유형 → **7유형** (테스트케이스 미작성 · **비기능 검증 누락** · 결함 미종결 추가)
