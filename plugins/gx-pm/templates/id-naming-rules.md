# ID 네이밍 규칙

## 시스템 코드

프로젝트의 각 시스템은 영문 1자리 코드를 가진다.
사용자에게 시스템 목록을 제공받거나, 기존 산출물에서 추출한다.

예시 (ENERGY202507 프로젝트):
| 코드 | 시스템명 |
|------|---------|
| A | 국내외 열사용기자재 검사 시스템 |
| B | 공공기관 에너지이용 합리화 시스템 |
| C | 연구용역 관리 시스템 |
| ... | ... |

## ID 체인

```
요구사항ID (기본 REQ-{3자리})
  └→ 기능ID (기본 FN-{3자리})            ← 파생 아님. 독립 채번, N:M 매핑
       ├→ 테이블·컬럼 (DE-08)            ← 입력항목이 컬럼으로 매핑된다
       └→ 테스트ID (기본 UT-{3자리})     ← 파생 아님. 독립 채번, N:1 매핑
```

**파생 ID 가 없다.** 어떤 ID 도 다른 ID 에서 만들어지지 않으므로,
상위 ID 가 바뀌어도 하위 ID 를 재채번할 필요가 없다. 연결은 전부 `연계~ID` 열이 맡는다.

기능ID 를 요구사항ID 에서 파생시키지 않는 이유: 기능 1개가 요구사항 여러 건을 덮는 경우가
흔하고, 파생형은 그 경우를 표현하지 못한다.

## 채번 규칙은 프로파일이 정한다

접두어·자릿수는 프로젝트마다 다르다. 프로파일에 없으면 커맨드가 AskUserQuestion 으로
한 번 묻고 저장한다. **저장 자리는 `profile.json` 의 `idNaming` 객체**이며
필드 정의는 `templates/project-profile-schema.md` 에 있다.

| ID | `idNaming` 필드 | 기본 제안 | 대안 예 |
|----|---------------|---------|--------|
| 요구사항ID | `requirement` | `REQ-001` | `B-RE-001` (시스템코드 포함) |
| 기능ID | `function` | `FN-001` | `B-FN-001` |
| 테스트ID | `test` | `UT-001` | `B-UT-001` |

묻는 자리는 **프로파일에 값이 없을 때 처음 채번하는 커맨드**다. 파이프라인이면
`/gx-spec` Step 0, 단독 실행이면 그 커맨드의 채번 단계다.
`/gx-프로젝트설정` Step 3-1 에서 미리 정해 두면 어디서도 묻지 않는다.
**한 번 저장하면 다시 묻지 않는다.**

## 불변 규칙

- 한 번 부여한 ID 는 바꾸지 않는다
- 삭제해도 재사용하지 않는다. 순번에 구멍이 남는 것을 허용한다
- 재실행 시 마지막 순번 다음부터 이어서 부여한다
- 산출물을 다시 만들 때는 **reconcile-ids** 스킬이 직전 버전과 대조해 ID 를 승계한다.
  같은 항목이면 기존 ID 를 그대로 쓰고, 신규만 다음 순번을 받는다

## 비기능 요구사항

기능ID 를 갖지 않는다. DE-13 에서 `연계기능ID` 공란 행으로 검증되면 정상이며,
`연계요구사항ID` 만으로 추적된다.

## 원문 ID (우리 채번 대상이 아니다)

RFP·과업지시서에는 자체 ID(예: `SFR-001`, `BR-01`)가 이미 붙어 있을 수 있다.
이건 우리가 부여하는 ID가 아니라 원문에 이미 있는 표기이므로, 위 채번 규칙을
적용하지 않고 그대로 옮겨 적는다.

AN-02 에는 이걸 담는 전용 열이 없다. `요구사항 근거` 열에 원문 그대로 병기한다
(예: `과업지시서 BR-01`). 이렇게 해야 원문의 어떤 항목이 어느 요구사항ID 가 됐는지
역추적할 수 있다.

## ID 접두어 일람

| 접두어 | 대상 | 파생 기준 |
|--------|------|----------|
| `REQ-` | 요구사항 | 독립 채번 |
| `FN-` | 기능 | 독립 채번 |
| `UT-` | 테스트 | 독립 채번 |
| `CR-` | 변경요청 | 날짜 + 순번 |

## 문서 공통 규칙

1. 문서 파일명의 `{시스템명}` 부분을 실제 시스템명으로 대체
2. 문서 내 업무구분은 해당 시스템명으로 기재
3. 문서 내 작성자는 감리대응 담당자명으로 기재
4. 프로젝트 코드: 프로젝트별 부여 (예: ENERGY202507)
