# ID 네이밍 규칙

## 시스템 코드

프로젝트의 각 시스템은 영문 1자리 코드를 가진다.
사용자에게 시스템 목록을 제공받거나, 기존 산출물에서 추출한다.

예시 (ENERGY202507 프로젝트):
| 코드 | 시스템명 |
|------|---------|
| A | 국내외 열사용기자재 검사 시스템 |
| B | 공공기관 에너지이용 합리화 시스템 |
| C | 연구용역 관리 시스템 |
| ... | ... |

## ID 체인

```
요구사항ID (기본 REQ-{3자리})
  └→ 기능ID (기본 FN-{3자리})            ← 파생 아님. 독립 채번, N:M 매핑
       ├→ 테이블·컬럼 (DE-08)            ← 입력항목이 컬럼으로 매핑된다
       └→ 테스트ID (기본 UT-{3자리})     ← 파생 아님. 독립 채번, N:1 매핑
```

**파생 ID 가 없다.** 어떤 ID 도 다른 ID 에서 만들어지지 않으므로,
상위 ID 가 바뀌어도 하위 ID 를 재채번할 필요가 없다. 연결은 전부 `연계~ID` 열이 맡는다.

기능ID 를 요구사항ID 에서 파생시키지 않는 이유: 기능 1개가 요구사항 여러 건을 덮는 경우가
흔하고, 파생형은 그 경우를 표현하지 못한다.

## 채번 규칙은 프로파일이 정한다

접두어·자릿수는 프로젝트마다 다르다. 프로파일에 없으면 커맨드가 AskUserQuestion 으로
한 번 묻고 저장한다.

| ID | 기본 제안 | 대안 예 |
|----|---------|--------|
| 요구사항ID | `REQ-001` | `B-RE-001` (시스템코드 포함) |
| 기능ID | `FN-001` | `B-FN-001` |
| 테스트ID | `UT-001` | `B-UT-001` |

## 불변 규칙

- 한 번 부여한 ID 는 바꾸지 않는다
- 삭제해도 재사용하지 않는다. 순번에 구멍이 남는 것을 허용한다
- 재실행 시 마지막 순번 다음부터 이어서 부여한다

## 비기능 요구사항

기능ID 를 갖지 않는다. DE-13 에서 `연계기능ID` 공란 행으로 검증되면 정상이며,
`연계요구사항ID` 만으로 추적된다.

## 그 외 ID 패턴 상세

이 절의 ID 들은 위 3단 체인과 독립적이다 — 각자 자기 완결적으로 순번 채번되며,
어떤 ID 에서도 파생되지 않는다.

### 제안요청ID
- 패턴: `SFR-{3자리 순번}`
- 예시: `SFR-001`, `SFR-027`
- 출처: RFP/과업지시서

### 통합테스트ID
- 패턴: `{시스템코드}-TE-{3자리 순번}`
- 예시: `A-TE-001`, `B-TE-003`
- 단위: **업무 흐름 1개 = 시나리오 1건**. 시나리오 안의 단계는 Step 번호로 분해한다.
- 예외 흐름: 정상 흐름 시나리오와 **별도 ID**를 부여한다 (예: `B-TE-003` 정상, `B-TE-004` 권한 없음)

### 시스템테스트ID
- 패턴: `{시스템코드}-ST-{3자리 순번}`
- 예시: `B-ST-001`, `A-ST-012`
- 대상: **비기능 요구사항** (성능·보안·호환성·접근성·가용성)
- 규칙: 하나의 비기능 요구사항에 여러 측정 항목이 있으면 항목별로 별도 ID를 부여한다
  (예: "응답시간 3초 이내 + 동시접속 500명" → `B-ST-001`, `B-ST-002`)

### 결함ID
- 패턴: `{시스템코드}-DF-{3자리 순번}`
- 예시: `B-DF-001`, `A-DF-047`
- 규칙: **테스트 레벨과 무관하게 프로젝트 전체에서 연속 채번**한다
  (단위/통합/시스템/인수 어디서 발견되든 같은 번호 체계)
- 중복 결함: 같은 원인이면 새 ID를 발급하지 않고 기존 결함ID에 발견 위치를 추가한다
- 재발 결함: 새 ID를 발급하고 비고에 원 결함ID를 참조한다 (`B-DF-012 재발`)

### 인터페이스ID
- 패턴: `IF-{시스템코드}-{3자리 순번}`
- 예시: `IF-B-001`, `IF-A-003`
- 규칙: 연동 목적이 다르면 같은 외부 시스템이라도 별도 ID 부여

## ID 접두어 일람

| 접두어 | 대상 | 파생 기준 |
|--------|------|----------|
| `SFR-` | 제안요청 | RFP 원문 |
| `REQ-` | 요구사항 | 독립 채번 |
| `FN-` | 기능 | 독립 채번 |
| `UT-` | 테스트 | 독립 채번 |
| `-TE-` | 통합테스트 | 순번 채번 |
| `-ST-` | 시스템테스트 | 순번 채번 |
| `-DF-` | 결함 | 순번 채번 |
| `IF-` | 인터페이스 | 순번 채번 |
| `CR-` | 변경요청 | 날짜 + 순번 |

## 문서 공통 규칙

1. 문서 파일명의 `{시스템명}` 부분을 실제 시스템명으로 대체
2. 문서 내 업무구분은 해당 시스템명으로 기재
3. 문서 내 작성자는 감리대응 담당자명으로 기재
4. 프로젝트 코드: 프로젝트별 부여 (예: ENERGY202507)
