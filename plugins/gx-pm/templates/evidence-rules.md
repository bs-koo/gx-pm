# 근거 규칙 (정본)

기능명세(AN-03)의 `입력항목`·`처리내용(로직)` 을 무엇으로 채웠는지, 못 채운 것이
얼마나 되는지를 세는 규칙이다. AN-03·DE-13·`/gx-spec` 이 이 문서를 참조한다.
**규칙을 복제하지 않는다.**

## 근거 4단

번호가 작을수록 우선한다.

| # | 근거 | 가용 판정 |
|---|------|----------|
| 1 | 요구사항 상세내용 | 항상 가용 — AN-02 가 하드 선행이다 |
| 2 | 처리내용 역산 | 항상 가용 — 자기 산출물이다 |
| 3 | 기존 DDL 의 컬럼 제약 | `profile.assets.ddlFile` 이 있으면 가용 |
| 4 | 기존 소스의 구현 | `profile.assets.sourcePath` 또는 `source-index.json` 이 있으면 가용 |

**3·4 단이 실제 변수다.** A유형(신규 구축)은 둘 다 없어 2/4 가 된다.
C유형(산출물 정비)은 대개 4/4 다.

4단은 `scan-source-index` 스킬이 만든 색인에서 읽는다. 소스에서 읽은 제약은
문서 근거와 어긋날 수 있으므로, 어긋나면 **문서를 우선하고 불일치를 게이트에 보고한다.**

## [가정] 과 [미확정] 은 2단 판정으로 갈린다

값이나 항목이 비었을 때 **누가 정할 값인가**를 먼저 가른다.

```
1. RFP 가 그 값을 줬는가?
     예   → 그대로 쓴다. 가정이 아니다
     아니오 ↓
2. 그 값 또는 그 항목이 없으면 요구사항을 구현할 수 없는가?
     예   → [미확정]   발주기관이 정할 값이다. 절대 채우지 않는다
     아니오 → [가정]   설계 재량이다. 값을 채우고 근거를 적는다
```

2번은 **그 값을 뺀 채로 요구사항 문장을 읽는 것**이다. 문장이 여전히 구현
지시로 성립하면 설계 재량이고, 성립하지 않으면 발주기관 몫이다.

| 표기 | 뜻 | 결과 |
|------|-----|------|
| `[가정]` | RFP 가 규정하지 않았고, 없어도 요구사항이 구현된다 | **값이 있다.** 경계 케이스가 나온다 |
| `[미확정]` | RFP 가 규정했으나 값이 없다. 없으면 구현 불가 | 값이 없다. 그 자리는 비운 채 추적한다 |

### 판정 예

| 항목 | RFP | 값을 빼면 | 판정 |
|------|-----|----------|------|
| 권한명 길이 | "권한명을 지정" — 길이 언급 없음 | 권한 등록은 구현된다 | `[가정] 100자` |
| 표본 최소 수 | "표본이 **지나치게 적은 경우** 안내" | "적은 경우" 판정 불가 | `[미확정]` |
| 가용률 | "**안정적으로** 운영되어야 한다" | 검증 불가 | `[미확정]` |
| 오류 코드값 | "오류 유형을 **코드로 관리**" | 코드 관리 불가 | `[미확정]` |
| 파일 항목 구성 | "원천 데이터 4종 등록" | 파싱 불가 | `[미확정]` |

**축이 값이냐 항목이냐는 판정을 가르지 않는다.** 파일 항목 구성처럼 항목 자체가
없는 것도 2번을 그대로 적용한다.

`[가정]` 의 근거에는 **`RFP 미규정`** 을 반드시 적는다 — 2번 판정을 통과했다는
증거이고, 이것이 없으면 지어낸 값과 구별되지 않는다.

AN-03 `입력항목` 열의 형식은 `항목명(타입, 제약, 필수여부, 기본값)` 이다.

### 제약이 비었다는 판정

괄호 안에 **길이·범위·형식·열거값**이 하나도 없으면 제약이 빈 것이다.
`필수` 만 있는 것은 제약이 아니다 — 미입력 예외 1건만 만들고 경계는 못 만든다.

| 표기 | 판정 |
|------|------|
| `이메일(필수)` | **비었다** → 위 2단 판정으로 간다 |
| `이메일(필수, 1~255자)` | 찼다 |
| `상태(필수, 대기\|승인\|반려)` | 찼다 — 열거값이다 |
| `등록일(date, 필수)` | 찼다 — 타입이 형식을 정한다 |

비었으면 2단 판정을 적용한다. `이메일(필수)` 는 RFP 가 길이를 규정하지 않았고
길이 없이도 구현되므로 `이메일(필수, [가정] 1~255자 — RFP 미규정, RFC 5321)` 이 된다.

판정 결과는 AN-03 의 `비고` 열에 적는다. **컬럼을 늘리지 않는다.**

집계는 `[가정] {N}건 · [미확정] {M}건 — 항목 {M1} / 제약 {M2}` 로 낸다.

### 표식은 세 홉을 관통한다

`[가정]` 을 AN-03 에만 적으면 DE-13 이 무표식 값에서 경계를 뽑는다.
**제약의 최종 승자는 DE-08 이기 때문이다**
(`skills/generate-unit-test-plan/SKILL.md` Step 2 — 제약이 다르면 DE-08 이 우선).

감리에 나가는 DE-13 에서 가정값 검증과 RFP 값 검증이 구별되지 않으면,
아래 §자동 보강 절이 경계하는 **"통과하면 검증됐다고 오독된다"** 가 그대로 된다.

| 홉 | 자리 | 표기 |
|----|------|------|
| AN-03 | `입력항목` 괄호 안 | `권한명(String, 필수, [가정] 100자 — RFP 미규정)` |
| DE-08 | `근거` 열 | `행안부표준 · 권한=AUTHRT, 명=NM · [가정] 길이 100 — RFP 미규정` |
| DE-13 | `입력` 칸 | `권한명 101자 [가정:100]` |

**컬럼은 늘리지 않는다.** DE-13 은 11열이고 `비고` 가 없어 `입력` 칸에 싣는다 —
경계값 자체가 입력이므로 그 값의 출처가 붙을 자리로 가장 가깝다.
`사전조건` 은 3유형으로 제한돼 있어 쓰지 않는다.

확정되면 태그만 뗀다: `권한명(String, 필수, 100자)`.

## 근거 가용도 경고

게이트 2 에 가용도를 함께 낸다.

```
근거 가용도 2/4 — 요구사항 상세 ✓ / 처리내용 역산 ✓ / 기존 DDL ✗ / 기존 소스 ✗
```

**가용도가 4/4 미만인데 `[미확정]` 이 0건이면 경고한다.**

```
⚠ 근거 4단 중 2단만 살아 있는데 [미확정] 이 0건입니다.
   발주기관이 정할 값을 가정으로 채운 것이 없는지 확인하세요.
```

근거가 덜 살아 있는데 아무것도 확인이 필요하지 않다는 건 산술적으로 이상하다.
이 한 줄이 없으면 A유형에서 「지어낸 값」과 「충분한 입력」이 화면에서 똑같아 보인다.

## [미확정] 제약은 자동 보강 대상이 아니다

`skills/generate-unit-test-plan/SKILL.md` Step 6 의 자동 보강을 두 갈래로 가른다.

| 제약 | 보강 | 이유 |
|------|------|------|
| 값이 있다 | 한다 | 원래 규칙 |
| **`[가정]`** | **한다** | 가정값은 근거를 갖는다 — `RFP 미규정 + 표준 도메인 기본값` |
| **`[미확정]`** | **하지 않는다** | 경계값을 **지어내는** 것이 된다 |

근거 없는 경계값은 없는 것보다 나쁘다 — 통과하면 검증됐다고 오독된다.
그래서 `[미확정]` 은 보강하지 않고 **`[미확정] 제약` 목록**에 넣어 게이트 3 에
보고하고, 사용자가 값을 주면 그때 보강한다.

**옛 규칙이 틀렸던 게 아니라 전제가 바뀌었다.** 옛 규칙은 "제약이 비면 근거가
없다" 를 전제했는데, 2단 판정은 RFP 미규정 항목에 근거를 만든다. 근거가 생겼으므로
그 경우의 보강은 지어내기가 아니다. `[미확정]` 에 대해서는 옛 규칙 그대로다.

보강된 케이스에는 §표식은 세 홉을 관통한다 의 DE-13 표기를 붙인다 —
`권한명 101자 [가정:100]`. 붙이지 않으면 가정값 검증이 RFP 값 검증처럼 보인다.
