# 확인요청서 (양식)

명세 5종의 `[가정]`·`[미확정]`과 원문 충돌·범위·누락 해석처럼 사용자 판단이 필요한 항목을 한 파일에 모은다. 수집과 발행은 `skills/review-confirmations/SKILL.md`가 맡는다.
5종 산출물이 아니라 **미결사항 관리대장**이므로 산출물 코드(AN-·DE-)를 붙이지 않는다
(`plugins/gx-pm/CLAUDE.md` §산출물 범위가 코드의 정본이다).

**다량 질문은 파일로 주고받고, 소량의 대화 답변도 같은 대장에 기록한다.** 이 층의 상한은
`templates/pipeline-protocol.md` §질문 정책이 정본이다 — 여기서 복제하지 않는다.
이 문서가 정하는 것은 **그 파일의 양식**이다.

## 언제 만드나

태그 유무와 관계없이 **사용자 판단이 필요한 항목**을 센다. 1건부터 md에 기록하며,
**6건 이상일 때** 또는 파일 검토를 요청받았을 때 xlsx도 만든다.

| 합계 | 어떻게 |
|------|--------|
| **0건** | 확인 필요 0건을 알리고 추가 발행하지 않는다. 빈 파일을 만들지 않는다 |
| **1~5건** | **그 자리에서 대화로 묻고 실제 응답을 기다린다.** 항목·응답·보류는 확인요청서 md에 기록한다. Excel 요청 시 xlsx도 낸다 |
| **6건 이상** | **확인요청서를 내고 중단한다.** 같은 항목은 최대 세 번까지 묻는다 |

이 기준은 기본값이다. 사용자가 확인요청서 파일을 요청하면 1~5건도 파일로 낸다. 대화 질문은 실제 도구의 한도 안에서 보통 1~3개씩 나눈다. 답이 없는 항목에 의존하는 확정만 보류하고 독립된 작업은 진행할 수 있다.

**갈음하지 않는다.** 5건 이하를 목록으로만 보여주고 넘어가면 답을 못 받은 채
값이 굳는다. **적어서 물을 수 있는 것이지, 적어서 안 물어도 되는 것이 아니다.**

### 무엇을 세나

합계는 **이번에 물을 항목**의 수다. 본문의 표식을 그대로 세지 않는다.

| 센다 | 세지 않는다 |
|------|------------|
| 표식 또는 원문 충돌·범위·연계 해석처럼 아직 등록하지 않은 판단 항목 | 닫힌 항목은 세지 않는다 — 시트 3 마지막 행이 `반영`·`철회` 인 것 |
| 확인요청서에 열려 있고 `물은 횟수` 가 3 미만인 것 | 세 번 물은 항목은 세지 않는다 — 시트 3 마지막 행이 `미해소` 인 것 |

**빈칸은 미응답이다.** `[가정]`도 닫지 않고 대기로 남긴다. 명시적으로 `맞음`·`수정` 또는 제시된 CQ 항목의 일괄 수락을 받은 항목만 닫는다. 닫힌 항목은 다시 세지 않는다. 과거 버전에서 묵시적 승인으로 닫힌 이력은 보존하되 새 빈칸에 그 규칙을 적용하지 않는다.

**한 표식은 한 항목이다.** `[가정]` 하나가 AN-03 입력항목 → DE-08 근거 → DE-13 입력으로
이어져도(`templates/evidence-rules.md` §표식은 세 홉을 관통한다) 항목은 하나다.
DE-08·DE-13 이 앞 산출물에서 이어받은 표식은 새 항목으로 세지 않는다 — 세면 같은
질문이 산출물마다 올라간다.

본문의 표식과 항목은 **`산출물` + `위치`** 로 잇는다. 그래서 한 번 쓴 `위치` 는
바꿔 쓰지 않는다.

## 차수는 발행 번호이고, 상한은 항목마다 세 번이다

**차수**는 새로운 질문 묶음을 실제로 제시한 번호다. 누가 냈든(게이트든 낱개 커맨드든)
새 질문·재질문을 제시할 때 1 씩 오르고 **상한이 없다.** 파일 재열기·추출·같은 답 재반영으로는 올리지 않는다.
**같은 항목은 최대 세 번 묻는다** — 그 횟수는 항목마다
`물은 횟수` 열이 센다.

상한을 파일에 걸면 안 되는 이유가 있다. 낱개 커맨드도 확인요청서를 내므로,
`/gx-기능명세서` 가 1차 · `/gx-테이블정의서` 가 2차 · `/gx-단위테스트계획서` 가 3차를 내면
그것으로 상한이 끝난다 — 정작 각 항목은 한 번씩만 물은 채로.

`/gx-명세일괄` 만 쓰는 흐름은 이렇다. 각 회차는 **앞 차수 답 반영 + 다음 차수 발행**이다.

| 회차 | 하는 일 | 끝난 뒤 |
|---|---|---|
| 1 | 게이트 1·2 통과 | **1차 발행** → 중단. 전 항목이 `물은 횟수` 1 |
| 2 | 1차 답 반영 → DE-13·AN-05 생성 → 게이트 3 | **2차 발행** → 중단. 남은 항목 2 · DE-13 새 항목 1 |
| 3 | 2차 답 반영 → 파급 처리 | **3차 발행** → 중단. 남은 항목 3 · DE-13 항목 2 |
| 4 | 3차 답 반영 | 세 번 물은 항목은 `미해소`. 이번에 물을 것이 6건 이상이면 4차 발행 |

**해당 문서의 미결 항목이 0이 되면 그 자리에서 끝난다.** 미응답 가정도 포함한다.
「최대 세 번」이지 「반드시 세 번」이 아니다.

**차수는 게이트 번호가 아니다.** 질문이 없거나 기존 답만 반영한 게이트는 차수가 늘지 않는다.
1~5건의 대화 질문도 기록하므로 새 질문 묶음이면 한 차수를 쓴다. 위 표는 매번 새 질문을 낸 예시다.

**세 번은 자동으로 묻는 상한이지 사람이 답할 기회의 상한이 아니다.** 세 번 물어도
답이 없으면 값을 대신 정하지 않는다 — `[미확정]` 그대로 두고 최종본을 내지 않는다.
값이 정해지면 언제든 이 파일에 적고 다시 부르면 반영된다 (아래 §세 번 물은 항목).

### 세 번 물은 항목

시트 3 마지막 행이 `미해소` 인 항목이다. 착수 협의로 값이 정해진 뒤 답이 오는 것이
대표적이다.

**해당 시트 1·2 에 그대로 남긴다.** 사람이 언제든 답을 적을 자리가 있어야 한다. 다만
`물은 횟수` 를 올리지 않고, 발행 여부를 가르는 합계에도 세지 않는다(§무엇을 세나).

| 들어온 답 | 처리 |
|------|------|
| 그 항목에 답이 왔다 | 해소하고 본문에 반영한다 |
| 여전히 빈칸이다 | 그대로 둔다. 그 항목 때문에 새 차수를 내지 않는다 |

시트 3 「요청 이력」은 **그 항목의 `미해소` 행의 `받은 답`·`처리` 를 갱신한다.**
다시 물은 것이 아니므로 행을 새로 만들지 않는다 — 새 행을 만들면 묻지 않은 네 번째
요청을 감리 증거가 주장한다.

**해당 문서에 영향을 주는 미결이 전건 해소되면 그때 최종본을 낸다.** 그 규칙의 정본은 아래
§미확정이 0이어야 최종본을 낸다 다.

## 파일 하나, 차수 누적

```
{프로젝트폴더}/
  {시스템코드}-확인요청서.md      ← 정본. 차수가 쌓인다
  xlsx/
    {시스템코드}-확인요청서.xlsx  ← 사람이 채우는 것
```

**파일명은 고정이다.** `_1차`·`_2차` 로 나누면 "어느 걸 채워야 하나" 가 매번
혼란스럽다. 항상 같은 파일을 열면 되고 이력은 안에 있다. 커맨드나 산출물마다
파일을 나누지 않는 것도 같은 이유다.

### 한 파일 안에서 가르는 법

여러 요청이 한 파일에 쌓이므로 **행마다 세 가지를 적어 가른다.** 문장인 `위치` 로는
걸러 볼 수도, 차수를 넘어 같은 항목을 이을 수도 없다.

| 무엇을 가르나 | 열 | 어디에 |
|---|---|---|
| 같은 항목인가 | `항목번호` (`CQ-001` …) | 시트 1·2·3 |
| 어느 산출물의 질문인가 | `산출물` (`AN-02` / `AN-03` / `DE-08` / `DE-13` / `AN-05`) | 시트 1·2·3 |
| 어느 요청이 물었나 | `차수` · `발행일` · `발행처` | 시트 3 (지금 차수는 시트 0 `현재`) |

- **`항목번호` 는 파일 안에서 1부터 매기고, 지우거나 다시 쓰지 않는다.** `철회` 로 끝난
  항목의 번호도 시트 3 에 남는다. 새 항목은 파일에 있는 가장 큰 번호 다음을 받는다.
  접두어는 `templates/id-naming-rules.md` §ID 접두어 일람에 있다.
- **`산출물` 은 표식이 처음 선 곳이다** (§무엇을 세나 — 한 표식은 한 항목이다).
- **엑셀에서는 `산출물` 열 필터로 나눠 본다.** 산출물 담당자에게 시트를 떼어 줄 때도
  이 열로 거른다.
- **어느 커맨드로 불러도 파일 전체를 반영한다.** `/gx-테이블정의서` 로 불렀다고 DE-08
  항목만 반영하면, 답이 적힌 다른 행이 반영 안 된 채 남고 다음 발행이 그 답을 덮는다.

## 낱개 커맨드에서도 같은 규칙으로 낸다

`/gx-요구사항정의서` · `/gx-기능명세서` · `/gx-테이블정의서` · `/gx-단위테스트계획서` ·
`/gx-추적매트릭스` 모두 **review-confirmations**를 호출한다. 태그가 없다는 이유만으로
AN-02·AN-05를 제외하지 않는다. 수집 범위·중복 제거는 그 스킬의 표를 따른다.

### Step 0: 재개

기존 파일을 읽고 새로운 응답·미응답 건수를 보여준다. 사용자가 응답 반영을 요청했으면
**apply-confirmations**로 파일 전체를 반영한다. 의도가 불분명할 때만
「확인요청서 반영하고 이어가기 / 반영하지 않고 계속」을 묻는다.
반영하지 않고 계속한 파일은 덮어쓰지 않는다. 기존 산출물의 3분기보다 이 확인이 먼저다.

### 저장 뒤, xlsx를 묻기 전에

이번에 물을 항목의 **합계**로 §언제 만드나를 적용한다. 1~5건도 목록 표시만으로 끝내지
않는다. 파일은 시스템당 하나이며 발행처에 호출한 커맨드를 적는다. 대화 응답도
`항목번호`와 요청 이력에 남겨 다음 실행에서 다시 묻지 않는다.

6건 이상이면 확인요청서 md를 저장하고 아래처럼 **xlsx까지 실제로 추출한 뒤**
해당 문서 확정을 보류한다. 사용자에게 실제 경로와 답할 칸을 보여준다.

```text
python {플러그인 루트}/utils/export-xlsx.py --separate --output {프로젝트폴더}/xlsx {프로젝트폴더}/{시스템코드}-확인요청서.md
```

확인요청서가 0건인 실행도 「확인 필요 0건 — 추가 발행 없음」을 알린다.
미결 최종본과 검토용 초안의 출력은 §미확정이 0이어야 최종본을 낸다를 따른다.

## 개정이력을 붙이지 않는다

`templates/revision-history.md` 는 산출물 5종의 첫 시트를 개정이력으로 정한다.
확인요청서는 그 5종이 아니므로 개정이력을 두지 않는다. 「요청 이력」 시트가
그 역할을 대신한다.

## 시트를 나누는 기준은 「값이 있나 없나」다

| # | 시트 | 누가 채우나 | 내용 |
|---|------|------------|------|
| 0 | 안내 | **읽기만** 한다 | 지금 몇 차인지 · 어디에 무엇을 쓰는지 · 다 채운 뒤 무엇을 하는지 |
| 1 | 가정 확인 | **채운다** | AI 가 정한 값을 반증한다. 후속 질문도 여기 |
| 2 | 미확정 확인 | **채운다** | 값이 아예 없는 것. 이 시트만 떼어 낼 수 있다 |
| 3 | 요청 이력 | **읽기만** 한다 | 지난 차수 기록. 감리 증거 |

**누구에게 물으라고 지시하지 않는다.** 값을 어디서 구할지는 이 파일을 받은
사람이 안다. 양식이 할 일은 **무엇이 비었는지와 어디에 쓰는지**를 알려주는
것까지다.

시트 1 은 있는 값을 반증하고 시트 2 는 없는 값을 채운다 — 답하는 성격이
달라 한 시트에 섞지 않는다. 시트 2 만 복사해 따로 공유할 수 있어야 한다.

## 시트 0 · 안내 — 본문 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | 구분 | 안내 항목 이름 |
| 2 | 안내 | 사람이 읽을 문장 |

### 예시 행

| 구분 | 안내 |
|------|------|
| 현재 | 2차 요청입니다 — 2026-09-20 /gx-테이블정의서 가 냈습니다. 같은 항목은 최대 세 번까지 묻습니다 |
| 채우는 법 | 노란 칸만 채우면 됩니다. 흰 칸은 읽기용입니다 |
| 시트1 가정 확인 (12건) | AI 가 값을 정해 뒀습니다. 맞으면 판정을 「맞음」으로, 틀리면 「수정」으로 고르고 정정값 칸에 옳은 값을 쓰세요 |
| 시트2 미확정 확인 (33건) | 값을 못 정해 비워 둔 것입니다. 값을 정해 응답 칸에 쓰고 상태를 「확정」으로 바꾸세요. 물은 횟수가 3 인 것은 더 묻지 않지만 값이 정해지면 언제든 적으세요 |
| 산출물별 | AN-03 30건 · DE-08 9건 · DE-13 6건 — 산출물 열의 필터로 나눠 볼 수 있습니다 |
| 시트3 요청 이력 | 지난 차수 기록입니다. 채우지 마세요 |
| 빈칸으로 두면 | 두 시트 모두 미응답으로 남습니다. 값이 맞으면 시트1 판정을 맞음으로 골라주세요 |
| 다 채운 뒤 | /gx-테이블정의서 를 다시 부르고 「확인요청서 반영하고 이어가기」를 고르세요. 어느 커맨드로 불러도 파일 전체가 반영됩니다 |
| 미확정이 남으면 | 마크다운은 저장되지만 최종본 엑셀은 나오지 않습니다 |

`현재` 에는 차수·발행일·발행처를 적는다 — 반영할 때 시트 3 의 `차수`·`발행일`·`발행처` 를
여기서 옮긴다. `현재`·건수는 매 차수 다시 쓴다. `다 채운 뒤` 에는 그 차수를 낸 커맨드를 적는다.

**시트 이름 옆에 건수를, 문장 안에 채울 칸 이름을 넣는다.** 「노란 칸만
채우세요」만으로는 무엇을 쓸지 모른다. 어느 칸에서 무엇을 고르고 어느 칸에
무엇을 적는지를 이 표가 말한다 — 사람이 시트 1 을 열기 전에 안다.

**강조 표기를 쓰지 않는다.** 엑셀은 마크다운을 모른다. 별표와 백틱이 글자로
보인다 — 사람이 맨 처음 읽는 시트에서 특히 나쁘다.
`utils/export-xlsx.py` 가 걷어내지만 정본에서도 쓰지 않는다.

## 시트 3 · 요청 이력 — 본문 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | 차수 | 그 행을 물은 발행의 번호. `1` 부터 오르고 상한이 없다 |
| 2 | 발행일 | 그 차수를 낸 날 |
| 3 | 발행처 | 그 차수를 낸 곳 — `/gx-명세일괄 게이트 2` · `/gx-명세일괄 게이트 3` · 명세 5개 단독 커맨드. 1~5건이라 대화로 물었으면 뒤에 ` (대화)` |
| 4 | 항목번호 | 시트 1·2 의 번호 그대로 |
| 5 | 산출물 | 시트 1·2 의 값 그대로 |
| 6 | 위치 | 물었던 자리 |
| 7 | 물은 것 | 질문 요지. 시트 1 항목이면 **AI 가 제시한 값을 괄호로 병기**한다 |
| 8 | 받은 답 | 받은 값 그대로. 미응답이면 `미응답` |
| 9 | 처리 | `반영` / `이월` / `되질문` / `미해소` / `철회` |

**대화 질문도 기록한다.** 처음이면 md를 만들고 차수 1을 쓴다. 같은 검토의 질문 묶음은 한 차수이며, 같은 응답을 다시 읽거나 파일을 열기만 해서는 차수·물은 횟수를 올리지 않는다. 재질문이나 새 질문을 실제 제시할 때만 센다.

### 시트 1 과 시트 2 를 **둘 다** 받는다

가정 확인(시트 1)도 요청이다. 「이 값이 맞습니까」라고 물었고 답을 받았거나
못 받았다. **시트 1 항목을 빼면 「AI 가 100자로 정했는데 사람이 50 으로
고쳤다」는 사실이 어디에도 안 남는다** — 값이 왜 그것인지가 지워진다.

### 행을 덮어쓰지 않고 쌓는다

차수마다 **새 행**이다. 같은 항목을 세 번 물었으면 세 줄이 남는다.
시트 1·2 는 **지금 답해야 할 것**만 보여주므로 지난 차수의 값이 거기서는
사라진다. **그 값이 남는 유일한 자리가 이 시트다.**

### 최종 결론은 각 항목의 **마지막 행**이다

`처리` 의 다섯 값이 곧 그 항목이 어떻게 끝났는지를 말한다.

| 처리 | 뜻 | 이 항목은 |
|------|-----|----------|
| `반영` | 명시적인 답을 받아 본문에 넣었다. 빈칸은 여기에 넣지 않는다 | **끝났다** |
| `이월` | 답이 없어 다음 차수로 넘겼다 | 진행 중 |
| `되질문` | 값 대신 질문이 왔다. 다음 차수에 답을 실어 돌려줬다 | 진행 중 |
| `미해소` | 세 번 물었는데 답이 없다 | **안 끝났다.** 최종본이 보류된다 |
| `철회` | `해당없음` 응답을 받았다 | **끝났다.** 물을 필요가 없어졌다 |

`이월` 로 끝나는 항목은 없다. 세 번 물어도 답이 없으면 마지막 행이 `미해소` 다 —
그래야 「진행 중인지 끝났는지」를 표만 보고 알 수 있다. **같은 항목의 행은
`항목번호` 로 묶는다** — `위치` 문장이 조금 달라져도 같은 항목이다.

`발행처`·`산출물` 은 거기에 **어느 요청이 어느 산출물에 대해 물었나**를 더한다.

**되질문의 답도 이 표에 남는다.** 값 대신 질문이 오면 대화로 답하지 않고 다음 차수
`물은 것` 에 답을 실어 돌려준다 (`skills/apply-confirmations/SKILL.md` §되질문에
답한다). 대화로 답하면 파일에는 질문만 남고 답이 사라진다.

**이 시트가 감리 증거다.** 「세 번 요청했으나 미응답」을 이 표가 증명하고,
「이 값은 우리가 정한 것이 아니라 답으로 받은 100 이다」도 이 표가 증명한다.

### 본문의 값이 최종 결론이다

「그래서 무엇으로 확정됐나」는 **산출물 본문**이 답한다. 값이 확정되면 본문에
들어가고 `[가정]`·`[미확정]` 태그가 떨어진다. 이 시트가 남기는 것은 **거기까지
어떻게 갔나** 다 — 같은 사실을 두 군데 적지 않는다.

## 미확정이 0이어야 최종본을 낸다

**`[미확정]` 또는 이 문서에 영향을 주는 미응답 확인 항목이 남아 있으면 최종본 xlsx를 뽑지 않는다.** 마크다운 5종은 게이트를
통과할 때마다 저장되므로 작업은 막히지 않는다. 감리와 개발자에게 나가는 최종본에만
도장을 찍지 않는 것이다.

**값을 대신 정하지 않기 때문이다.** 세 번 물어도 답이 없으면 관행값으로 채우지 않는다 —
채우면 해소된 것처럼 보이지만 실은 우리가 정한 값이라, 개발자가 그것을 확정값으로
읽고 착수한다. 그것이 이 규칙이 막으려는 일이다.

게이트가 남은 건수를 보고 이렇게 알린다.

```
아직 확정되지 않은 항목이 2건 있습니다. 최종본을 내지 않습니다.

  · DAR-001  원천 파일 4종 항목 구성
  · INR-001  평가프로그램 연계 규격

  마크다운 5종은 저장돼 있습니다.
  값이 정해지면 「미확정 확인」 시트의 응답 칸에 적고
  /gx-명세일괄 을 다시 부르세요.
```

**남은 것이 1~5건이면 그 자리에서 묻는다.** §언제 만드나 의 구간과 같다 — 적어서
물을 수 있는 것이지 적어서 안 물어도 되는 것이 아니다. 답이 오면 0이 되어 최종본이
나가고, 그 자리에서 답할 수 없으면 그대로 보류된다.

### 검토용 초안은 구분해서 낸다

사용자가 미결 문서를 Excel로 검토하려고 요청하면 최종본과 별도로 `검토용초안` 파일을 제공할 수 있다.
`utils/export-xlsx.py --draft --separate`를 사용한다. 파일명·모든 시트의 인쇄 머리말과 통합문서 제목에
검토용초안 표시가 남고 기존 최종본을 덮지 않는다. 확인요청서 링크와 미결 건수를 함께 안내한다.
초안 제공은 미결 해소나 승인으로 세지 않는다. 영향 없는 다른 문서의 최종본까지 일괄 보류하지 않는다.

## 빈칸이 정상이다

| 응답 | 결과 |
|------|------|
| 시트1 빈칸 | **미응답으로 유지**한다. 명시적 수락 없이 확정하거나 닫지 않는다 |
| 시트2 빈칸 | 미응답으로 유지한다. 실제 재질문할 때만 **다음 차수로 이월**하며, 세 번 물었으면 `미해소` 로 남는다 |

**값이 적힌 응답의 처리는 `skills/apply-confirmations/SKILL.md` Step 2 분기표가
정본이다.** 이 절이 정하는 것은 빈칸뿐이라 나머지를 여기서 복제하지 않는다.

**무응답도 보관 가능한 상태다.** 빈칸을 재촉하거나 자동 승인하지 않는다. 관련 판단만 보류하고 독립된 문서 작업은 이어간다. 응답 변화나 새 질문 없이 다시 열었다고 새 차수를 만들지 않는다.

## 응답란은 드롭다운이고 배경이 연노랑이다

`판정` 과 `상태` 는 xlsx 추출 시 데이터 검증(드롭다운)이 걸린다. 자유 텍스트로
받으면 「적당히」·「표준대로」 같은 답이 와서 되물어야 한다.

**채울 칸은 연노랑(`FFF9E3`) 배경이다.** 9열 중 3열만 입력란이라 색이 없으면
어디를 채울지 모른다. 드롭다운이 없는 `정정값`·`응답` 도 노란색이라 "여기 뭔가
써야 하는구나" 가 보인다.

| 시트 | 입력란 (연노랑) |
|------|----------------|
| 1 · 가정 확인 | `판정` · `정정값` · `비고` |
| 2 · 미확정 확인 | `상태` · `응답` · `확정일` |
| 0 · 안내, 3 · 요청 이력 | 없음 — 읽기만 한다 |

## 옛 양식 파일

`항목번호`·`산출물`·`물은 횟수` 열이 없는 확인요청서(구분 열 이전에 낸 것)는
**처음 반영할 때 한 번 채우고** 새 양식으로 다시 쓴다. 사람이 적은 응답은 그대로 옮긴다.

| 채울 것 | 어떻게 |
|---|---|
| `항목번호` | 시트 1 → 시트 2 순서로 `CQ-001` 부터 매긴다 |
| `산출물` | 본문에서 그 `위치` 의 표식이 처음 선 산출물. 못 찾으면 `위치` 의 ID 로 가른다 — `UT-` 는 DE-13, `테이블.컬럼` 은 DE-08, 그 밖은 AN-03 |
| `물은 횟수` | 시트 3 에서 같은 `위치` 가 나온 행 수. 시트 3 이 없으면 `1` |
| 시트 3 `발행처` | `/gx-명세일괄` — 구분 열 이전에는 그것만 확인요청서를 냈다. 게이트 번호는 모르므로 붙이지 않는다 |

옛 `#` 열은 버린다. 옛 `차수` 열은 시트 3 에만 남기고 시트 1·2 에서는 `물은 횟수` 로 바꾼다.
