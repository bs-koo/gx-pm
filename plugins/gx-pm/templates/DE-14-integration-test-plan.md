# DE-14 통합테스트계획서 양식

## 파일 형식
Excel (.xlsx)

## 시트 구성
1. **표지**
2. **개정이력**
3. **통합테스트시나리오** — 본문

## 본문 컬럼 구조

| 컬럼 | 설명 | 예시 |
|------|------|------|
| 통합테스트 ID | 테스트 시나리오 ID | A-TE-004 |
| 요구사항 ID | 매핑되는 요구사항 | SFR-030 |
| 시나리오명 | 테스트 시나리오 제목 | 운영자 권한 관리 |
| Step | 단계 번호 | 1, 2, 3... |
| 사용자구분 | 테스트 수행 역할 | 관리자 |
| 예상 입력 (사용자 행위) | 사용자가 하는 행동 | 운영자 권한 관리 메뉴 클릭 |
| 예상 출력 (시스템 결과) | 시스템 응답 | 운영자 권한 리스트 조회 |
| 테스트 데이터 | 사용할 테스트 데이터 | (빈칸 또는 데이터 설명) |
| 판정결과 | 적합/부적합 (계획서는 빈칸) | |
| 부적합 내역 | 부적합 시 상세 (계획서는 빈칸) | |
| 테스트 일시 | 테스트 수행일 (계획서는 빈칸) | |
| 수행자 | 테스트 수행자 (계획서는 빈칸) | |
| 부적합 원인 및 조치내역 | 조치 내용 | |
| 조치일시 | 조치 완료일 | |
| 조치자 | 조치 담당자 | |
| 조치후 판정결과 | 재판정 결과 | |
| 비고 | 참고사항 | |

## 작성 규칙

- 통합테스트ID: `{시스템코드}-TE-{순번}` 형식
- 하나의 시나리오에 여러 Step이 포함됨
- 통합테스트ID와 시나리오명은 첫 Step에만 기재, 이후 Step은 빈칸
- 하나의 시나리오가 여러 요구사항을 커버할 수 있음
- 시나리오는 실제 업무 흐름을 반영 (단순 CRUD가 아닌 업무 프로세스 기반)

## 통합테스트 vs 인수테스트

- **통합테스트 (TE-02)**: 개발팀이 수행, 기능 간 연계 검증
- **인수테스트 (TE-06)**: 발주처/감리가 수행, 요구사항 충족 검증
- 두 문서의 양식은 동일하나, 인수테스트는 발주처 관점의 시나리오
