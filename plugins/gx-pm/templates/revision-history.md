# 개정이력 (5종 공통)

산출물 5종(AN-02·AN-03·DE-08·DE-13·AN-05) 모두 **첫 시트가 개정이력, 둘째 시트가 본문**이다.
이 파일이 개정이력 규칙의 단일 정본이다. 산출물 템플릿은 이 파일을 참조만 하고 복제하지 않는다.

## 개정이력 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | 버전 | `1.0` 에서 시작, 개정마다 `+1.0`. 소수점 둘째 자리는 쓰지 않는다 |
| 2 | 개정일 | `YYYY.MM.DD` |
| 3 | 개정 사유 | `신규` / `추가` / `변경` / `삭제` / `보완` |
| 4 | 개정 내용 | 무엇이 몇 건 바뀌었는지. ID 를 병기한다 |
| 5 | 작성자 | 프로파일의 이름을 기본값으로 제시하고 확인받는다 |
| 6 | 승인자 | **자동으로 채우지 않는다.** 공란으로 두고 결재 후 사람이 기입한다 |

## 행이 추가되는 경우

| 트리거 | 개정 사유 | 개정 내용 자동 초안 |
|--------|----------|-------------------|
| 최초 생성 | `신규` | `최초 작성` |
| 항목이 늘어남 | `추가` | `요구사항 7건 추가` |
| 기존 항목의 내용이 바뀜 | `변경` | `요구사항 2건 변경(REQ-005, REQ-012)` |
| 항목이 삭제 상태로 전환 | `삭제` | `요구사항 1건 삭제(REQ-028)` |
| 오탈자·분류 정리 등 내용 무관 수정 | `보완` | `분류 체계 정리` |

여러 종류가 한 번에 일어나면 **행 하나에 합친다.** 사유는 가장 무거운 것을 쓴다:
`삭제` > `변경` > `추가` > `보완`.

## 행이 추가되지 않는 경우

- **승인 게이트 안에서의 수정** — 게이트에서 고쳐 재출력한 것은 확정 전이므로 개정이 아니다.
  파일 저장 시점에 1행만 만든다
- **다른 문서만 바뀐 경우** — AN-02 만 바뀌면 AN-03·DE-13 의 개정이력은 올라가지 않는다
- **파급 재생성 결과가 기존과 동일한 경우** — diff 가 0 이면 행을 만들지 않는다

## 버전은 문서마다 독립이다

AN-02 가 3.0 이어도 DE-13 은 1.0 일 수 있다. 파급으로 함께 재생성했더라도
내용이 안 바뀐 문서의 버전은 올리지 않는다.

## 근거 표기 — 무엇의 몇 버전으로 만들었나

산출물 머리말에 **자기가 근거로 삼은 상위 산출물의 버전**을 적는다.

```markdown
# AN-03 기능명세서 — {사업명}

> 생성: /gx-기능명세서 · 2026-09-10 14:20
> 근거: AN-02 v2.0

## 개정이력
```

| 산출물 | 근거로 적는 것 |
|--------|--------------|
| AN-02 요구사항정의서 | 없음 — RFP 가 근거이고 버전이 없다 |
| AN-03 기능명세서 | `AN-02` |
| DE-08 테이블정의서 | `AN-03`. DDL 이 있으면 `AN-03 v2.0 · DDL {파일명}` |
| DE-13 단위테스트계획서 | `AN-03 · DE-08`. 비기능 케이스가 있으면 `AN-02` 도 |
| AN-05 추적매트릭스 | **넷 전부** — `AN-02 · AN-03 · DE-08 · DE-13` |

**왜 필요한가.** 산출물은 낱개로도 만들 수 있어서, 요구사항정의서만 고치면
나머지 넷이 옛 값으로 남는다. ID 는 그대로라 **추적매트릭스가 초록이다** —
끊긴 것이 아니라 낡은 것이라 누락 판정에 안 걸린다.

근거 버전을 적어 두면 **낡음이 파일에 그대로 드러난다.** AN-02 가 v3.0 인데
AN-03 머리말이 `AN-02 v2.0` 이면 그 사이의 변경이 안 따라온 것이다.

**상태를 기억에 두지 않고 파일에서 매번 다시 읽는다.** 「나중에 하겠다」를
저장할 필요가 없다. 어느 커맨드를 부르든 대조하면 같은 답이 나온다 —
세션이 바뀌어도, 다른 사람이 열어도 마찬가지다.

### 대조가 안 되는 경우

| 상황 | 판정 |
|------|------|
| 근거 파일이 없다 | **대조 불가.** 낡았다고 하지 않는다 |
| 근거 표기가 없다 (옛 파일) | **대조 불가.** 다음 개정 때 붙는다 |
| 근거 버전 = 상위 현재 버전 | **최신** |
| 근거 버전 < 상위 현재 버전 | **낡음** |
| 근거 버전 > 상위 현재 버전 | **이상.** 상위가 백업에서 되돌려졌을 수 있다. 사람에게 묻는다 |

**대조 불가를 낡음으로 처리하지 않는다.** 처음 만든 산출물과 옛 파일이 전부
빨강이 되면 경고가 소음이 되어 진짜 낡음을 가린다.

**한계 — 손으로 고치면 못 잡는다.** 사람이 파일을 직접 편집하면 버전이
안 올라가 대조가 헛돈다. 이건 원래도 개정이력이 안 남는 문제라 새 위험은 아니다.

## 마크다운 표현

산출물 마크다운 파일의 **맨 위**에 이 표를 둔다. `export-xlsx.py` 가 첫 시트로 만든다.

```
## 개정이력

| 버전 | 개정일 | 개정 사유 | 개정 내용 | 작성자 | 승인자 |
|------|--------|----------|----------|--------|--------|
| 1.0 | 2026.09.03 | 신규 | 최초 작성 | 구본승 | |
```
