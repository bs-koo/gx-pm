# DE-13 단위테스트계획서 양식

## 파일 형식
Excel (.xlsx)

## 시트 구성
1. **표지**
2. **개정이력**
3. **검사기준** — 검사 항목 정의
4. **단위테스트계획** — 본문 (화면별 검사기준 체크리스트)
5. **테스트케이스** — 화면별 상세 케이스 ← v1.5.0 추가

> **두 시트의 역할이 다르다.**
> - **단위테스트계획** 시트: 화면마다 27개 검사기준 중 무엇이 해당하는지 (= 무엇을 확인했나)
> - **테스트케이스** 시트: 검사기준마다 어떤 데이터로 어떤 결과를 기대하는지 (= 어떻게 확인했나)
>
> 검사기준 체크리스트만으로는 "권한(7) 적합"의 근거를 제3자가 재현할 수 없다.
> 감리의 검사기준서가 요구하는 **예상결과·판정기준**이 테스트케이스 시트에 들어간다.

## 테스트케이스 시트 컬럼 (v1.5.0 추가)

단위테스트계획 시트의 각 검사기준 항목을 **실행 가능한 케이스**로 분해한다.
컬럼 구성은 ISO/IEC/IEEE 29119-3 Test Case Specification을 공공 양식에 맞춘 것이다.

| 컬럼 | 설명 | 예시 |
|------|------|------|
| 화면ID | 대상 화면 | EHR_01_01_020 |
| 화면명 | | 운영자 권한 등록 |
| 단위테스트ID | 상위 단위테스트 | U_EHR_01_01_020 |
| **테스트케이스ID** | `TC_{화면ID}_{2자리}` | TC_EHR_01_01_020_03 |
| **요구사항ID** | 추적성 — 이 케이스가 검증하는 요구사항 | B-RE-001 |
| 검사기준 항목 | 어느 검사기준에 속하는 케이스인지 | 입력(2) 유효성 |
| **설계기법** | 케이스 도출에 쓴 기법 | 경계값분석 |
| **케이스 구분** | 정상 / 예외 / 경계 | 경계 |
| **사전조건** | 케이스 실행 전 갖춰져야 할 상태 | 관리자 로그인, 권한코드 `A001` 미등록 상태 |
| **입력 데이터** | 구체적인 입력값 | 권한명 = 51자 문자열 |
| **수행 절차** | 재현 가능한 단계 | 1. 등록 버튼 클릭 2. 권한명 입력 3. 저장 클릭 |
| **기대 결과** | 판정 기준이 되는 결과 | "권한명은 50자 이내로 입력하세요" 안내 후 저장 차단 |
| 우선순위 | High / Medium / Low | High |
| 실행결과 | 적합 / 부적합 / 점검제외 (결과서에서 기입) | (계획서는 공란) |
| 점검제외 사유 | 판정이 점검제외일 때 필수 | (계획서는 공란) |
| **결함ID** | 부적합 시 DF-01 참조 | (계획서는 공란) |
| 수행자 | | (계획서는 공란) |
| 수행일 | | (계획서는 공란) |

### 케이스 구분 3종

| 구분 | 정의 | 최소 요구 |
|------|------|---------|
| **정상** | 유효한 입력으로 정상 처리되는 흐름 | 검사기준 항목당 1건 |
| **예외** | 무효한 입력·권한 없음·중복 등 거부되어야 하는 흐름 | 입력/수정/삭제 항목당 1건 이상 |
| **경계** | 경계값에서의 동작 (최소·최대·초과·미만) | 길이·범위 제약이 있는 항목마다 |

> **정상 케이스만 있는 테스트케이스 시트는 반려 대상이다.** 예외·경계가 없으면
> "정상 동작만 확인하고 검증을 끝냈다"는 뜻이 되어 감리에서 검증 충분성 지적을 받는다.

### 설계기법 → 케이스 도출 규칙

| 설계기법 | 언제 쓰나 | 도출되는 케이스 |
|---------|---------|--------------|
| **동등분할** | 입력값이 여러 그룹으로 나뉠 때 | 유효 그룹 대표값 1건 + 무효 그룹 대표값 1건 |
| **경계값분석** | 길이·수량·날짜·금액 제약이 있을 때 | 최소·최소-1·최대·최대+1 (4건) |
| **결정테이블** | 조건 조합에 따라 결과가 달라질 때 | 조건 조합별 1건 |
| **상태전이** | 데이터에 상태(등록→승인→반려)가 있을 때 | 유효 전이 + 무효 전이 각 1건 |
| **유스케이스** | 화면 여러 개를 거치는 흐름일 때 | 통합테스트로 이관 |

### 화면 유형별 기본 설계기법

| 화면 유형 | 적용 기법 | 최소 케이스 수 |
|----------|---------|-------------|
| 목록 화면 | 동등분할(검색조건 유효/무효), 경계값(페이징 첫·끝·범위초과, 날짜 시작=종료) | 6건 |
| 등록 화면 | 동등분할(필수/선택), 경계값(길이·범위), 결정테이블(필수값 조합), 예외(중복) | 8건 |
| 수정 화면 | 상태전이(상태별 수정 가능 여부), 경계값, 예외(동시 수정 충돌) | 6건 |
| 상세/조회 | 동등분할(존재/미존재 ID), 예외(권한 없는 데이터 접근) | 4건 |
| CRUD 통합 | 위 전부 | 12건 |
| API/배치 | 동등분할(파라미터), 경계값, 예외(오류 응답 코드) | 6건 |

> 최소 케이스 수는 **하한선**이다. 화면의 입력 항목 수와 분기 수에 따라 늘어난다.
