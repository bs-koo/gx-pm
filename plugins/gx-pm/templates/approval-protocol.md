# 승인 루프 프로토콜

모든 커맨드의 체크포인트에서 적용되는 공통 상호작용 규칙.
각 커맨드 파일에서 `[승인 루프 프로토콜 적용]`으로 참조한다.

**중요 — AskUserQuestion 도구 호출 필수**:

1. 모든 사용자 입력 요청은 반드시 **AskUserQuestion 도구**를 호출한다.
2. 텍스트로 질문을 출력하고 넘어가는 것은 **절대 금지**. AskUserQuestion을 호출해야 Claude가 사용자 응답을 기다린다.
3. 호출 시 반드시 다음 JSON 형식을 사용한다:

```json
AskUserQuestion({
  "question": "질문 내용을 여기에 작성한다.\n\n선택지가 있으면 번호로 나열한다."
})
```

4. 코드 블록(```)으로 질문 내용을 표시하되, 실제 사용자 입력은 **반드시 AskUserQuestion 도구 호출**로 받는다. 코드 블록 출력만으로 대체하지 않는다.
5. 커맨드/스킬 파일에 "AskUserQuestion 도구로 질문한다"라고 명시된 모든 지점에서 위 JSON 형식으로 호출한다.

---

## 0. 프로젝트 프로파일 로드 + 기존 산출물 감지

모든 커맨드의 워크플로우 시작 전에 다음 두 스킬을 순차 실행한다.

### 0-1. 프로젝트 프로파일 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다.

- 프로파일이 없으면 → `/프로젝트설정`을 먼저 실행하라고 안내 후 커맨드 종료
- 프로파일이 있으면 → 활성화 후 이후 단계에서 프로파일 정보를 자동 사용
  - `systemCode`, `prefix` → ID 접두어, 파일명에 사용
  - `framework`, `db` → 소스파일 구조, DDL 문법에 사용
  - `type` → 커맨드 워크플로우 분기에 사용
  - `author` → 산출물 작성자명에 사용
  - `assets.sourcePath` → 소스코드 스캔 경로에 사용

프로파일에 이미 있는 정보(시스템코드, 접두어 등)를 사용자에게 다시 물어보지 않는다.

### 0-2. 기존 산출물 감지

**detect-existing-artifact** 스킬로 활성 프로젝트 폴더에 해당 산출물 파일이 있는지 확인한다.

- 파일이 없으면 → 새로 생성 워크플로우 진행 (별도 안내 없음)
- 파일이 있으면 → AskUserQuestion으로 3가지 선택지 제공:

  1. **이어쓰기** — 기존 내용 유지 + 새 항목 추가 (ID 이어서 부여)
  2. **새로쓰기** — 기존 파일 backup/ 폴더에 백업 후 처음부터 재생성
  3. **열기** — 기존 내용 불러와서 특정 항목만 수정/삭제

상세 규칙: `skills/detect-existing-artifact/SKILL.md` 참조

### 0-3. 프로젝트 유형별 워크플로우 분기

프로파일의 `type`에 따라 해당 커맨드의 워크플로우가 분기된다:

| type | 분기 | 설명 |
|------|------|------|
| `new` (A) | 정방향 생성 | 기존 워크플로우 그대로 실행 |
| `enhancement` (B) | 기존 + 추가 | 기존 산출물 로드 → 이어쓰기 모드 기본값 |
| `documentation` (C) | 역방향 생성 | 소스코드/DB에서 산출물 역생성 |
| `change` (D) | 부분 갱신 | 변경 대상만 식별 → 해당 항목만 갱신 |

각 커맨드는 자신의 워크플로우 파일에서 유형별 분기 상세를 정의한다.

## 1. 시안/대안 감지 (detect-alternatives)

산출물 생성 **전**, 입력 데이터에서 다음 패턴을 감지한다:

| 패턴 | 예시 |
|------|------|
| N안 표기 | "1안", "2안", "제1안", "제2안" |
| 알파벳 안 | "A안", "B안" |
| 방안/대안 | "방안 1", "방안 2", "대안", "Alternative" |
| 선택 접속사 | "또는", "혹은"으로 연결된 상호배타적 선택지 |
| 섹션 마커 | 제목에 "(대안)", "(선택)", "(옵션)" 포함 |

감지되면 **AskUserQuestion**으로 선택을 요청한다:

```json
AskUserQuestion({
  "question": "⚠ 시안 선택이 필요합니다\n\n  1안: {시안1 요약}\n  2안: {시안2 요약}\n\n어떤 시안으로 진행할까요? (1/2/병행)"
})
```

**규칙**: 사용자가 시안을 선택할 때까지 산출물 생성을 진행하지 않는다.
"병행" 선택 시에만 양쪽 모두를 산출물에 포함하되, 각 시안을 명확히 구분 표기한다.

## 2. 단계별 승인 절차

각 Step의 산출물 생성 후 다음 절차를 따른다:

### 2-1. 결과 표시

해당 단계의 산출물을 마크다운 표로 출력한다.

### 2-2. 승인 요청 (AskUserQuestion 필수)

산출물 표를 출력한 직후, **반드시 AskUserQuestion 도구를 호출**하여 사용자 응답을 대기한다.
텍스트로 "승인해주세요"라고 출력만 하고 넘어가는 것은 금지.

```json
AskUserQuestion({
  "question": "추출된 {산출물명} {N}건을 확인해주세요.\n\n승인하려면 '승인' 또는 'OK'를 입력하세요.\n수정하려면 변경할 내용을 입력하세요.\n\n수정 예시:\n• \"3번 행의 화면명을 'XX 관리'로 변경\"\n• \"5번 행 삭제\""
})
```

### 2-3. 수정 반영

사용자가 수정을 요청하면:
1. 피드백을 반영하여 표를 **재생성**
2. 변경된 부분을 간략히 안내 ("→ 3건 변경됨")
3. 다시 **AskUserQuestion**으로 승인을 요청 (2-2로 복귀)

### 2-4. 확정

사용자가 다음 중 하나를 말하면 해당 단계를 확정하고 다음으로 진행한다:
- "승인", "OK", "확인", "넘어가", "다음", "좋아", "ㅇㅋ"

**핵심 규칙**: 위 표현이 없으면 **절대로** 다음 단계로 진행하지 않는다.

---

## 3. 정보 수집 (AskUserQuestion 필수)

프로젝트 기본 정보, 프레임워크 선택 등 사용자 입력이 필요한 단계에서도
반드시 **AskUserQuestion 도구**를 사용한다.

```json
AskUserQuestion({
  "question": "프로젝트 기본 정보를 입력해주세요\n\n1. 시스템 코드: 영문 1자리(A~I) 또는 자유 코드\n2. 시스템 접두어: 화면ID용 2~4자리 영문\n3. 망 구분: (1) 내부망 (2) 외부망 (3) 혼재\n4. 작성자명: 감리 대응 담당자"
})
```

---

## 4. xlsx 추출

각 단계 승인 후, **AskUserQuestion**으로 xlsx 추출 여부를 묻는다:

```json
AskUserQuestion({
  "question": "승인된 산출물을 xlsx로 추출할까요?\n  1. xlsx 추출\n  2. 마크다운만 저장"
})
```

추출 시:
1. `utils/export-xlsx.py` 스크립트를 실행
2. 실제 공공 산출물 Excel 양식의 **컬럼 순서에 맞춰** 생성
3. 생성된 xlsx 파일 경로를 사용자에게 안내

---

## 5. 워크플로우 전체 규칙

1. **한 단계씩 진행**: Step N이 승인되어야 Step N+1을 시작한다
2. **되돌림 허용**: 사용자가 "Step 2로 돌아가줘" 등을 요청하면 해당 단계부터 재시작
3. **중단 허용**: 사용자가 "여기까지만" 등을 말하면 현재까지 확정된 내용을 저장
4. **컨텍스트 유지**: 이전 단계에서 승인된 데이터를 다음 단계에서 참조
5. **AskUserQuestion 필수**: 모든 사용자 입력/승인 요청은 반드시 AskUserQuestion 도구를 사용한다. 텍스트 출력만으로 대체하지 않는다.
