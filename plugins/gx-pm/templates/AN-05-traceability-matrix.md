## 핵심 규칙

- 하나의 요구사항에 **복수의 화면/프로그램/테스트**가 매핑될 수 있음
- 복수 매핑 시 셀 내 **줄바꿈(\n)으로 구분**
- 모든 요구사항은 최소 하나의 화면, 프로그램, 테스트에 매핑되어야 함
- 누락된 매핑은 감리 지적 대상

## 요구사항 구분별 매핑 규칙

**기능 요구사항과 비기능 요구사항은 채워지는 컬럼이 다르다.** 같은 기준으로 누락을 판정하면 오탐이 난다.

| 컬럼 | 기능 요구사항 | 비기능 요구사항 |
|------|-------------|---------------|
| 화면ID / 화면명 | **필수** | 해당없음 (`-`) |
| 프로그램ID / 프로그램명 | **필수** | 해당없음 (`-`) |
| 단위테스트 / 테스트케이스 수 | **필수** | 해당없음 (`-`) |
| 통합테스트 | **필수** | 선택 |
| **시스템테스트** | 선택 | **필수** |

> 종전에는 비기능 요구사항의 검증 칸이 통째로 비었다.
> **시스템테스트ID가 비기능 요구사항의 검증 근거**이며, 이 칸이 비면 감리에서
> "비기능 요구사항 검증 누락"으로 지적된다.

## 커버리지 판정

| 지표 | 산식 | 목표 |
|------|------|------|
| 기능 요구사항 화면 매핑률 | 화면 매핑된 기능 요구사항 ÷ 전체 기능 요구사항 | 100% |
| **비기능 요구사항 검증률** | 시스템테스트 연결된 비기능 요구사항 ÷ 전체 비기능 요구사항 | **100%** |
| 테스트케이스 커버리지 | TC가 1건 이상 있는 화면 ÷ 전체 화면 | 100% |
| 결함 종결률 | Closed 결함 ÷ (전체 결함 − Rejected) | TE-01 종료기준 참조 |
