# /프로젝트설정 — 프로젝트 프로파일 설정

프로젝트 상황과 기본 정보를 한 번 설정하면, 이후 모든 커맨드가 이 정보를 자동으로 활용합니다.
새 대화를 열어도 설정이 유지됩니다 (파일로 저장).

> **프로파일 스키마**: `templates/project-profile-schema.md` 참조

---

## 워크플로우

### Step 1: 기존 프로젝트 탐지

작업 폴더 자체 및 하위 디렉토리를 스캔하여 `profile.json`이 있는 프로젝트를 찾는다.

#### 기존 프로젝트가 있는 경우 [필수 중단점]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
기존 프로젝트 {N}건을 찾았습니다:

  1. {프로젝트명1} ({유형라벨}, 마지막 작업: {lastUsed})
  2. {프로젝트명2} ({유형라벨}, 마지막 작업: {lastUsed})
  ...
  ─────────────
  S. 선택한 프로젝트의 설정 변경
  N. 새 프로젝트 생성

어떤 프로젝트로 작업할까요?
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 번호 선택 → 해당 프로파일 활성화 후 종료
- S 선택 → 번호 선택 후 Step 3부터 설정 변경 (기존 값을 기본값으로 표시)
- N 선택 → Step 2로 진행

#### 기존 프로젝트가 없는 경우

바로 Step 2로 진행.

---

### Step 2: 프로젝트 유형 선택 [필수 중단점]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
이 프로젝트의 현재 상황은 무엇인가요?

  A. 신규 구축
     RFP/과업지시서만 있고, 코드도 산출물도 없습니다.
     요구사항 분석부터 설계까지 처음부터 시작합니다.

  B. 추가 개발
     운영 중인 시스템에 새로운 기능(화면, 테이블 등)을 추가합니다.
     기존 코드와 산출물은 그대로 유지하고, 새 것만 추가합니다.

  C. 산출물 정비
     개발은 끝났는데 산출물이 없거나, 실제 코드/DB와 맞지 않습니다.
     소스코드와 DB 스키마를 기준으로 산출물을 역생성하거나 정비합니다.

  D. 변경 관리
     운영 중인 시스템의 기존 화면/기능/테이블을 수정합니다.
     변경 대상만 식별하여 영향받는 산출물만 골라서 갱신합니다.

(A/B/C/D 입력)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

### Step 3: 기본 정보 입력 [필수 중단점]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
프로젝트 기본 정보를 입력해주세요:

  1. 프로젝트명: (예: 교육행정시스템 고도화)
  2. 시스템 코드: 영문 1자리(A~I) 또는 자유 코드
     → 요구사항ID, 통합테스트ID의 접두어로 사용됩니다
     → 예: B → B-RE-001, B-TE-001
  3. 시스템 접두어: 화면ID용 2~4자리 영문
     → 화면ID의 접두어로 사용됩니다
     → 예: EHR → EHR_01_01_010
  4. 프레임워크: (1) eGovFrame  (2) Spring Boot  (3) 기타
  5. DB: (1) Oracle  (2) PostgreSQL  (3) MySQL  (4) 기타
  6. 작성자명: 산출물에 표시될 담당자명
  7. 망 구분: (1) 내부망 전용  (2) 외부망 전용  (3) 혼재
     → 화면목록표의 망구분 기본값으로 사용됩니다
  8. 감리 일정: YYYY-MM-DD (없으면 "없음")

예시: 교육행정시스템 고도화, B, EHR, 1, 1, 홍길동, 3, 2026-06-15
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

### Step 4: 기존 자산 입력 (B/C/D 유형만) [필수 중단점]

A(신규 구축) 유형이면 이 단계를 건너뛴다.

#### 4-1. 소스코드 경로

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
소스코드 프로젝트의 로컬 경로를 입력해주세요.

  준비 방법:
    1. Git 레포를 로컬에 clone합니다
       git clone https://github.com/your-org/project.git
    2. clone된 폴더의 전체 경로를 입력합니다

  경로 예시:
    • Windows: D:\projects\education-system
    • Mac/Linux: /Users/hong/projects/education-system

  경로: ___________
  (소스코드가 없으면 "없음" 입력)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

소스 경로가 입력되면, 해당 경로가 실제로 존재하는지 확인한다.
존재하지 않으면 경로를 다시 확인해달라고 요청한다.

#### 4-2. DB 스키마 DDL

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
DB 스키마의 전체 DDL을 복사해서 붙여넣어 주세요.
(테이블 구조를 파악하여 테이블정의서 등을 자동 생성할 수 있습니다)

  [DataGrip에서 복사하기]
    1. 좌측 Database 패널에서 스키마(Schema) 우클릭
    2. SQL Scripts → Generate DDL to Clipboard
    3. 여기에 Ctrl+V로 붙여넣기

  [DBeaver에서 복사하기]
    1. 좌측 Database Navigator에서 스키마(Schema) 우클릭
    2. Generate SQL → DDL 선택
    3. 팝업 창에서 Ctrl+A(전체선택) → Ctrl+C(복사)
    4. 여기에 Ctrl+V로 붙여넣기
    ※ 또는: 스키마 우클릭 → Tools → Generate DDL

  (DB DDL이 없으면 "없음" 입력)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

DDL이 입력되면 프로젝트 폴더에 `ddl.sql`로 저장한다.

#### 4-3. 기존 산출물 경로

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
기존에 작성된 산출물(엑셀, 마크다운 등)이 있는 폴더 경로를 입력해주세요.

  경로 예시: D:\docs\ehr-artifacts

  (기존 산출물이 없으면 "없음" 입력)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

### Step 5: 소스코드 스캔 (소스 경로가 있는 경우)

소스 경로가 입력된 경우, **scan-source-index** 스킬로 Level 1 스캔을 실행한다:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
소스코드를 스캔 중입니다...

  스캔 결과:
    • Java 파일: {N}개
    • JSP/HTML: {N}개
    • XML (MyBatis 등): {N}개
    • 패키지 수: {N}개

  주요 패키지 구조:
    {패키지 트리 요약}

이 정보는 프로그램정의서, 인터페이스정의서 등의
역생성 시 활용됩니다.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

스캔 결과를 `source-index.json`으로 프로젝트 폴더에 저장한다.

---

### Step 6: 설정 확인 + 저장 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
프로젝트 설정을 확인해주세요:

  프로젝트명: {name}
  유형: {typeLabel}
  시스템코드: {systemCode} / 접두어: {prefix}
  프레임워크: {framework} / DB: {db}
  작성자: {author}
  감리 일정: {auditDate 또는 "없음"}

  소스코드: {sourcePath 또는 "없음"}
  DDL: {있음/없음}
  기존 산출물: {existingArtifacts 또는 "없음"}

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경할 내용 입력 (예: "시스템코드를 A로 변경")
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

승인 시:
1. 프로젝트명으로 폴더 생성 (없으면)
2. `profile.json` 저장
3. DDL이 있으면 `ddl.sql` 저장
4. `backup/`, `xlsx/` 폴더 생성

---

### Step 7: 다음 안내

유형에 따라 다음 단계를 안내한다:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✓ 프로젝트 설정이 완료되었습니다!

[A. 신규 구축인 경우]
  다음 커맨드로 산출물을 생성하세요:
  • /요구사항정의서 — RFP에서 요구사항 추출
  • /화면목록표 — 화면 설계

[B. 추가 개발인 경우]
  기존 산출물이 있다면 해당 커맨드에서 자동 감지합니다.
  • /요구사항정의서 — 새 요구사항 추가 (이어쓰기)
  • /화면목록표 — 새 화면 추가

[C. 산출물 정비인 경우]
  소스코드/DB를 기준으로 산출물을 역생성합니다.
  • /프로그램정의서 — 소스코드에서 프로그램 목록 역추출
  • /테이블정의서 — DDL에서 테이블정의서 역생성
  • /인터페이스정의서 — API 코드에서 인터페이스 역추출

[D. 변경 관리인 경우]
  변경 대상을 식별하여 산출물을 갱신합니다.
  • /요구사항정의서 — 변경 요구사항 추가
  • /추적매트릭스 — 변경 영향도 확인
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
