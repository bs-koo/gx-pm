# /gx-통합테스트시나리오 — DE-14 통합테스트시나리오 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-통합테스트시나리오.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 요구사항+화면 기반 E2E 시나리오 (기존)
- **B (추가 개발)**: 새 요구사항에 대한 시나리오만 추가
- **C (산출물 정비)**: 전체 화면 목록 기반으로 시나리오 역생성
- **D (변경 관리)**: 변경 기능에 영향받는 시나리오만 갱신

### Step 1: 입력 데이터 로드

- 이전 `/gx-요구사항정의서`, `/gx-화면목록표` 결과가 있으면 자동 로드
- 없으면 입력 요청

### Step 2: 정상 시나리오 생성

**generate-integration-test** 스킬 적용:
- 요구사항-화면 매핑으로 업무 흐름 그룹핑
- 통합테스트ID 부여 (`{시스템코드}-TE-{순번}`)
- **사전조건 작성** (계정·권한 / 선행 데이터 / 시스템 상태 / 환경)
- Step 분해 (사용자행위 → 시스템결과)
- 테스트 데이터 제안

### Step 3: 예외 흐름 시나리오 생성

업무 흐름의 성격에서 필수 예외를 자동 도출한다:

| 흐름 성격 | 필수 예외 |
|---------|---------|
| 권한이 나뉘는 업무 | 권한 없음 |
| 신청·접수 업무 | 중복 신청, 상태 위반(마감·기간 외) |
| 승인·반려 업무 | 상태 위반(이미 처리된 건 재처리) |
| 외부 연계 업무 | 연계 실패·타임아웃 |
| 결제·정산 업무 | 중복 결제, 결제 실패 후 롤백 |
| 파일 처리 업무 | 허용 외 확장자·용량 초과 |

**정상 시나리오 1건마다 최소 1건의 예외 시나리오를 별도 ID로** 만든다.

> 정상 흐름만 있는 통합테스트는 감리에서 검증 충분성 지적을 받는다.
> 예외가 0건이면 승인 요청 전에 자동 보강하고 보강 내역을 표시한다.

### Step 4: 시나리오 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
통합테스트 시나리오 {N}건을 확인해주세요. (정상 {N} / 예외 {N})

주요 확인:
1. 시나리오 그룹핑이 실제 업무 흐름과 일치하는지
2. 사전조건이 재현 가능한 수준인지 (어느 권한의 계정인지 포함)
3. 예외 시나리오가 실제로 차단되어야 하는 상황인지
4. 테스트 데이터가 현실적인지
5. 현업 검토를 받을지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "B-TE-003 사전조건에 '관리자 로그인' 추가"
• "외부 연계 타임아웃 시나리오 추가해줘"
• "테스트 데이터를 실제 운영 기준으로 변경"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

> **작성 주체 안내**: 통합테스트 시나리오는 업무 흐름을 아는 현업·운영 담당자와 합동 작성이 원칙이다.
> 개발자 단독 작성 시 예외 업무 흐름이 누락되기 쉬우므로, 최소한 시나리오 목록에 대해
> 현업 검토 이력을 남기도록 안내한다.

### Step 5: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-통합테스트시나리오.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```
