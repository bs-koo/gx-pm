# /gx-시스템테스트 — ST-01 계획서 / ST-02 결과서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.
> **양식**: `templates/ST-01-system-test.md` 참조

**비기능 요구사항을 검증하는 유일한 산출물**이다.
이 산출물이 없으면 비기능 요구사항의 추적매트릭스 검증 칸이 통째로 빈다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 파일을 확인한다.
- 계획서 → `{시스템코드}-시스템테스트계획서.md`
- 결과서 → `{시스템코드}-시스템테스트결과서.md`

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 요구사항에서 측정 항목 도출 (기존)
- **B (추가 개발)**: 새 비기능 요구사항의 항목만 추가
- **C (산출물 정비)**: 운영 중 시스템의 실측값을 목표치와 대조하여 결과서 역생성
- **D (변경 관리)**: 변경 영향을 받는 비기능 항목만 재측정

### Step 1: 모드 선택 [필수 중단점]

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
무엇을 작성할까요?
  1. ST-01 시스템테스트계획서 (측정 항목·목표치 정의)
  2. ST-02 시스템테스트결과서 (측정값 기입·판정)
```

계획서가 이미 있으면 2번을 기본값으로 제안한다.

### Step 2: 비기능 요구사항 로드

- 이전 `/gx-요구사항정의서` 결과에서 **구분="비기능"** 항목을 전건 추출
- `classify-requirements`가 부여한 비기능 유형(성능/보안/접근성/호환성/유지보수성/법적준수)을 사용
- 비기능 요구사항이 0건이면 안내 후 종료:

```
비기능 요구사항이 없습니다.

요구사항정의서에 성능·보안·접근성 등의 요구사항이 있는데 "기능"으로 분류되었을 수 있습니다.
/gx-요구사항정의서 를 다시 실행하여 분류를 확인해주세요.
```

### [계획] Step 3a: 측정 항목 전개

**generate-system-test** 스킬 적용:
- 요구사항 1건에 측정 항목이 여럿이면 항목별로 `{시스템코드}-ST-{순번}` 분리 부여
- 유형별 표준 측정 항목 적용
- 목표치는 **요구사항 원문 수치를 그대로** 사용

### [계획] Step 4a: 목표치 확정 [필수 중단점]

목표치가 확정되지 않은 항목을 표로 출력한 후, **AskUserQuestion 도구**로 확정을 요청한다:

```
목표치가 확정되지 않은 항목이 {N}건 있습니다.

| ID | 요구사항 | 측정 항목 | 제안 목표치 | 근거 |
|----|--------|---------|-----------|------|
| B-ST-005 | B-RE-020 안정적 운영 | 가용성 | 99.9% | 관례 |
| B-ST-006 | B-RE-021 신속한 조회 | 대용량 조회 | ? | 발주처 협의 필요 |

목표치를 확정해주세요. 협의가 필요하면 "협의"로 두시면 비고에 표시합니다.

⚠ 목표치가 없으면 결과서에서 판정이 불가능하여 자동 "점검제외"가 됩니다.
```

### [결과] Step 3b: 측정값 기입 [필수 중단점]

**AskUserQuestion 도구**로 측정값을 받는다:

```
측정값을 입력해주세요.

| ID | 측정 항목 | 목표치 | 측정값 | 판정 |
|----|---------|--------|--------|------|
| B-ST-001 | 동시접속 처리 | 500명 오류율 1% 미만 | ? | |
| B-ST-002 | 화면 응답시간 | 3초 이내 | ? | |

입력 형식:
  B-ST-001 | 520명 오류율 0.3% | 적합
  B-ST-005 | 점검제외 | 사유: 운영 유사 환경 미구축

점검제외 인정 사유: 환경 미준비 / 선행 기능 결함 / 외부 환경 변화 / 과업 범위 외
```

### [결과] Step 4b: 부적합 처리 — 결함 등록

부적합 판정이 나오면 **manage-defects** 스킬을 호출하여 결함ID를 발급한다.

> **보안 유형 부적합은 심각도를 Critical로 발급**한다 (P1 법적 필수 영역).

### Step 5: 증적 확인 [필수 중단점]

**AskUserQuestion 도구**로 증적 파일명을 받는다:

```
증적을 확인해주세요. 성능·보안은 증적이 없으면 미측정으로 간주됩니다.

| ID | 유형 | 필요 증적 | 파일명 |
|----|------|---------|--------|
| B-ST-001 | 성능 | JMeter 결과 리포트 | ? |
| B-ST-003 | 보안 | 취약점 진단 결과서 | ? |
```

### Step 6: 결과 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
시스템테스트 항목 {N}건을 확인해주세요.

비기능 요구사항 커버리지: {N}/{N} = {N}%
{미연결 {N}건이 있으면 목록 표시}

주요 확인:
1. 목표치가 요구사항 원문 수치와 일치하는지
2. 측정 방법이 실제 수행 가능한지 (도구·환경 확보)
3. 커버리지 미달분을 어떻게 처리할지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "B-ST-001 목표를 300명으로 하향. 근거: 2026-04-10 발주처 협의"
• "접근성은 자동진단만. 수동점검은 범위 외"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 7: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-시스템테스트계획서.md` 또는 `{시스템코드}-시스템테스트결과서.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```
