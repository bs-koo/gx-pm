# /gx-결함관리대장 — DF-01 결함관리대장 생성·갱신

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.
> **선행조건**: `templates/prerequisites.md` 의 이 커맨드 행을 따른다.
> **파이프라인**: `/gx-spec` 또는 `/gx-testplan` 에서 호출된 경우 `templates/pipeline-protocol.md` 의 규약을 따른다.
> **양식**: `templates/DF-01-defect-log.md` 참조

테스트 레벨(단위/통합/시스템/인수)과 무관하게 **모든 결함을 하나의 번호 체계로 관리**한다.
결과서의 부적합 항목은 결함ID로 이 대장을 참조한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-결함관리대장.md` 파일을 확인한다.
- 파일 있음 → **이어쓰기가 기본값** (결함은 누적되는 문서이므로 새로쓰기를 권하지 않는다)
- 파일 없음 → 새로 생성

**선행조건 검사** — `templates/prerequisites.md` 의 이 커맨드 행을 읽고:
- **하드 선행이 없으면**: 해당 선행 커맨드를 안내하고 **종료한다**. 추정으로 채우지 않는다.
- **소프트 선행이 없으면**: AskUserQuestion 으로 "그대로 진행 / 중단하고 준비" 를 묻는다.
  그대로 진행하면 산출물 비고에 "축약 생성" 을 남긴다.

파이프라인에서 호출된 경우 이 검사는 파이프라인이 이미 수행했으므로 **건너뛴다**.

모든 유형(A/B/C/D)에서 동일하게 동작한다.

### Step 1: 모드 선택 [필수 중단점]

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
무엇을 할까요?

  1. 결함 등록 — 새 결함을 대장에 추가
  2. 상태 갱신 — 기존 결함의 조치·재테스트 결과 반영
  3. 현황 조회 — 통계와 잔존 결함 목록 확인
  4. 종료기준 판정 — 다음 테스트 레벨 진입 가능 여부 확인
```

### [등록] Step 2a: 결함 입력

다음 두 경로 중 하나로 결함을 받는다.

**경로 A — 결과서에서 자동 연계**
`/gx-테스트결과서` 또는 `/gx-시스템테스트` 실행 중 부적합 판정이 나오면 자동으로 이 단계가 호출된다.
부적합 내역이 그대로 전달된다.

**경로 B — 직접 입력**
**AskUserQuestion 도구**로 다음 형식을 안내한다:

```
결함을 입력해주세요.

입력 형식:
  발견단계 | 발견 테스트ID | 화면ID | 결함 제목 | 결함 내역

예시:
  통합 | B-TE-003 | EHR_03_01_020 | 마감 후 신청 가능 | 신청 마감일이 지난 과정에 신청이 완료 처리됨

여러 건은 줄바꿈으로 구분해서 입력하세요.
```

### [등록] Step 3a: 중복 판별 [조건부 중단점]

**manage-defects** 스킬이 기존 결함과의 중복을 판별한다. 중복 의심 시 **AskUserQuestion 도구**로 확인:

```
{시스템코드}-DF-007과 동일한 원인으로 보입니다.

  기존: B-DF-007 "중복 검사 미작동" (화면 EHR_01_01_020, 상태 Assigned)
  신규: B-TE-003 "과정 등록 시 중복 검사 미작동"

  1. 기존 결함에 병합 (발견 위치만 추가)
  2. 별개 결함으로 등록 (새 ID 발급)
```

### [등록] Step 4a: 심각도·우선순위 판정 [필수 중단점 — 승인 루프]

**manage-defects** 스킬이 키워드로 1차 판정한 결과를 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
결함 {N}건의 심각도·우선순위를 확인해주세요.

| 결함ID | 제목 | 심각도 | 우선순위 | 판정 근거 |
|--------|------|--------|--------|---------|
| B-DF-008 | 마감 후 신청 가능 | Critical | High | 데이터 정합성 훼손 (자동 격상) |
| B-DF-009 | 목록 정렬 오동작 | Minor | Medium | 우회 가능 |

⚠ 자동 격상 규칙 적용: 보안·개인정보·데이터 정합성·물리삭제 → Critical

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "B-DF-009는 Trivial. 표시 순서만 문제"
• "B-DF-008 담당자 박개발"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### [등록] Step 5a: 재현 절차 보강 [조건부 중단점]

재현 절차가 부실한 결함이 있으면 **AskUserQuestion 도구**로 보강을 요청한다:

```
재현 절차가 부족한 결함이 {N}건 있습니다.
제3자가 그대로 따라할 수 있어야 합니다.

  B-DF-009 "목록 정렬 오동작"
  현재: "정렬이 안 됨"
  필요: 계정·권한 / 진입 경로 / 입력값 / 조작 / 실제 결과

보강해주세요. (건너뛰려면 "생략")
```

### [갱신] Step 2b: 상태 갱신

**AskUserQuestion 도구**로 상태 변경을 받는다:

```
상태를 갱신할 결함을 입력해주세요.

현재 진행중 결함:
| 결함ID | 제목 | 심각도 | 상태 | 담당자 |
|--------|------|--------|------|-------|
| B-DF-007 | 중복 검사 미작동 | Major | Assigned | 김개발 |
| B-DF-008 | 마감 후 신청 가능 | Critical | Open | — |

입력 형식:
  B-DF-007 | Fixed | 원인: 쿼리 조건절 누락 | 조치: USE_YN 조건 추가 | 2026-04-11 | 김개발
  B-DF-007 | Closed | 재테스트 적합 | 2026-04-12 | 홍길동
```

상태 전이 시 필수 입력을 검증한다:
- → Fixed: 원인·조치내역·조치일·조치자
- → Closed: 재테스트 결과=적합·재테스트일·재테스트자
- → Deferred: **발주처/PM 승인 근거**
- → Rejected: **판단 사유**

### [현황] Step 2c: 통계 출력

`manage-defects` 스킬의 통계를 출력한다 (심각도별·상태별·발견단계별·조치율).

### [판정] Step 2d: 종료기준 판정

총괄 테스트계획서(TE-01) §7의 종료기준과 대조하여 판정한다.
TE-01이 없으면 기본값(Critical 0 · Major 0 · Minor 조치율 90%)을 사용하고 안내한다.

```
[종료기준 판정]

| 기준 | 목표 | 현재 | 판정 |
|------|------|------|------|
| Critical 잔존 | 0건 | 1건 | **미충족** |
| Major 잔존 | 0건 | 2건 | **미충족** |
| Minor 조치율 | 90% 이상 | 94% | 충족 |

종합: **다음 레벨 진입 불가**

미조치 Critical: B-DF-008
미조치 Major: B-DF-007, B-DF-012
```

미충족 시 **AskUserQuestion 도구**로 다음을 묻는다:

```
종료기준을 충족하지 않습니다.

  1. 결함 조치 후 재판정
  2. PM 승인으로 진입 (사유가 대장에 기록됩니다)
```

### Step 6: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-결함관리대장.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출 (대장 + 통계)
  2. 마크다운만 저장
```

### Step 7: 다음 제안

- 종료기준 충족: "`/gx-테스트결과서` 로 다음 레벨 결과를 기입할까요?"
- "`/gx-추적매트릭스` 로 잔존 결함이 반영된 과업완료여부를 확인할까요?"
