# /gx-요구사항정의서 — AN-02 요구사항정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-요구사항정의서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 정방향 — RFP에서 요구사항 추출 (기존 워크플로우)
- **B (추가 개발)**: 기존 요구사항정의서에 새 요구사항 이어쓰기
- **C (산출물 정비)**: 소스코드 구조에서 기능 목록을 역추출하여 요구사항으로 정리
- **D (변경 관리)**: 변경 요구사항만 추출하여 기존 목록에 추가

### Step 1: 시안/대안 감지 [필수 중단점]

**detect-alternatives** 스킬로 입력 문서를 스캔. 시안이 감지되면 사용자 선택을 요청한다. AskUserQuestion으로 선택을 받는다. 응답 전까지 다음 단계로 진행하지 않는다.

### Step 2: 요구사항 추출 + 분류

**extract-requirements** → **classify-requirements** 스킬 순차 적용:

추출 규칙:
- "ㅇ", "o"로 시작하는 기능 항목 식별
- "~해야 한다", "~를 제공한다", "~기능을 구현한다" 패턴 식별
- 번호가 매겨진 기능 목록, "기능 요구사항"/"비기능 요구사항" 섹션 항목

분류 규칙:
- 기능/비기능 분류, 대분류/중분류/소분류 자동 분류
- 요구사항ID 부여: `{시스템코드}-RE-{3자리순번}` (예: B-RE-001)
- 수용여부 초안: 명확한 기능→수용, 모호/범위초과→부분수용+사유, 기술적 불가→불가+사유

### Step 3: 요구사항 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
추출된 요구사항 {N}건을 확인해주세요.

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "RE-003과 004를 하나로 합쳐줘"
• "비기능에 보안 항목 추가"
• "5번 수용여부를 부분수용으로"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 4: 우선순위 부여 (선택)

"요구사항에 우선순위를 부여할까요?" → 승인 시 **prioritize-si** 스킬 적용:
- 공공/SI 5단계: P1 법적필수 → P2 감리필수 → P3 과업명시 → P4 발주처요청 → P5 품질개선
- 영향도(높/중/저) + 시급도 매트릭스
- 감리 지적 고위험 항목 자동 식별

### Step 5: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-요구사항정의서.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```
