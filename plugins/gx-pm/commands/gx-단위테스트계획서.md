# /gx-단위테스트계획서 — DE-13 단위테스트계획서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.
> **선행조건**: `templates/prerequisites.md` 의 이 커맨드 행을 따른다.
> **파이프라인**: `/gx-spec` 에서 호출된 경우 `templates/pipeline-protocol.md` 의 규약을 따른다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-단위테스트계획서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

**선행조건 검사** — `templates/prerequisites.md` 의 이 커맨드 행을 읽고:
- **하드 선행이 없으면**: 해당 선행 커맨드를 안내하고 **종료한다**. 추정으로 채우지 않는다.
- **소프트 선행이 없으면**: AskUserQuestion 으로 "그대로 진행 / 중단하고 준비" 를 묻는다.
  그대로 진행하면 산출물 비고에 "축약 생성" 을 남긴다.

파이프라인에서 호출된 경우 이 검사는 파이프라인이 이미 수행했으므로 **건너뛴다**.

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: AN-03 전체 기능에서 케이스 도출 (기존 워크플로우)
- **B (추가 개발)**: 기존 단위테스트계획서에 새 기능의 케이스만 이어서 추가
- **C (산출물 정비)**: AN-03 기능명세서가 없으면 `/gx-기능명세서`를 먼저 안내한다 —
  화면·소스에서 직접 케이스를 만들지 않는다. 기능 축으로 바뀌면서 AN-03 이 유일한 입력이다
- **D (변경 관리)**: 변경된 기능의 케이스만 갱신

### Step 1: AN-03·DE-08·AN-02 로드

- 이전 `/gx-기능명세서` 결과가 있으면 자동 로드. 없으면 AN-03 입력을 요청
- DE-08 테이블정의서가 있으면 함께 로드 (경계·필수값 제약의 우선 출처)
- AN-02 요구사항정의서를 로드해 비기능 요구사항 목록을 확보

### Step 2: 기능별 케이스 도출

**generate-unit-test-plan** 스킬 적용:
- `templates/DE-13-unit-test-plan.md` 의 케이스 도출 규칙표를 기능마다 기계적으로 적용
  (정상 1 / 제약당 경계 2 / 필수항목당 예외 1 / 분기당 예외 1 / 롤백 1)
- 설계기법 적용은 **design-test-cases** 스킬의 내부 규칙을 따른다 (컬럼으로 내보내지 않는다)
- 제약이 AN-03 과 DE-08 에서 다르면 DE-08 을 우선한다
- `연계요구사항ID` 는 `연계기능ID` 를 경유해 AN-03 에서 자동으로 채운다 — 사용자에게 묻지 않는다
- 테스트ID 부여 (`UT-{3자리}`)

### Step 3: 비기능 요구사항 케이스 반영

AN-02 에서 어느 기능에도 걸리지 않은 요구사항을 찾아 `연계기능ID` 공란 행으로 만든다.
측정 조건·목표치가 요구사항 상세내용에 없으면 그 자리에서 사용자에게 확인한다.

### Step 4: 충분성 검증

- **정상 케이스만 있는 기능이 있으면 차단**하고 자동 보강한다
- 필수 항목이 있는데 미입력 예외가 없으면 자동 보강한다
- 길이·범위 제약이 있는데 경계 케이스가 없으면 자동 보강한다
- 보강 내역을 다음 검토 단계에서 함께 표시한다

### Step 4-1: ID 승계

직전 버전이 `backup/` 에 있으면 **reconcile-ids** 스킬로 테스트ID 를 승계한다.
백업본이 없으면 첫 생성이므로 건너뛴다.

### Step 5: 케이스 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
기능 {N}건에서 테스트 케이스 {N}건을 확인해주세요.

주요 확인:
1. 경계값이 실제 컬럼 길이·업무 제약과 맞는지 (DE-08 우선)
2. 예외 케이스의 사후조건에 "변화 없음"이 정확히 표시됐는지
3. 정상 케이스만 있었던 기능 {N}건의 보강 내역이 맞는지
4. 비기능 요구사항 {N}건이 연계기능ID 공란 행으로 빠짐없이 반영됐는지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "권한명 길이는 50이 아니라 100이야"
• "FN-004에 동시 수정 충돌 케이스 추가"
• "UT-010은 UT-003에 의존하지 않아, 의존성 지워줘"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 6: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-단위테스트계획서.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```

### Step 7: 다음 제안

- "`/gx-추적매트릭스` 로 테스트 커버리지를 확인할까요?"
- 비기능 요구사항이 남아 있으면: "`/gx-요구사항정의서` 의 비기능 행을 확인해 주세요 —
  비기능은 `연계기능ID` 공란 행으로 이 계획서 안에서 검증합니다."
- DE-08 테이블정의서가 없으면: "`/gx-테이블정의서` 로 컬럼 제약을 먼저 확정하면
  경계값의 근거가 생깁니다."
