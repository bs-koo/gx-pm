# /gx-프로그램정의서 — DE-05 프로그램정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.
> **선행조건**: `templates/prerequisites.md` 의 이 커맨드 행을 따른다.
> **파이프라인**: `/gx-spec` 또는 `/gx-testplan` 에서 호출된 경우 `templates/pipeline-protocol.md` 의 규약을 따른다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-프로그램정의서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

**선행조건 검사** — `templates/prerequisites.md` 의 이 커맨드 행을 읽고:
- **하드 선행이 없으면**: 해당 선행 커맨드를 안내하고 **종료한다**. 추정으로 채우지 않는다.
- **소프트 선행이 없으면**: AskUserQuestion 으로 "그대로 진행 / 중단하고 준비" 를 묻는다.
  그대로 진행하면 산출물 비고에 "축약 생성" 을 남긴다.

파이프라인에서 호출된 경우 이 검사는 파이프라인이 이미 수행했으므로 **건너뛴다**.

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 정방향 — 화면목록표에서 프로그램 추정 (기존 워크플로우)
- **B (추가 개발)**: 기존 프로그램정의서에 새 화면의 프로그램만 추가
- **C (산출물 정비)**: **reverse-scan-source** 스킬로 소스코드에서 프로그램 목록 역추출
- **D (변경 관리)**: 변경 대상 프로그램만 갱신

### Step 1: 화면목록표 로드

- 이전 `/gx-화면목록표` 결과가 있으면 자동 로드
- 없으면 화면목록표 입력을 요청

### Step 2: 시안/대안 감지 [필수 중단점]

**detect-alternatives** 스킬 적용. 프로그램 구조에 대안이 있으면 선택을 요청한다:
- URL 패턴 (`.do` 확장자 vs REST 경로)
- 화면 없는 엔진·배치를 프로그램으로 등재할지 여부
- 공통 모듈 분리 방식

AskUserQuestion으로 선택을 받는다. 응답 전까지 다음 단계로 진행하지 않는다.

### Step 3: 프로그램정의서 생성

**generate-program-list** 스킬 적용:
- 화면ID → 프로그램ID 매핑 (PG_{화면ID})
- URL 패턴 생성 (프레임워크별)
- 소스파일 구조 매핑 (Controller/Service/DAO/SQL/JSP)

### Step 4: 프로그램 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
프로그램 {N}개 구성을 확인해주세요.

주요 확인:
1. PG_{화면ID} 규칙을 따르는지
2. 화면 없는 엔진/서비스 프로그램이 누락되지 않았는지
3. URL 패턴이 프로젝트 규칙과 맞는지
4. 소스파일 구조가 맞는지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "산출 엔진은 화면 없는 서비스로 분리해줘"
• "URL을 /api/v2/ 패턴으로 변경"
• "배치 프로그램 1건 추가"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 5: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-프로그램정의서.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```
