# /추적매트릭스 — AN-05 추적매트릭스 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-추적매트릭스.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 전체 생성 (기존)
- **B (추가 개발)**: 기존 매트릭스에 새 요구사항 행만 추가
- **C (산출물 정비)**: 소스코드/DB 기반으로 역추적하여 매트릭스 역생성
- **D (변경 관리)**: 변경 대상 ID 체인만 갱신

### Step 1: 추적 모드 결정

- 특정 ID 입력 → 단건 추적
- "전체" → 전체 교차 검증
- 없으면 선택 요청

### [단건] Step 2a: 단건 ID 추적

**id-trace** 스킬: ID 유형 자동 판별 후 양방향 추적 체인 출력. 누락 매핑은 ⚠ 표시.

### [전체] Step 2b: 전체 교차 검증

모든 산출물 데이터 로드 → 전체 추적 체인 확인 → 누락 리포트 생성.

### Step 3: 추적 결과 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
추적매트릭스 결과를 확인해주세요.

추적 완료: {N}건 / 누락: {M}건

주요 확인:
1. 누락이 실제 누락인지, 의도적 미매핑인지
2. 비기능 요구사항은 화면 매핑 불필요할 수 있음

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "RE-017은 비기능이라 화면 매핑 불필요. OK로"
• "RE-005에 화면 SC-003 연결해줘"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-추적매트릭스.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```

### Step 5: 다음 제안

누락이 있으면 해당 산출물 생성 커맨드 제안.
