# /통합테스트시나리오 — DE-14 통합테스트시나리오 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 1: 입력 데이터 로드

- 이전 `/요구사항정의서`, `/화면목록표` 결과가 있으면 자동 로드
- 없으면 입력 요청

### Step 2: 시나리오 생성

**generate-integration-test** 스킬 적용:
- 요구사항-화면 매핑으로 업무 흐름 그룹핑
- 통합테스트ID 부여 ({시스템코드}-TE-{순번})
- Step 분해 (사용자행위 → 시스템결과 → 판정기준)
- 테스트 데이터 제안

### Step 3: 시나리오 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 통합테스트 시나리오 {N}건을 확인해주세요

주요 확인:
1. 시나리오 그룹핑이 실제 업무 흐름과 일치하는지
2. 각 시나리오의 사전조건이 적절한지
3. 테스트 데이터가 현실적인지
4. 누락된 E2E 시나리오가 있는지

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "TE-003 사전조건에 '관리자 로그인 필요' 추가"
  • "실패 케이스 시나리오 추가해줘"
  • "테스트 데이터를 실제 운영 기준으로 변경"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-통합테스트시나리오.md`

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
