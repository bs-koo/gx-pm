# /gx-테이블정의서 — DE-08 테이블정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-테이블정의서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 역방향 선택 시 **generate-erd-guide** 스킬 적용, 정방향은 DDL 입력
- **B (추가 개발)**: DDL 붙여넣기 → 새 테이블만 기존에 추가
- **C (산출물 정비)**: profile의 DDL(ddl.sql) 자동 로드, 또는 소스코드의 Entity 클래스(@Entity, @Table) 스캔으로 역생성 (**convert-ddl-to-tablespec** 스킬의 Entity 역추출 경로)
- **D (변경 관리)**: 변경 테이블 DDL만 입력하여 해당 테이블만 갱신

### Step 1: 시안/대안 감지 [필수 중단점]

**detect-alternatives** 스킬 적용. 데이터 모델에 대안이 있으면 선택을 요청한다:
- 정규화 수준 (정규화 vs 반정규화)
- 이력 관리 방식 (별도 `_HIST` 테이블 vs 컬럼 내 버전)
- 코드 관리 방식 (공통코드 테이블 vs 개별 코드 테이블)

역방향(요구사항 → ERD)일 때 특히 중요하다. 정방향(DDL 입력)이면 대개 감지되지 않고 넘어간다.

AskUserQuestion으로 선택을 받는다. 응답 전까지 다음 단계로 진행하지 않는다.

### Step 2: 방향 결정

- DDL 입력 → 정방향 (DDL → 테이블정의서)
- "역방향" → 역방향 (요구사항 → DDL)
- 없으면 선택 요청: (1) DDL → 테이블정의서  (2) 요구사항 → ERD + DDL

### [정방향] Step 2a: DDL → 테이블정의서

**convert-ddl-to-tablespec** 스킬: DDL 파싱, COMMENT에서 한글명 추출, 없으면 추론.

### [역방향] Step 2b: 요구사항 → DDL

**generate-erd-guide** 스킬: 엔터티 식별, 관계 도출, DDL + 테이블정의서 초안 생성.

### Step 3: 테이블 구조 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
테이블 {N}개 정의를 확인해주세요.

주요 확인:
1. 한글 컬럼명이 올바른지
2. 데이터타입과 길이가 적절한지
3. PK/FK 관계가 맞는지
4. 공통 컬럼(등록일시, 수정일시 등)이 빠지지 않았는지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "USER_NM 컬럼명을 '사용자명'으로"
• "STN_ID 길이를 20으로"
• "API_CALL_LOG에 IP_ADDR 컬럼 추가"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-테이블정의서.md` / (역방향 시) `{시스템코드}-DDL.sql`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출 (테이블별 시트 분리)
  2. 마크다운만 저장
```
