# /gx-테이블정의서 — DE-08 테이블정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.
> **선행조건**: `templates/prerequisites.md` 의 이 커맨드 행을 따른다.
> **파이프라인**: `/gx-spec` 또는 `/gx-testplan` 에서 호출된 경우 `templates/pipeline-protocol.md` 의 규약을 따른다.

**이 커맨드는 역생성 전용이다.** 요구사항에서 테이블을 추론해 만들지 않는다 — 이유는
`templates/DE-08-table-definition.md` 의 "이 문서는 역생성 문서다" 절을 참조한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-테이블정의서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

**선행조건 검사** — `templates/prerequisites.md` 의 이 커맨드 행을 읽고:
- **하드 선행이 없으면**: 해당 선행 커맨드를 안내하고 **종료한다**. 추정으로 채우지 않는다.
- **소프트 선행이 없으면**: AskUserQuestion 으로 "그대로 진행 / 중단하고 준비" 를 묻는다.
  그대로 진행하면 산출물 비고에 "축약 생성" 을 남긴다.

파이프라인에서 호출된 경우 이 검사는 파이프라인이 이미 수행했으므로 **건너뛴다**.

### Step 1: DDL 로드 → 매핑 → 표준 판정 → 승인 게이트

**convert-ddl-to-tablespec** 스킬을 적용한다. 스킬의 처리 절차(기존 스키마 로드 →
기능명세 입력항목 매핑 → 기존 컬럼 표준 검증 → 신규 컬럼 표준 도출 → 승인 게이트 →
개정이력)를 그대로 따른다.

프로파일에 `ddl.sql` 이 없으면 스킬의 "DDL 복사 방법 안내"로 DDL 입력을 요청한다.
DDL 이 전혀 없으면 기존 스키마 없음으로 보고 전건을 신규로 취급한다.

### Step 2: 승인 [필수 중단점 — 승인 루프]

스킬이 출력한 `[신규 · 승인 필요]` / `[기존 · 변경하지 않음]` / `[제약 불일치]` 블록을
그대로 보여주고, **AskUserQuestion 도구**로 승인을 요청한다.

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.
신규 컬럼의 표준명 결정(Step 4 의 `decisionRequired`, `dataTypeCandidates`)은 이 게이트로
이월하지 않는다 — `templates/pipeline-protocol.md` §이월 금지 항목.

### Step 3: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-테이블정의서.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출 (테이블별 시트 분리)
  2. 마크다운만 저장
```
