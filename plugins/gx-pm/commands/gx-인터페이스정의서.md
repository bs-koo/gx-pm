# /gx-인터페이스정의서 — 인터페이스정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-인터페이스정의서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 정방향 — 요구사항에서 연동 키워드 추출 (기존 워크플로우)
- **B (추가 개발)**: 새 연동 요구사항만 추출하여 기존에 추가
- **C (산출물 정비)**: **reverse-scan-interfaces** 스킬로 소스코드의 API 호출에서 역추출
- **D (변경 관리)**: 변경 인터페이스만 갱신

### Step 1: 요구사항 로드

- 이전 `/gx-요구사항정의서` 결과가 있으면 자동 로드
- 연동 관련 요구사항 자동 식별 (API, SSO, 연계, 외부 등 키워드)

### Step 2: 시안/대안 감지 [필수 중단점]

**detect-alternatives** 스킬 적용. 연동 방식에 대안이 있으면 선택을 요청한다:
- REST API vs SOAP vs 파일 연동
- 실시간 vs 배치 동기화
- 직접 연동 vs 중계 서버 경유

AskUserQuestion으로 선택을 받는다. 응답 전까지 다음 단계로 진행하지 않는다.

### Step 3: 인터페이스 생성

**generate-interface-spec** 스킬 적용:
- 인터페이스ID 부여 (IF-{시스템코드}-{순번})
- 송신/수신 시스템, 연동방식, 연동주기 정의
- 요청/응답 데이터 항목 정의
- 오류 처리 정의

### Step 4: 인터페이스 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
인터페이스 {N}건을 확인해주세요.

주요 확인:
1. 외부 시스템 식별이 정확한지
2. 연동방식(REST/SOAP/파일)이 맞는지
3. 요청/응답 데이터 항목이 충분한지
4. 오류 처리가 적절한지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "IF-002의 연동방식을 SOAP에서 REST로 변경"
• "응답 데이터에 에러코드 항목 추가"
• "타임아웃을 10초로 변경"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 5: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-인터페이스정의서.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```
