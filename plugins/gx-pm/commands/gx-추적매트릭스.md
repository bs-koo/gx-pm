# /gx-추적매트릭스 — AN-05 추적매트릭스 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.
> **선행조건**: `templates/prerequisites.md` 의 이 커맨드 행을 따른다.
> **파이프라인**: `/gx-spec` 또는 `/gx-testplan` 에서 호출된 경우 `templates/pipeline-protocol.md` 의 규약을 따른다.

## 이 커맨드는 대조기를 돌린다

AN-05 는 새 정보를 만들지 않는다. 앞서 만든 AN-02(요구사항정의서)·AN-03(기능명세서)·
DE-08(테이블정의서)·DE-13(단위테스트계획서) 를 읽어 끊긴 곳을 찾는 것이 본업이고,
9컬럼 표는 그 부산물이다. 컬럼 구조와 누락 판정 기준의 정본은
`templates/AN-05-traceability-matrix.md` 다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/gx-프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-추적매트릭스.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

**선행조건 검사** — `templates/prerequisites.md` 의 이 커맨드 행을 읽고:
- **하드 선행이 없으면**: 해당 선행 커맨드를 안내하고 **종료한다**. 추정으로 채우지 않는다.
- **소프트 선행이 없으면**: AskUserQuestion 으로 "그대로 진행 / 중단하고 준비" 를 묻는다.
  그대로 진행하면 산출물 비고에 "축약 생성" 을 남긴다.

파이프라인에서 호출된 경우 이 검사는 파이프라인이 이미 수행했으므로 **건너뛴다**.

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 전체 생성 (기존)
- **B (추가 개발)**: 기존 매트릭스에 새 요구사항 행만 추가
- **C (산출물 정비)**: 소스코드/DB 기반으로 역추적하여 매트릭스 역생성
- **D (변경 관리)**: 변경 대상 ID 체인만 갱신

### Step 1: 추적 모드 결정

- 특정 ID 입력 → 단건 추적
- "전체" → 전체 교차 검증
- 없으면 선택 요청

### [단건] Step 2a: 단건 ID 추적

**id-trace** 스킬: ID 유형(요구사항ID·기능ID·테스트ID) 자동 판별 후 양방향 추적 체인 출력.
누락 매핑은 ⚠ 표시.

### [전체] Step 2b: 전체 교차 검증 + AN-05 생성

**trace-requirements** 스킬로 AN-05 추적매트릭스를 생성·갱신한다:
- 가용 산출물 확인 (AN-02 필수 / AN-03·DE-08·DE-13 은 있는 만큼만 — 없으면 해당 열 공란)
- AN-02 요구사항마다 AN-03 을 `연계요구사항ID` 로 역조회해 연계된 기능 단위로 행을 나눈다
  (0건이면 기능 칸을 비운다)
- 기능이 있는 행은 DE-08·DE-13 을 기능ID 로 역조회해 테이블·컬럼과 테스트 수·Pass/Fail 을 채운다
- 기능이 없는 행은 DE-13 에서 `연계기능ID` 공란 + `연계요구사항ID` 일치 행으로 비기능 테스트를 확인한다
- 9컬럼 표를 조립한 뒤 `templates/AN-05-traceability-matrix.md` 의 누락 판정표를 순서대로 적용한다

**id-trace** 스킬로 전체 교차 검증을 수행한다:
- 누락 7유형 탐지 (기능 미도출 · 테스트 미작성 · 비기능 검증 누락 · 예외 케이스 없음 ·
  미수행 · 실패 잔존 · 삭제 미정리)
- 요구사항 수 대비 유형별 건수 집계

### Step 3: 추적 결과 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
추적매트릭스 결과를 확인해주세요.

전체 요구사항 {N}건 / 누락 {M}건

누락 유형별:
  기능 미도출        {N}건
  테스트 미작성       {N}건
  비기능 검증 누락    {N}건
  예외 케이스 없음    {N}건
  미수행             {N}건
  실패 잔존          {N}건
  삭제 미정리         {N}건

주요 확인:
1. 누락이 실제 누락인지, 아직 진행 중이라 그런 것인지
2. 비기능 요구사항은 기능ID 없이 DE-13 비기능 테스트로만 검증됩니다 — 기능ID 공란 자체는 누락이 아닙니다
3. "예외 케이스 없음" 은 확정 판정이 아니라 확인 요청입니다 — 정말 예외 흐름이 없는 기능인지 봐주세요

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "REQ-032는 FN-014로 연계돼 있는데 놓쳤어"
• "REQ-045는 비기능이 맞아. 방금 실행한 테스트 결과로 미수행을 채워줘"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-추적매트릭스.md`

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
```

### Step 5: 다음 제안

누락 유형별로 해당 커맨드를 제안한다:

| 누락 유형 | 제안 커맨드 |
|---------|-----------|
| 기능 미도출 | `/gx-기능명세서` |
| 테스트 미작성 | `/gx-단위테스트계획서` |
| 비기능 검증 누락 | `/gx-단위테스트계획서` |
| 예외 케이스 없음 | `/gx-단위테스트계획서` |
| 미수행 · 실패 잔존 | `/gx-테스트결과서` |
| 삭제 미정리 | `/gx-기능명세서` 또는 `/gx-단위테스트계획서` (정리 대상에 따라) |
