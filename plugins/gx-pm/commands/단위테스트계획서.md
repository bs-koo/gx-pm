# /단위테스트계획서 — DE-13 단위테스트계획서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 0: 프로젝트 컨텍스트 로드

**load-project-profile** 스킬로 활성 프로젝트를 확인한다. 프로파일이 없으면 `/프로젝트설정`을 먼저 실행하라고 안내 후 종료.

**detect-existing-artifact** 스킬로 기존 `{시스템코드}-단위테스트계획서.md` 파일을 확인한다.
- 파일 있음 → 이어쓰기/새로쓰기/열기 선택
- 파일 없음 → 새로 생성

프로파일의 `type`에 따라 워크플로우가 분기된다:
- **A (신규 구축)**: 화면목록표 기반 검사기준 매핑 (기존)
- **B (추가 개발)**: 기존 단위테스트계획서에 새 화면의 테스트만 추가
- **C (산출물 정비)**: **scan-source-index** 스킬의 views 데이터에서 화면 파일 목록을 로드한 뒤, **generate-unit-test-plan** 스킬의 유형 판별 로직으로 검사기준을 자동 매핑
- **D (변경 관리)**: 변경된 화면에 대한 테스트 항목만 갱신

### Step 1: 화면목록표 로드

- 이전 `/화면목록표` 결과가 있으면 자동 로드
- 없으면 화면목록표 입력 요청

### Step 2: 화면 유형 판별

**generate-unit-test-plan** 스킬의 유형 판별: 목록형, 등록형, 수정형, 상세형, CRUD통합형, API형

### Step 3: 화면 유형 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
화면 유형 판별 결과를 확인해주세요.

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "EHR_01_01_030은 CRUD통합형이 아니라 입력+조회형"
• "EHR_02_01_010은 API형으로 변경"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 4: 검사기준 배정 (시트 1)

화면 유형 기반 검사기준 27개 자동 매핑, 단위테스트ID 부여 (`U_{화면ID}`).
계획서이므로 적합/부적합은 공란이고 **"해당없음"만 선기입**한다.

검사기준 항목명·예상결과·판정기준은 `templates/inspection-criteria.md`가 정본이다.

### Step 5: 검사기준 배정 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
화면 {N}개의 검사기준 배정을 확인해주세요.

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "EHR_01_01_010에 첨부파일(1~3) 추가"
• "출력(2) 인쇄는 전체 해당없음으로"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 6: 테스트케이스 설계 (시트 2)

**design-test-cases** 스킬 적용:
- 화면 유형별 설계기법 매핑 (동등분할·경계값분석·결정테이블·상태전이)
- 테스트케이스ID 부여 (`TC_{화면ID}_{2자리}`)
- 사전조건·입력데이터·수행절차·기대결과 작성
- **정상·경계·예외 케이스 강제 검증** — 예외가 0건이면 자동 보강

테이블정의서(DE-08)가 있으면 컬럼 길이·NotNull에서 경계값을 정확히 도출한다.

> 검사기준 체크리스트만으로는 감리 검사기준서가 요구하는 예상결과·판정기준을 만족하지 못한다.
> 이 단계를 건너뛰지 않는다.

### Step 7: 테스트케이스 검토 [필수 중단점 — 승인 루프]

산출물을 마크다운 표로 출력한 후, **AskUserQuestion 도구**로 승인을 요청한다:

```
테스트케이스 {N}건을 확인해주세요. (정상 {N} / 경계 {N} / 예외 {N})

주요 확인:
1. 경계값이 실제 컬럼 길이·업무 제약과 맞는지
2. 예외 케이스가 실제로 차단되어야 하는 것인지
3. 사전조건이 재현 가능한 수준인지 (계정·권한 포함)
4. 최소 기준 미달 화면 {N}건을 보강할지

승인하려면 '승인' 또는 'OK'를 입력하세요.
수정하려면 변경할 내용을 입력하세요.

수정 예시:
• "권한명 길이는 50이 아니라 100이야"
• "EHR_01_01_030에 타인 데이터 조회 케이스 추가"
```

사용자가 승인할 때까지 수정 → 재출력 → AskUserQuestion으로 승인 요청을 반복한다.

### Step 8: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-단위테스트계획서.md` (검사기준 시트 + 테스트케이스 시트)

**AskUserQuestion 도구**로 다음 내용을 질문한다:

```
승인된 산출물을 xlsx로 추출할까요?
  1. xlsx 추출 (검사기준 시트 + 테스트케이스 시트)
  2. 마크다운만 저장
```
