# 확인요청서 차수 왕복 — 질문을 대화에서 엑셀로 옮긴다

2026-09-09 · v3.4.0 대상

## 왜 하는가

v3.3.x 는 미확정을 **파이프라인 끝에서 한 번** 낸다. 그래서 두 가지가 남았다.

**① 이미 만든 것을 다시 고친다.** 2차 시험 실측에서 `[확인필요]` 80건의 분포는
AN-03 65 · DE-08 8 · DE-13 7 이었다. **게이트 2 시점에 73/80 이 이미 나온다.**
그런데 확인요청서는 게이트 3 뒤에 내므로, 답을 받으면 이미 만든 DE-13 의 경계
케이스를 파급 처리로 다시 쓴다. 게이트 2 에서 받으면 **처음부터 맞게 만든다.**

**② 되묻기가 아직 대화다.** `apply-confirmations` 의 「되묻는 네 경우」(상한 5건)가
AskUserQuestion 이다. 80건을 대화로 물으면 한 화면에 4개씩 **20 화면**이고,
매 화면이 세션 왕복이라 그때마다 컨텍스트가 다시 실린다.

| | 대화 방식 | 엑셀 방식 |
|---|---|---|
| 미확정 80건 | 20 화면 | 파일 1개 생성 |
| 사람이 답함 | 20 왕복 | 엑셀에서 한 번에 |
| 반영 | — | 파일 1개 읽기 |
| **세션 왕복** | **~20** | **2** |

## 설계 원칙

1. **질문은 파일로, 승인만 대화로.** 대화에 남는 것은 게이트 3개 · 정책 층 1회 ·
   이월 금지 4개뿐이다. 이월 금지는 미루면 뒤 산출물이 전부 틀리므로 예외다.
2. **차수는 유한하다.** 최대 3차. 답이 답을 낳아 무한히 이어지지 않게 상한을 둔다.
3. **미응답도 결론이다.** 3차까지 답이 없으면 값을 정해 개발자에게 넘긴다.
   **다만 누가 정했는지는 감추지 않는다.**
4. **빈칸이 정상이다.** 사람이 한 줄도 안 써도 다음 차수로 넘어간다.

## 표기 3종

`templates/evidence-rules.md` 의 2단 판정에 **세 번째 결과**를 더한다.

| 표기 | 뜻 | 누가 정했나 | 언제 붙나 |
|------|-----|------------|----------|
| `[가정]` | RFP 미규정 · 없어도 구현된다 | **우리** (설계 재량) | 2단 판정 결과 |
| `[미확정]` | RFP 가 규정했으나 값이 없다 · 없으면 구현 불가 | 아직 아무도 | 2단 판정 결과 |
| **`[임시확정]`** | **발주기관 몫인데 3차까지 미응답 · 임시로 정함** | **우리가 대신** | 3차 종료 시 전환 |

`[임시확정]` 은 2단 판정의 결과가 **아니다.** 미응답의 결과다. 그래서 판정 축에
넣지 않고 **전환 규칙**으로 따로 둔다.

```
[임시확정] 30건 — DAR-006 3차 미응답, 업계 관행 적용. 협의 시 변경
```

### 왜 `[가정]` 으로 바꾸면 안 되는가

`[가정]` 의 정의는 **"RFP 가 규정하지 않았다"** 이다. 3차 미응답 항목은 RFP 가
규정했고 값만 안 준 것이다. 같은 태그를 쓰면 **누가 정할 값이었는지가 지워진다.**

pm-test 함정 6건이 전부 이 자리다 — SFR-016 표본 기준값을 `[가정] 30건` 으로
적으면 *"임의 수치를 지어내면 실패(원본과 우연히 같아도 실패)"* 에 걸린다.
`[임시확정]` 은 **3차 요청 이력이 근거로 붙으므로** 지어냄이 아니다.

### 개발자가 받는 문서

```markdown
# AN-03 기능명세서 — 건물에너지 데이터 통합관리 시스템

> ⚠ 3차까지 요청했으나 미응답인 항목 8건을 [임시확정] 으로 채웠다.
>   설계 시 이 값들은 바뀔 수 있다고 보고 유연하게 가져간다.
>   목록과 요청 이력은 REB-확인요청서.xlsx 의 「요청 이력」 시트 참조.
```

`[미확정]` 이 남아 있으면 개발자가 "이건 못 만드나?" 하고 멈춘다.
`[임시확정]` 이면 **"이 값으로 만들되 바뀔 수 있다"** 가 명확하다.

## 차수 왕복

### 실행 4회 · 요청 최대 3차

각 회차는 **앞 차수 답 반영 + 다음 차수 질문 발행**이다. 마지막만 질문이 없다.

| 회차 | 하는 일 | 산출 | 끝난 뒤 |
|---|---|---|---|
| **1** | 게이트 1·2 통과 | AN-02 · AN-03 · DE-08 | **1차 발행** → 중단 |
| **2** | 1차 답 반영 → DE-13 · AN-05 생성 → 게이트 3 | 5종 전부 | **2차 발행** → 중단 |
| **3** | 2차 답 반영 → 파급 처리 | 5종 갱신 | **3차 발행** → 중단 |
| **4** | 3차 답 반영 → 미응답 `[임시확정]` 전환 | 5종 최종 | 완료 |

**미확정이 0이 되면 그 자리에서 끝난다.** 2차에서 남은 게 없으면 3차·4차가 없다.
「최대 3차」이지 「반드시 3차」가 아니다.

**DE-13 을 2회차에 만드는 이유**: 1차 답으로 제약의 대부분이 풀린다. 3차까지
기다리면 파이프라인이 두 달을 서 있고, 2회차에 만들면 경계 케이스가 처음부터
정확하다. 3·4차의 변경은 파급 처리로 흡수한다.

### 후속 질문 — AI 가 다음 차수에 쓴다

답변이 새 애매성을 만들면 **즉시 되묻지 않고 다음 차수 행으로 쓴다.**
이것이 대화 왕복을 0으로 만드는 자리다.

```
1차 답변    TB_USER.EML 길이 → 수정 → 100

AI 가 읽음   DE-13 UT-089 경계값이 "256자" 다. 101자로 바꿔야 하는데
             테스트를 유지할지 갈린다.

2차 행       | 8 | 2 | UT-089 경계값 | 101자로 조정 | EML 을 100 으로 정정하셔서 | ▾ |
```

`apply-confirmations` 의 「되묻는 네 경우」를 전부 이 경로로 보낸다.
**AskUserQuestion 을 쓰지 않는다.**

| 되묻던 경우 | 다음 차수 행으로 |
|---|---|
| `수정` 인데 정정값이 비었다 | `AI 가 정한 값` = 원래 값 · `근거` = "정정값이 비어 있어 원래 값을 유지했습니다" |
| 형식이 안 맞는다 | `근거` = "숫자가 필요한데 문장이 들어왔습니다" |
| 다른 행과 충돌한다 | `근거` = "TB_A.EML 은 100, TB_B.EML 은 255 로 갈립니다" |
| 파급 방향이 갈린다 | `AI 가 정한 값` = 제안 · `근거` = 파급 설명 |

## 확인요청서 파일 구성

### 파일 하나, 차수 누적

```
{프로젝트폴더}/
  REB-확인요청서.md      ← 정본. 차수가 쌓인다
  xlsx/
    REB-확인요청서.xlsx  ← 사람이 채우는 것
  backup/
    REB-확인요청서_260909.md   ← 차수가 넘어갈 때 백업
```

**파일명은 고정이다.** `_1차`·`_2차` 로 나누면 "어느 걸 채워야 하나"가 매번
혼란스럽다. 항상 같은 파일을 열면 되고, 이력은 안에 있다.

### 시트 4장

| # | 시트 | 누가 채우나 | 내용 |
|---|------|------------|------|
| 0 | **안내** | 읽기만 | 지금 몇 차인지 · 어디를 채우는지 · 다 채운 뒤 무엇을 하는지 |
| 1 | **가정 확인** | **PM** | AI 가 정한 값을 반증한다. 후속 질문도 여기 |
| 2 | **미확정 확인** | **발주기관** | 값이 없는 것. 이 시트만 떼어 보낼 수 있다 |
| 3 | **요청 이력** | 읽기만 | 지난 차수 기록. 감리 증거 |

**시트를 나누는 기준은 「답할 사람」이다.** 시트 1 은 PM 이, 시트 2 는 발주기관이
답한다. 시트 2 만 복사해 메일에 붙일 수 있어야 한다.

### 시트 0 · 안내 — 본문 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | 구분 | 안내 항목 이름 |
| 2 | 안내 | 사람이 읽을 문장 |

내용은 매 차수 다시 쓴다.

| 구분 | 안내 |
|------|------|
| 현재 | **2차 요청** · 최대 3차까지 진행합니다 |
| 시트1 가정 확인 | **PM 이 답합니다.** 노란 칸만 채우세요. 12건 |
| 시트2 미확정 확인 | **발주기관에 물어야 합니다.** 이 시트만 떼어 보내도 됩니다. 33건 |
| 시트3 요청 이력 | 지난 차수 기록입니다. 채우지 마세요 |
| 빈칸으로 두면 | 시트1 은 「그 값으로 진행」, 시트2 는 「다음 차수로 이월」입니다 |
| 다 채운 뒤 | `/gx-명세일괄` 을 다시 부르고 **「확인요청서 반영하고 이어가기」** 를 고르세요 |
| 3차까지 답이 없으면 | 관행값을 `[임시확정]` 으로 채우고, 산출물에 위험 항목으로 표시합니다 |

### 시트 1 · 가정 확인 — 본문 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | # | 일련번호 |
| 2 | 차수 | `1` · `2` · `3` |
| 3 | 위치 | 요구사항ID·기능ID·테이블.컬럼 중 그 값이 선 자리 |
| 4 | AI 가 정한 값 | 실제로 채운 값, 또는 후속 질문의 제안 |
| 5 | 근거 | `[가정]` 이면 **`RFP 미규정` 을 반드시 포함**. 후속 질문이면 사유 |
| 6 | 판정 | `맞음` / `수정` / `미확정으로` |
| 7 | 정정값 | `판정` 이 `수정` 일 때만 |
| 8 | 비고 | 정정 사유 |

`가정한 값` 이 아니라 **`AI 가 정한 값`** 이다 — 후속 질문의 제안도 같은 칸에
싣기 위해 일반화한다.

### 시트 2 · 미확정 확인 — 본문 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | # | 일련번호 |
| 2 | 차수 | `1` · `2` · `3` |
| 3 | 위치 | 그 값이 필요한 자리 |
| 4 | 무엇이 없나 | 없는 값·항목의 이름 |
| 5 | 왜 못 정했나 | 2단 판정 2번의 근거 — 이 값이 없으면 무엇이 구현 불가한지 |
| 6 | 상태 | `대기` / `확정` / `해당없음` |
| 7 | 응답 | `상태` 가 `확정` 일 때 받은 값 |
| 8 | 확정일 | 응답을 받은 날 |

### 시트 3 · 요청 이력 — 본문 컬럼 (정본)

| # | 컬럼 | 값 규칙 |
|---|------|--------|
| 1 | 차수 | `1` · `2` · `3` |
| 2 | 발행일 | 그 차수를 낸 날 |
| 3 | 위치 | 물었던 자리 |
| 4 | 물은 것 | 질문 요지 |
| 5 | 받은 답 | 응답값. 미응답이면 `미응답` |
| 6 | 처리 | `반영` / `이월` / `임시확정` |

**이 시트가 감리 증거다.** 「3차까지 요청했으나 미응답」을 이 표가 증명한다.

### 채울 칸을 색으로 표시한다

| 색 | 뜻 | 대상 |
|----|-----|------|
| 연노랑 (`FFF9E3`) | **여기를 채우세요** | 시트1 `판정`·`정정값`·`비고`, 시트2 `상태`·`응답`·`확정일` |
| 흰색 | 읽는 곳 | 나머지 데이터 열 |

`DOCUMENT_PROFILES` 에 `input_columns` 를 두고 그 열의 데이터 행에 채운다.
드롭다운이 걸린 열과 자연히 겹치지만, **드롭다운이 없는 `정정값`·`응답` 도
노란색**이라 "여기 뭔가 써야 하는구나"가 보인다.

## 안내 멘트

사용자가 **다음에 무엇을 할지 화면만 보고 알 수 있어야 한다.**

### 1회차 — 게이트 2 통과 후 중단

```
▣ 게이트 2 승인됨 — AN-03 · DE-08 저장했습니다.

┌─ 확인이 필요한 것이 80건 있습니다 ─────────────────────┐
│                                                        │
│  [가정]   34건  AI 가 값을 정했습니다. 맞는지 봐주세요  │
│  [미확정] 46건  발주기관이 정할 값이라 비워 뒀습니다     │
│                                                        │
└────────────────────────────────────────────────────────┘

1차 확인요청서를 만들었습니다.

  📄 건물에너지데이터통합관리시스템/xlsx/REB-확인요청서.xlsx

  ① 엑셀을 엽니다. 「안내」 시트를 먼저 보세요
  ② 노란 칸만 채웁니다. 빈칸은 「그대로 진행」이라는 뜻입니다
  ③ 「미확정 확인」 시트는 발주기관에 그대로 보내도 됩니다

다 채우신 뒤 /gx-명세일괄 을 다시 부르시면 「확인요청서 반영하고
이어가기」가 선택지에 뜹니다. 그때 단위테스트계획서·추적매트릭스를
만듭니다 — 답을 받은 값으로 만들어야 경계 케이스가 정확합니다.

지금 중단합니다. AN-02 · AN-03 · DE-08 은 이미 저장돼 있습니다.
```

**여기서 세 가지를 지킨다.**
- 파일 경로를 **그대로 복사할 수 있게** 한 줄로 준다
- 무엇을 하면 되는지 **번호로** 준다
- **왜** 지금 멈추는지 말한다 (경계 케이스 정확도)

### 2회차 — 반영 결과

```
1차 확인요청서를 읽었습니다.

  가정 34건 — 맞음 28 · 수정 4 · 미확정으로 2
  미확정 46건 — 확정 12 · 대기 33 · 해당없음 1

  반영
    AN-03  입력항목 4건의 제약 갱신
    DE-08  컬럼 길이 4건 갱신

  2차로 넘어가는 것 45건
    · 답을 못 받은 미확정 33건
    · 정정값에서 생긴 후속 확인 12건

이어서 단위테스트계획서를 만듭니다.
```

**「2차로 넘어가는 것」을 갈라 보여준다** — 사람이 "내가 안 한 게 아니라 발주기관
답이 안 온 것"을 구분할 수 있어야 한다.

### 4회차 — 최종

```
3차 확인요청서를 읽었습니다.

  확정 5건 · 미응답 8건

  미응답 8건을 [임시확정] 으로 채웠습니다.

    DAR-001  원천 파일 4종 항목 구성  → 파일당 최소 항목만 정의
    DAR-006  오류유형 코드값 목록      → EM01~EM09 임시 부여
    SFR-016  표본 최소 기준값          → 30건 (통계 관행)
    ...
```

## 위험과 완화

| 위험 | 경로 | 완화 |
|---|---|---|
| **파이프라인이 4회로 늘어 번거롭다** | 미확정이 적어도 4회를 돌면 낭비 | 10건 이하면 중단하지 않음 · 미확정 0 이면 그 자리에서 종료 |
| **`[임시확정]` 이 정직도를 무너뜨린다** | `[가정]` 과 섞이면 함정 6건 붕괴 | 태그를 갈라 두고, 근거에 **3차 요청 이력**을 붙임 |
| **파일을 못 찾는다** | 경로가 화면에서 흘러감 | 안내 멘트에 경로를 한 줄로 · 시트 0 에 다시 부르는 법 |
| **어디를 채울지 모른다** | 8열 중 3열만 입력란 | 연노랑 배경 + 시트 0 안내 |
| **차수가 꼬인다** | 사람이 옛 파일을 채움 | 파일명 고정 · 차수 열 · 시트 3 이력 |
| **xlsx 4세트가 처음 쓰는 경로** | 다중 세트는 v3.3.0 에서 2세트가 처음이었다 | 4세트 통합 테스트 · `sheet_names` 4개 검사 |

### 롤백

단계별 커밋. 표기(`[임시확정]`)와 차수는 한 덩어리라 함께 되돌린다.
`input_columns` 색과 시트 0 안내는 독립이라 개별 롤백이 가능하다.
