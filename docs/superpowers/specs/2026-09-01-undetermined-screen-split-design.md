## 1. 문제

### 1.1 감지되는 것과 감지되지 않는 것

`detect-alternatives` 스킬은 **말해진** 대안을 잡는다:

| 종류 | 예 |
|------|-----|
| 명시적 | `1안`/`2안`, `A안`, `Alternative 1` |
| 구조적 | "또는"/"혹은", `REST API / gRPC`, 비교표 |
| 암시적 | "검토 필요", "협의 필요", "~도 가능" |

세 종류 모두 **문서가 무언가를 말해야** 걸린다.

측정된 구멍은 정반대다 — **문서가 아무 말도 하지 않는데, 생성기가 그냥 정한다.**

### 1.2 실측

`실제 요구사항서(저장소 밖)` 의 `FR-05 · 예약 화면` (구현 전 원문):

```
- 날짜 선택기와 회의실별 타임슬롯 그리드(09:00~18:00, 30분 단위)가 보인다
- 빈 슬롯을 클릭하면 예약 폼이 열리고, 시작 시각이 채워진 채로 시작한다
- 예약된 슬롯을 클릭하면 취소 확인을 거쳐 취소를 요청한다
```

"열리고" · "거쳐" — 같은 화면 안의 모달인가, 별도 화면인가. **문서는 답하지 않는다.**

`detect-alternatives` 는 여기서 아무것도 감지하지 못한다. `1안/2안` 도, "또는" 도,
"검토 필요" 도 없기 때문이다. 그래서 중단점이 걸리지 않고,
`generate-screen-list` Step 3 의 화면 수 추론표가 조용히 판정한다:

| 읽는 방식 | 화면 수 |
|---|---|
| 예약 폼·취소 확인이 같은 화면의 모달 | **1개** |
| 추론표의 "목록 + 등록 + 상세" | **3개** |

그 수가 화면ID가 되고, `templates/pipeline-protocol.md` §재생성 파급 규칙에 따라
`PG_`·`U_`·`TC_` 가 **전부** 거기서 파생된다. 이 한 지점의 조용한 오추정이
나중에 정정되면 후속 산출물 전건이 재채번된다.

**C 유형(산출물 정비)은 같은 문제를 반대쪽에서 만난다.** `scan-source-index` 가
JSP/HTML 파일 목록을 주지만, 모달 프래그먼트와 탭을 화면으로 셀지는 파일 목록이
답하지 않는다.

### 1.3 왜 그릴 엔진이 아닌가

2026-08-31 초안은 mattpocock/skills 의 grill-me 를 그대로 옮긴 것이었다 —
design tree, frontier(선행이 해소된 결정들), 라운드, 권장 답변, 사실/결정 분리.
Momus 리뷰는 `/gx-spec` 에 REVISE, `/gx-testplan` 에 REJECT 를 냈다.

그 뒤 두 번의 드라이런이 **열려 있는 결정을 실제로 셌다**:

| 결정 | C유형 드라이런 | A유형 드라이런 | 지금 |
|------|---------|---------|------|
| 요구사항 분해 단위 | 1건 | 1건 | **해소됨** — PR #11 이 추출 규칙을 고쳐 BR 8건이 결정론적으로 나온다 |
| 화면 분리 단위 | 1건 | 1건 | **남아 있음** |

남은 결정은 **하나**다. 프론티어 엔진은 스케줄할 노드가 하나뿐인 스케줄러다.
라운드도, 선행 그래프도, 정렬 키도 대상이 없다.

그래서 이 설계는 엔진을 만들지 않는다. **결정 하나를, 그것이 실제로 발생하는
한 곳에서 묻는다.**

## 2. 해결

### 2.1 놓을 자리

`skills/generate-screen-list/SKILL.md` **Step 3, 화면 수 추론표를 적용하기 전**.

그 추론표가 곧 추정이다. 검사는 추정보다 앞서야 한다.
커맨드(`/gx-화면목록표` Step 2 = 시안/대안 감지)에서는 잡을 수 없다 —
"화면 수가 결정돼 있는가" 는 분해를 시도해봐야 알 수 있기 때문이다.

### 2.2 미결정 판정

| 미결정이다 | 결정돼 있다 |
|---|---|
| 화면·UI 요구사항인데 화면 수를 셀 근거가 본문에 없다 | 화면명이 열거돼 있다 (목록·등록·상세 등) |
| "열린다 / 표시된다 / 이동한다" 만 있고, 그것이 같은 화면 안인지 밖인지 말하지 않는다 | 모달·팝업·탭·페이지라고 명시돼 있다 |
| 소스에 모달 프래그먼트·탭이 있는데 화면 단위 규정이 없다 | 기존 화면목록표에 같은 기능의 분리 기준이 있다 |
| 한 요구사항이 조회·입력·확인을 모두 포함하는데 경계가 없다 | 화면 수가 본문에 숫자로 적혀 있다 |

### 2.3 유형별 동작

| 유형 | 동작 | 근거 |
|------|------|------|
| **A** 신규 구축 | 묻는다 | 근거가 RFP 밖에 없다 |
| **B** 추가 개발 | 기존 화면목록표의 분리 기준을 따른다. 같은 기능이 없을 때만 묻는다 | 기존 체계와 어긋나면 두 벌이 된다 |
| **C** 산출물 정비 | 묻는다 | 모달·탭을 화면으로 셀지는 소스가 답하지 않는다 |
| **D** 변경 관리 | **묻지 않는다** | 기존 화면ID는 바뀌면 안 된다 (§재생성 파급 규칙) |

### 2.4 정책 하나로 묻는다 — 건별로 묻지 않는다

UI 요구사항 20건이면 질문 20개가 되는 것을 막아야 한다.
실제로 공공 RFP 의 화면 분리 모호성은 **건별로 다르지 않고 정책 하나로 뭉친다** —
"모달을 화면으로 세는가" 가 20건에 똑같이 걸린다.

그래서 **AskUserQuestion 을 한 번** 부른다:

```
화면 분리 기준을 정해주세요. 요구사항 {N}건이 이 기준에 걸립니다.

  1. 모달·팝업·탭은 화면으로 세지 않는다      → 화면 {M1}개
  2. 모달·팝업은 별도 화면으로 센다            → 화면 {M2}개
  3. 건별로 정하겠다                            → {N}건을 하나씩 확인

⚠ 여기서 정한 화면 수가 화면ID가 되고,
   PG_·U_·TC_ 가 전부 여기서 파생됩니다. 나중에 바꾸면 전건 재채번입니다.
```

선택지 1·2 의 화면 수를 **양쪽 다 계산해서 보여준다.** 사용자가 감당할 비용을
모르는 채로 고르면 묻는 의미가 없다. 3번은 정책이 실제로 갈리는 경우의 탈출구다.

### 2.5 기록 — 두 자리에 남긴다

답을 받고 잊으면 재실행 때 다시 묻고, 감리에서 "화면 수 근거" 를 댈 수 없다.

| 자리 | 형식 | 왜 |
|------|------|-----|
| 화면목록표 표 위 인용줄 | `> 화면 분리 기준: 모달·팝업·탭은 화면으로 세지 않음 (2026-09-01 확인)` | 마크다운이 정본이고 `detect-existing-artifact` 가 이 파일을 읽는다 |
| 해당 행의 `비고` 열 | `화면 분리: 모달 병합 (미결정 확인)` | `비고` 는 xlsx 로 나가는 컬럼이라 납품물에 근거가 남는다 |

`비고` 는 `templates/DE-03-screen-list.md` 의 실제 컬럼이다. 없는 컬럼을 쓰면
xlsx 추출에서 조용히 사라진다.

인용줄(`>`)은 `utils/export-xlsx.py` 의 `parse_markdown_tables()` 가 제목 후보에서
명시적으로 제외하므로(`candidate.startswith((">", "|"))`), 시트명을 오염시키지 않는다.

**재질문 금지**: 표 위 인용줄에 `화면 분리 기준:` 이 이미 있으면 묻지 않고 그 기준을
적용한다. B·D 유형과 이어쓰기가 성립하는 근거가 이 규칙이다.

### 2.6 파이프라인 결속

이 중단점은 게이트로 이월할 수 없다 — 시안/대안과 같은 이유로, 결정이 뒤 산출물
전부에 선행한다. `templates/pipeline-protocol.md` §이월 금지 항목에 **4번**으로 넣는다.

**새 Step 을 만들지 않는다.** `/gx-spec` Step 3 은 이미 화면 구성 대안에서
중단한다고 적혀 있고, 거기에 미결정 중단을 함께 적는다.

> `[필수 중단점]` 라벨은 붙이지 않는다. 그 라벨은 게이트 전용이고,
> `test_파이프라인에_필수_중단점이_2개_있다` 가 `/gx-spec` 의 게이트를 정확히 2개로
> 고정하고 있다. 라벨을 붙이면 게이트가 3개가 된다. 시안/대안 중단점도 같은 이유로
> 산문("**여기서 중단한다**")으로만 적혀 있다 — 그 관례를 따른다.
>
> 이 선택의 대가: 이월 금지 중단점은 라벨이 없어 정규식으로 셀 수 없다.
> 대신 §이월 금지 항목 표가 정본이고, 테스트가 **그 절 안에서** 검사한다.

## 3. 검증

마크다운 스킬은 실행 검증이 불가능하다. **문서에 적힌 규칙 자체를 시험한다.**

| # | 시험 | 반증 (일부러 깨뜨려 확인) |
|---|------|------|
| 1 | Step 3 안에 미결정 판정표가 있고 양쪽(미결정/결정)으로 갈린다 | "결정돼 있다" 열을 지우면 실패해야 한다 |
| 2 | 유형 A·B·C·D 각각의 동작이 정의돼 있고, D 는 "묻지 않는다" 다 | D 를 "묻는다" 로 바꾸면 실패해야 한다 |
| 3 | 기록 규칙이 `비고` 를 지목하고, `비고` 가 DE-03 템플릿의 실제 컬럼이다 | 규칙이 없는 컬럼명을 쓰면 실패해야 한다 |
| 4 | `pipeline-protocol.md` **§이월 금지 항목 절 안에** 화면 분리 미결정이 있다 | 문구를 다른 절로 옮기면 실패해야 한다 |

4번의 절 단위 검사는 v2.0.0 최종 리뷰가 찾아낸 구멍의 재발 방지다 —
파일 전체 substring 으로 훑으면 지키겠다고 선언한 표가 통째로 사라져도 통과한다.

**회귀로 지켜야 하는 것** (새 테스트 아님, 기존 테스트가 깨지면 안 됨):

- `test_파이프라인에_필수_중단점이_2개_있다` — `/gx-spec` 게이트는 여전히 2개
- `test_필수_중단점이_게이트_단계에만_붙어_있다` — 라벨은 게이트 1·2 에만
- `test_커맨드의_Step_번호가_중복되지_않는다` — 새 Step 을 만들지 않으므로 무관

**이 장치가 고정하는 것은 판정표·유형표·기록 규칙·이월 금지 항목의 존재와 형태다.**
그것을 감싼 산문의 정확성은 테스트가 아니라 리뷰의 몫이다.

## 4. 범위 밖

- **`/gx-testplan` 그릴** — Momus 가 REJECT 했고, 두 드라이런 어느 쪽도 여기서
  열린 결정을 찾지 못했다. 종료기준·제외 범위는 이미 `templates/pipeline-protocol.md`
  의 **입력 수집 중단점**으로 매번 묻는다. 더 물을 것이 없다
- **라운드·프론티어·design tree** — 결정이 하나면 스케줄할 것이 없다 (§1.3)
- **질문 정렬 키** — 질문이 하나면 정렬 대상이 없다
- **`Step N-G` 별도 단계** — 새 Step 을 만들지 않으므로 발생하지 않는다
- **`generate-screen-list` 의 화면 수 추론표 자체** — 표의 행은 고치지 않는다. 다만 §3-3 에서
  정한 기준이 그 표의 `팝업 검색창 포함` 행과 §주의사항 4항보다 **우선한다**는 규정은 넣는다.
  그것이 없으면 사용자가 1번(모달·팝업을 화면으로 세지 않음)을 골라도 추론표가 팝업에 별도 SN 을
  주어, 사용자가 고른 화면 수와 산출물이 어긋난다
- **`근거` 열 불일치** (`trace-requirements` 출력과 `export-xlsx.py` 추적매트릭스
  컬럼 세트에 `근거` 가 없어 원문 ID 가 AN-02 에서 멈추는 문제) — 별건
