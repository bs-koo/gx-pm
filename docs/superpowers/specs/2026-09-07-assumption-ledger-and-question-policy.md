# 가정 대장과 질문 정책 — 산출물을 사업부 단독 사용 수준으로

2026-09-07 · v3.3.0 대상

## 왜 하는가

v3.2.0 으로 pm-test 시험(`D:\SQ\pm-test`, RFP 56건)을 재실행한 결과, 산출물의
**정확성은 합격선에 올라왔으나 완결성이 못 미친다.**

| 항목 | 실측 | 판정 |
|---|---|---|
| RFP 56건 커버리지 | 56 / 56 | 합격 |
| 정직도(지어냄) | 0건 | 합격 |
| 함정 | 6 / 6 | 합격 |
| 문서 간 ID 정합 | 고아 0건 | 합격 |
| `[확인필요]` | **80건** | — |
| DE-13 케이스 밀도 | 5.2 → **3.3건/기능** | 퇴행 |
| 행 분할 (12건 중) | 정확 6 | 불합격 |

`[확인필요]` 80건과 케이스 밀도 하락은 **같은 원인**이다.
`templates/evidence-rules.md` 가 정한 대로 제약이 비면 경계 케이스가 안 나오는데,
제약 미상이 59건이라 DE-13 이 그만큼 얇아졌다.

지금 구조에서 이 80건은 **영원히 해소되지 않는다.** `[확인필요]` 는 빈칸이고,
빈칸을 채우려면 사람이 답해야 하고, 답을 받으려면 파이프라인이 멈춰야 하는데,
파이프라인은 Step 10 에서 한 번에 저장하므로 멈추면 산출물이 사라진다.

## 설계 원칙

1. **미확정이 0이어야 완성인 게 아니다.** 미확정이 전부 명시적으로 추적되고 있으면
   완성이다. 실제 SI 설계서의 「가정 및 전제조건」 절이 하는 일과 같다.
2. **질문에는 상한이 있다.** 파이프라인 1회가 던지는 질문 수는 유한해야 한다.
3. **사람의 일은 창작이 아니라 검토다.** 빈칸을 채우게 하지 말고, 채워둔 값을
   반증하게 한다.
4. **관행값과 사실을 가른다.** 업계 관행이 있는 것은 가정으로 채우고, 발주기관만
   아는 사실은 절대 지어내지 않는다. 이 경계가 무너지면 함정 6건이 전부 무너진다.

## 변경 1 — `[확인필요]` 를 `[가정]` / `[미확정]` 으로 재편

`templates/evidence-rules.md` 의 「`[확인필요]` 는 두 종류다」 절을 다시 쓴다.

현재 분류는 **무엇이 비었는가**(항목 / 제약)를 가른다. 새 분류는 **지금 채울 수
있는가**를 가른다. 축이 다르므로 대체이지 추가가 아니다.

| 표기 | 판별 | 본문 | 결과 |
|------|------|------|------|
| `[가정]` | 업계·표준·유사사례에 관행값이 있고, 틀려도 되돌리는 비용이 작다 | **값이 있다** | 하위 산출물이 정상 생성된다 |
| `[미확정]` | 발주기관·현업만 아는 **사실** | 값이 없다 | 그 행은 비운 채 추적된다 |

### 가정으로 채워도 되는 것

- 수치 제약 중 도메인 관행이 있는 것 — 표본 최소 수, 세션 타임아웃, 페이지 크기,
  명칭 길이, 코드 길이
- 표준 도메인 기본값 — 여부 `CHAR(1)`, 연월 `CHAR(6)`, 코드 `VARCHAR(20)`
- 일반적 검증 규칙 — 이메일 형식, 날짜 형식

### 절대 채우면 안 되는 것

- 원천 파일·연계 규격의 **항목 구성**
- 코드 체계의 **코드값 목록**
- 조직·권한 체계의 실제 구성
- 발주기관이 정하는 정량 목표치 (가용률, SLA)

이 목록은 pm-test 함정 6건이 그대로 대응한다. 경계를 넘으면 함정에 걸린다.

### 본문 표기

```
| 입력항목 |
| 표본수(int, 필수, [가정] 최소 30) |

↓ 확정되면 태그만 떨어진다

| 표본수(int, 필수, 최소 30) |
```

`[가정]` 태그는 감리 제출본에도 그대로 나간다. 「지어냈다」가 아니라
「근거를 밝혔다」로 읽히는 표기이므로 숨기지 않는다.

`[미확정]` 은 값 자리를 비우고 사유를 남긴다:
`[미확정] 파일 항목 구성 — DAR-001 착수 후 발주기관 제공`

### 집계 표기

`[가정] {N}건 · [미확정] {M}건` 으로 낸다. 근거 가용도 경고와 같은 자리에 붙인다.

## 변경 2 — 확인요청서

### 언제 내는가

`[가정] + [미확정]` 합계가 **10건을 넘을 때만** 낸다.
10건 이하면 게이트 3 에서 표로 보여주고 승인만 받는다. 파일을 만들지 않는다.

### 형태

`{시스템코드}-확인요청서.xlsx` — 한 파일, 두 시트.

**시트 1 · 가정 확인**

| # | 위치 | 가정한 값 | 근거 | 판정 ▼ | 정정값 | 비고 |
|---|---|---|---|---|---|---|
| 1 | SFR-016 표본 최소 | 30건 | 통계 유의성 관행 | 맞음 | | |
| 2 | AUTHRT_NM 길이 | VARCHAR(100) | 명칭 도메인 기본값 | 수정 | 50 | 사번 체계상 |

`판정` 은 **맞음 / 수정 / 미확정으로** 3값 드롭다운.

**시트 2 · 미확정 확인**

| # | 위치 | 무엇이 없나 | 왜 못 정했나 | 상태 ▼ | 응답 | 확정일 |
|---|---|---|---|---|---|---|
| 1 | DAR-001 원천 4종 항목 | 컬럼 구성 전체 | 착수 후 제공 | 대기 | | |

`상태` 는 **대기 / 확정 / 해당없음** 3값 드롭다운.

### 왜 드롭다운인가

응답란이 자유 텍스트면 「적당히」·「표준대로」 같은 답이 와서 되물어야 한다.
드롭다운으로 잠그면 **모호성이 원천 차단**된다. `맞음` 이면 파싱이 끝나고,
`수정` 일 때만 정정값을 본다.

### 부산물이 아니다

이 파일은 그대로 발주기관·현업에 보내 답을 받을 수 있다. 실무에서 어차피
만들어야 하는 「미결사항 관리대장」이므로 산출물로 취급한다.

## 변경 3 — 게이트 통과 시점마다 저장

`commands/gx-spec.md` 를 고친다.

```
게이트 1 통과 → AN-02 저장
게이트 2 통과 → AN-03 · DE-08 저장
게이트 3 통과 → DE-13 · AN-05 저장 + 확인요청서
Step 10       → xlsx 추출
```

### 백업과의 관계

게이트별 저장은 **파이프라인 1회 안의 중간 저장**이지 버전이 아니다.
`backup/` 은 `새로쓰기` 를 고를 때 직전 **버전**을 넣는 자리이므로 여기서
건드리지 않는다. 게이트 2 가 AN-02 를 다시 쓰지 않는 것도 같은 이유다 —
한 번 저장한 산출물은 그 파이프라인 안에서 다시 저장하지 않는다.

중단 후 재개하면 `detect-existing-artifact` 가 저장된 것을 감지해
「이어서 진행」을 제안한다. 이때 이미 통과한 게이트를 다시 세우지 않는다.

### 왜 필요한가

`templates/pipeline-protocol.md` §중단 후 재개는 *"이미 저장된 산출물은 그대로
둔다"* 고 정해두었는데, 정작 저장이 Step 10 에만 있어 규약이 헛돌고 있었다.
`gx-spec.md` 자신이 *"Step 5 에서 중단되면 게이트 1 을 통과한 AN-02·AN-03 이
저장(Step 10) 전이라 사라진다"* 고 적어둔 것이 그 증거다.

게이트별 저장이 들어가면 그 방어가 필요 없어지므로, `sqi-comn-term` MCP 를
Step 1 에서 하드로 막던 근거도 재검토 대상이 된다. **다만 이번 변경에서는
막는 것을 유지한다** — Step 5 에서 끊기면 DE-08 이 없는 채로 남고, AN-05 의
「설계 제약 미반영」 판정이 건너뛰어져 시험 조건이 달라지기 때문이다.

## 변경 4 — 확인요청서 반영 경로

**신설 스킬** `apply-confirmations`.

커맨드는 늘리지 않는다. `/gx-spec` Step 0 의 기존 산출물 감지 분기에
선택지를 한 줄 더한다:

```
5종이 이미 있습니다. 어떻게 할까요?
  1. 요구사항정의서부터 전체
  ...
  N. 확인요청서 반영하고 확정   ← 본문은 그대로, 응답만 반영한다
```

### 처리 분기

| 응답 | 처리 | 되묻나 |
|---|---|---|
| `맞음` | 가정을 확정으로 승격. `[가정]` 태그를 뗀다 | 아니오 |
| `수정` + 정정값 정상 | 값 교체 + 파급 처리 | 아니오 |
| `미확정으로` | 가정을 걷어내고 시트 2 로 이동 | 아니오 |
| **무응답 (빈칸)** | **가정 그대로 유지.** 묵시적 승인 | 아니오 |
| `확정` + 응답값 | 미확정 해소 + 본문 반영 + 파급 | 아니오 |
| `해당없음` | 그 미확정 항목을 **대장에서만** 지운다. 산출물 본문은 손대지 않는다 | 아니오 |

`해당없음` 이 본문 행을 지우지 않는 이유는 AN-02 §상태 판정과 같다 —
**행은 지우지 않고 상태만 바꾼다.** 본문에서 빼려면 `열기` 경로로 명시적으로
지워야 한다. 대장 응답 하나로 산출물 행이 사라지면 되돌릴 근거가 없어진다.

**무응답도 정상 종료다.** 사람이 한 줄도 안 써도 문서는 완성된다.

### 파급

`templates/pipeline-protocol.md` §재생성 파급 규칙을 그대로 적용한다.
규칙표는 5줄이고 깊이는 최대 3단(요구사항→기능→테이블→테스트)이라 **유한하다.**

### 되묻는 네 경우

1. `수정` 인데 정정값이 비었다
2. 정정값 형식이 안 맞는다 (길이 자리에 문장)
3. 정정값이 다른 행과 충돌한다 (같은 컬럼에 서로 다른 길이)
4. 파급 방향이 갈린다

이 넷 말고는 묻지 않는다. **상한 5건.** 넘으면 나머지는 확인요청서에
`반영 보류` 로 남기고 진행한다.

## 변경 5 — 질문 정책: 정책 층과 애매성 층

`templates/pipeline-protocol.md` 에 §질문 정책 절을 신설한다.

### 두 층

| 층 | 언제 | 무엇을 | 상한 |
|---|---|---|---|
| **정책 층** | Step 0 에서 한 화면에 묶어 | 분할 기준 · 미확정 처리 · 테스트 밀도 · 비기능 검증 방법 | 1회 (4개 질문) |
| **애매성 층** | 판정이 안 설 때 그 자리에서 | 이월 금지 4개 | **5회** |

**정책 위반 감지는 5번째 항목이 아니다.** 이월 금지 4개 각각의 **권장안을 정하는
방식**이 달라지는 것이다. 지금은 권장안이 그때그때 정해지는데, 정책이 있으면
정책을 따르는 선택지가 권장이 된다. 항목 수는 4개 그대로다.

정책 층의 답은 결정 기록에 남아 **다음 PM 이 근거를 본다.**

### 정책 층 질문 4개

1. **분할 기준** — `1 요구사항 = 1 검증 단위` / `RFP 원문 1:1 유지` / `기능 도메인 단위`
2. **미확정 처리** — `관행값을 가정으로 채운다(권장)` / `전부 비우고 확인요청서로`

   변경 1 이 정하는 것은 **무엇을 가정으로 채울 수 있는가**(경계)이고,
   이 질문이 정하는 것은 **이 프로젝트에서 채울 것인가**(적용 여부)다.
   `전부 비우고` 를 고르면 경계 안쪽도 채우지 않으므로 **DE-13 케이스 밀도가
   다시 얇아진다** — 그 대가를 선택지 설명에 명시한다. 어느 쪽을 골라도
   「절대 채우면 안 되는 것」은 채우지 않는다.
3. **테스트 밀도** — 기능당 최소 케이스 수 `3` / `5(권장)` / `제약이 있는 만큼`
4. **비기능 검증 방법** — `설계 검토로 대체` / `측정 절차를 기술(권장)` / `도구 지정`

### 애매성 층이 달라지는 점

지금은 되묻기의 권장안이 취향으로 정해진다. 2차 실행에서 SFR-012 를
*"한 기능이 맞음"* 으로 권장해 분할이 3 → 1 로 퇴행했다.

정책 층이 있으면 **권장안이 정책을 따르는 쪽으로 고정된다.**

```
분할 기준을 '1 요구사항 = 1 검증 단위' 로 정하셨습니다.
REB-RE-014 가 6개 검증 단위를 가집니다.

  → 정책대로 6건으로 가른다 (권장)
  ・ 예외로 두고 1건 유지 — 사유를 적어주세요
```

### 상한을 넘으면

애매성 질문이 5회를 넘으면 나머지는 **정책 기본값으로 처리하고 확인요청서에
올린다.** 파이프라인은 멈추지 않는다.

## 변경 7 — 결함 3건

### 7-1. `/gx-spec` 이 프로파일을 대신 만든다

2차 실행 결정 기록(`.dev/no-branch/decisions.md` 12:33)이 증거다.

> **Q.** 프로젝트 프로파일이 없어 **지금 생성합니다**. 시스템코드를 무엇으로 할까요?

`/gx-프로젝트설정` Step 2 의 유형 선택(A/B/C/D)이 통째로 건너뛰어졌고,
`profile.json` 의 `type: "new"` 는 **묻지 않고 추론한 값**이다.

v3.2.0 이 넣은 규칙문(`gx-spec.md:38`)은 설치본에 그대로 있다. **문장은 있는데
실행이 안 지켰다.** 문장을 늘리는 것으로는 못 고친다.

**조치**: Step 0 을 선행조건 검사 전용 절로 분리하고, 프로파일 부재 시
그 절에서 출력 후 종료하도록 구조를 바꾼다. 뒤 Step 들을 같은 절에 이어 쓰지
않는다 — 이어 쓰여 있으면 실행이 계속 읽어 내려간다.

### 7-2. AN-05 `미수행` 이 판정 사다리를 선점

86행 전건이 `미수행` 이다. `skills/trace-requirements/SKILL.md` Step 5 의
4번 `미수행` 이 *"테스트는 있는데 `결과` 가 전건 공란"* 인데, **계획 단계 문서는
`결과` 가 언제나 전건 공란**이므로 5·6·7번이 구조적으로 발화하지 못한다.

v3.2.0 이 넣은 7번 `설계 제약 미반영` 이 **영원히 안 뜨는 코드**였다.

**조치**: `미수행` 을 사다리 맨 뒤로 내린다. `미수행` 은 진행 상태이고
5·6·7은 산출물 결함이라 성격이 다르다. 결함이 먼저 걸려야 한다.

```
1. 삭제 미정리
2. 기능도 비기능 테스트도 0건
3. 기능은 있는데 테스트 수 0
4. Fail 이 1건 이상          ← 기존 5
5. 테스트 수가 정확히 1건     ← 기존 6
6. 설계 제약 미반영           ← 기존 7
7. 결과가 전건 공란 → 미수행  ← 기존 4. 맨 뒤로
8. 어디에도 안 걸리면 빈칸
```

### 7-3. 분할 되묻기의 권장안이 뭉치는 쪽

변경 5 의 정책 층으로 해소한다. 별도 조치를 두지 않는다.
