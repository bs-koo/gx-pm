# 가정 대장과 질문 정책 — 산출물을 사업부 단독 사용 수준으로

2026-09-07 · v3.3.0 대상 · **rev.2** (Momus 리뷰 REJECT 반영)

## 왜 하는가

v3.2.0 으로 pm-test 시험을 재실행한 결과, 산출물의 **정확성은 합격선에 올라왔으나
완결성이 못 미친다.**

### 실측 (계수 방법 포함)

대상 폴더는 `D:\SQ\pm-test\건물에너지데이터통합관리시스템\` 의 5종이다.
1차(v3.1.0) 산출물은 `D:\SQ\pm-test\정답지\1차산출물\` 로 옮겨져 있다.

| 항목 | 실측 | 계수 방법 |
|---|---|---|
| RFP 커버리지 | 56 / 56 | `rfp-통합웹\02-요구사항명세.md` 의 요구사항ID 를 AN-02 `요구사항 근거` 열에서 역조회 |
| 정직도(지어냄) | 0건 | RFP 미등장 고유값 40여 종을 산출물에서 grep, 전건 무매치 |
| 함정 | 6 / 6 | `정답지\채점기준.md` 4절 6건. **§함정 대응 참조** |
| `[확인필요]` | **80건** | `grep -o '\[확인필요' \| wc -l` — **태그 출현 수**. 행 수(`grep -c`)로 세면 42다. 한 행에 태그가 여럿 들어가므로 출현 수로 센다 |
| 그중 `:제약` | 59건 | `grep -o '\[확인필요:제약\]'` |
| DE-13 케이스 밀도 | 205건 / 53기능 = **3.87** | 고유 `REB-UT-\d{3}` 수 ÷ 고유 `REB-FN-\d{3}` 수. 1차는 283 / 49 = 5.78 |

**함정 6/6 에 대하여**: `정답지\채점결과-함정품질.md` 는 **1차 채점 문서**라 함정 6
(이관 범위)을 `미언급` 으로 적었다. 2차는 대응했다 —
`REB-요구사항정의서.md:48` 의 `REB-RE-036`, `REB-기능명세서.md:68` 의 `REB-FN-053`.
1차 채점 문서를 2차 판정으로 읽지 않도록 주의한다.

### 진단

`[확인필요]` 80건과 케이스 밀도 하락은 **같은 원인**이다.
`templates/evidence-rules.md` §제약이 비었다는 판정이 정한 대로 제약이 비면 경계
케이스가 안 나오는데, 제약 미상이 59건이라 DE-13 이 그만큼 얇아졌다.

그리고 이 80건은 지금 구조에서 **영원히 해소되지 않는다.** `[확인필요]` 는 빈칸이고,
빈칸을 채우려면 사람이 답해야 하고, 답을 받으려면 파이프라인이 멈춰야 하는데,
파이프라인은 Step 10 에서 한 번에 저장하므로 멈추면 산출물이 사라진다.

## 설계 원칙

1. **미확정이 0이어야 완성인 게 아니다.** 미확정이 전부 명시적으로 추적되고 있으면
   완성이다.
2. **질문에는 상한이 있고, 상한은 출력 형식으로 강제한다.** 산문으로 적은 상한은
   지켜지지 않는다 — §변경 7-1 이 그 실증이다.
3. **사람의 일은 창작이 아니라 검토다.** 빈칸을 채우게 하지 말고, 채워둔 값을
   반증하게 한다.
4. **판정 기준은 기계가 확인할 수 있어야 한다.** "업계 관행이 있는가" 는 사람마다
   다르지만 "RFP 에 그 값이 있는가" 는 grep 으로 확인된다.

## 변경 1 — `[확인필요]` 를 `[가정]` / `[미확정]` 으로 재편

`templates/evidence-rules.md` 의 「`[확인필요]` 는 두 종류다」 절을 다시 쓴다.

현재 분류는 **무엇이 비었는가**(항목 / 제약)를 가른다. 새 분류는 **누가 정할 값인가**를
가른다. 축이 다르므로 대체이지 추가가 아니다.

### 2단 판정 (정본)

```
1. RFP 가 그 값을 줬는가?
     예   → 그대로 쓴다. 가정이 아니다
     아니오 ↓
2. 그 값이 없으면 요구사항을 구현할 수 없는가?
     예   → [미확정]   발주기관이 정할 값이다. 절대 채우지 않는다
     아니오 → [가정]   설계 재량이다. 값을 채우고 근거를 적는다
```

2번의 판정은 **그 값을 뺀 채로 요구사항 문장을 읽어보는 것**이다. 문장이 여전히
구현 지시로 성립하면 설계 재량이고, 성립하지 않으면 발주기관 몫이다.

### 함정 6건 대응 (검증표)

`정답지\채점기준.md` 4절의 함정 6건이 전부 2번에서 `[미확정]` 으로 갈린다.

| 함정 | RFP 원문 | 값을 빼면 | 판정 |
|---|---|---|---|
| 1 · INR-001 연계 규격 | "평가 프로그램과 연계" | 연계 구현 불가 | `[미확정]` |
| 2 · DAR-001 파일 항목 구성 | "원천 데이터 4종 등록" | 파싱 불가 | `[미확정]` |
| 3 · DAR-006 오류코드값 | "오류 유형을 코드로 관리" | 코드 관리 불가 | `[미확정]` |
| 4 · PFR-010 가용률 | "**안정적으로** 운영되어야 한다" | 검증 불가 | `[미확정]` |
| 5 · SFR-016 표본 기준값 | "표본이 없거나 **지나치게 적은 경우** 안내" | "적은 경우" 판정 불가 | `[미확정]` |
| 6 · 3.1.2 이관 범위 | "이관 여부·범위 착수 협의" | 이관 불가 | `[미확정]` |

### 가정이 되는 것 (검증표)

| 항목 | RFP | 값을 빼면 | 판정 |
|---|---|---|---|
| 권한명 길이 | SFR-027 이 "권한명을 지정"만 함. **길이 언급 없음** | 권한 등록은 구현된다 | `[가정]` |
| 여부 `CHAR(1)` · 코드 `VARCHAR(20)` | 언급 없음 | 구현된다 | `[가정]` |
| 이메일 형식 검증 | SFR-024 가 "이메일로 발송"만 함 | 표준 형식으로 구현된다 | `[가정]` |

**주의**: 페이지 크기는 가정이 아니다 — `PFR-006` 이 *"페이지당 100건을 기준으로
한다"* 로 값을 줬다. 1번에서 걸러진다.

### 이미 작동하던 판단이다

2차 산출물 `REB-테이블정의서.md:150` 이 이미 이렇게 썼다.

> `AUTHRT_NM VARCHAR(100)` — 근거: **원문에 최대 길이 없음** — 표준 도메인 기본값 적용

「원문에 없음」이 판정 근거로 이미 쓰이고 있었다. 새 규칙을 발명하는 것이 아니라
우연히 맞았던 판단을 정본으로 올린다.

### 본문 표기

```
| 입력항목 |
| 표본수(int, 필수, [미확정] 최소 기준값 — SFR-016 착수 후 협의) |
| 권한명(String, 필수, [가정] 100자 — RFP 미규정, 표준 도메인 기본값) |

↓ 확정되면 태그만 떨어진다

| 권한명(String, 필수, 100자) |
```

`[가정]` 태그는 감리 제출본에도 그대로 나간다. 근거에 **RFP 미규정**을 반드시 적는다 —
그것이 2번 판정을 통과했다는 증거다.

### 집계 표기

`[가정] {N}건 · [미확정] {M}건` 으로 낸다. 근거 가용도 경고와 같은 자리에 붙인다.

### 형태

`{시스템코드}-확인요청서.md` 를 만들고, xlsx 추출이 두 시트로 변환한다.

**시트 1 · 가정 확인**

| # | 위치 | 가정한 값 | 근거 | 판정 ▼ | 정정값 | 비고 |
|---|---|---|---|---|---|---|
| 1 | SFR-027 권한명 길이 | 100자 | RFP 미규정, 표준 도메인 기본값 | 맞음 | | |
| 2 | TB_USER.EML 길이 | 255자 | RFP 미규정, RFC 5321 | 수정 | 100 | 사내 메일 정책 |

`판정` = **맞음 / 수정 / 미확정으로** 드롭다운.

**시트 2 · 미확정 확인**

드롭다운으로 잠그면 모호성이 원천 차단된다.

### 부산물이 아니다

이 파일은 그대로 발주기관·현업에 보내 답을 받을 수 있다. 실무의 「미결사항
관리대장」이므로 산출물로 취급한다.

## 변경 3 — 게이트 통과 시점마다 저장

`commands/gx-spec.md` 를 고친다.

```
게이트 1 통과 → AN-02 저장
게이트 2 통과 → AN-03 · DE-08 저장
게이트 3 통과 → DE-13 · AN-05 저장 + 확인요청서
Step 10       → xlsx 추출
```

### 생성 표지 (신설)

**파일 존재는 게이트 통과의 증거가 못 된다** — `/gx-요구사항정의서` 단독 실행도 같은
파일을 만든다. 그래서 산출물 머리말에 생성 표지를 한 줄 적는다.
근거 가용도 경고와 같은 자리다.

```
> 생성: /gx-spec 게이트 1 통과 · 2026-09-07 12:48
```

단독 커맨드면 `> 생성: /gx-요구사항정의서 · 2026-09-07 12:48` 로 적는다.
파이프라인이 재개될 때 이 줄을 읽어 어디까지 통과했는지 판정한다.

**이 표지가 없으면 변경 3 은 성립하지 않는다.** 상태를 저장할 다른 자리가 없다.

### 백업과의 관계 — 오염 경로 차단

`skills/detect-existing-artifact/SKILL.md` 의 `새로쓰기` 는
`backup/{시스템코드}-{산출물명}_{YYMMDD}.md` 로 백업하고 원본을 지운다.
`skills/reconcile-ids/SKILL.md` Step 1 은 그 백업을 ID 승계의 유일한 기준선으로 읽는다.

게이트 저장을 넣으면 이런 경로가 생긴다.

```
1. 5종 새로쓰기 → 진짜 직전 버전이 backup/..._260907.md 로 들어감
2. 게이트 1 통과 → AN-02 저장 (신설)
3. Step 5 에서 중단
4. 재실행 → 감지 → 다시 새로쓰기 선택
5. 같은 날짜 파일명이라 2단계의 진짜 직전 버전을 덮어씀
   → reconcile-ids 가 "반쯤 만들다 만 산출물" 을 직전 버전으로 삼는다
```

**차단 두 겹**:

1. **생성 표지가 `게이트 N 통과` 인 산출물은 백업 대상에서 제외한다.** 완결되지
   않은 중간 저장분이라 「직전 버전」이 아니다. `detect-existing-artifact` Step 3 의
   새로쓰기 절차에 이 조건을 넣는다
2. 그럼에도 같은 날 두 번 백업하게 되면 `_{YYMMDD}_2.md` 로 순번을 붙인다.
   **기존 백업을 덮어쓰지 않는다**

### 재개 분기

`detect-existing-artifact` 에는 **「이어서 진행」 분기가 없다.** 3분기는
`이어쓰기 / 새로쓰기 / 열기` 다. 파이프라인 재개는 커맨드 층에서 처리한다 —
`gx-spec.md` Step 0-3 이 생성 표지를 읽어 「게이트 N 까지 통과한 중간 산출물」을
감지하면, 3분기를 묻기 전에 **재개 여부를 먼저 묻는다.**

```
게이트 2 까지 통과한 중간 산출물이 있습니다. (AN-02 · AN-03 · DE-08)

  1. 이어서 진행 — 게이트 3 부터 계속합니다. 통과한 게이트를 다시 세우지 않습니다
  2. 처음부터 — 3분기(이어쓰기/새로쓰기/열기)로 갑니다
```

### MCP 하드 차단은 유지한다

게이트별 저장이 들어가면 `sqi-comn-term` MCP 를 Step 1 에서 하드로 막던 근거
(`gx-spec.md:81-83`)가 약해진다. **다만 이번 변경에서는 유지한다** — Step 5 에서
끊기면 DE-08 이 없는 채로 남고, AN-05 의 「설계 제약 미반영」 판정이 건너뛰어져
3차 시험 조건이 달라진다. 별도 과제로 둔다.

## 변경 4 — 확인요청서 반영 경로

**신설 스킬** `apply-confirmations`. 커맨드는 늘리지 않는다.

`/gx-spec` Step 0-3 의 기존 산출물 분기에 선택지를 한 줄 더한다.

```
  N. 확인요청서 반영하고 확정   ← 본문은 그대로, 응답만 반영한다
```

### 처리 분기

| 응답 | 처리 | 되묻나 |
|---|---|---|
| `맞음` | 가정을 확정으로 승격. `[가정]` 태그를 뗀다 | 아니오 |
| `수정` + 정정값 정상 | 값 교체 + 파급 처리 | 아니오 |
| `미확정으로` | 가정을 걷어내고 시트 2 로 이동 | 아니오 |
| **무응답 (빈칸)** | **가정 그대로 유지.** 묵시적 승인 | 아니오 |
| `확정` + 응답값 | 미확정 해소 + 본문 반영 + 파급 | 아니오 |
| `해당없음` | 그 항목을 **대장에서만** 지운다. 본문은 손대지 않는다 | 아니오 |

**무응답도 정상 종료다.**

`해당없음` 이 본문 행을 지우지 않는 이유는 `templates/AN-02-requirements-definition.md`
§상태 판정과 같다 — **행은 지우지 않고 상태만 바꾼다.** 본문에서 빼려면 `열기` 경로로
명시적으로 지운다.

### 파급

`templates/pipeline-protocol.md` §재생성 파급 규칙을 적용한다. 규칙표는 5줄이고
깊이는 최대 3단(요구사항→기능→테이블→테스트)이라 **유한하다.**

### 되묻는 네 경우와 상한

1. `수정` 인데 정정값이 비었다
2. 정정값 형식이 안 맞는다
3. 정정값이 다른 행과 충돌한다
4. 파급 방향이 갈린다

**상한 5건.** §변경 5 의 카운터 표기로 강제한다. 넘으면 나머지는 확인요청서에
`반영 보류` 로 남기고 진행한다.

## 변경 5 — 질문 정책과 그 강제 수단

`templates/pipeline-protocol.md` 에 §질문 정책 절을 신설한다.

### 두 층

|---|---|---|---|
