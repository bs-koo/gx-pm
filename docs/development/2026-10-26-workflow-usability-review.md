# 명세 5종·단위테스트 실행 사용성 점검

점검일: 2026-10-26. 대상: 4.5.0 PR의 커맨드·스킬·양식·Excel 변환기와 Claude/Codex 연결.

## 확인요청서가 만들어지는 경로

기존에는 AN-03·DE-08·DE-13에만 확인요청서 진입·발행 경로가 있었다. AN-02와 AN-05는
본문에 `[가정]`·`[미확정]` 태그를 쓰지 않는다는 이유로 빠져 있었다. 태그가 없어도
원문 충돌, 범위, 연계 해석에는 사용자 판단이 필요하다.

| 커맨드 | 기존 경로 | 이번에 확인하는 항목 |
|---|---|---|
| `/gx-요구사항정의서` | 없음 | 원문 충돌, 범위·해석 미결, 역추출한 내용의 요구사항 해당 여부 |
| `/gx-기능명세서` | 있음 | 입력·처리·출력의 가정과 미확정 |
| `/gx-테이블정의서` | 있음 | 제약·근거와 사용자 판단이 필요한 표준 판정 |
| `/gx-단위테스트계획서` | 있음 | 입력·기대결과·경계값·실행 조건의 미결 |
| `/gx-추적매트릭스` | 없음 | 예외 흐름, 범위 제외, 연계 해석 등 사람이 판단할 항목 |

다섯 커맨드 모두 시작할 때 기존 답을 읽고 저장·추출 전에 같은
[`review-confirmations`](../../plugins/gx-pm/skills/review-confirmations/SKILL.md)를 사용한다.
명세일괄의 게이트 1·2·3도 같은 스킬에 연결했다. 명백한 끊긴 ID나 실제 시험 실패를
사용자 승인으로 정상화하지 않는다.

| 이번에 물을 항목 | 동작 |
|---|---|
| 0건 | 확인 필요 0건 안내. 빈 파일 추가 생성 없음 |
| 1~5건 | 실제 대화 응답을 기다리고 항목·답·보류를 확인요청서 md에 기록 |
| 6건 이상 | 확인요청서 md와 xlsx 발행. 답이 필요한 결정은 보류 |
| 사용자가 파일 검토 요청 | 소량이어도 xlsx 제공 |

시스템당 고정 파일 하나에 항목번호·산출물·발행처·차수를 쌓는다. 같은 원인의 질문은
상위 CQ를 이어받아 중복을 제거한다. 소량의 대화 응답도 파일이 없으면 새 md에 기록한다.

## 수정한 사용성 문제

- **빈칸 자동 승인:** 새 미응답은 대기다. 과거 버전에서 닫힌 이력은 보존한다.
- **재실행으로 답 덮어쓰기:** 입력 칸을 먼저 읽고 백업한다. 한쪽의 새 답과 양쪽 수정 충돌을 구별한다.
  같은 답 재반영·재열기만으로 이력이나 물은 횟수를 늘리지 않는다.
- **질문 반복:** 현재 자료·프로파일·대화에서 답을 먼저 찾는다. 내용·개정이력·출력 형식을 함께
  검토하고 이미 받은 수정 지시와 출력 형식을 재사용한다. 단순 다음 작업 안내는 질문으로 만들지 않는다.
- **입력 도구 오용:** Claude와 Codex의 실제 스키마를 분리하고 비동기 질문 제출과 응답 수신을
  구별한다. 자유 입력에 의미 없는 승인 선택지를 넣지 않으며 부분 답은 해당 항목에만 반영한다.
- **검토용 Excel 부재:** `export-xlsx.py --draft --separate`로 파일명·시트 제목·인쇄 머리말에
  검토용초안을 표시한다. 기존 최종본을 보존하고, 영향 없는 다른 문서까지 보류하지 않는다.
- **짧은 확인요청서의 안내 시트 누락:** 양식에 선언된 헤더는 소형 메타 표 제거 규칙에서 제외했다.
- **새로쓰기 중 작업 손실:** 완료본은 `backup/`, 중간본은 `backup/partial/`에 보관한다.
  원본은 새 문서 검증·저장까지 유지하고 복구용 중간본을 ID 승계 기준선으로 쓰지 않는다.
- **부분 수행을 완료처럼 읽는 문제:** 추적 요약에 Pass·Fail·미구현·미검증·미수행 건수와 부분 수행
  기능을 표시하고 과거 계획서에 대한 결과를 구별한다. 본문의 9컬럼·누락 8유형은 유지한다.

## 작성 근거와 Excel 가독성

확인요청과 사용자의 판단은 유지하며, 기존 `근거`·`왜 못 정했나` 칸을 읽으면 왜 그 값이나 문장을
작성했는지 알 수 있게 한다. 확인한 출처와 사실 → 적용한 기준 → 작성 이유를 1~2문장으로 연결한다.
출처 이름만 적거나 `RFP 미규정`으로 끝내지 않는다. 제안과 확인된 사실을 구분하며, 답에 따라
달라지는 문서·시험 내용도 설명한다. 별도 근거 대장이나 승인 단계를 추가하지 않는다.

Excel은 모든 열에 적용하던 최대 너비 60을 설명 열별로 늘리고, 빈 정정값·응답 칸에도 최소 너비를
준다. 명시적 줄바꿈은 가장 긴 줄을 기준으로 열 너비를 계산하며 `<br>`를 실제 줄바꿈으로 바꾼다.
한글 표시 폭과 글꼴 크기로 행 높이를 추정하고, 세로 병합 셀은 범위 전체의 높이를 확보한다.
글자를 줄이거나 내용을 생략하지 않는다. 화면의 행 고정에 더해 인쇄 제목 행을 반복한다.

높이는 글꼴·Excel 환경에 따라 차이가 생길 수 있는 추정값이다. [Excel의 행 높이 상한](https://support.microsoft.com/en-us/excel/change-the-column-width-and-row-height)을
넘는 내용은 원문을 보존하고 해당 셀의 위치를 경고한다. 전체 문서가 한 화면에 들어가도록 축소하는
기능은 아니며, 긴 문서를 읽을 때는 가로 스크롤이 필요할 수 있다.

## 커맨드 이름

사용자 선택에 따라 **`/gx-단위테스트실행`**을 대표 이름으로 사용한다.
계획서를 읽어 로컬 프로젝트를 띄우고 API·필요한 브라우저 조작을 수행한다는 동작을 드러낸다.
**`/gx-단위테스트결과반영`**은 인자와 문맥을 그대로 넘기는 별칭이다. 두 이름에 절차를 복제하지 않는다.

개정이력과 실제결과는 IM-03 결과서에, 실행별 관측과 반영 내역은 증적·수행대장에 남긴다.
DE-13 계획서는 결과에 맞춰 수정하지 않는다. README·Pages 설정·Claude/Codex 연결표를 함께 갱신했다.

## 추가 스킬 판단과 후속 후보

이번에는 반복되는 확인 항목 수집·발행을 `review-confirmations` 하나로 분리했다.
응답 적용은 기존 `apply-confirmations`가 계속 맡는다. 총 20개 스킬, 별칭 포함 9개 커맨드다.

| 후속 후보 | 해결할 구체적인 문제 | 구현 전 필요한 것 |
|---|---|---|
| `review-artifact-edits` — Excel 수정 검토·반영 | 사용자가 Excel 본문을 고쳤을 때 md와 값·ID·개정이력이 어긋나는 문제 | 원본 지문, ID 기반 차이 미리보기, 충돌 처리, 선택 적용·복구를 담당할 실행 도구 |
| `check-test-readiness` — 로컬 시험 준비 점검 | 시간 고정·시험 계정·브라우저·DB 관측 부재로 많은 행이 미검증이 되는 문제 | 프로젝트별 준비 항목과 행별 의존성. 기존 실행 스킬 Step 1·2와 책임 분리 |

두 후보는 안내문만 추가하면 기존 스킬과 겹치므로 이번 릴리스에는 생성하지 않았다.
특히 Excel 수정 반영을 먼저 구현하면 문서 작성·검토 왕복을 줄일 수 있다.

프로파일의 미사용 필드 `prefix`·`networkType`도 기본 질문에서 빼는 것이 좋다. 현재는 필수 필드
검사와 옛 양식 호환이 연결돼 있으므로 스키마·로더·설정 커맨드를 함께 이관하는 후속 변경으로 남겼다.
늦게 도착한 답을 마지막 `미해소` 행에 갱신하는 기존 정책도 유지했다. 과거 상태까지 불변으로
감사하려면 요청 횟수와 별도로 응답 이벤트를 추가 저장하는 구조가 필요하다.

## 검증 범위

- 전체 회귀 테스트 385개 통과. 스킬 형식 검사 중 발견한 기존 `prioritize-si` 설명의
  허용되지 않는 꺾쇠 문자를 일반 문장으로 고쳤다.
- 다섯 커맨드의 진입·발행 연결, 별칭 위임, 공통 정책은 계약 테스트로 검사한다.
- 다섯 산출물 코드를 각각 넣은 확인요청서를 실제 xlsx로 저장하고 다시 열어 4개 시트,
  미응답 빈칸, 응답값, 요청 이력, 입력 칸 색상을 확인한다.
- 초안 출력은 최종본 보존, 분리·합본·표준입력 경로, 제목·필터·행 고정,
  드롭다운과 입력 칸의 위치를 실제 통합문서로 검사한다.
- 추가 6개 테스트는 긴 근거·빈 입력 칸의 너비와 정렬, 줄바꿈, 병합 범위 높이, 높이 상한과 원문
  보존, 인쇄 제목·초안 배너를 저장·재열기로 검사한다.
- 가상 확인요청서와 실제 memo 산출물 6종을 전후 버전으로 출력해 셀 값·병합·드롭다운·입력 색상·
  글꼴 보존을 대조했다. `<br>`의 표시용 줄바꿈 변환만 허용했다. 확인요청서 3개 시트와 memo의
  기능명세·단위테스트계획·결과 대표 범위를 렌더링해 긴 문장이 잘리지 않는지 확인했다.
- 이전 단계의 memo 로컬 시연은 139행 중 Pass 107·Fail 0·미검증 32였다. 이번 사용성 변경 뒤
  memo의 전체 API·브라우저 시험이나 두 AI 환경의 대화 세션을 다시 실행한 것은 아니다.
  정적 지침 검사를 실제 질문·응답·문서 반영의 종단 검증으로 간주하지 않는다.

확인요청 응답 반영은 아직 스킬 지침을 실행하는 에이전트에 의존한다. 입력 충돌·재반영 방지 지침은
검사했지만 별도 결정적 응답 가져오기 도구가 보장하는 기능이라고 주장하지 않는다.
