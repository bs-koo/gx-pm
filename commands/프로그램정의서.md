# /프로그램정의서 — DE-05 프로그램정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 1: 화면목록표 로드

- 이전 `/화면목록표` 결과가 있으면 자동 로드
- 없으면 화면목록표 입력을 요청

### Step 2: 프레임워크 확인 [필수 중단점]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 프로젝트 기술 정보를 입력해주세요

1. 프레임워크: (1) eGovFrame  (2) Spring Boot  (3) 기타
2. 베이스 패키지명: (예: kr.go.energy.ehr)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 3: 프로그램정의서 생성

**generate-program-list** 스킬 적용:
- 화면ID → 프로그램ID 매핑 (PG_{화면ID})
- URL 패턴 생성 (프레임워크별)
- 소스파일 구조 매핑 (Controller/Service/DAO/SQL/JSP)

### Step 4: 프로그램 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 프로그램 {N}개 구성을 확인해주세요

주요 확인:
1. PG_{화면ID} 규칙을 따르는지
2. 화면 없는 엔진/서비스 프로그램이 누락되지 않았는지
3. URL 패턴이 프로젝트 규칙과 맞는지
4. 소스파일 구조가 맞는지

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "산출 엔진은 화면 없는 서비스로 분리해줘"
  • "URL을 /api/v2/ 패턴으로 변경"
  • "배치 프로그램 1건 추가"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.
