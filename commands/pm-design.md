# /pm-design — 설계 산출물 생성

요구사항정의서(AN-02)를 기반으로 화면목록표(DE-03)와 프로그램정의서(DE-05) 초안을 생성하는 워크플로우.

> **공통 규칙**: 모든 체크포인트에서 `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 호출 예시

```
/pm-design
/pm-design [요구사항정의서 업로드]
/pm-design B 시스템 화면목록 만들어줘
```

## 워크플로우

### Step 1: 요구사항 로드

- 이전 `/pm-analyze` 결과가 있으면 자동 로드
- 없으면 요구사항정의서 입력을 요청

### Step 2: 시안/대안 감지 [필수 중단점]

**detect-alternatives** 스킬 적용:
- 요구사항에서 시안(1안/2안)이 감지되면 사용자에게 선택 요청
- `/pm-analyze`에서 이미 선택된 시안이 있으면 자동 반영

감지 대상:
- 화면 구성 방식 (단일 화면 vs 별도 메뉴)
- 기술 스택 (프레임워크, 라이브러리)
- UI 레이아웃 (탭 vs 페이지 분리)

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
⚠ 시안 선택이 필요합니다

  1안: {시안1 요약} → 화면 {N}개 예상
  2안: {시안2 요약} → 화면 {N}개 예상

→ 어떤 시안으로 진행할까요? (1/2/병행)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 3: 화면목록표 생성

**generate-screen-list** 스킬 적용:
- 요구사항을 기능 그룹으로 묶기
- 기능구분ID, 기능ID 부여
- 화면 식별 및 화면ID 자동 계산 ({기능ID}_{SN})
- 망구분 (내부/외부) 판별 — Step 1에서 받은 프로젝트 망 유형 적용

### Step 4: 화면목록 검토 [필수 중단점 — 승인 루프]

화면목록표 초안을 사용자에게 표시하고 **반드시** 확인을 받는다.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 화면 {N}개 구성을 확인해주세요

주요 확인 사항:
1. 화면 분리가 적절한가요?
   (같은 페이지의 영역을 별도 화면으로 분리하지 않았는지)
2. 기능구분/기능 분류가 실제 업무와 일치하나요?
3. 망구분(내부/외부)이 올바른가요?
4. 누락된 화면이 있나요?

✅ 승인 — "승인" 또는 "OK" 입력
✏️ 수정 — 아래에 변경할 내용을 입력해주세요

  수정 예시:
  • "SC-003, 004, 005는 실제로 한 화면이야. 합쳐줘"
  • "망구분 전부 내부망으로 변경"
  • "팝업 화면 2개 추가 필요"
  • "기능구분 '산출 엔진'은 화면이 아니라 서비스야"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 5: 프로그램정의서 생성

**generate-program-list** 스킬 적용:
- 화면ID → 프로그램ID 매핑 (PG_{화면ID})
- URL 패턴 추정
- 소스 파일 구조 매핑 (Controller/Service/DAO/SQL/JSP)

### Step 6: 프로그램 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 프로그램 {N}개 구성을 확인해주세요

주요 확인 사항:
1. 프로그램ID가 PG_{화면ID} 규칙을 따르나요?
2. 화면 없는 엔진/서비스 프로그램이 누락되지 않았나요?
3. URL 패턴이 프로젝트 규칙과 맞나요?
4. 소스파일 구조(Controller/Service 등)가 맞나요?

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "PG_SC-003의 URL을 /api/v2/comfort로 변경"
  • "배치 프로그램 1건 추가 필요"
  • "산출 엔진은 화면 없는 서비스로 분리해줘"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.

### Step 7: 인터페이스 정의서 (선택)

**generate-interface-spec** 스킬 적용 (외부 연동 요구사항이 있는 경우):
- 연동 관련 요구사항 자동 식별 (API, SSO, 연계 등 키워드)
- 인터페이스ID 부여 (IF-{시스템코드}-{순번})
- 연동방식/데이터항목/오류처리 정의

"외부 시스템 연동이 포함된 요구사항이 {N}건 있습니다. 인터페이스 정의서를 만들까요?"

생성 후 동일하게 [승인 루프] 적용.

### Step 8: 결과 저장 + xlsx 추출

- `{시스템코드}-화면목록표.md`
- `{시스템코드}-프로그램정의서.md`
- `{시스템코드}-인터페이스정의서.md` (Step 7 실행 시)

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 승인된 설계 산출물을 xlsx로 추출할까요?
  1. 전체 xlsx 추출 (화면목록 + 프로그램 + 인터페이스)
  2. 개별 선택하여 추출
  3. 마크다운만 저장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
