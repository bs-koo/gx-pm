# /pm-design — 설계 산출물 생성

요구사항정의서(AN-02)를 기반으로 화면목록표(DE-03)와 프로그램정의서(DE-05) 초안을 생성하는 워크플로우.

## 호출 예시

```
/pm-design
/pm-design [요구사항정의서 업로드]
/pm-design B 시스템 화면목록 만들어줘
```

## 워크플로우

### Step 1: 요구사항 로드

- 이전 `/pm-analyze` 결과가 있으면 자동 로드
- 없으면 요구사항정의서 입력을 요청

### Step 2: 화면목록표 생성

**generate-screen-list** 스킬 적용:
- 요구사항을 기능 그룹으로 묶기
- 기능구분ID, 기능ID 부여
- 화면 식별 및 화면ID 자동 계산 ({기능ID}_{SN})
- 망구분 (내부/외부) 판별

### Step 3: 프로그램정의서 생성

**generate-program-list** 스킬 적용:
- 화면ID → 프로그램ID 매핑 (PG_{화면ID})
- URL 패턴 추정
- 소스 파일 구조 매핑 (Controller/Service/DAO/SQL/JSP)

### Step 4: 인터페이스 정의서 (선택)

**generate-interface-spec** 스킬 적용 (외부 연동 요구사항이 있는 경우):
- 연동 관련 요구사항 자동 식별 (API, SSO, 연계 등 키워드)
- 인터페이스ID 부여 (IF-{시스템코드}-{순번})
- 연동방식/데이터항목/오류처리 정의

"외부 시스템 연동이 포함된 요구사항이 {N}건 있습니다. 인터페이스 정의서를 만들까요?"

### Step 5: 확인 체크포인트

"화면 {N}개, 프로그램 {N}개를 확인해주세요."

### Step 6: 결과 저장

- `{시스템코드}-화면목록표.md`
- `{시스템코드}-프로그램정의서.md`
- `{시스템코드}-인터페이스정의서.md` (Step 4 실행 시)

### Step 7: 다음 단계 제안

- "/pm-table 로 ERD/테이블정의서를 만들까요?"
- "/pm-test 로 테스트 계획서를 만들까요?"
- "/pm-trace 로 추적매트릭스를 갱신할까요?"
