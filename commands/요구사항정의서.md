# /요구사항정의서 — AN-02 요구사항정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 1: 프로젝트 기본 정보 수집 [필수 중단점]

사용자에게 아래 정보를 **반드시** 확인받는다. 답변이 올 때까지 다음 단계로 진행하지 않는다.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 프로젝트 기본 정보를 입력해주세요

1. 시스템 코드: 영문 1자리(A~I) 또는 자유 코드 (예: ACT)
2. 시스템 접두어: 화면ID용 2~4자리 영문 (예: EHR)
3. 망 구분: (1) 내부망 전용  (2) 외부망 전용  (3) 혼재
4. 작성자명: 감리 대응 담당자
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 2: 시안/대안 감지 [필수 중단점]

**detect-alternatives** 스킬로 입력 문서를 스캔. 시안이 감지되면 사용자 선택을 요청한다. 선택 전까지 다음 단계로 진행하지 않는다.

### Step 3: 요구사항 추출 + 분류

**extract-requirements** → **classify-requirements** 스킬 순차 적용:
- 기능/비기능 분류, 대분류/중분류, 요구사항ID 부여 ({시스템코드}-RE-{순번})
- 수용여부 초안 (수용/부분수용/불가)

### Step 4: 요구사항 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 추출된 요구사항 {N}건을 확인해주세요

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "RE-003과 004를 하나로 합쳐줘"
  • "비기능에 보안 항목 추가"
  • "5번 수용여부를 부분수용으로"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.

### Step 5: 우선순위 부여 (선택)

"요구사항에 우선순위를 부여할까요?" → 승인 시 **prioritize-si** 스킬 적용.

### Step 6: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-요구사항정의서.md`

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 xlsx로 추출할까요?
  1. xlsx 추출  2. 마크다운만 저장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
