# /주간보고서 — 주간보고서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 1: 기본 정보 수집 [필수 중단점]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 주간보고 기본 정보를 입력해주세요

1. 보고 기간: (예: 2026.03.23 ~ 03.27)
2. 현재 단계: (분석/설계/구현/시험)
3. 감리 여부: (감리 기간인지)
4. 금주 실적: (주요 업무 — Dooray 복붙, 자유 텍스트 모두 가능)
5. 이슈/리스크: (있으면)
6. 차주 계획: (있으면)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

답변이 올 때까지 다음 단계로 진행하지 않는다.

### Step 2: 주간보고서 작성

**weekly-report** 스킬 적용:
- 금주 실적 구조화 (파트별 업무, 산출물, 진척률)
- 이슈/리스크 정리 (유형, 영향도, 대응방안)
- 단계별 진척률 (계획 vs 실적)
- 감리 대응 현황 (감리 기간인 경우)
- 차주 계획 정리

### Step 3: 보고서 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 주간보고서를 확인해주세요

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "진척률을 설계 70% → 80%로 수정"
  • "이슈에 '감리 일정 변경' 추가"
  • "차주 계획에 '추적매트릭스 보완' 추가"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

파일명: `주간보고서-{YYYYMMDD}.md`

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 xlsx로 추출할까요?
  1. xlsx 추출  2. 마크다운만 저장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 5: 후속 제안

- 진척률 지연: "지연 사유를 이슈 섹션에 추가할까요?"
- 감리 미조치: "/감리대응 으로 조치 계획을 확인할까요?"
