# /인터페이스정의서 — 인터페이스정의서 생성

> **공통 규칙**: `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 워크플로우

### Step 1: 요구사항 로드

- 이전 `/요구사항정의서` 결과가 있으면 자동 로드
- 연동 관련 요구사항 자동 식별 (API, SSO, 연계, 외부 등 키워드)

### Step 2: 인터페이스 생성

**generate-interface-spec** 스킬 적용:
- 인터페이스ID 부여 (IF-{시스템코드}-{순번})
- 송신/수신 시스템, 연동방식, 연동주기 정의
- 요청/응답 데이터 항목 정의
- 오류 처리 정의

### Step 3: 인터페이스 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 인터페이스 {N}건을 확인해주세요

주요 확인:
1. 외부 시스템 식별이 정확한지
2. 연동방식(REST/SOAP/파일)이 맞는지
3. 요청/응답 데이터 항목이 충분한지
4. 오류 처리가 적절한지

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "IF-002의 연동방식을 SOAP에서 REST로 변경"
  • "응답 데이터에 에러코드 항목 추가"
  • "타임아웃을 10초로 변경"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

파일명: `{시스템코드}-인터페이스정의서.md`

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📊 xlsx로 추출할까요?
  1. xlsx 추출
  2. 마크다운만 저장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
