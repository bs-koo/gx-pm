# /pm-table — 테이블 설계 (ERDCloud 연계)

ERDCloud DDL ↔ 테이블정의서(DE-08) 양방향 변환 워크플로우.

> **공통 규칙**: 모든 체크포인트에서 `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 호출 예시

```
/pm-table CREATE TABLE users (...)
/pm-table [DDL 파일 업로드]
/pm-table 역방향               # 요구사항 → DDL 생성
/pm-table                      # 방향 선택
```

## 워크플로우

### Step 1: 방향 결정

인자가 DDL이면 → 정방향 (DDL → 테이블정의서)
"역방향"이면 → 역방향 (요구사항 → DDL)
없으면 → 사용자에게 선택:
  1. "ERDCloud DDL → 테이블정의서" (정방향)
  2. "요구사항/화면 → ERD 설계 + DDL" (역방향)

### [정방향] Step 2a: DDL → 테이블정의서

**convert-ddl-to-tablespec** 스킬 적용:
1. DDL 파싱 (테이블, 컬럼, 타입, PK/FK/NotNull)
2. COMMENT 파싱 (있으면 한글명 추출)
3. 한글명 추론 (COMMENT 없으면 컬럼명에서 추론)

### [역방향] Step 2b: 요구사항 → DDL

**generate-erd-guide** 스킬 적용:
1. 요구사항/화면에서 필요한 엔터티 식별
2. 엔터티 간 관계 도출 (1:N, N:M)
3. 주요 컬럼 + PK/FK 설계
4. ERDCloud 입력용 DDL 생성
5. 테이블정의서 초안도 함께 출력

### Step 3: 테이블 구조 검토 [필수 중단점 — 승인 루프]

테이블정의서 초안을 테이블별로 표시하고 확인을 받는다.

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 테이블 {N}개 정의를 확인해주세요

주요 확인 사항:
1. 한글 컬럼명이 올바른가요?
2. 데이터타입과 길이가 적절한가요?
3. PK/FK 관계가 맞나요?
4. 누락된 테이블이나 컬럼이 있나요?
5. 공통 컬럼(등록일시, 수정일시 등)이 빠지지 않았나요?

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "USER_NM 컬럼명을 '사용자명'으로 변경"
  • "ACT_COMFORT_CALC_HIST에 IP_ADDR 컬럼 추가"
  • "STN_ID 길이를 20으로 늘려줘"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

사용자가 승인할 때까지 수정 → 재출력 → 승인 요청을 반복한다.

### Step 4: 결과 저장 + xlsx 추출

- `{시스템코드}-테이블정의서.md`
- (역방향 시) `{시스템코드}-DDL.sql`

```

📊 승인된 테이블정의서를 xlsx로 추출할까요?
  1. xlsx 추출 (테이블별 시트 분리)
  2. 마크다운만 저장
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
