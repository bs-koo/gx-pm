# /pm-result — 테스트 결과 기입

테스트 계획서에 수행 결과를 기입하여 단위테스트결과서(IM-03), 통합테스트결과서(TE-02), 인수테스트결과서(TE-06)를 생성하는 워크플로우.

> **공통 규칙**: 모든 체크포인트에서 `templates/approval-protocol.md`의 승인 루프 프로토콜을 적용한다.

## 호출 예시

```
/pm-result 단위               # 단위테스트 결과 기입
/pm-result 통합               # 통합테스트 결과 기입
/pm-result 인수               # 인수테스트 결과 기입
/pm-result                    # 유형 선택부터 시작
```

## 워크플로우

### Step 1: 결과서 유형 선택

인자가 없으면 사용자에게 선택:
1. 단위테스트결과서 (IM-03) — 화면별 검사기준 적합/부적합 기입
2. 통합테스트결과서 (TE-02) — 시나리오 Step별 판정결과 기입
3. 인수테스트결과서 (TE-06) — 발주처 수행 시나리오 판정결과 기입

### Step 2: 계획서 로드

- 이전 `/pm-test` 결과가 있으면 자동 로드
- 없으면 계획서 데이터 입력 요청

### [단위] Step 3a: 단위테스트 결과 기입

**fill-unit-test-result** 스킬 적용:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 결과 입력 방식을 선택해주세요

  1. 전체 적합 — 모든 항목을 "적합"으로 일괄 처리
  2. 부적합 목록 — 부적합 항목만 입력 (나머지 자동 적합)
  3. 항목별 입력 — 화면별로 하나씩 입력

→ 번호를 입력해주세요 (1/2/3)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 검사기준 항목 결과 기입
- 부적합 항목: 내역, 원인, 조치, 조치일, 조치자 기입
- 결과 통계 산출 (적합률)

### [통합/인수] Step 3b: 통합/인수테스트 결과 기입

**fill-integration-test-result** 스킬 적용:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 결과 입력 방식을 선택해주세요

  1. 전체 적합 — 모든 Step을 "Pass"로 일괄 처리
  2. 부적합 목록 — Fail 항목만 입력 (나머지 자동 Pass)
  3. 시나리오별 입력 — 시나리오별로 하나씩 입력

→ 번호를 입력해주세요 (1/2/3)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 문서 유형 확인 (TE-02 vs TE-06)
- 각 Step 판정결과, 테스트 데이터, 수행자 기입
- 부적합 처리 워크플로우 (원인→조치→재테스트→조치후판정)
- 결과 통계 산출

### Step 4: 결과서 검토 [필수 중단점 — 승인 루프]

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 테스트 결과서를 확인해주세요

  적합률: {N}% ({적합건}/{전체건})
  부적합: {M}건

주요 확인 사항:
1. 부적합 항목의 조치 내용이 적절한가요?
2. 조치 후 판정이 모두 "적합"인가요?
3. 수행자, 수행일이 올바른가요?

✅ 승인 — "승인" 또는 "OK"
✏️ 수정 — 변경 내용 입력

  수정 예시:
  • "U_SC-003_04의 결과를 부적합으로 변경, 원인: 연동 오류"
  • "TE-002 Step 3 수행자를 '김철수'로"
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
