# /pm-report — 보고 문서 생성

회의록 또는 주간보고서를 공공/SI 프로젝트 표준 양식으로 생성하는 워크플로우.

## 호출 예시

```
/pm-report 회의록              # 회의록 작성
/pm-report 주간보고            # 주간보고서 작성
/pm-report                    # 유형 선택부터 시작
```

## 워크플로우

### Step 1: 보고서 유형 선택

인자가 없으면 사용자에게 선택:
1. 회의록 — 회의 내용을 구조화 (결정사항, 지시사항, 액션아이템 추출)
2. 주간보고서 — 금주 실적, 이슈, 진척률, 차주 계획

### [회의록] Step 2a: 회의록 작성

**meeting-notes** 스킬 적용:
1. 입력 유형 파악 (녹취 전사 / 메모 / 슬랙 대화)
2. 기본 정보 수집 (일시, 장소, 참석자, 회의 유형)
3. 참석자 구분 (발주처 / 감리단 / 개발팀)
4. 안건별 논의 내용 구조화
5. 공공/SI 특화 추출: 지시사항(발주처→개발팀), 협의사항
6. 결정사항 + 액션아이템 테이블 생성
7. 회의록 번호 부여 ({프로젝트코드}-MTG-{순번})

### [주간보고] Step 2b: 주간보고서 작성

**weekly-report** 스킬 적용:
1. 기본 정보 수집 (보고 기간, 현재 단계, 감리 여부)
2. 금주 실적 입력 (업무, 산출물, 진척률)
3. 이슈/리스크 입력 (유형, 영향도, 대응방안)
4. 단계별 진척률 (분석/설계/구현/시험 계획 vs 실적)
5. 감리 대응 현황 (감리 기간인 경우)
6. 차주 계획 입력

### Step 3: 결과 저장

- 회의록: `{프로젝트코드}-MTG-{순번}.md`
- 주간보고: `주간보고서-{YYYYMMDD}.md`

### Step 4: 후속 제안

회의록:
- 감리회의인 경우: "/pm-audit 로 지적사항 대응을 시작할까요?"
- 지시사항이 있는 경우: "액션아이템을 Redmine 이슈로 등록할까요?"

주간보고:
- 진척률 지연 시: "지연 사유를 이슈 섹션에 추가할까요?"
- 감리 미조치 항목 시: "/pm-audit 로 조치 계획을 확인할까요?"
