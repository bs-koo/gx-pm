# /pm-analyze — 요구사항 분석

RFP, 과업지시서, 제안서에서 요구사항을 추출하여 AN-02 요구사항정의서 형식으로 정리하는 워크플로우.

## 호출 예시

```
/pm-analyze 과업지시서에서 요구사항 뽑아줘
/pm-analyze [파일 업로드]
/pm-analyze                    # 대화형 시작
```

## 워크플로우

### Step 1: 시스템 정보 확인

사용자에게 확인:
- 어떤 시스템의 요구사항인가? (시스템 코드 A~I 또는 새 프로젝트)
- 시스템 접두어는? (화면ID에 사용할 3~4자리 영문, 예: EHR)

기존 산출물이 있으면 기존 ID 체계를 자동 감지하여 제안.

### Step 2: 요구사항 추출

**extract-requirements** 스킬 적용:
- RFP/과업지시서에서 기능 요구사항 추출
- "ㅇ", "o"로 시작하는 항목, "~해야 한다" 패턴 식별
- 요구사항ID 자동 부여 ({시스템코드}-RE-{순번})

### Step 3: 요구사항 분류

**classify-requirements** 스킬 적용:
- 기능/비기능 분류
- 대분류/중분류/소분류 자동 분류
- 수용여부 초안 (수용/부분수용/불가)

### Step 4: 확인 체크포인트

추출된 요구사항 표를 사용자에게 표시:
"추출된 요구사항 {N}건을 확인해주세요."

수정사항이 있으면 반영 후 재출력.

### Step 5: 우선순위 부여 (선택)

**prioritize-si** 스킬 적용 (사용자 선택 시):
- 공공/SI 5단계 우선순위 (P1 법적필수 ~ P5 품질개선)
- 영향도(높/중/저) + 시급도 매트릭스
- 감리 지적 고위험 항목 자동 식별

"요구사항에 우선순위를 부여할까요?" → 사용자 승인 시 실행

### Step 6: 결과 저장

확정된 요구사항을 마크다운 파일로 저장:
- 파일명: `{시스템코드}-요구사항정의서.md`

### Step 7: 다음 단계 제안

- "/pm-trace 로 기존 산출물과 매핑을 확인할까요?"
