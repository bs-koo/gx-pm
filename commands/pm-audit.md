# /pm-audit — 감리 대응

감리 지적사항을 분석하여 대응 문서를 생성하고, 필요한 증빙 산출물 체크리스트를 작성하는 워크플로우.

## 호출 예시

```
/pm-audit 화면정의서 누락 지적
/pm-audit [감리 지적사항 파일 업로드]
/pm-audit                      # 대화형 시작
```

## 워크플로우

### Step 1: 지적사항 입력

사용자로부터 감리 지적사항을 받는다:
- 텍스트 입력
- 파일 업로드 (Excel, HWP)
- 여러 건 한꺼번에 가능

### Step 2: 지적사항 분류

**audit-response** 스킬 적용:

각 지적사항을 유형별로 분류:
| 유형 | 설명 | 예시 |
|------|------|------|
| 산출물 누락 | 필수 산출물이 제출되지 않음 | "화면정의서 미제출" |
| 내용 미흡 | 산출물은 있으나 내용이 부족 | "요구사항 상세내역 부족" |
| 추적성 부족 | 산출물 간 ID 매핑이 누락 | "추적매트릭스 미완성" |
| 품질 미달 | 테스트, 코드 품질 문제 | "단위테스트 커버리지 부족" |
| 절차 미준수 | 프로세스/절차 위반 | "변경관리 절차 미이행" |

### Step 3: 영향 범위 분석

**impact-analysis** 스킬 적용:
- 지적사항과 관련된 산출물 식별
- 관련 요구사항, 화면, 프로그램, 테스트 범위 파악
- 조치에 필요한 작업량 추정

### Step 4: 조치계획 수립

각 지적사항에 대해:
- **지적사항**: 원문 그대로
- **원인 분석**: 왜 발생했는지
- **조치 계획**: 구체적 조치 내용
- **담당자**: 누가 조치할지 (사용자에게 확인)
- **완료 예정일**: 언제까지 (사용자에게 확인)
- **필요 증빙**: 조치 완료를 증명할 산출물/증적

### Step 5: 증빙 체크리스트 생성

조치에 필요한 증빙 산출물을 체크리스트로 정리:
```
□ DE-03 화면정의서 — {시스템명} 전체 화면 (N건)
□ AN-05 추적매트릭스 — 설계단계 컬럼 완성
□ DE-17 과업이행여부증적 — 해당 요구사항 증적 추가
```

### Step 6: 결과 출력

```
## 감리 대응 문서

### 지적사항 1: {지적내용}
- 유형: {분류}
- 원인: {원인분석}
- 조치계획: {구체적 내용}
- 담당자: {이름}
- 완료예정일: {날짜}
- 필요 증빙:
  □ {산출물1}
  □ {산출물2}

### 지적사항 2: ...
```

### Step 7: 결과 저장

- `감리대응-{날짜}.md`

### Step 8: 후속 조치 제안

지적 유형에 따라 관련 커맨드 제안:
- 산출물 누락 → 해당 산출물 생성 커맨드 (/pm-design, /pm-test 등)
- 추적성 부족 → "/pm-trace 전체"
- 내용 미흡 → 해당 산출물 보완 스킬
