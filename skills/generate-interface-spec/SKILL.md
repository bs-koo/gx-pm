# 인터페이스 정의서 생성 (generate-interface-spec)

요구사항과 화면목록을 분석하여 시스템 간 연동이 필요한 인터페이스를 식별하고, 연동 대상, 방식, 데이터 항목, 오류처리를 정의한 DE-04 인터페이스정의서를 생성한다.

---

## 입력

| 항목 | 필수 여부 | 설명 |
|---|---|---|
| 요구사항정의서 | 필수 | AN-02 기준. 연동 관련 요구사항 포함 |
| 시스템코드 | 필수 | 인터페이스ID 채번에 사용 (예: B, EHR, KSC) |
| 화면목록표 | 선택 | DE-03. 연동이 필요한 화면 특정에 활용 |
| 연동 대상 시스템 목록 | 선택 | 사전에 파악된 외부 시스템 목록 |
| 기존 인터페이스 목록 | 선택 | 있으면 기존 번호 체계 유지, 없으면 001부터 채번 |

---

## 처리 절차

### Step 1: 외부 시스템 연동 요구사항 식별

요구사항 설명에서 다음 키워드가 포함된 항목을 연동 후보로 추출한다.

식별 키워드 분류:

| 키워드 유형 | 키워드 예시 | 연동 유형 추정 |
|---|---|---|
| 연계/연동 | "연계한다", "연동한다", "인터페이스" | API 또는 DB Link |
| API 호출 | "API", "웹서비스", "SOAP", "REST", "호출" | REST API 또는 SOAP |
| 데이터 전송/수신 | "전송", "수신", "송신", "전달", "제공" | API 또는 파일 연동 |
| 동기화 | "동기화", "갱신", "배치", "야간 처리" | DB Link 또는 파일 연동 |
| 인증/SSO | "SSO", "통합인증", "로그인 연동", "OAuth", "LDAP" | SSO/인증 연동 |
| 공공 데이터 | "공공데이터포털", "행정정보공유", "G4C", "표준API" | REST API |
| 결제 | "결제", "PG사", "카드사", "가상계좌" | REST API |
| 문자/알림 | "문자 발송", "SMS", "알림톡", "이메일 발송" | REST API |

---

### Step 2: 인터페이스 ID 부여

부여 규칙:
- 패턴: `IF-{시스템코드}-{3자리순번}` (순번은 001부터 시작)
- 예시: `IF-B-001`, `IF-EHR-001`, `IF-KSC-003`

순번 채번 규칙:
- 기존 인터페이스 목록이 있는 경우: 마지막 번호 이후부터 채번
- 신규 프로젝트: 001부터 채번
- 동일 외부 시스템과의 여러 인터페이스: 각각 별도 ID 부여 (한 시스템이라도 연동 목적이 다르면 분리)

---

### Step 3: 인터페이스 유형별 정의

#### 유형 1: REST API 연동

| 정의 항목 | 내용 |
|---|---|
| 연동방식 | REST API |
| 메서드 | GET / POST / PUT / DELETE |
| URL | 외부 시스템이 제공하는 엔드포인트 URL |
| 요청 파라미터 | 요청 시 전송할 필드명, 타입, 필수여부 |
| 응답 파라미터 | 응답으로 받는 필드명, 타입 |
| 인증방식 | API Key / Bearer Token / OAuth2.0 |
| 주기 | 실시간 / 배치(일1회, 시간1회 등) |

#### 유형 2: SOAP 웹서비스 연동

| 정의 항목 | 내용 |
|---|---|
| 연동방식 | SOAP |
| WSDL URL | 외부 시스템의 WSDL 주소 |
| 오퍼레이션명 | 호출할 SOAP 오퍼레이션 |
| 요청/응답 | XML 구조 정의 |

#### 유형 3: DB Link 연동

| 정의 항목 | 내용 |
|---|---|
| 연동방식 | DB Link |
| 연결 DB | 원격 DB 서버 정보 (DB명, 스키마) |
| 대상 테이블 | 조회/동기화할 테이블명 |
| 동기화 방향 | 단방향(읽기 전용) / 양방향 |
| 동기화 주기 | 실시간 / 야간배치(매일 02:00) 등 |
| 조건 | WHERE 조건 또는 델타 조건 (변경분만 등) |

#### 유형 4: 파일 연동

| 정의 항목 | 내용 |
|---|---|
| 연동방식 | 파일(FTP/SFTP/NFS) |
| 파일 형식 | CSV / TXT / XML / JSON / Excel |
| 전송 경로 | 소스 경로 → 대상 경로 |
| 파일명 규칙 | 예: `{시스템코드}_{YYYYMMDD}.csv` |
| 전송 주기 | 실시간 / 매일 / 매주 |
| 전송 방향 | 송신(내→외) / 수신(외→내) / 양방향 |

#### 유형 5: SSO/인증 연동

| 정의 항목 | 내용 |
|---|---|
| 연동방식 | SSO |
| 인증 프로토콜 | SAML 2.0 / OAuth 2.0 / OpenID Connect / LDAP |
| 인증서버 URL | 외부 인증 서버 주소 |
| 토큰 처리 | 토큰 발급 / 검증 / 갱신 / 만료 처리 방식 |
| 세션 연계 | SSO 세션과 로컬 세션 동기화 방안 |

---

### Step 4: 각 인터페이스 정의 항목 작성

각 인터페이스별로 아래 항목을 빠짐없이 작성한다:

| 항목 | 설명 |
|---|---|
| 인터페이스ID | IF-{시스템코드}-{순번} |
| 인터페이스명 | 연동 목적을 명확히 나타내는 명칭 |
| 연동대상 시스템 | 연동하는 외부 시스템명 및 주관기관 |
| 연동방식 | REST API / SOAP / DB Link / 파일 / SSO |
| 송수신 방향 | 송신(Send) / 수신(Receive) / 양방향(Both) |
| 데이터 항목 | 주고받는 데이터 필드 목록 (필드명, 타입, 설명) |
| 주기 | 실시간 / 배치 주기 |
| 오류 처리 | 연동 실패 시 재시도 횟수, 알림, 롤백 방안 |
| 관련 요구사항ID | 해당 인터페이스를 요구하는 요구사항ID |

## 체크포인트 (사용자 확인 필수)

인터페이스 목록 초안 생성 후 아래 문구로 확인을 요청한다:

> "인터페이스 목록이 맞는지 확인해주세요.
> - 식별된 외부 시스템 연동이 실제 연동 범위와 일치하는지
> - 연동방식(REST/DB Link/파일/SSO)이 올바른지
> - 누락된 연동이 있는지
> - 각 인터페이스의 데이터 항목이 충분히 정의되었는지
> 수정 또는 추가가 필요한 항목을 알려주시면 반영하겠습니다."

## 주의사항 / 규칙

1. **인터페이스ID 고유성**: 전체 프로젝트에서 인터페이스ID는 중복 불가. 시스템코드가 다른 연동 시스템이 있을 경우 시스템코드로 구분.
2. **개인정보 포함 연동**: 주민등록번호, 의료정보 등 민감 데이터가 포함된 인터페이스는 반드시 암호화 전송(TLS 1.2 이상) 명시.
3. **공공 API 연동**: 행정정보공유, G4C 등 공공 API는 해당 기관의 연동 신청 절차가 선행되어야 함을 비고란에 기재.
4. **오류 처리 필수**: 연동 장애 발생 시 서비스 중단을 최소화하는 폴백(Fallback) 방안을 반드시 정의.
5. **배치 연동 시**: 연동 실패 건의 재처리 방안 (배치 재실행 또는 수동 재처리 화면) 여부를 명시.
6. **SSO 연동 시**: 로그아웃 처리(로컬 세션 + SSO 세션 동시 만료) 방안을 반드시 정의.
7. **인터페이스 변경 시**: 연동 대상 외부 시스템 측과 사전 협의 후 변경해야 하며, 변경 이력을 비고란에 기재.
