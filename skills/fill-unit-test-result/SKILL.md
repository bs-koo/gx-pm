# 단위테스트 결과 기입 (fill-unit-test-result)

단위테스트계획서(DE-13)를 기반으로 테스트 수행 결과를 기입하여 단위테스트결과서(IM-03)를 완성한다.
결과서는 계획서와 동일한 구조(화면 목록, 검사항목 27개)를 유지하되, 검사기준 칸에 적합/부적합/해당없음이 채워진다.

---

## 검사항목 구조 (총 27개)

| 구분 | 항목번호 | 검사항목 내용 |
|------|---------|-------------|
| 공통부문 | (1)~(8) | 화면제목, 메뉴경로, 도움말, 권한, 필수값표시, 오류메시지, 공통코드, 인쇄 |
| 조회 | (1)~(4) | 검색조건, 결과목록, 페이징, 정렬 |
| 입력 | (1)~(6) | 저장기능, 입력유효성, 중복체크, 파일업로드, 초기화, 취소 |
| 수정 | (1)~(2) | 수정저장, 수정유효성 |
| 삭제 | (1)~(2) | 삭제확인팝업, 삭제후처리 |
| 첨부파일 | (1)~(3) | 업로드, 다운로드, 삭제 |
| 출력 | (1)~(2) | 출력레이아웃, 출력데이터 |

> "해당없음"은 계획서(DE-13) 작성 시 이미 결정된 것을 유지한다. 결과서 작성 단계에서 변경하지 않는다.

---

## Step 1: 기본 정보 수집

사용자에게 다음 정보를 확인한다.

```
- 프로젝트명:
- 시스템명:
- 테스트 실시자 (전체 동일이면 1명, 화면별로 다르면 "화면별 입력" 선택):
- 테스트 일자 (전체 동일이면 1개 날짜, 화면별로 다르면 "화면별 입력" 선택):
- 결재선 (작성자 / 검토자 / 승인자):
```

---

## Step 2: 입력 모드 선택

다음 3가지 모드 중 하나를 선택하도록 안내한다.

```
[단위테스트 결과 입력 모드를 선택하세요]

1. 전체 적합
   - 모든 "해당있음" 항목을 일괄 "적합"으로 기입
   - 부적합 항목이 없는 경우 사용

2. 부적합 목록 입력
   - 부적합 항목만 입력하고, 나머지는 자동으로 "적합" 처리
   - 권장 방식: 부적합이 소수일 때

3. 항목별 입력
   - 화면별로 하나씩 확인하며 입력
   - 정밀 입력이 필요할 때 사용
```

---

## Step 3-A: 전체 적합 처리

모드 1 선택 시:
- 계획서의 모든 "해당있음" 항목 → "적합" 기입
- "해당없음" 항목 → 그대로 유지
- 테스트 실시자, 테스트 일자 → Step 1에서 수집한 값으로 일괄 기입
- 부적합 관련 컬럼(부적합 내역, 원인, 조치내역, 조치일, 조치자)은 공란

---

## Step 3-B: 부적합 목록 입력 처리

모드 2 선택 시, 다음 형식으로 부적합 항목을 입력받는다.

```
[부적합 항목 입력 형식]
화면ID | 화면명 | 구분 | 항목번호 | 부적합 내역 | 원인 | 조치내역 | 조치일 | 조치자

예시:
SCR-001 | 사용자관리 | 입력 | (3) | 중복체크 미작동 | 쿼리 오류 | 조건절 수정 | 2025-03-10 | 홍길동
```

- 입력된 항목 → "부적합" 기입 + 조치 정보 채움
- 나머지 "해당있음" 항목 → 자동 "적합" 처리

---

## Step 3-C: 항목별 입력 처리

모드 3 선택 시, 화면 단위로 순서대로 확인한다.

```
[화면: SCR-001 사용자관리]
공통부문 (1)~(8) 결과를 입력하세요.
(해당없음 항목은 자동 스킵됩니다)

공통(1) 화면제목: [적합/부적합]
공통(2) 메뉴경로: [적합/부적합]
...

→ 부적합 항목 발생 시 즉시 조치 정보 요청
```

---

## Step 4: 부적합 항목 처리

부적합 항목이 있을 경우, 반드시 다음 5개 필드를 기입한다.

| 필드 | 내용 | 예시 |
|------|------|------|
| 부적합 내역 | 구체적으로 어떤 문제가 발생했는지 | "저장 버튼 클릭 시 오류 팝업 없이 넘어감" |
| 원인 | 기술적/프로세스적 원인 | "유효성 검사 로직 누락" |
| 조치내역 | 수행한 조치 내용 | "입력값 검증 로직 추가 및 오류메시지 처리" |
| 조치일 | 조치 완료일 (YYYY-MM-DD) | "2025-03-12" |
| 조치자 | 조치 수행자 성명 | "김개발" |

> 부적합 조치가 완료되지 않은 경우, 조치일과 조치자를 공란으로 두고 상태를 "조치중"으로 표시한다.

---

## Step 5: IM-03 결과서 출력

### 문서 헤더

```
문서번호: IM-03
문서명: 단위테스트결과서
프로젝트명: {프로젝트명}
시스템명: {시스템명}
작성일: {작성일}
작성자 / 검토자 / 승인자: {결재선}
```

### 결과서 본문 표 (화면별)

| 화면ID | 화면명 | 구분 | 항목번호 | 검사항목 | 계획여부 | 검사결과 | 부적합내역 | 원인 | 조치내역 | 조치일 | 조치자 | 테스트일자 | 테스트실시자 |
|--------|--------|------|---------|---------|---------|---------|----------|------|---------|--------|--------|-----------|------------|
| SCR-001 | 사용자관리 | 공통 | (1) | 화면제목 | 해당 | 적합 | | | | | | 2025-03-10 | 홍길동 |
| SCR-001 | 사용자관리 | 입력 | (3) | 중복체크 | 해당 | 부적합 | 중복체크 미작동 | 쿼리 오류 | 조건절 수정 | 2025-03-12 | 김개발 | 2025-03-10 | 홍길동 |
| SCR-001 | 사용자관리 | 출력 | (1) | 출력레이아웃 | 해당없음 | 해당없음 | | | | | | | |

---

## Step 6: 결과 통계 산출

결과서 하단에 다음 통계를 자동 산출하여 표시한다.

```
[단위테스트 결과 통계]

총 검사항목 (해당있음): N건
- 적합:    N건 (X%)
- 부적합:  N건 (X%)
해당없음:  N건

적합률: 적합 / (적합 + 부적합) × 100 = X%

※ 적합률 기준: 95% 이상 권장 (부적합 항목은 전수 조치 후 재검사 필요)
```

---

## 체크포인트 (사용자 확인 요청)

결과서 출력 전 다음 항목을 사용자에게 확인한다.

```
[최종 확인]
1. 부적합 항목 중 조치완료 되지 않은 항목이 있습니다. 계속 진행하시겠습니까?
   → 미조치 항목 목록을 함께 표시

2. 테스트 실시자 / 일자가 화면별로 다릅니다. 일괄 적용하시겠습니까?
   → 화면 목록과 현재 입력값 표시

3. 결과서를 최종 확정하시겠습니까? (확정 후에는 수정이 어렵습니다)
```

---

## 주의사항 및 규칙

1. "해당없음"은 계획서(DE-13)에서 결정된 것이므로 결과서 단계에서 임의 변경 금지
2. 부적합 항목은 반드시 5개 필드(내역/원인/조치내역/조치일/조치자) 전부 기입
3. 적합률이 95% 미만이면 경고 메시지 출력 및 PM 보고 권고
4. 동일 화면에서 동일 항목번호의 중복 입력은 불가
5. 결과서 문서번호 IM-03은 변경 불가 (공공 SI 표준 산출물 코드)
6. 테스트 실시자는 실제 테스트를 수행한 담당자 성명이어야 함 (PM 이름 대리 기입 금지)
