# 요구사항 추출 (extract-requirements)

RFP, 과업지시서, 제안서 등의 텍스트에서 기능/비기능 요구사항을 추출하고, AN-02 요구사항정의서 양식에 맞는 구조화된 데이터를 생성한다.

## 입력

사용자로부터 다음 중 하나를 받는다:
- RFP/과업지시서 텍스트 (붙여넣기)
- 파일 업로드 (PDF, HWP 텍스트, Word)
- 구두 설명

추가로 확인할 정보:
- 시스템 코드 (A~I 중 해당 코드, 또는 새 프로젝트면 코드 정의)
- 시스템 접두어 (화면ID에 사용할 3~4자리 영문, 예: EHR, KSC)

## 처리 절차

### Step 1: 시스템 정보 확인
- 시스템 코드와 접두어를 사용자에게 확인
- 기존 산출물이 있으면 기존 코드 체계를 따름

### Step 2: 요구사항 추출
문서에서 다음 패턴으로 요구사항을 식별한다:
- "~해야 한다", "~를 제공한다", "~기능을 구현한다"
- "ㅇ" 또는 "o"로 시작하는 기능 항목
- 번호가 매겨진 기능 목록
- "기능 요구사항", "비기능 요구사항" 섹션의 항목

### Step 3: 분류
각 요구사항을 분류한다:
- **구분**: 기능 / 비기능
- **근거**: 과업지시서 / 제안서 / 협의사항
- **대분류**: 업무 영역 (시스템관리, 교육관리 등)
- **중분류**: 세부 업무 (권한관리, 코드관리 등)
- **소분류**: 상세 기능 (선택)

### Step 4: ID 부여
- 요구사항ID: `{시스템코드}-RE-{3자리순번}` (예: B-RE-001)
- 순번은 001부터 시작

### Step 5: 수용여부 초안
- 명확한 기능 → "수용"
- 모호하거나 범위 초과 → "부분수용" + 사유
- 기술적 불가 → "불가" + 사유

## 출력 형식

마크다운 표로 출력한다:

```
## 요구사항정의서 (기능) — {시스템명}

| 제안요청ID | 요구사항ID | 구분 | 근거 | 대분류 | 중분류 | 소분류 | 요구내역 | 요구사항 상세내역 | 수용여부 |
|-----------|-----------|------|------|--------|--------|--------|---------|-----------------|---------|
| SFR-001 | B-RE-001 | 기능 | 과업지시서 | ... | ... | | ㅇ ... | ... | 수용 |
```

## 주의사항

- 하나의 제안요청ID에 여러 요구사항이 포함될 수 있음
- 요구사항은 가능한 원문 표현을 유지 (해석하지 않음)
- "ㅇ" 기호로 시작하는 항목은 각각 별도 요구사항으로 분리
- 상세내역이 길면 핵심만 요약하되, 원문 참조를 명시
