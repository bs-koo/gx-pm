# 회의록 작성 (meeting-notes)

회의 내용(텍스트, 메모, 녹취 전사, 슬랙/메신저 대화)을 입력받아
공공/SI 프로젝트 표준 회의록으로 구조화한다.

---

## 지원 회의 유형

| 유형 | 설명 | 주요 참석자 |
|------|------|-----------|
| 착수보고회 | 프로젝트 시작 공식 보고 | 발주처 + 개발팀 + (감리단) |
| 주간회의 | 매주 진행상황 공유 | 발주처 + 개발팀 |
| 중간보고회 | 단계 완료 중간 보고 | 발주처 + 개발팀 + (감리단) |
| 감리회의 | 감리단 지적 및 확인 | 발주처 + 감리단 + 개발팀 |
| 검수회의 | 최종 산출물 검수 | 발주처 + (감리단) + 개발팀 |
| 실무회의 | 개발팀 내부 협의 | 개발팀 (PM, 개발자) |

---

## Step 1: 입력 유형 파악

사용자 입력을 자동으로 판별하거나, 다음 중 선택하도록 안내한다.

```
[입력 유형 선택]
1. 녹취 전사 텍스트
   - 발화자 구분이 포함된 전사 텍스트
   - 예: "홍PM: 이번 주 화면 설계 완료했습니다. / 발주처김팀장: 일정이 맞나요?"

2. 메모/요약 텍스트
   - 회의 중 작성한 불완전한 메모
   - 예: "UI 변경 요청, 인증 방식 논의, 다음주까지 목록 화면 완료"

3. 슬랙/메신저 대화
   - 채팅 형식의 텍스트 (시간+이름+메시지)
   - 예: "[14:23] 홍길동: 기능 명세서 수정 부탁드립니다"
```

---

## Step 2: 기본 정보 수집

입력 내용에서 자동 추출을 시도하고, 추출 불가 항목은 사용자에게 확인한다.

```
[회의 기본 정보]
- 회의 유형: (착수보고회 / 주간회의 / 중간보고회 / 감리회의 / 검수회의 / 실무회의)
- 회의명: (예: 2025년 3월 3주차 주간회의)
- 일시: YYYY-MM-DD HH:MM ~ HH:MM
- 장소: (예: 발주처 3층 대회의실 / 화상회의(Zoom))
- 프로젝트명:
- 회의록 번호: {프로젝트코드}-MTG-{순번} (예: GXPM-MTG-012)
- 작성자:
```

---

## Step 3: 참석자 파악 및 구분

참석자를 발주처/감리단/개발팀으로 구분하여 정리한다.

```
[참석자 구분 형식]

발주처: 소속 | 직위 | 성명
감리단: 소속 | 직위 | 성명  (해당 없으면 생략)
개발팀: 소속 | 역할 | 성명
```

| 구분 | 소속 | 직위/역할 | 성명 |
|------|------|---------|------|
| 발주처 | 행정지원과 | 팀장 | 김발주 |
| 감리단 | OO감리법인 | 수석감리원 | 이감리 |
| 개발팀 | OO정보 | PM | 홍길동 |
| 개발팀 | OO정보 | 개발자 | 박개발 |

---

## Step 4: 입력 유형별 처리

### 4-A. 녹취 전사 처리

1. 발화자별 발언을 정리
2. 안건별로 발언을 묶어 논의 내용 구성
3. 결정사항/지시사항/협의사항을 발언에서 추출
4. 액션아이템으로 이어지는 발언 식별

### 4-B. 메모/요약 처리

1. 단편적 메모를 안건 단위로 재구성
2. 동사 표현(~하기로, ~요청, ~결정)으로 결정사항 식별
3. 담당자 이름이 언급된 항목을 액션아이템으로 추출
4. 모호한 항목은 사용자에게 확인 요청

### 4-C. 슬랙/메신저 대화 처리

1. 타임스탬프와 발신자 분리
2. 요청/답변 쌍으로 결정사항 식별
3. "완료", "확인", "결정" 키워드 중심으로 확정 사항 추출
4. 파일 공유, 링크 등은 참고자료로 분리

---

## Step 5: 공공/SI 특화 항목 추출

### 지시사항 (발주처 → 개발팀)

발주처가 개발팀에 지시하거나 요구한 사항을 별도 추출한다.
이행 여부를 차기 회의에서 확인해야 하는 공식 지시 사항이다.

| # | 지시사항 | 지시자 | 수신자 | 이행기한 | 이행상태 |
|---|---------|--------|--------|---------|---------|
| 1 | 화면 설계서 재작성 후 재제출 | 김발주 팀장 | PM 홍길동 | 2025-03-21 | 미완료 |

### 협의사항 (발주처 ↔ 개발팀 합의)

양측이 합의한 사항을 별도 추출한다.

| # | 협의내용 | 협의결과 | 비고 |
|---|---------|---------|------|
| 1 | 로그인 인증 방식 | SAML 2.0 적용으로 최종 합의 | 추가 공수 검토 필요 |

## 체크포인트 (사용자 확인 요청)

```
[회의록 작성 전 확인]
1. 입력 내용에서 발주처 지시사항으로 분류된 항목이 있습니다. 확인해주세요.
2. 액션아이템의 기한이 명시되지 않은 항목이 있습니다. 기한을 지정하시겠습니까?
3. 회의록 번호를 {프로젝트코드}-MTG-{순번}으로 부여합니다. 순번이 맞습니까?
4. 감리회의의 경우 지적사항을 /audit-response 스킬로 연결하시겠습니까?
```

---

## 주의사항 및 규칙

1. 회의록 번호 형식 {프로젝트코드}-MTG-{순번}은 반드시 준수 (프로젝트 식별자 포함)
2. 지시사항과 협의사항은 반드시 구분하여 별도 섹션에 기록
3. 감리회의 회의록은 감리단의 지적사항을 "지시사항" 섹션에 별도 기록
4. 참석자 성명은 확인 가능한 경우 직위/소속과 함께 기재
5. 액션아이템 담당자가 불명확한 경우 공란 처리 후 사용자에게 확인 요청
6. 결정사항과 단순 논의사항을 혼동하지 않도록 구분 (합의된 사항만 결정사항)
7. 차기 회의 정보가 없는 경우 해당 섹션 생략 가능
