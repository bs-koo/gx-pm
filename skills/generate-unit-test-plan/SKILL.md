# 단위테스트계획서 생성 (generate-unit-test-plan)

화면목록표(DE-03)의 화면 목록을 기반으로, 각 화면의 유형을 판별하고 검사기준을 자동 매핑하여 DE-13 단위테스트계획서 데이터를 생성한다.

## 입력

다음 중 하나:
- 화면목록표 데이터 (마크다운 표 또는 텍스트)
- 화면목록표 Excel 파일 업로드
- `/pm-design` 결과로 생성된 화면목록

필요 정보:
- 시스템 코드 (A~I)
- 화면별 사용자구분 (관리자/일반사용자/민원인)

## 처리 절차

### Step 1: 화면 목록 파싱
화면목록표에서 추출:
- 기능구분ID, 기능구분명
- 기능ID, 기능명
- 화면ID, 화면명

### Step 2: 화면 유형 판별
화면명과 기능명에서 유형을 추론한다:

| 키워드 | 화면 유형 |
|--------|----------|
| 목록, 리스트, 조회, 현황, 이력 | 목록형 |
| 등록, 신청, 작성, 입력 | 등록형 |
| 수정, 편집, 변경 | 수정형 |
| 상세, 보기, 확인 | 상세형 |
| 관리 (단독) | CRUD 통합형 |
| 매핑, 설정, 배정 | 설정형 (≈ 수정형) |
| 대시보드, 통계 | 조회형 (≈ 목록형) |
| 팝업 | 부모 화면 유형 따름 |

### Step 3: 검사기준 자동 매핑
화면 유형에 따라 적합/해당없음을 자동 배정:

**목록형:**
- 공통(1~8): 모두 해당
- 조회(1~4): 모두 해당
- 입력(1~6): 해당없음
- 수정(1~2): 해당없음
- 삭제(1~2): 해당없음
- 첨부(1~3): 해당없음
- 출력(1~2): 해당 (엑셀 다운로드 등)

**등록형:**
- 공통(1~8): 모두 해당
- 조회(1~4): 해당없음
- 입력(1~6): 모두 해당
- 수정(1~2): 해당없음
- 삭제(1~2): 해당없음
- 첨부(1~3): 해당 (파일 업로드 있으면)
- 출력(1~2): 해당없음

**수정형:**
- 공통(1~8): 모두 해당
- 조회(1~4): 해당없음
- 입력(1~6): 해당없음
- 수정(1~2): 모두 해당
- 삭제(1~2): 해당 (삭제 기능 있으면)
- 첨부(1~3): 해당 (파일 기능 있으면)
- 출력(1~2): 해당없음

**상세형:**
- 공통(1~8): 모두 해당
- 조회(1~4): 해당 (상세 조회)
- 입력~삭제: 해당없음
- 첨부(1~3): 해당없음
- 출력(1~2): 해당 (인쇄 등)

**CRUD 통합형:**
- 모든 검사기준: 해당

### Step 4: 단위테스트ID 부여
- 패턴: `U_{화면ID}`
- 예시: `U_EHR_01_01_010`

### Step 5: 사용자구분 판별
- 관리자 전용 (시스템관리, 권한관리 등) → "관리자"
- 일반 사용자 화면 → "일반사용자"
- 민원/외부 화면 → "민원인"
- 판별이 어려우면 사용자에게 확인

## 출력 형식

```
## 단위테스트계획서 — {시스템명}

| 기능구분ID | 기능구분명 | 기능ID | 기능명 | 화면ID | 화면명 | 사용자 | 테스트ID | (1) | (2) | ... | (8) | 조회(1) | ... |
|-----------|-----------|--------|--------|--------|--------|--------|---------|-----|-----|-----|-----|---------|-----|
| EHR_01 | 시스템관리 | EHR_01_01 | 권한관리 | EHR_01_01_010 | 운영자 권한 관리 | 관리자 | U_EHR_01_01_010 | | | ... | | | ... |
```

계획서이므로 적합/부적합 칸은 빈칸으로 둔다. 화면 유형에 따라 "해당없음"만 미리 기입한다.

## 체크포인트

화면 유형 판별 결과를 사용자에게 확인:
"다음 화면 유형 판별이 맞는지 확인해주세요:
- EHR_01_01_010 (운영자 권한 관리) → CRUD 통합형
- EHR_01_01_020 (권한-메뉴 매핑) → 설정형
- ..."
