# 감리 대응 (audit-response)

감리 지적사항을 입력받아 유형별로 분류하고, 원인 분석, 조치 계획,
증빙 체크리스트를 포함한 감리 대응 문서를 생성한다.
DE-17 과업이행여부증적에 반영할 사항과 후속 산출물 생성 커맨드를 함께 안내한다.

---

## 감리 지적사항 유형 5가지

| 유형 | 설명 | 일반적 원인 |
|------|------|-----------|
| 산출물 누락 | 필수 산출물이 미제출되었거나 목록에 없음 | 산출물 목록 미관리, 일정 지연 |
| 내용 미흡 | 산출물이 있으나 내용이 부족하거나 오류 | 작성 기준 미숙지, 검토 부재 |
| 추적성 부족 | 요구사항-설계-구현-테스트 간 ID 매핑 누락 | 추적매트릭스 미관리, ID 체계 미통일 |
| 품질 미달 | 테스트 커버리지 부족, 코드 품질 기준 미충족 | 테스트 계획 미수립, 자동화 도구 미사용 |
| 절차 미준수 | 변경관리, 형상관리, 승인 절차 위반 | 내부 프로세스 미준수, 이력 미기록 |

---

## 유형별 일반 조치 패턴

### 산출물 누락
- 조치: 해당 산출물 즉시 작성 + 산출물 관리대장에 등록
- 증적: 산출물 파일 + 등록 이력 + 결재 완료 스크린샷
- 후속 커맨드: `/pm-design`, `/pm-test`, `/pm-trace` (누락 산출물 유형에 따라)

### 내용 미흡
- 조치: 산출물 보완 작성 + 변경 이력(개정번호) 기록 + 재검토 이력 추가
- 증적: 보완된 산출물(개정본) + 검토 확인서 또는 검토 이메일
- 후속 커맨드: 해당 산출물 생성 스킬 재실행

### 추적성 부족
- 조치: 추적매트릭스(AN-05) 갱신 + 요구사항-화면-테스트케이스 ID 전수 매핑
- 증적: 갱신된 추적매트릭스(AN-05) + ID 매핑 현황표
- 후속 커맨드: `/pm-trace`

### 품질 미달
- 조치: 단위/통합 테스트 보강 + 코드 리뷰 수행 + 테스트 결과 문서화
- 증적: 테스트결과서(IM-03/TE-02) + 코드 리뷰 체크리스트 + 테스트 커버리지 보고서
- 후속 커맨드: `/pm-test`

### 절차 미준수
- 조치: 변경관리 이력 소급 작성 + 형상관리 이력 정비 + 승인 이력 추가 확보
- 증적: 변경요청서(CR) + 변경관리대장 + 형상관리 로그
- 후속 커맨드: `/pm-design`

## Step 1: 지적사항 입력 및 파악

사용자에게 지적사항을 입력받는다.

```
[지적사항 입력 형식]
번호 | 지적사항 내용 | 지적일 | 감리원 성명

예시:
1 | 화면설계서(DE-05) 내 일부 화면의 입력 유효성 규칙이 기재되지 않음 | 2025-03-18 | 이감리
2 | 요구사항추적매트릭스(AN-05)에서 기능요구사항 17건의 테스트케이스 매핑 누락 | 2025-03-18 | 이감리
3 | 2차 변경요청(CR-002)에 대한 변경관리위원회 승인 이력 없음 | 2025-03-18 | 박감리
```

---

## Step 2: 유형 자동 분류 및 확인

입력된 지적사항을 5개 유형으로 자동 분류하고 사용자에게 확인한다.

```
[자동 분류 결과 확인]
지적 #1 → 내용 미흡 (화면설계서 내용 부족)
지적 #2 → 추적성 부족 (추적매트릭스 ID 매핑 누락)
지적 #3 → 절차 미준수 (변경관리 승인 이력 없음)

분류가 맞으면 "확인", 수정이 필요하면 번호와 올바른 유형을 입력하세요.
```

---

## Step 3: 시급도 판단

감리 종료일을 기준으로 각 지적사항의 조치 시급도를 자동 판단한다.

```
[시급도 판단 기준]
- D-3 이하: 긴급 (즉시 착수 필요)
- D-4 ~ D-7: 높음 (당일 착수 필요)
- D-8 ~ D-14: 보통 (이번 주 내 착수)
- D-15 이상: 낮음 (일정 내 처리)

감리 종료일: {YYYY-MM-DD}
오늘: {오늘 날짜}
남은 일수: D-{N}일

→ 전체 시급도: {긴급/높음/보통/낮음}
```

---

## Step 4: 조치계획 수립

각 지적사항에 대해 담당자와 완료 예정일을 입력받는다.

```
[조치계획 입력 형식]
지적번호 | 담당자 | 완료예정일

예시:
1 | 김설계 | 2025-03-21
2 | 홍길동(PM) | 2025-03-20
3 | 홍길동(PM) | 2025-03-19
```

담당자 미입력 시 PM을 기본값으로 제안한다.

---

## Step 5: 증빙 체크리스트 자동 생성

지적 유형에 따라 필요한 증빙 목록을 자동으로 생성한다.

### 유형별 증빙 체크리스트

| 유형 | 필수 증빙 | 선택 증빙 |
|------|---------|---------|
| 산출물 누락 | 완성된 산출물 파일, 산출물관리대장 등록 이력 | 결재 완료 문서 |
| 내용 미흡 | 개정된 산출물(개정번호 표기), 개정 이력표 | 검토 확인 이메일 |
| 추적성 부족 | 갱신된 추적매트릭스(AN-05), ID 매핑 현황표 | 요구사항 목록 대조표 |
| 품질 미달 | 테스트결과서(IM-03 또는 TE-02), 코드리뷰 체크리스트 | 테스트 커버리지 보고서 |
| 절차 미준수 | 변경요청서(CR), 변경관리대장, 회의록(승인 근거) | 형상관리 시스템 로그 |

---

## Step 6: DE-17 과업이행여부증적 반영 안내

조치 완료된 사항은 DE-17 과업이행여부증적에 반영해야 한다.

```
[DE-17 반영 안내]

지적 #1 (내용 미흡 - 화면설계서):
→ DE-17 항목: 설계 단계 / 화면설계서(DE-05)
→ 기재 내용: "감리 지적에 따라 입력 유효성 규칙 보완 작성 완료 (개정번호 v1.1)"
→ 증빙 등록: 보완된 화면설계서 파일 첨부

지적 #2 (추적성 부족 - 추적매트릭스):
→ DE-17 항목: 설계 단계 / 요구사항추적매트릭스(AN-05)
→ 기재 내용: "누락된 17건 테스트케이스 ID 매핑 완료"
→ 증빙 등록: 갱신된 AN-05 파일 첨부
```

## 체크포인트 (사용자 확인 요청)

```
[최종 확인]
1. 시급도 "긴급" 항목이 있습니다 (D-{N}일). 즉시 착수하시겠습니까?
2. 담당자가 지정되지 않은 지적사항이 있습니다. PM을 기본 담당자로 지정할까요?
3. 증빙 체크리스트 중 미준비 항목이 있습니다. 해당 산출물을 지금 생성하시겠습니까?
   → 후속 커맨드: /pm-design / /pm-test / /pm-trace
4. DE-17 반영 내용을 확인하셨습니까? 감리 종료 전 반드시 등록이 필요합니다.
```

## 주의사항 및 규칙

1. 감리 지적사항은 감리 종료일 전까지 전수 조치 완료가 원칙 (공공 계약 조건)
2. 유형 분류는 자동 제안이며, 반드시 PM이 최종 확인 후 확정
3. 증빙 산출물은 반드시 파일명과 버전(개정번호)을 명시하여 관리
4. DE-17 과업이행여부증적은 감리 대응 완료 후 가장 먼저 업데이트
5. 동일 산출물에 복수 지적이 있는 경우 한 번의 보완으로 통합 대응 가능 (통합 처리 시 증빙은 각각 제출)
6. 절차 미준수 지적의 소급 작성은 감리원에게 사전 협의 후 진행 권고
7. 조치 완료된 항목은 상태를 "완료"로 업데이트하고 감리원에게 즉시 통보
